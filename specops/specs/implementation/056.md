# Implementation: SingleShapePointValidator

## 1. Module location

```
src/gtfs_validator/validators/single_shape_point.py
```

## 2. Function signature

```python
def validate_single_shape_point(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

`ctx` is accepted but unused; the validator is a single-table group-by count check.

## 3. Notice definitions

### `single_shape_point` — WARNING

Emitted once per distinct `shape_id` that appears in exactly one row of `shapes.txt`.

```python
Notice(
    code="single_shape_point",
    severity=Severity.WARNING,
    fields={
        "shape_id": str,        # the shape_id with only one associated point row
        "csv_row_number": int,  # csv_row_number of the sole occurrence
    },
)
```

The `fields` dict contains exactly two keys: `shape_id` and `csv_row_number`.

## 4. Implementation approach

### Guard clauses (return `[]` immediately if)

1. `"shapes"` is not in `feed` — file absent, nothing to validate.
2. `feed["shapes"].is_empty()` — file present but empty, no rows to group.

### Algorithm (Polars, group-by count)

This is a pure single-table aggregation. No cross-table join is required.

```
# Step 1: group by shape_id, count rows, and capture last csv_row_number
counts = (
    feed["shapes"]
    .group_by("shape_id")
    .agg(
        pl.len().alias("point_count"),
        pl.col("csv_row_number").last().alias("csv_row_number"),
    )
    .filter(pl.col("point_count") == 1)
)

# Step 2: emit one notice per row in the filtered result
FOR row IN counts.iter_rows(named=True):
    EMIT Notice(
        code="single_shape_point",
        severity=WARNING,
        fields={
            "shape_id": row["shape_id"],
            "csv_row_number": row["csv_row_number"],
        },
    )
```

### Why `.last()` for `csv_row_number`

The Java implementation overwrites `shapePointRowNumbers[shapeId]` on every iteration, so the stored value is always the last row seen in file order. Using `.last()` faithfully mirrors this. When the count equals exactly 1 — the only case that triggers a notice — `.first()` and `.last()` are interchangeable because there is only one row. `.last()` is used for semantic alignment with the Java behavior.

### Polars note: `pl.len()` vs `pl.count()`

Use `pl.len()` (Polars ≥ 0.20) to count all rows in the group, including any with null values. `pl.count("shape_id")` would exclude nulls and could undercount. Since `shape_id` is a required field and nulls are handled at load time, both produce the same result in practice — but `pl.len()` is the correct and idiomatic choice.

### Output ordering

The output order of notices depends on Polars `group_by` hashing, which is not guaranteed to be stable. Tests should not assert a particular notice order; use set membership or sort before asserting when multiple notices are expected.

## 5. Registry entry

Add to `VALIDATOR_REGISTRY` in `src/gtfs_validator/validators/__init__.py`:

```python
from gtfs_validator.validators.single_shape_point import validate_single_shape_point

# In VALIDATOR_REGISTRY list:
ValidatorEntry(
    name="single_shape_point",
    fn=validate_single_shape_point,
    requires=["shapes"],
),
```

The `requires` list contains only `"shapes"`. No other tables are consulted.

Place the entry near the other shapes-related validators (`shape_increasing_distance`, `shape_usage`, `shape_to_stop_matching`).

Test file: `tests/test_validators/test_single_shape_point.py`

### Fixtures / helpers

```python
from datetime import date
import polars as pl
import pytest
from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Severity
from gtfs_validator.validators.single_shape_point import validate_single_shape_point

CTX = ValidationContext(country_code="US", date_for_validation=date(2024, 1, 1))

def make_shapes(
    shape_ids: list[str],
    csv_row_numbers: list[int],
    sequences: list[int] | None = None,
) -> pl.DataFrame:
    """Minimal shapes DataFrame with the columns the validator reads."""
    n = len(shape_ids)
    return pl.DataFrame({
        "shape_id": shape_ids,
        "csv_row_number": csv_row_numbers,
        "shape_pt_sequence": sequences if sequences is not None else list(range(1, n + 1)),
    })
```

- shapes: `[("first shape id", 1, 1), ("first shape id", 2, 2)]` — one shape, two points
- Expected: `notices == []`

**`test_single_point_shape_emits_notice`**

- Expected: exactly 1 notice
  - `code == "single_shape_point"`
  - `severity == Severity.WARNING`
  - `fields["shape_id"] == "second shape id"`
  - `fields["csv_row_number"] == 3`

**`test_shapes_empty_no_notice`**

**`test_all_shapes_multiple_points_no_notice`**

---

**`test_csv_row_number_is_sole_occurrence_row`**

Verifies the `csv_row_number` field carries the row number of the only row for that shape.

- shapes: `[("s1", 42, 1)]` — single row with csv_row_number 42
- Expected: 1 notice with `fields["csv_row_number"] == 42`

---

**`test_notice_fields_are_complete`**

Assert that `fields` contains exactly the keys `{"shape_id", "csv_row_number"}` and no others.

- shapes: `[("s1", 1, 1)]`
- Expected: 1 notice; `set(notice.fields.keys()) == {"shape_id", "csv_row_number"}`

---

**`test_ctx_unused`**

Pass a `ValidationContext` with obviously wrong values and assert the result is identical to the normal case.

- shapes: `[("s1", 1, 1)]`
- ctx_wrong: `ValidationContext(country_code="XX", date_for_validation=date(1900, 1, 1))`
- Expected: same 1 notice as the normal-ctx call — confirms `ctx` has no effect

---

**`test_mixed_single_and_multi_point_shapes`**

Ensures only the single-point shapes are flagged when the feed contains a mix.

- shapes:
  - `("multi", 1, 1)`, `("multi", 2, 2)`, `("multi", 3, 3)` — 3 points
  - `("solo_a", 4, 1)` — 1 point
  - `("solo_b", 5, 1)` — 1 point
- Expected: exactly 2 notices with `shape_id` in `{"solo_a", "solo_b"}`; `"multi"` not present in any notice
