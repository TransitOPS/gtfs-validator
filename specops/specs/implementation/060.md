# Implementation: StopTimeArrivalAndDepartureTimeValidator

## 1. Module Location

**Validator:** `src/gtfs_validator/validators/stop_time_arrival_departure.py`

This is a single-table validator that reads only `stop_times.txt`. No
cross-table joins are required. Two checks are performed in a single pass:

- **Check 1** (vectorized) — each row must have either both `arrival_time`
  and `departure_time` present, or both absent.
- **Check 2** (stateful, plain Python) — within each trip, no stop's
  `arrival_time` may be earlier than the most recent preceding stop's
  `departure_time`.

No new shared utilities are needed.

## 2. Function Signature

from __future__ import annotations

def validate_stop_time_arrival_departure(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,

## 3. Notice Definitions

### `stop_time_with_only_arrival_or_departure_time` (ERROR)

Emitted once per `stop_times.txt` row where exactly one of `arrival_time`
or `departure_time` is present (XOR condition).

```python
Notice(
    code="stop_time_with_only_arrival_or_departure_time",
    severity=Severity.ERROR,
    fields={
        "csv_row_number": <int>,       # 1-based row number from loader
        "trip_id":        <str>,       # stop_times.trip_id
        "stop_sequence":  <int>,       # stop_times.stop_sequence
        "specified_field": <str>,      # "arrival_time" or "departure_time"
    },
)
```

`specified_field` is the name of the field that IS present:
- `"arrival_time"` when only `arrival_time` is non-null.
- `"departure_time"` when only `departure_time` is non-null.

### `stop_time_with_arrival_before_previous_departure_time` (ERROR)

Emitted when a stop's `arrival_time` is strictly less than the
`departure_time` of the most recently preceding stop (within the same trip)
that carried a `departure_time`.

```python
Notice(
    code="stop_time_with_arrival_before_previous_departure_time",
    severity=Severity.ERROR,
    fields={
        "csv_row_number":      <int>,  # row number of the current (offending) stop
        "prev_csv_row_number": <int>,  # row number of the previous stop whose departure is used
        "trip_id":             <str>,  # shared trip_id
        "arrival_time":        <int>,  # current stop's arrival_time (seconds since midnight)
        "departure_time":      <int>,  # previous stop's departure_time (seconds since midnight)
    },
)
```

The comparison is strictly less-than: equal times do not trigger a notice.

## 4. Implementation Approach

### Guard clauses

```
if "stop_times" not in feed:
    return []
if feed["stop_times"].is_empty():
    return []
```

After the guards, collect all notices from Check 1 and Check 2 into a single
`list[Notice]` and return it.

### Required columns

```python
_REQUIRED_COLS = {"csv_row_number", "trip_id", "stop_sequence",
                  "arrival_time", "departure_time"}
```

If any of these columns is absent from the DataFrame header, return `[]`.
The loading layer injects null cells for missing values within an existing
column, but it does not add columns that were entirely absent from the file
header. Returning `[]` when required columns are missing is safe because the
load-time validator would already have flagged missing required fields.

### Check 1: Arrival/departure pairing (vectorized)

```
stop_times = feed["stop_times"]

has_arrival   = pl.col("arrival_time").is_not_null()
has_departure = pl.col("departure_time").is_not_null()

# XOR: exactly one is present
offenders = stop_times.filter(has_arrival != has_departure)

for row in offenders.iter_rows(named=True):
    specified_field = "arrival_time" if row["arrival_time"] is not None
                      else "departure_time"
    emit Notice(
        code="stop_time_with_only_arrival_or_departure_time",
        severity=Severity.ERROR,
        fields={
            "csv_row_number": row["csv_row_number"],
            "trip_id":        row["trip_id"],
            "stop_sequence":  row["stop_sequence"],
            "specified_field": specified_field,
        },
    )
```

Using `iter_rows` on the offender subset is acceptable because the number of
offending rows is bounded and each row must produce one `Notice` object.

### Check 2: Arrival before previous departure (plain Python, per-trip)

Check 2 requires ordered, stateful traversal within each trip group. Plain
Python is preferred over forced Polars for this type of stateful scan (per
AGENTS.md).

```
# Sort once globally: primary key = trip_id, secondary = stop_sequence
sorted_st = stop_times.sort(["trip_id", "stop_sequence"])

for trip_df in sorted_st.partition_by("trip_id", maintain_order=True):
    rows = trip_df.select([
        "csv_row_number", "trip_id", "stop_sequence",
        "arrival_time", "departure_time",
    ]).iter_rows(named=True)

    prev_dep_row = None   # most recent row that had a departure_time

    for row in rows:
        arrival   = row["arrival_time"]
        departure = row["departure_time"]

        if arrival is not None and prev_dep_row is not None:
            if arrival < prev_dep_row["departure_time"]:
                emit Notice(
                    code="stop_time_with_arrival_before_previous_departure_time",
                    severity=Severity.ERROR,
                    fields={
                        "csv_row_number":      row["csv_row_number"],
                        "prev_csv_row_number": prev_dep_row["csv_row_number"],
                        "trip_id":             row["trip_id"],
                        "arrival_time":        arrival,
                        "departure_time":      prev_dep_row["departure_time"],
                    },
                )

        if departure is not None:
            prev_dep_row = row
```

Key points:
- `prev_dep_row` is reset to `None` at the start of each trip group.
- `prev_dep_row` is updated whenever a row has a non-null `departure_time`,
  regardless of whether that row also triggered Check 1 or Check 2.
- A row with only `arrival_time` (no `departure_time`) participates in
  Check 2 as a potential current row but does NOT update `prev_dep_row`.
- A row with only `departure_time` (no `arrival_time`) updates
  `prev_dep_row` for future comparisons but does not trigger Check 2's
  comparison on that row.
- Both checks run independently; a row can trigger both simultaneously.

### Time representation

`arrival_time` and `departure_time` are loaded as nullable integers
(seconds since midnight). Values may exceed 86400 for trips operating past
midnight. Direct integer `<` comparison is used for Check 2.

### Guard clause ordering

1. `"stop_times"` not in feed → return `[]`.
2. `feed["stop_times"].is_empty()` → return `[]`.
3. Required columns absent → return `[]`.
4. Run Check 1 (vectorized filter → emit notices).
5. Run Check 2 (sort + partition_by → stateful per-trip scan → emit notices).
6. Return combined `notices` list.
