validator and is not shared with any existing notice.

with `single_row=True`. The relevant columns consumed at runtime are:

- `feed_info.txt`: `feed_contact_email` (optional EMAIL), `feed_contact_url`

time — the loading pipeline attaches it. Do not derive it via `with_row_index`.

No schema changes are required. Both `feed_contact_email` and `feed_contact_url`
already exist in `FEED_INFO` as optional columns.

## 3. Notice Definitions

### `missing_feed_contact_email_and_url`

Severity: **WARNING**

Emitted when a row in `feed_info.txt` has neither `feed_contact_email` nor
`feed_contact_url` set to a non-blank value. The GTFS Best Practices recommend
that feeds provide at least one contact field so that consumers can reach the
feed publisher.

```python
Notice(
    code="missing_feed_contact_email_and_url",
    severity=Severity.WARNING,
    fields={
        "csv_row_number": <int>,   # CSV row number of the offending row
    },
)
```

**Blank semantics:** A field is considered blank if it is `null` (absent from
the CSV or an empty cell) or if its string value, after stripping leading and
trailing whitespace, is empty. This mirrors the Java `!hasX() || x().isBlank()`
pattern:

- `!entity.hasFeedContactEmail()` — maps to `is_null()` in Polars.
- `entity.feedContactEmail().isBlank()` — maps to `str.strip_chars() == ""`.

After the two-phase load, absent or empty CSV cells for optional string columns
arrive as `null` in Polars. A whitespace-only string (e.g., `"   "`) that
survived loading arrives as a non-null Polars string and is caught by the strip
check. The `is_blank` helper below handles both cases faithfully.

## 4. Implementation Approach

```
function validate_feed_contact(feed, ctx):

    # --- Skip guard ---
    if "feed_info" not in feed or feed["feed_info"].is_empty():
        return []

    df = feed["feed_info"]
    notices = []

    # Helper: a field is blank when it is null or strips to ""
    def is_blank(col: str) -> pl.Expr:
        return pl.col(col).is_null() | (pl.col(col).str.strip_chars() == "")

    # Filter rows where both contact fields are blank
    violating = df.filter(
        is_blank("feed_contact_email") & is_blank("feed_contact_url")
    )

    for row in violating.iter_rows(named=True):
        notices.append(Notice(
            code="missing_feed_contact_email_and_url",
            severity=Severity.WARNING,
            fields={"csv_row_number": row["csv_row_number"]},
        ))

    return notices
```

**Key design decisions:**

- **Single vectorized filter pass.** The entire check is expressed as one Polars
  filter expression over the `feed_info` DataFrame. No Python-level row iteration
  is required except to build `Notice` objects from the (at most one) violating
  row.

- **`is_blank` helper is a module-level pure function.** Defining it as a named
  helper inside the function body keeps the filter expression readable. It can
  also be extracted as a module-level helper if re-used by other validators.

- **`iter_rows` on the filtered subset only.** Because `feed_info.txt` is a
  single-row table (`single_row=True`), at most one row is ever processed. The
  Python loop imposes no performance concern.

- **No column-presence guard needed.** The schema defines `feed_contact_email`
  and `feed_contact_url` as optional columns of `feed_info.txt`. The loading
  pipeline ensures both columns are present on the DataFrame when the table is
  loaded, even if the CSV omits them (in which case they are all-null). The
  validator may reference both columns unconditionally once the skip guard has
  passed.

- **`feed_contact_email` and `feed_contact_url` dtype is `Utf8` (string).**
  After the two-phase load, optional string columns are `pl.Utf8`. Null values
  and whitespace-only strings are handled correctly by the `is_blank` expression.
  No numeric comparisons are needed.

- **Load-time checks not duplicated.** The following are handled at load time
  and must not be re-checked here: `feed_publisher_name` required and non-null;
  `feed_publisher_url` required, non-null, and valid URL format; `feed_lang`
  required and valid BCP-47 language code; `feed_contact_email` format
  validation (valid email address) when present; `feed_contact_url` format
  validation (valid URL) when present; `feed_start_date` end-range check
  relative to `feed_end_date`; single-row enforcement (at most one row in
  `feed_info.txt`).

- **`ctx` unused.** The validator does not inspect the validation date or
  country code. The parameter is accepted to satisfy the `ValidatorFn` type
  alias.

```python
import polars as pl
from datetime import date

from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Severity
from gtfs_validator.validators.feed_contact import validate_feed_contact

CTX = ValidationContext(country_code="US", date_for_validation=date(2024, 1, 1))


def make_feed_info(
    feed_contact_email: str | None,
    feed_contact_url: str | None,
    csv_row_number: int = 2,
) -> pl.DataFrame:
    """Build a minimal feed_info DataFrame with the two contact fields."""
    return pl.DataFrame(
        {
            "feed_contact_email": pl.Series(
                [feed_contact_email], dtype=pl.Utf8
            ),
            "feed_contact_url": pl.Series(
                [feed_contact_url], dtype=pl.Utf8
            ),
            "csv_row_number": [csv_row_number],
        }
    )
```
