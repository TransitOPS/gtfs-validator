# Implementation: OverlappingFrequencyValidator

## 1. Module location

`src/gtfs_validator/validators/overlapping_frequency.py`

## 2. Function signature

```python
def validate_overlapping_frequency(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

`ctx` is accepted for signature consistency but is not used by this validator.

## 3. Notice definitions

### `overlapping_frequency` — ERROR

Emitted when two `frequencies.txt` entries for the same trip have overlapping time windows, i.e. when `curr.start_time < prev.end_time` after sorting by `(start_time_secs, end_time_secs, headway_secs)`.

```python
Notice(
    code="overlapping_frequency",
    severity=Severity.ERROR,
    fields={
        "prev_csv_row_number": <int>,   # 1-based CSV row number of the earlier-starting entry
        "prev_end_time": <str>,         # end_time string of the earlier entry, e.g. "07:00:00"
        "curr_csv_row_number": <int>,   # 1-based CSV row number of the overlapping entry
        "curr_start_time": <str>,       # start_time string of the overlapping entry, e.g. "06:00:00"
        "trip_id": <str>,               # shared trip_id for both entries
    },
)
```

| Field | Type | Source | Description |
|---|---|---|---|
| `prev_csv_row_number` | `int` | `prev` row's `csv_row_number` | Row number of the first (earlier-starting) frequency entry |
| `prev_end_time` | `str` | `prev.end_time` (original HH:MM:SS string) | End time of the first frequency entry |
| `curr_csv_row_number` | `int` | `curr` row's `csv_row_number` | Row number of the overlapping (later-starting) frequency entry |
| `curr_start_time` | `str` | `curr.start_time` (original HH:MM:SS string) | Start time of the overlapping frequency entry |
| `trip_id` | `str` | `prev.trip_id` (same as `curr.trip_id`) | The shared trip identifier |

Severity: `Severity.ERROR`.

Multiple notices may be emitted per trip if more than two entries in the group overlap. The scan does not short-circuit after the first overlap.

## 4. Implementation approach

Mixed Polars + plain Python. Polars is used for table access, null filtering, time-to-seconds conversion, and per-trip grouping/sorting. Plain Python is used for the adjacent-pair sweep, which is inherently sequential.

### Helper function

Define a module-level pure helper to convert a GTFS time string to integer seconds:

```python
def _time_to_secs(t: str) -> int:
    h, m, s = t.split(":")
    return int(h) * 3600 + int(m) * 60 + int(s)
```

This is applied as a Polars `map_elements` expression to produce `start_secs` and `end_secs` columns before sorting.

### Algorithm (pseudocode)

```
frequencies = feed.get("frequencies")
if frequencies is None or frequencies.is_empty():
    return []

# Drop rows with null start_time or end_time (schema-required but guard defensively)
frequencies = frequencies.filter(
    pl.col("start_time").is_not_null() & pl.col("end_time").is_not_null()
)
if frequencies.is_empty():
    return []

# Add integer-seconds columns for sorting
frequencies = frequencies.with_columns([
    pl.col("start_time").map_elements(_time_to_secs, return_dtype=pl.Int64).alias("start_secs"),
    pl.col("end_time").map_elements(_time_to_secs, return_dtype=pl.Int64).alias("end_secs"),
])

notices = []

# Group by trip_id; process each group independently
for (trip_id,), group in frequencies.group_by("trip_id"):
    if len(group) < 2:
        continue

    # Sort ascending by (start_secs, end_secs, headway_secs) — matches Java sort order
    sorted_group = group.sort(["start_secs", "end_secs", "headway_secs"])
    rows = sorted_group.to_dicts()

    # Adjacent-pair sweep
    for i in range(len(rows) - 1):
        prev = rows[i]
        curr = rows[i + 1]
        if curr["start_secs"] < prev["end_secs"]:
            notices.append(Notice(
                code="overlapping_frequency",
                severity=Severity.ERROR,
                fields={
                    "prev_csv_row_number": prev["csv_row_number"],
                    "prev_end_time": prev["end_time"],
                    "curr_csv_row_number": curr["csv_row_number"],
                    "curr_start_time": curr["start_time"],
                    "trip_id": trip_id,
                },
            ))

return notices
```

### Key implementation notes

- `group_by` returns tuple keys; unpack as `(trip_id,)` to get the scalar string.
- `to_dicts()` is appropriate here: the per-trip group is small and the sweep requires sequential row access.
- `start_time` and `end_time` are kept as original strings in the notice fields; only `start_secs` and `end_secs` are used for comparison and sorting.
- The null guard on `start_time`/`end_time` uses a Polars filter before adding the seconds columns, avoiding `map_elements` errors on null input.
- Do not use `headway_secs` as an integer seconds value for the overlap comparison — it is only a sort tiebreaker.
- The `headway_secs` column must be present in `frequencies.txt` (it is `@Required` in the schema), so it is safe to reference in `sort()` without a null guard. If defensive null handling is needed, use `fill_null(0)` before the sort.

### Full implementation

```python
"""Validator: OverlappingFrequencyValidator.

Detects pairs of frequencies.txt entries for the same trip whose time
windows overlap (curr.start_time < prev.end_time after sorting).
"""

from __future__ import annotations

from typing import TYPE_CHECKING

import polars as pl

from gtfs_validator.notices import Notice, Severity

if TYPE_CHECKING:
    from gtfs_validator.context import ValidationContext


def _time_to_secs(t: str) -> int:
    """Convert a GTFS HH:MM:SS time string to total seconds since midnight."""
    h, m, s = t.split(":")
    return int(h) * 3600 + int(m) * 60 + int(s)


def validate_overlapping_frequency(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
    """Emit overlapping_frequency (ERROR) for frequencies.txt entries whose windows overlap."""
    frequencies = feed.get("frequencies")
    if frequencies is None or frequencies.is_empty():
        return []

    # Guard against null required time columns
    frequencies = frequencies.filter(
        pl.col("start_time").is_not_null() & pl.col("end_time").is_not_null()
    )
    if frequencies.is_empty():
        return []

    # Add integer-seconds columns for sorting and comparison
    frequencies = frequencies.with_columns([
        pl.col("start_time")
        .map_elements(_time_to_secs, return_dtype=pl.Int64)
        .alias("start_secs"),
        pl.col("end_time")
        .map_elements(_time_to_secs, return_dtype=pl.Int64)
        .alias("end_secs"),
    ])

    notices: list[Notice] = []

    for (trip_id,), group in frequencies.group_by("trip_id"):
        if len(group) < 2:
            continue

        sorted_group = group.sort(["start_secs", "end_secs", "headway_secs"])
        rows = sorted_group.to_dicts()

        for i in range(len(rows) - 1):
            prev = rows[i]
            curr = rows[i + 1]
            if curr["start_secs"] < prev["end_secs"]:
                notices.append(
                    Notice(
                        code="overlapping_frequency",
                        severity=Severity.ERROR,
                        fields={
                            "prev_csv_row_number": prev["csv_row_number"],
                            "prev_end_time": prev["end_time"],
                            "curr_csv_row_number": curr["csv_row_number"],
                            "curr_start_time": curr["start_time"],
                            "trip_id": trip_id,
                        },
                    )
                )

    return notices
```

Add an import and a `ValidatorEntry` to `src/gtfs_validator/validators/__init__.py`.

**Import** (group with other `o*` imports or near frequency-related validators):

```python
from gtfs_validator.validators.overlapping_frequency import validate_overlapping_frequency
```

**Registry entry:**

```python
ValidatorEntry(
    name="overlapping_frequency",
    fn=validate_overlapping_frequency,
    requires=["frequencies"],
),
```

`requires=["frequencies"]` allows the runner's `should_skip` logic to bypass this validator automatically when `frequencies.txt` is absent from the feed. The check is entirely within `frequencies.txt`; no cross-table join is needed.

#### `test_overlapping_three_intervals`
