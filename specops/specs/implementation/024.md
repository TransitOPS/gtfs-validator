# Implementation: GtfsTripServiceIdForeignKeyValidator

## 1. Module Location

**Validator:** `src/gtfs_validator/validators/trip_service_id_foreign_key_validator.py`

This is a cross-table multi-parent foreign key validator that checks `trips.txt` against both `calendar.txt` and `calendar_dates.txt`. The standard single-parent FK loader in `load_validators.py` cannot handle multi-parent FK relationships, so this exists as a separate cross-table validator.

## 2. Function Signature

```python
from __future__ import annotations

import polars as pl

from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Notice, Severity


def validate_trip_service_id_foreign_key(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

No internal helpers are needed; the logic is a single set-membership check.

## 3. Notice Definitions

### `foreign_key_violation`

Severity: **ERROR**

Emitted when a `trips.txt` row has a `service_id` that does not exist in either `calendar.txt` or `calendar_dates.txt`.

```python
Notice(
    code="foreign_key_violation",
    severity=Severity.ERROR,
    fields={
        "childFilename": "trips.txt",
        "childFieldName": "service_id",
        "parentFilename": "calendar.txt or calendar_dates.txt",
        "parentFieldName": "service_id",
        "fieldValue": <str>,       # the unresolved service_id value
        "csvRowNumber": <int>,     # 1-based row number in trips.txt
    },
)
```

This reuses the existing `foreign_key_violation` notice code already used by the load-time FK infrastructure in `load_validators.py`.

## 4. Implementation Approach

### Strategy: Polars expressions (set-membership anti-join)

This is a straightforward set-membership check well-suited to Polars. No geometry, graph traversal, or complex logic is involved.

### Algorithm

```
1. trips = feed.get("trips")
2. if trips is None or trips.is_empty():
3.     return []
4.
5. if "service_id" not in trips.columns:
6.     return []
7.
8. # Collect valid service_id values from both parent tables
9. valid_ids: set[str] = set()
10.
11. calendar = feed.get("calendar")
12. if calendar is not None and "service_id" in calendar.columns:
13.     cal_ids = calendar.select("service_id")
14.         .filter(pl.col("service_id").is_not_null() & (pl.col("service_id") != ""))
15.         .to_series().to_list()
16.     valid_ids.update(cal_ids)
17.
18. calendar_dates = feed.get("calendar_dates")
19. if calendar_dates is not None and "service_id" in calendar_dates.columns:
20.     cd_ids = calendar_dates.select("service_id")
21.         .filter(pl.col("service_id").is_not_null() & (pl.col("service_id") != ""))
22.         .to_series().to_list()
23.     valid_ids.update(cd_ids)
24.
25. # Filter trips to rows with non-null, non-empty service_id
26. candidates = trips.filter(
27.     pl.col("service_id").is_not_null() & (pl.col("service_id") != "")
28. )
29.
30. if candidates.is_empty():
31.     return []
32.
33. # Find violations: rows whose service_id is not in valid_ids
34. violations = candidates.filter(~pl.col("service_id").is_in(list(valid_ids)))
35.
36. # Emit one notice per violating row
37. notices = []
38. for row in violations.iter_rows(named=True):
39.     notices.append(Notice(
40.         code="foreign_key_violation",
41.         severity=Severity.ERROR,
42.         fields={
43.             "childFilename": "trips.txt",
44.             "childFieldName": "service_id",
45.             "parentFilename": "calendar.txt or calendar_dates.txt",
46.             "parentFieldName": "service_id",
47.             "fieldValue": row["service_id"],
48.             "csvRowNumber": row["csvRowNumber"],
49.         },
50.     ))
51. return notices
```

### Handling missing tables

- If `trips` is absent from the feed dict, the runner skips this validator entirely via the `requires` list (never called).
- If `calendar` is absent from the feed dict, its service_id set is treated as empty.
- If `calendar_dates` is absent from the feed dict, its service_id set is treated as empty.
- If both parent tables are absent, every trip row with a non-empty `service_id` produces a violation.
- If `trips` has no `service_id` column, return early with no notices.

## 5. Registry Entry

In `src/gtfs_validator/validators/__init__.py`, add the import:

```python
from gtfs_validator.validators.trip_service_id_foreign_key_validator import (
    validate_trip_service_id_foreign_key,
)
```

Append the entry to `VALIDATOR_REGISTRY`:

```python
ValidatorEntry(
    name="trip_service_id_foreign_key",
    fn=validate_trip_service_id_foreign_key,
    requires=["trips"],
),
```

Note: `requires` lists only `trips` because the validator must run whenever that table is present (even if both parent tables are absent, in which case every non-empty service_id produces a violation). The validator handles the absence of `calendar` and `calendar_dates` internally by treating their ID sets as empty.
