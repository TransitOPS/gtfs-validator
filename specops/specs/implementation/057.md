# Implementation: StopAccessValidator

## 1. Module location

```
src/gtfs_validator/validators/stop_access.py
```

## 2. Function signature

```python
def validate_stop_access(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

`ctx` is accepted but unused; the validator is a single-table filter check over `stops.txt`.

## 3. Notice definitions

### `stop_access_specified_for_stop_with_no_parent_station` — ERROR

Emitted when a stop row has `location_type == 0` (STOP) and `stop_access` is set, but
`parent_station` is absent/null.

```python
Notice(
    code="stop_access_specified_for_stop_with_no_parent_station",
    severity=Severity.ERROR,
    fields={
        "csv_row_number": int,   # 1-based row number from stops.csv_row_number
        "stop_id":        str,   # stops.stop_id
        "stop_name":      str | None,  # stops.stop_name; None when null in feed
        "stop_access":    int,   # stops.stop_access enum value (0 or 1)
        "location_type":  int,   # stops.location_type; will always be 0
    },
)
```

Filter condition: `stop_access IS NOT NULL AND location_type == 0 AND parent_station IS NULL`.

### `stop_access_specified_for_incorrect_location` — ERROR

Emitted when any row with a non-STOP `location_type` (1, 2, 3, or 4) has `stop_access` set,
regardless of whether `parent_station` is present.

```python
Notice(
    code="stop_access_specified_for_incorrect_location",
    severity=Severity.ERROR,
    fields={
        "csv_row_number": int,   # 1-based row number from stops.csv_row_number
        "stop_id":        str,   # stops.stop_id
        "stop_name":      str | None,  # stops.stop_name; None when null in feed
        "stop_access":    int,   # stops.stop_access enum value (0 or 1)
        "location_type":  int,   # stops.location_type; will be 1, 2, 3, or 4
    },
)
```

Filter condition: `stop_access IS NOT NULL AND location_type != 0`.

### Enum reference

| `location_type` value | Name |
|---|---|
| 0 | STOP |
| 1 | STATION |
| 2 | ENTRANCE/EXIT |
| 3 | GENERIC_NODE |
| 4 | BOARDING_AREA |

| `stop_access` value | Name |
|---|---|
| 0 | ACCESSIBLE_VIA_PATHWAYS |
| 1 | NOT_ACCESSIBLE_VIA_PATHWAYS |

## 4. Implementation approach

### Guard clauses (return `[]` immediately if)

1. `feed.get("stops")` returns `None` — `stops.txt` is absent from the feed.
2. `stops.is_empty()` — file is present but contains no data rows.
3. `"stop_access" not in stops.columns` — column-level guard; the `stop_access` column is
   not present in the file header at all. This mirrors the Java
   `shouldCallValidate(header.hasColumn(...))` behavior.

### Algorithm (Polars, two independent filter passes)

Both notice conditions are evaluated as independent vectorized filter passes over the
`stops` DataFrame. No row-by-row Python iteration is used for the filtering logic.

```
CONSTANT STOP_LOCATION_TYPE = 0

# Pre-filter: discard rows where stop_access is null (per-row null guard)
with_access = stops.filter(pl.col("stop_access").is_not_null())

IF with_access.is_empty():
    RETURN []

notices = []

# --- Pass 1: stop_access_specified_for_stop_with_no_parent_station ---
# Condition: location_type == 0 (STOP) AND parent_station is null/absent
IF "parent_station" in stops.columns:
    no_parent_filter = (
        (pl.col("location_type") == STOP_LOCATION_TYPE)
        & pl.col("parent_station").is_null()
    )
ELSE:
    # parent_station column absent entirely — all STOP rows lack a parent
    no_parent_filter = (pl.col("location_type") == STOP_LOCATION_TYPE)

no_parent = with_access.filter(no_parent_filter)

FOR row IN no_parent.iter_rows(named=True):
    EMIT Notice(
        code="stop_access_specified_for_stop_with_no_parent_station",
        severity=ERROR,
        fields={
            "csv_row_number": row["csv_row_number"],
            "stop_id":        row["stop_id"],
            "stop_name":      row.get("stop_name"),
            "stop_access":    row["stop_access"],
            "location_type":  row["location_type"],
        },
    )

# --- Pass 2: stop_access_specified_for_incorrect_location ---
# Condition: location_type != 0 (any non-STOP type)
wrong_type = with_access.filter(
    pl.col("location_type") != STOP_LOCATION_TYPE
)

FOR row IN wrong_type.iter_rows(named=True):
    EMIT Notice(
        code="stop_access_specified_for_incorrect_location",
        severity=ERROR,
        fields={
            "csv_row_number": row["csv_row_number"],
            "stop_id":        row["stop_id"],
            "stop_name":      row.get("stop_name"),
            "stop_access":    row["stop_access"],
            "location_type":  row["location_type"],
        },
    )

RETURN notices
```

### Null semantics for `parent_station`

The loading layer normalizes empty strings to null for optional ID fields. The check
`pl.col("parent_station").is_null()` is the correct Polars equivalent of the Java
`!entity.hasParentStation()`. If any ambiguity exists about whether empty strings are
preserved, add `.or_(pl.col("parent_station") == "")` as a safety net.

### Default `location_type`

When `location_type` is omitted from a row, the schema applies a default of `0` (STOP)
at load time. The validator assumes this default has already been applied; a null
`location_type` in the DataFrame would incorrectly fall into the non-STOP branch.

### `stop_name` null handling

`stop_name` is optional and may be null. Use `row.get("stop_name")` (returns `None` on
missing key) rather than `row["stop_name"]` to avoid `KeyError` if the column is absent.
When the column is present but the value is null, Polars `iter_rows(named=True)` returns
`None` for that cell — pass it through to the notice fields as-is. This matches the Java
behavior of passing null into the notice constructor directly.

### Guard clause ordering

The following order must be preserved:

1. `feed.get("stops") is None` → return `[]`
2. `stops.is_empty()` → return `[]`
3. `"stop_access" not in stops.columns` → return `[]`
4. Filter to `with_access` where `stop_access` is not null
5. `with_access.is_empty()` → return `[]` (optional early exit; avoids allocating empty results)

The `requires` list contains only `"stops"`. No other tables are consulted.

Place the entry near the other `stops`-only validators such as `location_type_single_entity`
