## 3. Notice definitions

### `transfer_with_invalid_stop_location_type` (ERROR)

Emitted when `from_stop_id` or `to_stop_id` in `transfers.txt` references a stop whose `location_type` is anything other than 0 (STOP) or 1 (STATION).

This notice code is shared with `TransfersInSeatTransferTypeValidator` (074). Both validators construct `Notice` objects with the same `code` string and identical field shapes. No shared dataclass is needed — both modules construct `Notice(...)` directly with the same literal `code="transfer_with_invalid_stop_location_type"`.

```python
Notice(
    code="transfer_with_invalid_stop_location_type",
    severity=Severity.ERROR,
    fields={
        "csv_row_number": int,          # from transfers row
        "stop_id_field_name": str,      # "from_stop_id" or "to_stop_id"
        "stop_id": str,                 # the referenced stop ID
        "location_type_value": int,     # numeric value (e.g., 2)
        "location_type_name": str,      # string name (e.g., "ENTRANCE")
    },
)
```

Conditions:
- Stop ID is non-null AND found in `stops.txt`, AND
- `location_type` is NOT IN {0, 1}.

A single transfer row may produce zero, one, or two notices of this type (one per direction).

Severity: ERROR.

## 4. Implementation approach

**Strategy**: Pre-build a Python dict mapping `stop_id -> location_type` from `stops.txt` (built once, O(n)), then iterate all transfer rows in Python checking both directions. The validator applies to all rows in `transfers.txt` without filtering on `transfer_type`. Plain Python row-by-row iteration is appropriate here: `transfers.txt` is small in practice, the logic is not naturally vectorized, and the two-direction per-row pattern is clearer in Python than with Polars joins. Per AGENTS.md: "Use plain Python algorithms for graph/geometry/interval logic when clearer and safer than forcing Polars."

### Module-level constants

```python
VALID_TRANSFER_LOCATION_TYPES: frozenset[int] = frozenset({0, 1})  # STOP, STATION

LOCATION_TYPE_NAMES: dict[int, str] = {
    0: "STOP",
    1: "STATION",
    2: "ENTRANCE",
    3: "GENERIC_NODE",
    4: "BOARDING_AREA",
}
```

### Guard clauses

Return `[]` immediately if any of the following hold:

1. `"transfers"` not in `feed`
2. `feed["transfers"].is_empty()`
3. Required columns `{"from_stop_id", "to_stop_id", "csv_row_number"}` are not all present in `feed["transfers"].columns`

The `stops` table is an optional input; its absence is handled by building an empty dict, causing all stop lookups to miss and all rows to be silently skipped for this validator.

### Pre-build lookup structure

```python
stops_by_id: dict[str, int | None] = {}
stops_df = feed.get("stops")
if (
    stops_df is not None
    and "stop_id" in stops_df.columns
    and "location_type" in stops_df.columns
):
    for row in stops_df.select(["stop_id", "location_type"]).iter_rows(named=True):
        if row["stop_id"] is not None:
            stops_by_id[row["stop_id"]] = row["location_type"]
```

`location_type` values in the loaded DataFrame are typed integers or null (after load-time casting). A null `location_type` means the column was present but the field was empty; such stops are stored with value `None` and will not be in `VALID_TRANSFER_LOCATION_TYPES`, so they will produce a notice. This matches Java behavior where a missing `location_type` defaults to 0 (STOP) at the schema level — however, if the loaded value is null, the check correctly treats it as not valid. FK validators separately handle any stops with completely missing stop_id values.

### Direction iteration

For each transfer row, process the FROM direction then the TO direction. This ordering matches the Java implementation.

| Direction | stop_id field  | stop_id_field_name value |
|-----------|----------------|--------------------------|
| FROM      | `from_stop_id` | `"from_stop_id"`         |
| TO        | `to_stop_id`   | `"to_stop_id"`           |

### Per-direction logic

For each direction:

1. Read `stop_id` from the row for the relevant field (`from_stop_id` or `to_stop_id`).
2. If `stop_id` is `None` or not in `stops_by_id`: silently skip (FK validation deferred).
3. Look up `location_type = stops_by_id[stop_id]`.
4. If `location_type` is `None` or `location_type not in VALID_TRANSFER_LOCATION_TYPES`: emit notice.
5. Resolve `location_type_name` using `LOCATION_TYPE_NAMES.get(location_type, str(location_type))` to handle any unknown future values gracefully.

### Pseudocode

```python
DIRECTIONS = [
    ("from_stop_id", "from_stop_id"),
    ("to_stop_id",   "to_stop_id"),
]

notices: list[Notice] = []

for row in transfers.iter_rows(named=True):
    csv_row_number = row["csv_row_number"]

    for stop_field, stop_id_field_name in DIRECTIONS:
        stop_id = row.get(stop_field)

        if stop_id is None or stop_id not in stops_by_id:
            continue  # FK absence handled elsewhere

        location_type = stops_by_id[stop_id]

        if location_type is None or location_type not in VALID_TRANSFER_LOCATION_TYPES:
            notices.append(
                Notice(
                    code="transfer_with_invalid_stop_location_type",
                    severity=Severity.ERROR,
                    fields={
                        "csv_row_number": csv_row_number,
                        "stop_id_field_name": stop_id_field_name,
                        "stop_id": stop_id,
                        "location_type_value": location_type,
                        "location_type_name": LOCATION_TYPE_NAMES.get(
                            location_type, str(location_type)
                        ) if location_type is not None else "UNKNOWN",
                    },
                )
            )

return notices
```

## 6. Test plan

Test file: `tests/test_validators/test_transfers_stop_type.py`

All tests build minimal DataFrames inline. Integer columns use Python `int` (or `None`); string columns use Python `str` (or `None`). Assertions check exact notice count, `code`, `severity`, and key `fields` values.

### Helper factories (suggested)

```python
from datetime import date
import polars as pl
from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Severity

def _ctx() -> ValidationContext:
    return ValidationContext(country_code="US", date_for_validation=date(2024, 1, 1))

def _make_transfers(rows: list[dict]) -> pl.DataFrame:
    return pl.DataFrame({
        "from_stop_id":   [r.get("from_stop_id") for r in rows],
        "to_stop_id":     [r.get("to_stop_id") for r in rows],
        "csv_row_number": [r.get("csv_row_number", 2) for r in rows],
    })

def _make_stops(rows: list[dict]) -> pl.DataFrame:
    return pl.DataFrame({
        "stop_id":       [r["stop_id"] for r in rows],
        "location_type": [r.get("location_type", 0) for r in rows],
    })
```
