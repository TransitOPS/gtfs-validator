# Implementation: RouteColorContrastValidator

## 1. Module Location

**Validator:** `src/gtfs_validator/validators/route_color_contrast.py`

No shared utilities needed. This is a single-table validator that reads
only `routes.txt`. All luma computation is done via Polars expressions
defined as module-level helpers in the same file.


The `ctx` argument is unused but required by the standard validator
signature. `MAX_ROUTE_COLOR_LUMA_DIFFERENCE` and `_hex_luma_expr` are
module-level definitions; the constant is defined at the top of the
module, and the helper is defined above the validator function.

## 3. Notice Definitions

### `route_color_contrast` (WARNING)

Emitted when a route row has both `route_color` and `route_text_color`
present and their Rec 601 luma difference is strictly less than 72.

```python
Notice(
    code="route_color_contrast",
    severity=Severity.WARNING,
    fields={
        "route_id": <str>,           # routes.route_id
        "csv_row_number": <int>,     # 1-based row number from routes.txt
        "route_color": <str>,        # e.g. "4a4444" (no '#')
        "route_text_color": <str>,   # e.g. "3d3838" (no '#')
    },
)
```

One notice is emitted per failing route row. There is no pairing or
grouping across rows.

## 4. Implementation Approach

### Module-level constant

```
MAX_ROUTE_COLOR_LUMA_DIFFERENCE = 72
```

Define at the top of the module, before any function definitions.

### Luma helper expression

```
function _hex_luma_expr(col_name):
    # Parse 6-digit hex string column to integer
    v = pl.col(col_name).str.to_integer(base=16)
    # Extract RGB channels via bitwise ops
    r = (v >> 16) & 0xFF
    g = (v >> 8) & 0xFF
    b = v & 0xFF
    # Apply Rec 601 formula; cast channels to Float64 first, then
    # truncate to Int32 (matching Java int-cast behavior)
    return (
        r.cast(pl.Float64) * 0.30
        + g.cast(pl.Float64) * 0.59
        + b.cast(pl.Float64) * 0.11
    ).cast(pl.Int32)
```

This is a pure expression factory — it takes a column name string and
returns a composable Polars `Expr`. It is not called with data directly;
it is embedded in a `with_columns` call.

### Validator algorithm

```
function validate_route_color_contrast(feed, ctx):
    # 1. Guard: table must exist and be non-empty
    if "routes" not in feed or feed["routes"].is_empty():
        return []

    routes = feed["routes"]

    # 2. Guard: only process rows where both color columns are non-null
    both_present = routes.filter(
        pl.col("route_color").is_not_null()
        & pl.col("route_text_color").is_not_null()
    )
    if both_present.is_empty():
        return []

    # 3. Compute luma for both columns, filter to failing rows
    flagged = both_present.with_columns([
        _hex_luma_expr("route_color").alias("_luma_color"),
        _hex_luma_expr("route_text_color").alias("_luma_text"),
    ]).filter(
        (pl.col("_luma_color") - pl.col("_luma_text")).abs()
        < MAX_ROUTE_COLOR_LUMA_DIFFERENCE
    )

    # 4. Emit one notice per failing row
    notices = []
    for row in flagged.iter_rows(named=True):
        notices.append(
            Notice(
                code="route_color_contrast",
                severity=Severity.WARNING,
                fields={
                    "route_id": row["route_id"],
                    "csv_row_number": row["csv_row_number"],
                    "route_color": row["route_color"],
                    "route_text_color": row["route_text_color"],
                },
            )
        )
    return notices
```

**Key design decisions:**

- **Polars for all heavy computation.** Hex parsing, bitwise channel
  extraction, floating-point multiply-accumulate, absolute difference,
  and threshold filtering are all expressed as Polars expressions.
  Python-level iteration is deferred to the final notice-emission step
  over flagged rows only.
- **`iter_rows` after filtering.** The number of color-contrast
  violations is expected to be small in practice. Iterating in Python
  only over flagged rows keeps the hot path in Polars.
- **Null guard before luma computation.** `str.to_integer` would fail or
  produce nulls on null input. Filtering to `both_present` before
  applying the luma expressions ensures the hex parser only receives
  valid 6-character strings.
- **`csv_row_number` is provided by the loader.** The loading pipeline
  attaches `csv_row_number` to every table as a 1-based integer column
  (header = row 1, first data row = row 2). The validator reads it
  directly from the DataFrame without computing it.
- **Threshold comparison is strict less-than.** A diff of exactly 72
  does not trigger a notice. A diff of 71 does. This matches the Java
  implementation.
- **No rounding in luma.** Python `int()` truncates towards zero,
  matching Java's `(int)` cast. The `.cast(pl.Int32)` in the Polars
  expression also truncates.

## 5. Registry Entry

In `src/gtfs_validator/validators/__init__.py`, add the import and
registry entry:

```python
from gtfs_validator.validators.route_color_contrast import (
    validate_route_color_contrast,
)

# Add to VALIDATOR_REGISTRY list:
ValidatorEntry(
    name="route_color_contrast",
    fn=validate_route_color_contrast,
    requires=["routes"],
),
```

The `requires` list contains only `"routes"`. The runner will skip this
validator entirely if `routes.txt` is absent from the feed, so no
additional guard is needed for the missing-table case beyond the
`if "routes" not in feed` check inside the function.

- **Expected:** 1 notice. Luma diff of 0 is less than 72.

### Test 7: `test_luma_diff_exactly_72_should_not_generate_notice`

- **Input:** A pair of colors whose Rec 601 luma values differ by
  exactly 72. One convenient pair: `route_color="000000"` (luma=0) and
  `route_text_color="797979"` where luma("797979") = int(0.30*121 +
  0.59*121 + 0.11*121) = int(121) = 121; luma diff = 121 which is not
  72. Instead use specific values that yield an exact diff of 72:
  `route_color="000000"` (luma=0) and a greyscale hex string with
  luma=72. Since luma = int(0.30*v + 0.59*v + 0.11*v) = int(1.0*v) = v
  for a greyscale (R=G=B=v), find v=72 → hex "484848".
  - `route_color="000000"`, `route_text_color="484848"`, `csv_row_number=2`.
- **Luma diff:** |0 - 72| = 72. Threshold is strict less-than; 72 is not
  less than 72.
- **Expected:** No notices.

### Test 8: `test_luma_diff_exactly_71_should_generate_notice`

- **Luma diff:** 71 < 72.
