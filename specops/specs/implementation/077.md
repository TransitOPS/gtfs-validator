# Implementation: TranslationFieldAndReferenceValidator

## 1. Module location

`src/gtfs_validator/validators/translation_field_and_reference.py`

## 2. Function signature

```python
def validate_translation_field_and_reference(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

## 3. Notice definitions

Notices are constructed as `Notice(code=..., severity=..., fields={...})` using the project's existing `Notice` dataclass from `gtfs_validator.notices`.

### `missing_required_field` — ERROR

Reuses the general-purpose notice already defined in load-time validators. Emitted in two contexts within this validator.

**Context A — standard required fields missing (phase 2)**

```python
Notice(
    code="missing_required_field",
    severity=Severity.ERROR,
    fields={
        "filename": "translations.txt",
        "csvRowNumber": int,   # from translations row
        "fieldName": str,      # "table_name", "field_name", or "language"
    },
)
```

Condition: standard format detected (column `table_name` is present and not all-null), AND the named field is null or empty for that row.

**Context B — reference integrity: `record_id` or `record_sub_id` missing (phase 3)**

```python
Notice(
    code="missing_required_field",
    severity=Severity.ERROR,
    fields={
        "filename": "translations.txt",
        "csvRowNumber": int,   # from translations row
        "fieldName": str,      # "record_id" or "record_sub_id"
    },
)
```

Condition: `field_value` is absent, the parent table exists, the referenced table requires the given key field (key column count >= 1 for `record_id`, >= 2 for `record_sub_id`), but the field is null/empty in the translation row.

---

### `translation_unexpected_value` — ERROR

A field in a translation row has a value but must be empty.

```python
Notice(
    code="translation_unexpected_value",
    severity=Severity.ERROR,
    fields={
        "csvRowNumber": int,   # from translations row
        "fieldName": str,      # "record_id" or "record_sub_id"
        "fieldValue": str,     # the unexpected value found
    },
)
```

Conditions — three cases, any combination of which may fire for a single row:

1. `field_value` is present AND `record_id` is also present: `fieldName="record_id"`, `fieldValue=record_id`.
2. `field_value` is present AND `record_sub_id` is also present: `fieldName="record_sub_id"`, `fieldValue=record_sub_id`.
3. `field_value` is absent AND parent table exists AND the referenced table does NOT use the field (key column count < 1 for `record_id`, or < 2 for `record_sub_id`), but the field is present anyway.

Cases 1 and 2 may both fire for the same row (when `field_value`, `record_id`, and `record_sub_id` are all set).

---

### `translation_unknown_table_name` — WARNING

A translation row references an unknown or missing GTFS table.

```python
Notice(
    code="translation_unknown_table_name",
    severity=Severity.WARNING,
    fields={
        "csvRowNumber": int,   # from translations row
        "tableName": str,      # the unrecognized table name
    },
)
```

Condition: `table_name` is not a key in `TRANSLATION_KEYS`, OR the corresponding table is absent from the feed dict.

---

### `translation_foreign_key_violation` — ERROR

An entity with the given `record_id` and `record_sub_id` cannot be found in the referenced table.

```python
Notice(
    code="translation_foreign_key_violation",
    severity=Severity.ERROR,
    fields={
        "csvRowNumber": int,   # from translations row
        "tableName": str,      # translations.table_name
        "recordId": str,       # translations.record_id
        "recordSubId": str,    # translations.record_sub_id (empty string when absent)
    },
)
```

Condition: `field_value` is absent, parent table exists, `record_id`/`record_sub_id` presence matches expectations, AND no entity with those key values exists in the parent table. Also emitted when `record_sub_id` is expected to be an integer (e.g., `stop_sequence`) but the string cannot be parsed as one.

---

## 4. Implementation approach

### 4.1 Module-level table key mapping

Define as a module-level constant. Keys are the bare table name stem (no `.txt`). Each value is a `(record_id_col, record_sub_id_col)` tuple where each element is either a column name string or `None`.

```python
# (record_id_column, record_sub_id_column) — None means the field is not used
TRANSLATION_KEYS: dict[str, tuple[str | None, str | None]] = {
    "agency":          ("agency_id",       None),
    "stops":           ("stop_id",         None),
    "routes":          ("route_id",        None),
    "trips":           ("trip_id",         None),
    "calendar":        ("service_id",      None),
    "fare_attributes": ("fare_id",         None),
    "levels":          ("level_id",        None),
    "pathways":        ("pathway_id",      None),
    "attributions":    ("attribution_id",  None),
    "stop_times":      ("trip_id",         "stop_sequence"),
    "calendar_dates":  ("service_id",      "date"),
    "shapes":          ("shape_id",        "shape_pt_sequence"),
    "frequencies":     ("trip_id",         "headway_secs"),
    "transfers":       ("from_stop_id",    "to_stop_id"),
    "feed_info":       (None,              None),
    "fare_rules":      (None,              None),
}
```

Tables not present in this dict are treated as unknown → `translation_unknown_table_name`.

### 4.2 Integer sub-key columns

`stop_sequence`, `shape_pt_sequence`, and `headway_secs` are integer columns. When performing entity lookup for tables that use these as `record_sub_id`, the string value from the translation row must be parseable as an integer. If parsing fails, the lookup produces no match → `translation_foreign_key_violation`.

Define a module-level set:

```python
_INTEGER_SUB_ID_COLS: frozenset[str] = frozenset({
    "stop_sequence",
    "shape_pt_sequence",
    "headway_secs",
})
```

### 4.3 Guard clauses

```python
def validate_translation_field_and_reference(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
    if "translations" not in feed:
        return []
    translations = feed["translations"]
    if translations.is_empty():
        return []
    # Legacy format guard: standard format requires the "table_name" column.
    # If the column is absent or entirely null, treat as legacy format and skip.
    if "table_name" not in translations.columns:
        return []
    if translations["table_name"].is_null().all():
        return []
```

### 4.4 Phase 2 — required-fields scan

Iterate all translation rows and collect `missing_required_field` notices for any row where `table_name`, `field_name`, or `language` is null or empty. If any such notice is emitted, abort before phase 3 (return all collected notices immediately after the scan loop).

```python
notices: list[Notice] = []
any_missing = False

for row in translations.iter_rows(named=True):
    row_num = row["csvRowNumber"]
    for field_name in ("table_name", "field_name", "language"):
        val = row.get(field_name)
        if val is None or val == "":
            notices.append(Notice(
                code="missing_required_field",
                severity=Severity.ERROR,
                fields={
                    "filename": "translations.txt",
                    "csvRowNumber": row_num,
                    "fieldName": field_name,
                },
            ))
            any_missing = True

if any_missing:
    return notices
```

### 4.5 Pre-build entity lookup sets (phase 3 setup)

Before entering the per-row loop, pre-build lookup sets for every table referenced in `TRANSLATION_KEYS` that is present in the feed. This avoids repeated Polars filter calls inside the loop.

Use a `dict[str, set[tuple[str | None, str | None]]]` mapping table name → set of `(record_id_value, record_sub_id_value)` tuples. For 0-key tables, store a boolean sentinel (`None, None`) if the table is non-empty.

```python
# Pre-build lookup: table_name -> set of (record_id_val, record_sub_id_val) tuples
_lookup: dict[str, set[tuple[str | None, str | None]]] = {}

for tname, (id_col, sub_col) in TRANSLATION_KEYS.items():
    df = feed.get(tname)
    if df is None or df.is_empty():
        continue
    keys: set[tuple[str | None, str | None]] = set()
    if id_col is None:
        # 0-key table: any non-empty table counts as having the single entity
        keys.add((None, None))
    elif sub_col is None:
        # 1-key table
        if id_col in df.columns:
            for (val,) in df.select([id_col]).iter_rows():
                if val is not None:
                    keys.add((val, None))
    else:
        # 2-key table
        cols_present = {id_col, sub_col}.issubset(df.columns)
        if cols_present:
            for (id_val, sub_val) in df.select([id_col, sub_col]).iter_rows():
                if id_val is not None:
                    # Store sub_val as string for consistent comparison
                    keys.add((str(id_val), str(sub_val) if sub_val is not None else None))
    _lookup[tname] = keys
```

### 4.6 `_is_missing_or_unexpected` module-level helper

```python
def _is_missing_or_unexpected(
    *,
    has_value: bool,
    expected_present: bool,
    field_name: str,
    field_value: str | None,
    csv_row_number: int,
    notices: list[Notice],
) -> bool:
    """Return True and append a notice if there is a mismatch; False if correct."""
    if has_value == expected_present:
        return False
    if has_value and not expected_present:
        notices.append(Notice(
            code="translation_unexpected_value",
            severity=Severity.ERROR,
            fields={
                "csvRowNumber": csv_row_number,
                "fieldName": field_name,
                "fieldValue": field_value or "",
            },
        ))
        return True
    # not has_value and expected_present
    notices.append(Notice(
        code="missing_required_field",
        severity=Severity.ERROR,
        fields={
            "filename": "translations.txt",
            "csvRowNumber": csv_row_number,
            "fieldName": field_name,
        },
    ))
    return True
```

### 4.7 Phase 3 — per-row validation loop

Iterate each translation row. The `translations` DataFrame is typically small so plain Python iteration is appropriate.

```python
for row in translations.iter_rows(named=True):
    row_num = row["csvRowNumber"]
    table_name = row.get("table_name") or ""
    field_value = row.get("field_value")       # None if absent or null
    record_id = row.get("record_id")           # None if absent or null
    record_sub_id = row.get("record_sub_id")   # None if absent or null

    has_field_value = field_value is not None and field_value != ""
    has_record_id = record_id is not None and record_id != ""
    has_record_sub_id = record_sub_id is not None and record_sub_id != ""

    # Step A: field_value mutual exclusion
    if has_field_value:
        if has_record_id:
            notices.append(Notice(
                code="translation_unexpected_value",
                severity=Severity.ERROR,
                fields={
                    "csvRowNumber": row_num,
                    "fieldName": "record_id",
                    "fieldValue": record_id,
                },
            ))
        if has_record_sub_id:
            notices.append(Notice(
                code="translation_unexpected_value",
                severity=Severity.ERROR,
                fields={
                    "csvRowNumber": row_num,
                    "fieldName": "record_sub_id",
                    "fieldValue": record_sub_id,
                },
            ))
        # Step B still runs (parent table unknown check) but Step C is skipped
        _validate_parent_table(
            row_num=row_num,
            table_name=table_name,
            feed=feed,
            lookup=_lookup,
            notices=notices,
            check_reference=False,
            record_id=record_id,
            record_sub_id=record_sub_id,
        )
    else:
        _validate_parent_table(
            row_num=row_num,
            table_name=table_name,
            feed=feed,
            lookup=_lookup,
            notices=notices,
            check_reference=True,
            record_id=record_id,
            record_sub_id=record_sub_id,
        )
```

### 4.8 `_validate_parent_table` module-level helper

Encapsulates Steps B and C from the analysis spec. Keep as a module-level function to satisfy the project's composability convention.

```python
def _validate_parent_table(
    *,
    row_num: int,
    table_name: str,
    feed: dict[str, pl.DataFrame],
    lookup: dict[str, set[tuple[str | None, str | None]]],
    notices: list[Notice],
    check_reference: bool,
    record_id: str | None,
    record_sub_id: str | None,
) -> None:
    # Step B: resolve parent table
    if table_name not in TRANSLATION_KEYS or table_name not in feed:
        notices.append(Notice(
            code="translation_unknown_table_name",
            severity=Severity.WARNING,
            fields={
                "csvRowNumber": row_num,
                "tableName": table_name,
            },
        ))
        return

    if not check_reference:
        return

    # Step C: reference integrity
    id_col, sub_col = TRANSLATION_KEYS[table_name]
    record_id_expected = id_col is not None
    record_sub_id_expected = sub_col is not None

    has_record_id = record_id is not None and record_id != ""
    has_record_sub_id = record_sub_id is not None and record_sub_id != ""

    # Check record_id presence vs expectation
    mismatch = _is_missing_or_unexpected(
        has_value=has_record_id,
        expected_present=record_id_expected,
        field_name="record_id",
        field_value=record_id,
        csv_row_number=row_num,
        notices=notices,
    )
    if mismatch:
        return

    # Check record_sub_id presence vs expectation
    mismatch = _is_missing_or_unexpected(
        has_value=has_record_sub_id,
        expected_present=record_sub_id_expected,
        field_name="record_sub_id",
        field_value=record_sub_id,
        csv_row_number=row_num,
        notices=notices,
    )
    if mismatch:
        return

    # Entity lookup
    entity_set = lookup.get(table_name, set())
    found = _entity_exists(
        entity_set=entity_set,
        record_id=record_id,
        record_sub_id=record_sub_id,
        sub_col=sub_col,
    )
    if not found:
        notices.append(Notice(
            code="translation_foreign_key_violation",
            severity=Severity.ERROR,
            fields={
                "csvRowNumber": row_num,
                "tableName": table_name,
                "recordId": record_id or "",
                "recordSubId": record_sub_id or "",
            },
        ))
```

### 4.9 `_entity_exists` module-level helper

Handles 0-key, 1-key, and 2-key lookup including integer parsing for numeric sub-key columns.

```python
def _entity_exists(
    *,
    entity_set: set[tuple[str | None, str | None]],
    record_id: str | None,
    record_sub_id: str | None,
    sub_col: str | None,
) -> bool:
    if not entity_set:
        return False

    # 0-key table: always exists if the table is non-empty
    if record_id is None or record_id == "":
        return (None, None) in entity_set

    # 1-key table
    if sub_col is None:
        return (record_id, None) in entity_set

    # 2-key table: normalize sub-id for integer columns
    if sub_col in _INTEGER_SUB_ID_COLS:
        try:
            parsed_sub = str(int(record_sub_id or ""))
        except (ValueError, TypeError):
            return False   # unparseable → FK violation
    else:
        parsed_sub = record_sub_id

    return (record_id, parsed_sub) in entity_set
```

Note on 2-key lookup set construction (section 4.5): sub-values are stored as `str(sub_val)` so that integer columns stored as Polars `Int64` compare correctly against string keys derived from the translation row.

Expected: one `translation_foreign_key_violation` (row 2) + one `translation_unknown_table_name` (row 3). No notice for row 1.

## 7. Key implementation details

- `csvRowNumber` is always present in loaded DataFrames (the loader appends it). Access it directly from the row dict without `.get()`.
- All translation content fields (`record_id`, `record_sub_id`, `field_value`, `table_name`, `field_name`, `language`) may be null; use `row.get(field)` or treat `None` as absent.
- The "is present" test for a field is: `value is not None and value != ""`. Polars loads optional string columns as `Utf8` with null for absent CSV values; empty-string handling matches the Java `!isNullOrEmpty` guard.
- `_lookup` is built once before the per-row loop. Do not call `feed.get(...)` or filter DataFrames inside the per-row loop.
- For 2-key tables, sub-values in `_lookup` are stored as `str(sub_val)` to normalize across Polars integer and string column types. The `_entity_exists` helper normalizes the incoming `record_sub_id` string the same way.
- The `_validate_parent_table` helper is called from both `field_value`-present and `field_value`-absent branches; the `check_reference` flag controls whether Step C runs.
- No `ctx` (ValidationContext) fields are used by this validator; the parameter is accepted but ignored, consistent with other validators that do not need date or country context.
- JSON-backed tables (e.g., GeoJSON locations) are not present as feed dict keys with standard names, so they naturally fall through to `translation_unknown_table_name`. No special handling is needed.
- Notice ordering within a single row: Step A mutual-exclusion notices (for `record_id`, then `record_sub_id`) appear before Step B/C notices. Within Step C, the `record_id` mismatch check runs before `record_sub_id`.
