# Implementation: GtfsFareLegRuleNetworkIdForeignKeyValidator

## 1. Module Location

**Validator:** `src/gtfs_validator/validators/fare_leg_rule_network_id_foreign_key.py`

This is a cross-table multi-parent foreign key validator that checks `fare_leg_rules.txt` against both `routes.txt` and `networks.txt`. It does not fit into any existing validator file and warrants its own module because it has a unique multi-parent FK pattern that the standard single-parent FK loader in `load_validators.py` cannot handle.

## 2. Function Signature

```python
from __future__ import annotations

import polars as pl

from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Notice, Severity


def validate_fare_leg_rule_network_id_foreign_key(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

No internal helpers are needed; the logic is a single set-membership check.

## 3. Notice Definitions

### `foreign_key_violation`

Severity: **ERROR**

Emitted when a `fare_leg_rules.txt` row has a non-empty `network_id` that does not exist in either `routes.txt` or `networks.txt`.

```python
Notice(
    code="foreign_key_violation",
    severity=Severity.ERROR,
    fields={
        "childFilename": "fare_leg_rules.txt",
        "childFieldName": "network_id",
        "parentFilename": "routes.txt or networks.txt",
        "parentFieldName": "network_id",
        "fieldValue": <str>,       # the unresolved network_id value
        "csvRowNumber": <int>,     # 1-based row number in fare_leg_rules.txt
    },
)
```

This reuses the existing `foreign_key_violation` notice code already used by the load-time FK infrastructure in `load_validators.py`.

## 4. Implementation Approach

### Strategy: Polars expressions (set-membership anti-join)

This is a straightforward set-membership check well-suited to Polars. No geometry, graph traversal, or complex logic is involved.

### Algorithm

```
1. fare_leg_rules = feed.get("fare_leg_rules")
2. if fare_leg_rules is None or fare_leg_rules.is_empty():
3.     return []
4.
5. # Collect valid network_id values from both parent tables
6. valid_ids: set[str] = set()
7.
8. routes = feed.get("routes")
9. if routes is not None and "network_id" in routes.columns:
10.    route_ids = routes.select("network_id")
11.        .filter(pl.col("network_id").is_not_null() & (pl.col("network_id") != ""))
12.        .to_series().to_list()
13.    valid_ids.update(route_ids)
14.
15. networks = feed.get("networks")
16. if networks is not None and "network_id" in networks.columns:
17.    net_ids = networks.select("network_id")
18.        .filter(pl.col("network_id").is_not_null() & (pl.col("network_id") != ""))
19.        .to_series().to_list()
20.    valid_ids.update(net_ids)
21.
22. # Filter fare_leg_rules to rows with non-null, non-empty network_id
23. if "network_id" not in fare_leg_rules.columns:
24.     return []
25.
26. candidates = fare_leg_rules.filter(
27.     pl.col("network_id").is_not_null() & (pl.col("network_id") != "")
28. )
29.
30. if candidates.is_empty():
31.     return []
32.
33. # Find violations: rows whose network_id is not in valid_ids
34. violations = candidates.filter(~pl.col("network_id").is_in(list(valid_ids)))
35.
36. # Emit one notice per violating row
37. notices = []
38. for row in violations.iter_rows(named=True):
39.     notices.append(Notice(
40.         code="foreign_key_violation",
41.         severity=Severity.ERROR,
42.         fields={
43.             "childFilename": "fare_leg_rules.txt",
44.             "childFieldName": "network_id",
45.             "parentFilename": "routes.txt or networks.txt",
46.             "parentFieldName": "network_id",
47.             "fieldValue": row["network_id"],
48.             "csvRowNumber": row["csvRowNumber"],
49.         },
50.     ))
51. return notices
```

### Handling missing tables

- If `fare_leg_rules` is absent from the feed dict, the runner skips this validator entirely via the `requires` list (never called).
- If `routes` is absent from the feed dict, its network_id set is treated as empty.
- If `networks` is absent from the feed dict, its network_id set is treated as empty.
- If `fare_leg_rules` has no `network_id` column, return early with no notices.

## 5. Registry Entry

In `src/gtfs_validator/validators/__init__.py`, add the import:

```python
from gtfs_validator.validators.fare_leg_rule_network_id_foreign_key import (
    validate_fare_leg_rule_network_id_foreign_key,
)
```

Append the entry to `VALIDATOR_REGISTRY`:

```python
ValidatorEntry(
    name="fare_leg_rule_network_id_foreign_key",
    fn=validate_fare_leg_rule_network_id_foreign_key,
    requires=["fare_leg_rules"],
),
```

Note: `requires` lists only `fare_leg_rules` because the validator must run whenever that table is present (even if both parent tables are absent, in which case every non-empty network_id produces a violation). The validator handles the absence of `routes` and `networks` internally by treating their ID sets as empty.
