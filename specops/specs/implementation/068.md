# Implementation: TimeframeOverlapValidator

## 1. Module Location

**Validator file:** `src/gtfs_validator/validators/timeframe_overlap.py`

No shared utilities are required beyond the existing `_time_to_secs`
pattern already established in `overlapping_frequency.py`. Because
`timeframes.txt` uses the same `HH:MM:SS` time format (which can
exceed `23:59:59`), times must be converted to integer seconds for
sorting and comparison — standard Python/Polars `time` types cannot
represent values >= `24:00:00`. The analysis spec confirms that
`schemas.py` stores these columns as `FieldType.TIME` (raw Utf8
strings after loading), so the same string-to-seconds helper used in
`overlapping_frequency.py` applies here.

This is a pure single-table interval-sweep validator. No joins, no
geometry, no date arithmetic.

## 2. Function Signature

```python
from __future__ import annotations

from typing import TYPE_CHECKING

import polars as pl

from gtfs_validator.notices import Notice, Severity

if TYPE_CHECKING:
    from gtfs_validator.context import ValidationContext


def _time_to_secs(t: str) -> int:
    """Convert a GTFS HH:MM:SS time string to total seconds since midnight."""
    h, m, s = t.split(":")
    return int(h) * 3600 + int(m) * 60 + int(s)


def validate_timeframe_overlap(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

`ctx` is unused but required by the standard validator signature.

## 3. Notice Definitions

### `timeframe_overlap` (ERROR)

Emitted once per overlapping consecutive pair within a
`(timeframe_group_id, service_id)` group after sorting by
`(start_time ASC, end_time ASC)`. The overlap condition is
`curr.start_time < prev.end_time` (strict less-than; touching
intervals where `curr.start_time == prev.end_time` do not overlap).

```python
Notice(
    code="timeframe_overlap",
    severity=Severity.ERROR,
    fields={
        "prev_csv_row_number": <int>,   # csv_row_number of the earlier row
        "prev_end_time": <str>,         # end_time of the earlier row (HH:MM:SS)
        "curr_csv_row_number": <int>,   # csv_row_number of the later row
        "curr_start_time": <str>,       # start_time of the later row (HH:MM:SS)
        "timeframe_group_id": <str>,    # shared timeframe_group_id
        "service_id": <str>,            # shared service_id
    },
)
```

The time values in `prev_end_time` and `curr_start_time` are emitted
as the original Utf8 strings from the feed (e.g. `"09:00:00"`), not
as integers. Integer seconds are used only for internal comparison.

## 4. Implementation Approach

Use a mixed strategy: Polars for null-filtering and column selection,
then plain Python grouping and consecutive-pair scanning — exactly the
same approach as `overlapping_frequency.py`. The analysis spec
explicitly endorses this pattern ("Use plain Python algorithms for
graph/geometry/interval logic when clearer and safer than forcing
Polars"), and the grouping key here is two columns instead of one,
which maps naturally to a plain Python `dict`-based grouping.

### Pseudocode

```
function validate_timeframe_overlap(feed, ctx):

    # Guard: timeframes.txt absent or empty
    if "timeframes" not in feed or feed["timeframes"].is_empty():
        return []

    tf = feed["timeframes"]

    # Drop rows where start_time or end_time are null.
    # These should have been caught at load time, but be defensive.
    tf = tf.filter(
        pl.col("start_time").is_not_null() & pl.col("end_time").is_not_null()
    )
    if tf.is_empty():
        return []

    # Select only the columns this validator needs
    tf = tf.select(
        ["timeframe_group_id", "service_id", "start_time", "end_time", "csv_row_number"]
    )

    # Add integer-seconds columns for sorting and comparison.
    # HH:MM:SS strings can represent times >= 24:00:00 (e.g. "25:00:00"),
    # so we cannot use Polars time dtype — convert to int seconds instead.
    tf = tf.with_columns([
        pl.col("start_time")
          .map_elements(_time_to_secs, return_dtype=pl.Int64)
          .alias("start_secs"),
        pl.col("end_time")
          .map_elements(_time_to_secs, return_dtype=pl.Int64)
          .alias("end_secs"),
    ])

    notices = []

    # Group by (timeframe_group_id, service_id); check each group independently
    for (group_id, svc_id), group in tf.group_by(["timeframe_group_id", "service_id"]):
        if len(group) < 2:
            continue

        # Sort by start_secs ASC, then end_secs ASC (tie-break)
        sorted_group = group.sort(["start_secs", "end_secs"])
        rows = sorted_group.to_dicts()

        # Scan consecutive pairs only (not all-pairs)
        for i in range(len(rows) - 1):
            prev = rows[i]
            curr = rows[i + 1]
            if curr["start_secs"] < prev["end_secs"]:
                notices.append(
                    Notice(
                        code="timeframe_overlap",
                        severity=Severity.ERROR,
                        fields={
                            "prev_csv_row_number": prev["csv_row_number"],
                            "prev_end_time": prev["end_time"],
                            "curr_csv_row_number": curr["csv_row_number"],
                            "curr_start_time": curr["start_time"],
                            "timeframe_group_id": group_id,
                            "service_id": svc_id,
                        },
                    )
                )

    return notices
```

### Key design decisions

- **Plain Python consecutive-pair scan mirrors Java exactly.** The
  Java implementation iterates sorted rows in each group and compares
  only adjacent pairs — it does not compare all `O(n²)` pairs. A
  `shift(1)`-based Polars approach would also replicate this, but the
  plain Python loop is clearer and matches the established pattern in
  `overlapping_frequency.py`.

- **Group key is `(timeframe_group_id, service_id)`.** Rows with
  different `timeframe_group_id` OR different `service_id` belong to
  independent groups. No cross-group comparison is ever made.

- **Overlap condition is strict:** `curr.start_secs < prev.end_secs`.
  Adjacent intervals where `curr.start_secs == prev.end_secs` do NOT
  overlap and emit no notice.

- **`_time_to_secs` for comparison; original strings in notice
  fields.** Integer seconds are used only for `sort` and the `<`
  comparison. The emitted `prev_end_time` and `curr_start_time` fields
  carry the original HH:MM:SS strings from the feed, preserving
  human-readable output consistent with the Java notice payload.

- **`to_dicts()` after sorting.** Each group is small (timeframe
  entries within one service/group pair). Converting to a list of
  dicts for the pair scan is safe and idiomatic for this pattern.

- **`csv_row_number` guard not needed.** The `timeframes` schema in
  `schemas.py` does not define `csv_row_number` as a named column, but
  the loader injects it for all tables at load time. Select it
  explicitly in the `select()` call. If for any reason it is absent,
  the `select()` will raise a `ColumnNotFoundError` — this is an
  appropriate crash rather than silent data loss, consistent with
  project rules against swallowing parse errors.

- **No feature flag.** The validator self-guards on the presence and
  emptiness of `timeframes.txt`. No external feature detection is
  required.

## 5. Registry Entry

Add import to `src/gtfs_validator/validators/__init__.py`:

```python
from gtfs_validator.validators.timeframe_overlap import validate_timeframe_overlap
```

Add to `VALIDATOR_REGISTRY`:

```python
ValidatorEntry(
    name="timeframe_overlap",
    fn=validate_timeframe_overlap,
    requires=["timeframes"],
),
```

The single entry in `requires` causes the runner to skip this
validator entirely if `timeframes.txt` is absent from the feed. The
internal `is_empty()` guard handles the case where the file is present
but contains zero data rows.

**Test file:** `tests/test_validators/test_timeframe_overlap.py`

All tests construct minimal `feed` dicts with Polars DataFrames and
call `validate_timeframe_overlap` directly. No file I/O.

### Shared helpers

```python
from datetime import date

import polars as pl
import pytest

from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Severity
from gtfs_validator.validators.timeframe_overlap import validate_timeframe_overlap

CTX = ValidationContext(country_code="US", date_for_validation=date(2024, 1, 1))

TIMEFRAMES_SCHEMA = {
    "timeframe_group_id": pl.Utf8,
    "service_id": pl.Utf8,
    "start_time": pl.Utf8,
    "end_time": pl.Utf8,
    "csv_row_number": pl.Int64,
}


def make_timeframes(rows: list[dict]) -> pl.DataFrame:
    if not rows:
        return pl.DataFrame(schema=TIMEFRAMES_SCHEMA)
    return pl.DataFrame(rows).cast(TIMEFRAMES_SCHEMA)
```
