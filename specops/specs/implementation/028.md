# Implementation: LocationIdForeignKeyValidator

## 1. Module Location

**Validator:** `src/gtfs_validator/validators/location_id_foreign_key.py`

This is a cross-table validator that checks `stop_times.location_id` references against feature IDs in `locations.geojson`. Because `locations_geojson` is stored as a Python list of feature dicts (not a Polars DataFrame), the validator extracts IDs from the list and uses Polars `is_in` for the FK check.

## 3. Notice Definitions

### `foreign_key_violation` (ERROR)

This reuses the shared `foreign_key_violation` notice code already used by load-time FK validation and other cross-table FK validators (e.g., `fare_leg_rule_network_id_foreign_key.py`).

```python
Notice(
    code="foreign_key_violation",
    severity=Severity.ERROR,
    fields={
        "childFilename": "stop_times.txt",
        "childFieldName": "location_id",
        "parentFilename": "locations.geojson",
        "parentFieldName": "id",
        "fieldValue": <str>,       # the unmatched location_id value
        "csvRowNumber": <int>,     # row number in stop_times.txt
    },
)
```

## 4. Implementation Approach

### Strategy: Set lookup with Polars filter

The `locations_geojson` entry in the feed dict is a Python list of feature dicts, each with an `"id"` field. Since this is not a DataFrame, the approach is:

1. Extract all feature IDs into a Python set for O(1) lookup.
2. Filter `stop_times` to rows with non-null, non-empty `location_id`.
3. Use `pl.col("location_id").is_in(...)` to find violations via anti-match.
4. Emit one `foreign_key_violation` notice per unmatched row.

### Algorithm

```
1.  geojson_features = feed.get("locations_geojson")
2.  stop_times = feed.get("stop_times")
3.
4.  # Guard: both tables must be present
5.  if not geojson_features or stop_times is None:
6.      return []
7.
8.  # Guard: location_id column must exist in stop_times
9.  if "location_id" not in stop_times.columns:
10.     return []
11.
12. # Extract valid feature IDs from GeoJSON list
13. valid_ids: set[str] = {f["id"] for f in geojson_features if f.get("id")}
14.
15. # Filter to rows with non-null, non-empty location_id
16. candidates = stop_times.filter(
17.     pl.col("location_id").is_not_null() & (pl.col("location_id") != "")
18. )
19.
20. if candidates.is_empty():
21.     return []
22.
23. # Find violations: location_id values not in the valid set
24. violations = candidates.filter(
25.     ~pl.col("location_id").is_in(list(valid_ids))
26. )
27.
28. notices: list[Notice] = []
29. for row in violations.iter_rows(named=True):
30.     notices.append(
31.         Notice(
32.             code="foreign_key_violation",
33.             severity=Severity.ERROR,
34.             fields={
35.                 "childFilename": "stop_times.txt",
36.                 "childFieldName": "location_id",
37.                 "parentFilename": "locations.geojson",
38.                 "parentFieldName": "id",
39.                 "fieldValue": row["location_id"],
40.                 "csvRowNumber": row["csvRowNumber"],
41.             },
42.         )
43.     )
44. return notices
```

### Handling missing tables and columns

- If `locations_geojson` is absent from the feed dict or is an empty list, return early with no notices. The `requires` list in the registry entry also guards against this.
- If `stop_times` is absent from the feed dict, return early with no notices.
- If `stop_times` does not contain the `location_id` column, return early with no notices. This column is optional/conditionally-required.
- If all `location_id` values are null or empty after filtering, return early with no notices.

### Key design decisions

- The `locations_geojson` feed entry is a list of feature dicts (established by GeoJsonGeometryValidator #22), not a Polars DataFrame. Feature IDs are extracted via `f["id"]` from each dict.
- The set comprehension in step 13 skips features with falsy `id` values (None, empty string) to avoid false negatives in the lookup.
- Using `is_in` with a materialized list is efficient for this case since the number of GeoJSON features is typically small.
- The `iter_rows` loop for notice emission is acceptable because only violation rows are iterated.
- Notice field names (`childFilename`, `childFieldName`, `parentFilename`, `parentFieldName`, `fieldValue`, `csvRowNumber`) match the existing `foreign_key_violation` convention used throughout the codebase.

## 5. Registry Entry

In `src/gtfs_validator/validators/__init__.py`, add the import:

```python
from gtfs_validator.validators.location_id_foreign_key import (
    validate_location_id_foreign_key,
)
```

Append the entry to `VALIDATOR_REGISTRY`:

```python
ValidatorEntry(
    name="location_id_foreign_key",
    fn=validate_location_id_foreign_key,
    requires=["stop_times", "locations_geojson"],
),
```

Both `stop_times` and `locations_geojson` are listed in `requires` since the validator cannot produce meaningful results without both.

```python
from datetime import date
import polars as pl
import pytest
from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Severity
from gtfs_validator.validators.location_id_foreign_key import (
    validate_location_id_foreign_key,
)

CTX = ValidationContext(country_code="US", date_for_validation=date(2026, 3, 8))


def make_stop_times(
    rows: list[tuple[int, str | None]],
) -> pl.DataFrame:
    """Each row is (csvRowNumber, location_id)."""
    return pl.DataFrame(
        {
            "csvRowNumber": [r[0] for r in rows],
            "location_id": [r[1] for r in rows],
        },
        schema={
            "csvRowNumber": pl.Int64,
            "location_id": pl.Utf8,
        },
    )


def make_geojson_features(ids: list[str]) -> list[dict]:
    """Create minimal GeoJSON feature dicts with the given IDs."""
    return [{"id": fid, "index": i, "geometry_type": "Polygon", "coordinates": []} for i, fid in enumerate(ids)]
```
