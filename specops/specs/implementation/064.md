# Implementation: StopTimesRecordValidator

## 1. Module location

`src/gtfs_validator/validators/stop_times_record.py`

## 2. Function signature

```python
def validate_stop_times_record(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

## 3. Notice definitions

### `missing_stop_times_record` (ERROR)

Emitted when a `stop_times.txt` row satisfies all four conditions — both pickup/drop-off
window times are present, and both `pickup_type` and `drop_off_type` are `MUST_PHONE (2)`
— and is the only record for its `trip_id`.

```python
Notice(
    code="missing_stop_times_record",
    severity=Severity.ERROR,
    fields={
        "csv_row_number": int,           # stop_times.csv_row_number
        "trip_id": str,                  # stop_times.trip_id
        "location_group_id": str | None, # stop_times.location_group_id; None if absent/null
        "location_id": str | None,       # stop_times.location_id; None if absent/null
    },
)
```

Condition: `start_pickup_drop_off_window` is non-null AND `end_pickup_drop_off_window` is
non-null AND `pickup_type == 2` AND `drop_off_type == 2` AND the count of rows in
`stop_times.txt` sharing the same `trip_id` is exactly 1.

## 4. Implementation approach

**Strategy**: Fully vectorized Polars. One `group_by` aggregation precomputes trip-level
row counts; one `join` attaches the count back to the table; one `filter` expression
identifies violations. A Python `iter_rows` loop over the (typically small) violation
set constructs notice objects.

### 4.1 Column naming note

The GTFS flex window columns in this codebase are named
`start_pickup_drop_off_window` and `end_pickup_drop_off_window` — matching `schemas.py`
and all existing validators. The analysis spec uses a slightly different spelling
(`_dropoff_` without an underscore before "window"); ignore that variant and use the
underscore form used throughout the codebase.

### 4.2 Module-level constant

```python
_MUST_PHONE = 2
```

Corresponds to `GtfsPickupDropOff.MUST_PHONE` in the Java source.

### 4.3 Guard clauses (ordered)

```
1. if "stop_times" not in feed:
       return []

2. st = feed["stop_times"]
   required_cols = {
       "start_pickup_drop_off_window",
       "end_pickup_drop_off_window",
       "pickup_type",
       "drop_off_type",
   }
   if not required_cols.issubset(set(st.columns)):
       return []

3. if st.is_empty():
       return []
```

Guard 1 handles a missing `stop_times.txt`. Guard 2 mirrors the Java
`shouldCallValidate` check: if any of the four columns that drive the logic are absent
from the file header, the validator skips entirely. Guard 3 short-circuits on an empty
table (the filter would naturally produce no results, but being explicit is cleaner and
consistent with other validators).

### 4.4 Precompute trip-level row counts

```python
trip_counts = (
    st.group_by("trip_id")
    .agg(pl.len().alias("trip_stop_count"))
)
st_with_count = st.join(trip_counts, on="trip_id", how="left")
```

This is O(n) rather than O(n²). The join adds a `trip_stop_count` column to every row
containing the total number of `stop_times` rows for that row's `trip_id`.

### 4.5 Filter for violations

```python
violations = st_with_count.filter(
    pl.col("start_pickup_drop_off_window").is_not_null()
    & pl.col("end_pickup_drop_off_window").is_not_null()
    & (pl.col("pickup_type") == _MUST_PHONE)
    & (pl.col("drop_off_type") == _MUST_PHONE)
    & (pl.col("trip_stop_count") == 1)
)
```

All five predicates must hold simultaneously for a row to produce a notice.

### 4.6 Handle optional columns in the notice payload

`location_group_id` and `location_id` are optional GTFS flex fields that may not be
present as columns in the DataFrame at all. Record their presence before the join so
the notice construction can fall back safely:

```python
has_location_group = "location_group_id" in st.columns
has_location_id = "location_id" in st.columns
```

Then during iteration:

```python
location_group_id = row.get("location_group_id") if has_location_group else None
location_id = row.get("location_id") if has_location_id else None
```

### 4.7 Notice construction

```python
notices: list[Notice] = []
for row in violations.iter_rows(named=True):
    notices.append(
        Notice(
            code="missing_stop_times_record",
            severity=Severity.ERROR,
            fields={
                "csv_row_number": row["csv_row_number"],
                "trip_id": row["trip_id"],
                "location_group_id": row.get("location_group_id") if has_location_group else None,
                "location_id": row.get("location_id") if has_location_id else None,
            },
        )
    )
return notices
```

## 5. Registry entry

Add the import and entry to `src/gtfs_validator/validators/__init__.py`.

Import (alongside the other `stop_times`-only validators):

```python
from gtfs_validator.validators.stop_times_record import (
    validate_stop_times_record,
)
```

Registry entry:

```python
ValidatorEntry(
    name="stop_times_record",
    fn=validate_stop_times_record,
    requires=["stop_times"],
),
```

No feature flag is required. The runner's `requires` list ensures `stop_times` is
present before invocation; the validator's own guard clauses handle column-level
skipping internally.

## 6. Test plan

Test file: `tests/test_validators/test_stop_times_record.py`

All tests construct minimal `stop_times` DataFrames directly. Use a `make_stop_times`
helper that accepts a list of row dicts and a `columns` parameter controlling which
optional columns (`location_group_id`, `location_id`) are included in the schema.

Module-level context:

```python
CTX = ValidationContext(country_code="US", date_for_validation=date(2026, 3, 8))
```

The helper should build a DataFrame with at minimum:
- `csv_row_number` (Int64)
- `trip_id` (Utf8)
- `start_pickup_drop_off_window` (Utf8 or Duration — match what the loader produces)
- `end_pickup_drop_off_window` (Utf8 or Duration)
- `pickup_type` (Int64)
- `drop_off_type` (Int64)
- Optionally: `location_group_id` (Utf8), `location_id` (Utf8)
