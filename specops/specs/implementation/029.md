# Implementation: LocationTypeSingleEntityValidator

## 1. Module Location

**Validator:** `src/gtfs_validator/validators/location_type_single_entity.py`

This is a single-table validator that checks each row in `stops.txt` for correct `parent_station` presence/absence based on `location_type`. Three distinct notice types are emitted depending on the combination of `location_type`, `parent_station`, and `platform_code`.

## 2. Function Signature

```python
from __future__ import annotations

import polars as pl

from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Notice, Severity


def validate_location_type_single_entity(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

No internal helper functions are needed. The three checks map directly to three Polars filter expressions.

## 3. Notice Definitions

### `station_with_parent_station` (ERROR)

A station (`location_type=1`) must not have a `parent_station`.

```python
Notice(
    code="station_with_parent_station",
    severity=Severity.ERROR,
    fields={
        "csvRowNumber": <int>,
        "stopId": <str>,
        "stopName": <str>,
        "parentStation": <str>,
    },
)
```

### `location_without_parent_station` (ERROR)

An entrance (`location_type=2`), generic node (`location_type=3`), or boarding area (`location_type=4`) is missing the required `parent_station`.

```python
Notice(
    code="location_without_parent_station",
    severity=Severity.ERROR,
    fields={
        "csvRowNumber": <int>,
        "stopId": <str>,
        "stopName": <str>,
        "locationType": <int>,
    },
)
```

### `platform_without_parent_station` (INFO)

A stop (`location_type=0`) with `platform_code` set has no `parent_station`. Less severe than `location_without_parent_station` because isolated stops without `platform_code` are valid.

```python
Notice(
    code="platform_without_parent_station",
    severity=Severity.INFO,
    fields={
        "csvRowNumber": <int>,
        "stopId": <str>,
        "stopName": <str>,
    },
)
```

## 4. Implementation Approach

### Strategy: Three vectorized Polars filters

Each of the three notice types corresponds to a simple column filter over `stops`. No joins or cross-table lookups are required. The validator defines a helper expression for "parent_station is present" (non-null and non-empty) and its negation, then applies three independent filters.

### Algorithm

```
1.  stops = feed.get("stops")
2.  if stops is None:
3.      return []
4.
5.  # Ensure required columns exist; return early if not
6.  required = {"stop_id", "location_type"}
7.  if not required.issubset(stops.columns):
8.      return []
9.
10. notices: list[Notice] = []
11.
12. # Expression: parent_station is present (non-null and non-empty)
13. has_parent = (
14.     pl.col("parent_station").is_not_null()
15.     & (pl.col("parent_station") != "")
16. ) if "parent_station" in stops.columns else pl.lit(False)
17.
18. # Expression: platform_code is present (non-null and non-empty)
19. has_platform_code = (
20.     pl.col("platform_code").is_not_null()
21.     & (pl.col("platform_code") != "")
22. ) if "platform_code" in stops.columns else pl.lit(False)
23.
24. # --- Check 1: station_with_parent_station ---
25. # Stations (location_type == 1) that have a parent_station
26. if "parent_station" in stops.columns:
27.     station_violations = stops.filter(
28.         (pl.col("location_type") == 1) & has_parent
29.     )
30.     for row in station_violations.iter_rows(named=True):
31.         notices.append(
32.             Notice(
33.                 code="station_with_parent_station",
34.                 severity=Severity.ERROR,
35.                 fields={
36.                     "csvRowNumber": row["csvRowNumber"],
37.                     "stopId": row["stop_id"],
38.                     "stopName": row.get("stop_name", ""),
39.                     "parentStation": row["parent_station"],
40.                 },
41.             )
42.         )
43.
44. # --- Check 2: location_without_parent_station ---
45. # Entrances (2), generic nodes (3), boarding areas (4) without parent_station
46. loc_violations = stops.filter(
47.     pl.col("location_type").is_in([2, 3, 4]) & ~has_parent
48. )
49. for row in loc_violations.iter_rows(named=True):
50.     notices.append(
51.         Notice(
52.             code="location_without_parent_station",
53.             severity=Severity.ERROR,
54.             fields={
55.                 "csvRowNumber": row["csvRowNumber"],
56.                 "stopId": row["stop_id"],
57.                 "stopName": row.get("stop_name", ""),
58.                 "locationType": row["location_type"],
59.             },
60.         )
61.     )
62.
63. # --- Check 3: platform_without_parent_station ---
64. # Stops (location_type == 0) with platform_code set but no parent_station
65. if "platform_code" in stops.columns:
66.     platform_violations = stops.filter(
67.         (pl.col("location_type") == 0) & ~has_parent & has_platform_code
68.     )
69.     for row in platform_violations.iter_rows(named=True):
70.         notices.append(
71.             Notice(
72.                 code="platform_without_parent_station",
73.                 severity=Severity.INFO,
74.                 fields={
75.                     "csvRowNumber": row["csvRowNumber"],
76.                     "stopId": row["stop_id"],
77.                     "stopName": row.get("stop_name", ""),
78.                 },
79.             )
80.         )
81.
82. return notices
```

### Handling missing tables and columns

- If `stops` is absent from the feed dict, return early with no notices.
- If `stop_id` or `location_type` columns are missing, return early (data is too incomplete to validate).
- If `parent_station` column is missing, `has_parent` evaluates to `False` for all rows. Check 1 (station_with_parent_station) is skipped entirely. Check 2 (location_without_parent_station) will fire for any entrance/node/boarding area rows. Check 3 (platform_without_parent_station) may fire if `platform_code` is present.
- If `platform_code` column is missing, Check 3 is skipped entirely.
- If `stop_name` is missing, the field defaults to empty string via `row.get("stop_name", "")`.

### Key design decisions

- **Vectorized filters over row-by-row loops**: Each check is a single Polars `filter()` call. Only violation rows are iterated in Python for notice construction.
- **location_type default**: Per GTFS spec, `location_type` defaults to 0 when omitted. The schema/loading layer handles this default value, so the validator assumes the column always contains a valid integer.
- **Null vs empty semantics**: The loading phase normalizes empty strings to null for most columns. The `has_parent` / `has_platform_code` expressions check both null and empty string for defensive correctness.
- **Notice field naming**: Uses camelCase field names (`csvRowNumber`, `stopId`, `stopName`, `parentStation`, `locationType`) to match Java-era report conventions used throughout the codebase.

```python
    validate_location_type_single_entity,
)

CTX = ValidationContext(country_code="US", date_for_validation=date(2026, 3, 8))


def make_stops(
    rows: list[dict],
) -> pl.DataFrame:
    """Build a stops DataFrame from row dicts.

    Each dict should contain keys like stop_id, location_type, stop_name,
    parent_station, platform_code, csvRowNumber.
    """
    schema = {
        "csvRowNumber": pl.Int64,
        "stop_id": pl.Utf8,
        "stop_name": pl.Utf8,
        "location_type": pl.Int64,
        "parent_station": pl.Utf8,
        "platform_code": pl.Utf8,
    }
    data: dict[str, list] = {col: [] for col in schema}
    for r in rows:
        for col in schema:
            data[col].append(r.get(col))
    return pl.DataFrame(data, schema=schema)
```
