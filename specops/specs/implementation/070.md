# Implementation: TimeframeStartAndEndTimeValidator

## 1. Module location

`src/gtfs_validator/validators/timeframe_start_and_end_time.py`

## 2. Function signature

```python
def validate_timeframe_start_and_end_time(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

Standard validator signature per AGENTS.md. `ctx` is accepted but not used.

## 3. Notice definitions

### `timeframe_only_start_or_end_time_specified`

```python
Notice(
    code="timeframe_only_start_or_end_time_specified",
    severity=Severity.ERROR,
    fields={
        "csv_row_number": int,  # from timeframes.csv_row_number
    },
)
```

Condition: exactly one of `start_time` / `end_time` is non-null on the row
(XOR: `start_time IS NOT NULL` != `end_time IS NOT NULL`).

### `timeframe_start_or_end_time_greater_than_twenty_four_hours`

```python
Notice(
    code="timeframe_start_or_end_time_greater_than_twenty_four_hours",
    severity=Severity.ERROR,
    fields={
        "csv_row_number": int,    # from timeframes.csv_row_number
        "field_name": str,        # literal "start_time" or "end_time"
        "time": str,              # original Utf8 value, e.g. "24:00:01"
    },
)
```

Condition: the named field is non-null AND its value parsed to seconds since
midnight is strictly greater than 86400 (`24 * 3600`). `24:00:00` (86400 s)
is valid and does NOT trigger this notice. `24:00:01` (86401 s) does.

## 4. Implementation approach

**Strategy**: Polars vectorized filtering. Three independent filter passes over
the `timeframes` DataFrame produce three separate violation DataFrames. Notices
are built by iterating over each violation DataFrame in order (Check 1, then
Check 2, then Check 3).

**Time parsing**: `start_time` and `end_time` columns are Utf8 strings after
loading (FieldType.TIME columns are not cast to a numeric type). GTFS allows
`H:MM:SS` (one-digit hour) as well as `HH:MM:SS`. Use `str.split(":")` +
`list.get(index)` to handle both forms robustly.

**Module-level constant**:

```
TWENTY_FOUR_HOURS_SECONDS = 24 * 3600  # 86400
```

**Module-level helper** (used in two filter expressions):

```
_parse_time_seconds(col_name: str) -> pl.Expr
    Split pl.col(col_name) on ":", cast each part to Int32, return
    hours*3600 + minutes*60 + seconds as an Int64 expression.
    This expression is only evaluated on non-null rows (caller gates with
    is_not_null() first).
```

**Pseudocode**:

```
def validate_timeframe_start_and_end_time(feed, ctx):
    if "timeframes" not in feed or feed["timeframes"].is_empty():
        return []

    tf = feed["timeframes"].select(["start_time", "end_time", "csv_row_number"])

    has_start = pl.col("start_time").is_not_null()
    has_end   = pl.col("end_time").is_not_null()

    # Check 1: XOR — exactly one field is present
    xor_mask = has_start != has_end
    xor_violations = tf.filter(xor_mask)

    # Check 2: start_time present and > 24:00:00
    start_violations = tf.filter(
        has_start & (_parse_time_seconds("start_time") > TWENTY_FOUR_HOURS_SECONDS)
    )

    # Check 3: end_time present and > 24:00:00
    end_violations = tf.filter(
        has_end & (_parse_time_seconds("end_time") > TWENTY_FOUR_HOURS_SECONDS)
    )

    notices = []

    for row in xor_violations.iter_rows(named=True):
        notices.append(Notice(
            code="timeframe_only_start_or_end_time_specified",
            severity=Severity.ERROR,
            fields={"csv_row_number": row["csv_row_number"]},
        ))

    for row in start_violations.iter_rows(named=True):
        notices.append(Notice(
            code="timeframe_start_or_end_time_greater_than_twenty_four_hours",
            severity=Severity.ERROR,
            fields={
                "csv_row_number": row["csv_row_number"],
                "field_name": "start_time",
                "time": row["start_time"],
            },
        ))

    for row in end_violations.iter_rows(named=True):
        notices.append(Notice(
            code="timeframe_start_or_end_time_greater_than_twenty_four_hours",
            severity=Severity.ERROR,
            fields={
                "csv_row_number": row["csv_row_number"],
                "field_name": "end_time",
                "time": row["end_time"],
            },
        ))

    return notices
```

**Emission order**: Check 1 notices precede Check 2 notices, which precede
Check 3 notices. Within each check, row order follows DataFrame order (input
CSV row order). This matches the Java per-row emission sequence (Check 1 →
Check 2 → Check 3) when projected across the full table.

**Null safety**: The `_parse_time_seconds` expression is guarded by
`is_not_null()` in every filter that calls it. Null fields are never
parsed to seconds.

**No joins or cross-table references**: This validator operates entirely within
`timeframes`. No other table is needed.

## 6. Test plan

Test file: `tests/test_validators/test_timeframe_start_and_end_time.py`

All tests build minimal DataFrames with at least the columns `start_time`,
`end_time`, and `csv_row_number`. All time values are Utf8 strings (or None
for absent). Assertions check exact notice count, `code`, `severity`, and
`fields` contents.

---

### `test_explicit_full_day_interval`

**Input**: one row, `start_time="00:00:00"`, `end_time="24:00:00"`, `csv_row_number=1`.

**Expected**: `[]` — both fields present; `24:00:00` is exactly at the
boundary (86400 s == 86400), not strictly greater, so no notices.

---

### `test_implicit_full_day_interval`

**Input**: one row, `start_time=None`, `end_time=None`, `csv_row_number=1`.

**Expected**: `[]` — both absent; XOR is false; no presence checks fire.

---

### `test_beyond_twenty_four_hours_end_time`

**Input**: one row, `csv_row_number=2`, `start_time="00:00:00"`,
`end_time="24:00:01"`.

**Expected**: exactly one notice:
```
code="timeframe_start_or_end_time_greater_than_twenty_four_hours"
severity=Severity.ERROR
fields={"csv_row_number": 2, "field_name": "end_time", "time": "24:00:01"}
```
`start_time` is within bounds (no Check 2 notice); `end_time` is 86401 s >
86400 s.

---

### `test_only_start_time_specified`
