# Implementation: FareTransferRuleTransferCountValidator

## 1. Module Location

**Validator:** `src/gtfs_validator/validators/fare_transfer_rule_transfer_count.py`

No new shared utilities are needed. All three notice codes are specific to this
validator and are not shared with any existing notice.

The schema constant `FARE_TRANSFER_RULES` is already defined in `schemas.py`
(line 403). The relevant columns consumed at runtime are:

- `fare_transfer_rules.txt`: `from_leg_group_id` (optional ID), `to_leg_group_id`
  (optional ID), `transfer_count` (conditionally required integer, part of composite
  PK), `csv_row_number` (injected by the loading pipeline).

The `csv_row_number` column is present on the DataFrame at validator dispatch time —
the loading pipeline attaches it. Do not derive it via `with_row_index`.

## 3. Notice Definitions

### `fare_transfer_rule_invalid_transfer_count`

Severity: **ERROR**

Emitted when both `from_leg_group_id` and `to_leg_group_id` are present and
equal (a self-loop rule) and `transfer_count` is also present, but its value
is invalid. Valid values are `-1` (unlimited) and any integer `>= 1`. Invalid
values are `0` and any integer `< -1`.

```python
Notice(
    code="fare_transfer_rule_invalid_transfer_count",
    severity=Severity.ERROR,
    fields={
        "csv_row_number": <int>,   # CSV row number of the offending row
        "transfer_count": <int>,   # The invalid transfer_count value
    },
)
```

---

### `fare_transfer_rule_without_transfer_count`

Severity: **ERROR**

Emitted when both `from_leg_group_id` and `to_leg_group_id` are present and
equal (a self-loop rule) but `transfer_count` is absent. The GTFS spec
requires `transfer_count` when `from_leg_group_id == to_leg_group_id`.

```python
Notice(
    code="fare_transfer_rule_without_transfer_count",
    severity=Severity.ERROR,
    fields={
        "csv_row_number": <int>,   # CSV row number of the offending row
    },
)
```

---

### `fare_transfer_rule_with_forbidden_transfer_count`

Severity: **ERROR**

Emitted when the two leg group IDs are not equal or at least one is absent,
and `transfer_count` is present. The GTFS spec forbids `transfer_count` in
that case.

```python
Notice(
    code="fare_transfer_rule_with_forbidden_transfer_count",
    severity=Severity.ERROR,
    fields={
        "csv_row_number": <int>,   # CSV row number of the offending row
    },
)
```

---

**Null semantics:** After the two-phase load (raw string → typed cast), a
missing or empty CSV cell for an optional or conditionally-required column is
represented as `null` in Polars. `is_null()` / `is_not_null()` map directly
to the Java `hasFromLegGroupId()`, `hasToLegGroupId()`, and
`hasTransferCount()` semantics.

The Java equality check `Objects.equals(rule.fromLegGroupId(), rule.toLegGroupId())`
returns `false` when either argument is `null`. The Polars expression
`pl.col("from_leg_group_id") == pl.col("to_leg_group_id")` returns `null`
(not `false`) when either operand is `null`. The Branch A filter guards both
columns with `is_not_null()` before the equality comparison, which replicates
the Java behaviour faithfully.

## 4. Implementation Approach

```
function validate_fare_transfer_rule_transfer_count(feed, ctx):

    # --- Skip guard ---
    if "fare_transfer_rules" not in feed or feed["fare_transfer_rules"].is_empty():
        return []

    df = feed["fare_transfer_rules"]
    notices = []

    # --- Branch A: both leg group IDs are present and equal (self-loop) ---
    self_loop = df.filter(
        pl.col("from_leg_group_id").is_not_null()
        & pl.col("to_leg_group_id").is_not_null()
        & (pl.col("from_leg_group_id") == pl.col("to_leg_group_id"))
    )

    # Branch A, sub-case 1: transfer_count present but invalid (< -1 or == 0)
    invalid_count = self_loop.filter(
        pl.col("transfer_count").is_not_null()
        & ((pl.col("transfer_count") < -1) | (pl.col("transfer_count") == 0))
    )
    for row in invalid_count.iter_rows(named=True):
        notices.append(Notice(
            code="fare_transfer_rule_invalid_transfer_count",
            severity=Severity.ERROR,
            fields={
                "csv_row_number": row["csv_row_number"],
                "transfer_count": row["transfer_count"],
            },
        ))

    # Branch A, sub-case 2: transfer_count absent (required when IDs are equal)
    missing_count = self_loop.filter(pl.col("transfer_count").is_null())
    for row in missing_count.iter_rows(named=True):
        notices.append(Notice(
            code="fare_transfer_rule_without_transfer_count",
            severity=Severity.ERROR,
            fields={"csv_row_number": row["csv_row_number"]},
        ))

    # --- Branch B: leg group IDs not equal, or at least one absent ---
    not_self_loop = df.filter(
        pl.col("from_leg_group_id").is_null()
        | pl.col("to_leg_group_id").is_null()
        | (pl.col("from_leg_group_id") != pl.col("to_leg_group_id"))
    )

    # Branch B: transfer_count present (forbidden in this case)
    forbidden_count = not_self_loop.filter(pl.col("transfer_count").is_not_null())
    for row in forbidden_count.iter_rows(named=True):
        notices.append(Notice(
            code="fare_transfer_rule_with_forbidden_transfer_count",
            severity=Severity.ERROR,
            fields={"csv_row_number": row["csv_row_number"]},
        ))

    return notices
```

**Key design decisions:**

- **Two-branch partition, three filter passes.** `self_loop` and `not_self_loop`
  together cover every row exactly once. They are computed as separate Polars
  filter expressions over the full DataFrame; no Python-level branching per row
  is required. Within `self_loop`, two further filter passes separate the invalid
  value case from the missing value case.

- **Branch A and Branch B are mutually exclusive.** Every row falls into exactly
  one of the two parent filters. The Branch B filter is the logical complement of
  the Branch A filter (it matches when either guard from Branch A fails). This
  mirrors the Java `if / else` structure.

- **Polars null semantics for equality.** `pl.col("from_leg_group_id") != pl.col("to_leg_group_id")`
  evaluates to `null` (not `true`) when either operand is `null`. However, in the
  Branch B filter this expression is OR-combined with the two `is_null()` guards.
  If either ID is null, the `is_null()` arm short-circuits to `true` before the
  equality arm is evaluated. A row where both IDs are non-null but unequal
  reaches the `!=` arm, which correctly evaluates to `true`. The partition is
  therefore exhaustive and correct.

- **`iter_rows` only on filtered result sets.** Python-level iteration is
  confined to the (typically very small) subsets of violating rows. The filter
  expressions themselves are fully vectorized Polars operations.

- **Notice ordering.** Notices appear in this order: `fare_transfer_rule_invalid_transfer_count`
  notices (Branch A, sub-case 1, in CSV row order), then
  `fare_transfer_rule_without_transfer_count` notices (Branch A, sub-case 2, in
  CSV row order), then `fare_transfer_rule_with_forbidden_transfer_count` notices
  (Branch B, in CSV row order). This is a natural consequence of the sequential
  filter passes.

- **No column-presence guard needed.** The schema defines `from_leg_group_id`,
  `to_leg_group_id`, and `transfer_count` as columns of `fare_transfer_rules.txt`.
  The loading pipeline ensures all columns are present when the table is loaded,
  even if the CSV omits them (in which case they are all-null). The validator may
  reference all three columns unconditionally once the skip guard has passed.

- **`transfer_count` dtype is `Int64`.** After the two-phase load, `transfer_count`
  is cast to `pl.Int64`. The comparison expressions `< -1` and `== 0` operate on
  this integer column. When the column value is `null`, `is_not_null()` guards
  prevent the comparison from running. The `transfer_count` value carried in the
  `fields` dict is a Python `int` (not a Polars scalar), retrieved via
  `iter_rows(named=True)`.

- **Load-time checks not duplicated.** The following are handled at load time and
  must not be re-checked here: `fare_transfer_type` required and non-null;
  `duration_limit` positive integer constraint; `duration_limit_type` valid enum
  range; FK checks for `from_leg_group_id`, `to_leg_group_id`, and
  `fare_product_id`; composite PK uniqueness for
  `(from_leg_group_id, to_leg_group_id, fare_product_id, transfer_count, duration_limit)`.
  Consistency between `duration_limit` and `duration_limit_type` is handled by
  `FareTransferRuleDurationLimitTypeValidator`.

- **`ctx` unused.** The validator does not inspect the validation date or country
  code. The parameter is accepted to satisfy the `ValidatorFn` type alias.

from datetime import date

from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Severity

    validate_fare_transfer_rule_transfer_count,

def make_fare_transfer_rules(rows: list[dict]) -> pl.DataFrame:
    """Build a fare_transfer_rules DataFrame from a list of dicts.

            "csv_row_number": [r["csv_row_number"] for r in rows],
        }
    )
