# Implementation: FeedValidTodayValidator

## 1. Module Location

**Validator:** `src/gtfs_validator/validators/feed_valid_today.py`

This validator checks whether the feed covers the current date by
examining the minimum `feed_start_date` in `feed_info.txt`. It is
distinct from the existing `feed_expiration_date.py` (which checks
`feed_end_date` expiry) and `feed_service_date.py` (which checks
field-pair presence). A dedicated file is appropriate because the logic
and notice are unique to this concern.

## 2. Function Signature

```python
from __future__ import annotations

import polars as pl

from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Notice, Severity


def validate_feed_valid_today(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

This validator uses `ctx.date_for_validation` to determine the current
date for comparison.

## 3. Notice Definitions

### `future_feed`

Severity: **INFO**

Emitted when the minimum `feed_start_date` across all `feed_info.txt`
rows is strictly greater than the current validation date. This means
the feed covers only future service.

```python
Notice(
    code="future_feed",
    severity=Severity.INFO,
    fields={
        "feed_start_date": <str>,   # YYYYMMDD format, minimum start date found
        "current_date": <str>,      # YYYYMMDD format, the validation date
    },
)
```

This notice has no `csv_row_number` because it is an aggregate check
across all rows, not tied to a specific row.

## 4. Implementation Approach

### Skip conditions

```python
if "feed_info" not in feed or feed["feed_info"].is_empty():
    return []
```

Also skip if the `feed_start_date` column is not present in the
DataFrame (defensive, in case the column was not loaded):

```python
if "feed_start_date" not in df.columns:
    return []
```

### Algorithm

1. Get the `feed_info` DataFrame.
2. Compute `pl.col("feed_start_date").min()` — Polars handles nulls by
   ignoring them in aggregation functions.
3. If the result is `None` (all values were null), return no notices.
4. Compare the minimum start date against `ctx.date_for_validation`.
5. If `min_start > current_date`, emit one `future_feed` notice.

### Polars implementation

`feed_info.txt` is a single-row table, so `df.select(...).item()` is
the simplest approach. Polars `min()` ignores null values natively.

```python
def validate_feed_valid_today(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
    """Emit info notice when the feed covers only future service."""
    if "feed_info" not in feed or feed["feed_info"].is_empty():
        return []

    df = feed["feed_info"]

    if "feed_start_date" not in df.columns:
        return []

    min_start = df.select(pl.col("feed_start_date").min()).item()

    if min_start is None:
        return []

    current_date = ctx.date_for_validation

    if min_start > current_date:
        return [
            Notice(
                code="future_feed",
                severity=Severity.INFO,
                fields={
                    "feed_start_date": min_start.strftime("%Y%m%d"),
                    "current_date": current_date.strftime("%Y%m%d"),
                },
            )
        ]

    return []
```

### What is not checked here

The following are handled elsewhere and must not be duplicated:

- Type validation of `feed_start_date` (load-time casting).
- Whether both `feed_start_date` and `feed_end_date` are present
  (`FeedServiceDateValidator`, spec 020).
- Whether the feed has expired (`FeedExpirationDateValidator`, spec 019).
- Whether `feed_start_date <= feed_end_date` (load-time end-range check).

### Schema reference

`FEED_INFO` in `src/gtfs_validator/schemas.py`:

- `feed_start_date`: typed `_DATE` (`datetime.date` after load),
  annotated `_REC` (recommended).
- `csv_row_number`: injected by the loader as `Int64` on every loaded
  table (not used by this validator).

No schema changes are needed.

## 5. Registry Entry

In `src/gtfs_validator/validators/__init__.py`, add the import alongside
the other `feed_info`-dependent validators:

```python
from gtfs_validator.validators.feed_valid_today import validate_feed_valid_today
```

Append the entry to `VALIDATOR_REGISTRY` after the existing
`feed_service_date` entry to keep `feed_info`-dependent validators
grouped together:

```python
ValidatorEntry(
    name="feed_valid_today",
    fn=validate_feed_valid_today,
    requires=["feed_info"],
),
```
