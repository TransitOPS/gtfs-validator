# Implementation: TimeframeServiceIdForeignKeyValidator

## 1. Module Location

**Validator file:** `src/gtfs_validator/validators/timeframe_service_id_foreign_key.py`

This is a straightforward FK check against a union of two parent tables, using
the same pattern as `trip_service_id_foreign_key_validator.py`. No shared
utilities are needed beyond the standard imports.

## 2. Function Signature

```python
from __future__ import annotations

from typing import TYPE_CHECKING

import polars as pl

from gtfs_validator.notices import Notice, Severity

if TYPE_CHECKING:
    from gtfs_validator.context import ValidationContext


def validate_timeframe_service_id_foreign_key(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

`ctx` is unused but required by the standard validator signature.

## 3. Notice Definitions

### `foreign_key_violation` (ERROR)

This is a shared notice code used by many FK validators. Confirm that no new
notice class is required — emit a `Notice` directly with `code="foreign_key_violation"`
and `severity=Severity.ERROR`, matching the pattern in
`trip_service_id_foreign_key_validator.py`.

Emitted once per row in `timeframes.txt` whose `service_id` is absent from
both `calendar.txt` and `calendar_dates.txt`.

```python
Notice(
    code="foreign_key_violation",
    severity=Severity.ERROR,
    fields={
        "childFilename": "timeframes.txt",
        "childFieldName": "service_id",
        "parentFilename": "calendar.txt or calendar_dates.txt",
        "parentFieldName": "service_id",
        "fieldValue": <str>,      # the invalid service_id value
        "csvRowNumber": <int>,    # csv_row_number of the offending timeframes row
    },
)
```

The `parentFilename` value must be the exact string `"calendar.txt or calendar_dates.txt"`.
This reproduces the Java validator's output verbatim (constructed from
`GtfsCalendar.FILENAME + " or " + GtfsCalendarDate.FILENAME`).

Field key names use camelCase to match the existing `foreign_key_violation`
notice shape used by all other FK validators in the registry (see
`trip_service_id_foreign_key_validator.py` for the canonical field names:
`childFilename`, `childFieldName`, `parentFilename`, `parentFieldName`,
`fieldValue`, `csvRowNumber`).

## 4. Implementation Approach

Use Polars for column selection and set-membership filtering, following the
established pattern in `trip_service_id_foreign_key_validator.py` exactly.

### Pseudocode

```
function validate_timeframe_service_id_foreign_key(feed, ctx):

    # Guard: timeframes.txt absent from feed
    if "timeframes" not in feed or feed["timeframes"].is_empty():
        return []

    tf = feed["timeframes"]

    # Guard: service_id column must exist (defensive check)
    if "service_id" not in tf.columns:
        return []

    # Build union of valid service_id values from both parent tables.
    # Each absent or empty parent table contributes an empty set.
    valid_ids: set[str] = set()

    calendar = feed.get("calendar")
    if calendar is not None and not calendar.is_empty() and "service_id" in calendar.columns:
        valid_ids.update(
            calendar.select("service_id")
                    .filter(pl.col("service_id").is_not_null() & (pl.col("service_id") != ""))
                    .to_series()
                    .to_list()
        )

    calendar_dates = feed.get("calendar_dates")
    if calendar_dates is not None and not calendar_dates.is_empty() and "service_id" in calendar_dates.columns:
        valid_ids.update(
            calendar_dates.select("service_id")
                          .filter(pl.col("service_id").is_not_null() & (pl.col("service_id") != ""))
                          .to_series()
                          .to_list()
        )

    # Candidate rows: timeframes rows with non-null, non-empty service_id
    candidates = tf.filter(
        pl.col("service_id").is_not_null() & (pl.col("service_id") != "")
    )

    if candidates.is_empty():
        return []

    # Violations: rows whose service_id is not in the union set
    violations = candidates.filter(~pl.col("service_id").is_in(list(valid_ids)))

    # Emit one notice per violating row
    notices: list[Notice] = []
    for row in violations.iter_rows(named=True):
        notices.append(
            Notice(
                code="foreign_key_violation",
                severity=Severity.ERROR,
                fields={
                    "childFilename": "timeframes.txt",
                    "childFieldName": "service_id",
                    "parentFilename": "calendar.txt or calendar_dates.txt",
                    "parentFieldName": "service_id",
                    "fieldValue": row["service_id"],
                    "csvRowNumber": row["csvRowNumber"],
                },
            )
        )

    return notices
```

### Key design decisions

- **Set union built once before filtering.** Both parent sets are computed
  up-front and unioned. The single `is_in` call against the combined set
  is more efficient than two separate membership checks per row.

- **`is_in` on a Polars column against a Python list.** This is the exact
  pattern used in `trip_service_id_foreign_key_validator.py` and is
  appropriate here: parent tables are small relative to the number of
  unique `service_id` values, and the union set is computed only once.

- **One notice per violating row, no deduplication.** The same invalid
  `service_id` appearing on multiple `timeframes.txt` rows produces one
  notice per row, matching the Java behavior.

- **`csvRowNumber` field name.** The loader injects a `csvRowNumber`
  column (camelCase) for all tables. Use `row["csvRowNumber"]` to
  access it, consistent with `trip_service_id_foreign_key_validator.py`.

- **No feature flag.** The validator self-guards on the presence and
  emptiness of `timeframes.txt`. The `requires=["timeframes"]` registry
  entry causes the runner to skip the validator entirely when
  `timeframes.txt` is absent.

- **Null/empty `service_id` skipped.** `service_id` is required in
  `timeframes.txt` and null values should be caught at load time.
  Defensively, the `candidates` filter excludes null and empty-string
  values — they are not forwarded into the violation check and do not
  produce notices from this validator.

## 5. Registry Entry

Add import to `src/gtfs_validator/validators/__init__.py`:

```python
from gtfs_validator.validators.timeframe_service_id_foreign_key import (
    validate_timeframe_service_id_foreign_key,
)
```

Add to `VALIDATOR_REGISTRY` (place near the existing `timeframe_overlap` entry
for logical grouping):

```python
ValidatorEntry(
    name="timeframe_service_id_foreign_key",
    fn=validate_timeframe_service_id_foreign_key,
    requires=["timeframes"],
),
```

`requires` lists only `"timeframes"`. The validator must still run when
`calendar` and/or `calendar_dates` are absent — those absences are treated as
empty parent sets, which causes every timeframe row to produce a notice.
Including `"calendar"` or `"calendar_dates"` in `requires` would incorrectly
skip the validator when those tables are missing.

## 6. Test Plan

**Test file:** `tests/test_validators/test_timeframe_service_id_foreign_key.py`

### Shared helpers

```python
from datetime import date

import polars as pl

from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Severity
from gtfs_validator.validators.timeframe_service_id_foreign_key import (
    validate_timeframe_service_id_foreign_key,
)

CTX = ValidationContext(country_code="US", date_for_validation=date(2026, 3, 8))


def make_timeframes(service_ids: list[str | None], row_numbers: list[int] | None = None) -> pl.DataFrame:
    if row_numbers is None:
        row_numbers = list(range(2, 2 + len(service_ids)))
    return pl.DataFrame({
        "service_id": service_ids,
        "csvRowNumber": row_numbers,
    })


def make_calendar(service_ids: list[str]) -> pl.DataFrame:
    return pl.DataFrame({"service_id": service_ids})


def make_calendar_dates(service_ids: list[str]) -> pl.DataFrame:
    return pl.DataFrame({"service_id": service_ids})
```
