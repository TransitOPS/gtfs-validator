# Implementation: MissingCalendarAndCalendarDateValidator

## 1. Module Location

**File:** `src/gtfs_validator/validators/missing_calendar_and_calendar_date.py`

There is no existing calendar-grouping file in the validators directory. Each existing calendar-related validator occupies its own module (e.g., `expired_calendar.py`). This validator follows the same convention and lives in its own file.

This validator does not require `calendar` or `calendar_dates` to be present in the feed — the entire point is to detect their joint absence — so neither table appears in `requires`. The validator always runs regardless of feed content.

## 2. Function Signature

```python
from __future__ import annotations

import polars as pl

from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Notice, Severity


def validate_missing_calendar_and_calendar_date(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

No internal helper functions are needed. The logic is a single boolean condition on `feed` dict key presence.

## 3. Notice Definitions

### `missing_calendar_and_calendar_date_files` (ERROR)

Neither `calendar.txt` nor `calendar_dates.txt` is present in the feed. At least one of the two files must be provided to define service schedules.

```python
Notice(
    code="missing_calendar_and_calendar_date_files",
    severity=Severity.ERROR,
    fields={},
)
```

This notice carries no additional fields. It fires at most once per feed validation run, only when both tables are absent from the `feed` dict.

## 4. Implementation Approach

### Strategy: Pure Python dict key presence check

No Polars operations are needed. The validator inspects only whether the string keys `"calendar"` and `"calendar_dates"` are present in the `feed` dict. A key present with an empty DataFrame (zero rows) counts as present and does not trigger the notice.

### Algorithm

```
1. calendar_missing      = "calendar" not in feed
2. calendar_dates_missing = "calendar_dates" not in feed
3.
4. if calendar_missing and calendar_dates_missing:
5.     return [Notice(
6.         code="missing_calendar_and_calendar_date_files",
7.         severity=Severity.ERROR,
8.         fields={},
9.     )]
10.
11. return []
```

### Key design decisions

- **Presence, not content**: File presence is determined solely by whether the key exists in `feed`. Row count, column validity, and parse status are irrelevant. The orchestrator populates `feed` with a key only when the file was found in the GTFS archive; absent files produce no key.
- **No early return guards needed**: The condition is a single two-part boolean. There is no multi-stage logic.
- **Empty `fields` dict**: The notice carries no contextual fields because there is nothing to report beyond the bare fact that both files are missing. Pass an empty dict `{}` rather than omitting the `fields` argument, to match the `Notice` dataclass signature.
- **No Polars import is strictly needed**: The function signature references `pl.DataFrame` only via the type annotation on `feed`. The `import polars as pl` is retained to satisfy the consistent module pattern and the `TYPE_CHECKING` guard pattern used elsewhere.
- **`ctx` is unused**: `ValidationContext` is accepted to satisfy the `ValidatorFn` protocol but is not read. This is the same pattern used by other presence-only validators.

## 5. Registry Entry

In `src/gtfs_validator/validators/__init__.py`, add the import:

```python
from gtfs_validator.validators.missing_calendar_and_calendar_date import (
    validate_missing_calendar_and_calendar_date,
)
```

Append the entry to `VALIDATOR_REGISTRY`:

```python
ValidatorEntry(
    name="missing_calendar_and_calendar_date",
    fn=validate_missing_calendar_and_calendar_date,
    requires=[],
),
```

`requires` is an empty list because this validator does not consume any table data — it only checks for key absence. The runner's `should_skip` logic skips validators whose `requires` tables are all absent; an empty `requires` list means the validator always runs, which is the correct behavior here.

from datetime import date
import polars as pl
from gtfs_validator.context import ValidationContext

            "friday": pl.Int64,
            "saturday": pl.Int64,

def make_calendar_dates() -> pl.DataFrame:
    """Minimal calendar_dates.txt DataFrame with one exception row."""
    return pl.DataFrame(
        {
            "service_id": ["WEEK"],

        schema={
            "service_id": pl.Utf8,
            "date": pl.Utf8,
            "exception_type": pl.Int64,

    )


def make_empty_calendar() -> pl.DataFrame:
    """calendar.txt present but zero data rows (headers only)."""

    """calendar_dates.txt present but zero data rows."""

            "exception_type": pl.Int64,
        }
    )
