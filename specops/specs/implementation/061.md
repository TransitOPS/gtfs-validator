# Implementation: StopTimeIncreasingDistanceValidator

## 1. Module Location

**Validator:** `src/gtfs_validator/validators/stop_time_increasing_distance.py`

This is a single-table validator operating exclusively on `stop_times.txt`. No
cross-table joins are required. The check is stateful and ordered (per-trip
traversal), so plain Python iteration is used rather than forcing a Polars
expression approach.

No new shared utilities are needed.

## 2. Function Signature

```python
from __future__ import annotations

import polars as pl

from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Notice, Severity


def validate_stop_time_increasing_distance(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

`ctx` is accepted for interface consistency but is not consulted by this
validator.

## 3. Notice Definitions

### `decreasing_or_equal_stop_time_distance` (ERROR)

Emitted when two consecutive eligible stop times within a trip (ordered by
`stop_sequence`, excluding rows where `stop_id` is null) have a
non-increasing `shape_dist_traveled` — that is, when
`prev.shape_dist_traveled >= curr.shape_dist_traveled`.

Both values must be non-null for the comparison to occur. Equal values trigger
the notice in the same way as strictly decreasing values.

```python
Notice(
    code="decreasing_or_equal_stop_time_distance",
    severity=Severity.ERROR,
    fields={
        "trip_id":                  <str>,   # stop_times.trip_id
        "stop_id":                  <str>,   # stop_times.stop_id of the offending (current) row
        "csv_row_number":           <int>,   # 1-based CSV row of the current (offending) row
        "shape_dist_traveled":      <float>, # shape_dist_traveled of the current row
        "stop_sequence":            <int>,   # stop_sequence of the current row
        "prev_csv_row_number":      <int>,   # 1-based CSV row of the previous eligible row
        "prev_shape_dist_traveled": <float>, # shape_dist_traveled of the previous eligible row
        "prev_stop_sequence":       <int>,   # stop_sequence of the previous eligible row
    },
)
```

## 4. Implementation Approach

### Strategy

The check requires stateful, ordered traversal within each trip group. Per
AGENTS.md conventions, plain Python is preferred over Polars for stateful
graph/interval/ordering logic. The recommended pattern is:

1. Sort globally by `["trip_id", "stop_sequence"]`.
2. Partition by `"trip_id"` (maintaining order).
3. Iterate each per-trip sub-DataFrame row by row using `iter_rows(named=True)`.

This avoids converting the full DataFrame to a Python list while still
supporting the per-row `prev` state tracker.

### Guard Clause Ordering

```
1. "stop_times" not in feed                          → return []
2. feed["stop_times"].is_empty()                     → return []
3. "stop_id" column absent from DataFrame columns    → return []
4. "shape_dist_traveled" column absent from columns  → return []
5. Sort globally by ["trip_id", "stop_sequence"]
6. Partition by "trip_id" (maintain_order=True)
7. Run per-trip stateful algorithm
8. Return all collected notices
```

Steps 3 and 4 mirror the Java `shouldCallValidate()` guard, which skips
validation entirely when either column is absent from the file header. In the
Python loading layer, columns absent from the file header will not appear in
the DataFrame (unlike null-filled present columns). Check for column name
membership in `df.columns` before proceeding.

### Algorithm (pseudocode)

```
stop_times = feed["stop_times"]

sorted_st = stop_times.sort(["trip_id", "stop_sequence"])

for trip_df in sorted_st.partition_by("trip_id", maintain_order=True):
    prev = None
    for row in trip_df.iter_rows(named=True):
        if row["stop_id"] is None:
            continue                      # skip; do not update prev
        if (
            prev is not None
            and prev["shape_dist_traveled"] is not None
            and row["shape_dist_traveled"] is not None
            and prev["shape_dist_traveled"] >= row["shape_dist_traveled"]
        ):
            emit Notice(
                code="decreasing_or_equal_stop_time_distance",
                severity=Severity.ERROR,
                fields={
                    "trip_id":                  row["trip_id"],
                    "stop_id":                  row["stop_id"],
                    "csv_row_number":           row["csv_row_number"],
                    "shape_dist_traveled":      row["shape_dist_traveled"],
                    "stop_sequence":            row["stop_sequence"],
                    "prev_csv_row_number":      prev["csv_row_number"],
                    "prev_shape_dist_traveled": prev["shape_dist_traveled"],
                    "prev_stop_sequence":       prev["stop_sequence"],
                },
            )
        prev = row                        # always update prev for eligible rows
```

Key properties:

- `prev` is only updated when `curr` has a non-null `stop_id`. Null-`stop_id`
  rows are skipped entirely — they neither trigger a comparison nor advance
  `prev`.
- When `prev` is updated to a row that lacks `shape_dist_traveled`, the
  condition `prev["shape_dist_traveled"] is not None` will prevent a notice
  on the next eligible row.
- The comparison is `>=`, so equal values produce a notice.
- `prev` is reset to `None` at the start of each trip group (implicit in the
  `for trip_df in ...` loop scope).
- One notice is emitted per offending adjacent pair; multiple violations in
  one trip produce one notice each.

### Column Selection

Only the columns needed by the algorithm should be selected before
`iter_rows` to reduce memory pressure:

```python
trip_df.select([
    "csv_row_number",
    "trip_id",
    "stop_id",
    "stop_sequence",
    "shape_dist_traveled",
]).iter_rows(named=True)
```

### Type Notes

- `shape_dist_traveled` is loaded as `pl.Float64` (nullable). The `>=`
  comparison is a standard Python float comparison.
- `stop_sequence` is loaded as `pl.Int64`.
- `csv_row_number` is loaded as `pl.Int64`.

## 5. Registry Entry

Add the import in `src/gtfs_validator/validators/__init__.py` near the other
`stop_times`-only validators (e.g. `missing_trip_edge`,
`stop_time_arrival_departure`, `pickup_drop_off_type`):

```python

    validate_stop_time_increasing_distance,
)
```

Add the entry to `VALIDATOR_REGISTRY`:

```python
ValidatorEntry(
    name="stop_time_increasing_distance",
    fn=validate_stop_time_increasing_distance,
    requires=["stop_times"],
),
```

Place it grouped with the other `requires=["stop_times"]` entries for
readability.

### Tests Derived from Java Contracts

**Test 1: `test_increasing_distance_no_notice`**

Covers: `increasingDistanceAlongShapeShouldNotGenerateNotice`.

- Input: three stop times for `"first trip"`:
  - Row 1: `csv_row_number=1`, `stop_id="s0"`, `stop_sequence=2`, `shape_dist_traveled=10.0`
  - Row 2: `csv_row_number=2`, `stop_id="s1"`, `stop_sequence=42`, `shape_dist_traveled=45.0`
  - Row 3: `csv_row_number=3`, `stop_id="s2"`, `stop_sequence=46`, `shape_dist_traveled=64.0`
- Expected: `notices == []`.

**Test 2: `test_last_stop_decreasing_distance_emits_notice`**

Covers: `lastShapeWithDecreasingDistanceAlongShapeShouldGenerateNotice`.

- Input: three stop times for `"first trip"`, sequences 2/42/46, distances
  10.0/45.0/4.0. All rows have `stop_id`.
- Expected: exactly 1 notice:
  - `code == "decreasing_or_equal_stop_time_distance"`
  - `severity == Severity.ERROR`
  - `fields["trip_id"] == "first trip"`
  - `fields["stop_id"] == "s2"`
  - `fields["csv_row_number"] == 3`
  - `fields["shape_dist_traveled"] == 4.0`
  - `fields["stop_sequence"] == 46`
  - `fields["prev_csv_row_number"] == 2`
  - `fields["prev_shape_dist_traveled"] == 45.0`
  - `fields["prev_stop_sequence"] == 42`

**Test 3: `test_equal_distance_emits_notice`**

Covers: `twoShapesWithTheSameDistanceShouldGenerateNotice`.

- Input: three stop times for `"first trip"`, sequences 2/42/46, distances
  10.0/45.0/45.0. All rows have `stop_id`.
- Expected: exactly 1 notice:
  - `fields["shape_dist_traveled"] == 45.0`
  - `fields["prev_shape_dist_traveled"] == 45.0`
  - `fields["stop_sequence"] == 46`
  - `fields["prev_stop_sequence"] == 42`
- Rationale: confirms `>=` (not `>`) triggers the notice on equal values.

**Test 4: `test_intermediate_decreasing_distance_emits_notice`**

Covers: `oneIntermediateShapeWithDecreasingDistanceAlongShapeShouldGenerateNotice`.

- Input: three stop times for `"first trip"`, sequences 2/42/46, distances
  10.0/8.6/46.0. All rows have `stop_id`.
- Expected: exactly 1 notice for the pair at sequences 2 vs 42:
  - `fields["stop_id"] == "s1"`
  - `fields["csv_row_number"] == 2`
  - `fields["shape_dist_traveled"] == 8.6`
  - `fields["stop_sequence"] == 42`
  - `fields["prev_csv_row_number"] == 1`
  - `fields["prev_shape_dist_traveled"] == 10.0`
  - `fields["prev_stop_sequence"] == 2`
- Rationale: the offending row need not be the last; recovery at seq 46 does
  not suppress the notice already emitted for seq 42.

**Test 5: `test_null_stop_id_row_skipped_no_notice`**

Covers: `oneIntermediateShapeWithoutStopShouldBeIgnored`.

- Input: four stop times for `"first trip"`, sequences 1/2/3/4, distances
  0.0/45.0/4.0/64.0. Row 3 (`stop_sequence=3`) has `stop_id=None`.
- Expected: `notices == []`.
- Rationale: row 3's decreasing distance (4.0) is invisible because its
  `stop_id` is null; rows 2 and 4 are compared directly (45.0 → 64.0,
  which is increasing).

**Test 6: `test_null_stop_id_does_not_reset_prev_emits_notice`**

Covers: `oneIntermediateShapeWithoutStopAndPreviousDecreasingDistanceShouldGenerateNotice`.

- Input: four stop times for `"first trip"`, sequences 1/2/3/4, distances
  0.0/85.0/444.0/64.0. Row 3 (`stop_sequence=3`) has `stop_id=None`.
- Expected: exactly 1 notice for row 4 vs row 2:
  - `fields["stop_id"] == "s3"`
  - `fields["csv_row_number"] == 4`
  - `fields["shape_dist_traveled"] == 64.0`
  - `fields["stop_sequence"] == 4`
  - `fields["prev_csv_row_number"] == 2`
  - `fields["prev_shape_dist_traveled"] == 85.0`
  - `fields["prev_stop_sequence"] == 2`
- Rationale: the null-`stop_id` middle row does not update `prev`; `prev`
  remains at row 2 when row 4 is evaluated.

**Test 7: `test_multiple_null_stop_id_rows_skipped_emits_notice`**

Covers: `multipleIntermediateShapeWithoutStopAndPreviousDecreasingDistanceShouldGenerateNotice`.

- Input: five stop times for `"first trip"`, sequences 1/2/3/4/5, distances
  0.0/85.0/114.0/444.0/64.0. Rows 3 and 4 (`stop_sequence=3,4`) have
  `stop_id=None`.
- Expected: exactly 1 notice for row 5 vs row 2:
  - `fields["stop_id"] == "s3"`
  - `fields["csv_row_number"] == 5`
  - `fields["shape_dist_traveled"] == 64.0`
  - `fields["stop_sequence"] == 5`
  - `fields["prev_csv_row_number"] == 2`
  - `fields["prev_shape_dist_traveled"] == 85.0`
  - `fields["prev_stop_sequence"] == 2`
- Rationale: multiple consecutive null-`stop_id` rows are all ignored; `prev`
  stays at the last eligible row.

**Test 8: `test_null_stop_id_at_end_ignored_no_notice`**

Covers: `lastShapeWithoutStopShouldBeIgnored`.

- Input: six stop times for `"first trip"`, sequences 1–6, distances
  0.0/2.0/114.0/444.0/3.0/1.0. Rows 3, 4, and 6 have `stop_id=None`.
- Expected: `notices == []`.
- Rationale: row 5 (dist=3.0, has `stop_id`) is compared to row 2
  (dist=2.0) — increasing, no notice. Row 6 (dist=1.0, no `stop_id`) is
  skipped entirely.
