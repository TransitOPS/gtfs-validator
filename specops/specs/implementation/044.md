# Implementation: PathwayStopAccessValidator

## 1. Module location

```
src/gtfs_validator/validators/pathway_stop_access.py
```

The validator is a standalone module following the same convention as `pathway_endpoint_type.py` and `pathway_dangling_generic_node.py`.

## 2. Function signature

```python
def validate_pathway_stop_access(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

`ctx` is accepted but not used; it is required by the `ValidatorFn` protocol.

## 3. Notice definitions

### `pathway_to_stop_with_access_outside_of_station_pathways`

| Attribute | Value |
|---|---|
| `code` | `"pathway_to_stop_with_access_outside_of_station_pathways"` |
| `severity` | `Severity.ERROR` |

Fields dict:

| Key | Type | Source |
|---|---|---|
| `"csvRowNumber"` | `int` | `pathways["csv_row_number"]` for the offending row |
| `"platformCode"` | `str \| None` | `stops["platform_code"]` of the referenced stop (may be `None`) |
| `"pathwayId"` | `str` | `pathways["pathway_id"]` |
| `"stopId"` | `str` | The `from_stop_id` or `to_stop_id` value that has `stop_access == 1` |

Example construction:

```python
Notice(
    code="pathway_to_stop_with_access_outside_of_station_pathways",
    severity=Severity.ERROR,
    fields={
        "csvRowNumber": row["csv_row_number"],
        "platformCode": external_map[stop_id],   # str or None
        "pathwayId": row["pathway_id"],
        "stopId": stop_id,
    },
)
```

## 4. Implementation approach

### Guards

1. If `"stops"` is not in `feed`, return `[]`.
2. If `"stop_access"` is not a column in `feed["stops"]`, return `[]`.
3. If `"pathways"` is not in `feed` or `feed["pathways"].is_empty()`, return `[]`.

These guards mirror the Java `shouldCallValidate()` semantics described in the analysis spec.

### Phase 1 — Build the external-access stop map

Use Polars to filter stops where `stop_access == 1`, then convert to a plain Python dict for O(1) lookup during pathway iteration. Null `stop_access` values are excluded naturally by the equality filter.

```
external_df = feed["stops"]
    .filter(pl.col("stop_access") == 1)
    .select(["stop_id", "platform_code"])

if external_df.is_empty():
    return []

external_map: dict[str, str | None] = dict(
    zip(
        external_df["stop_id"].to_list(),
        external_df["platform_code"].to_list(),
    )
)
```

### Phase 2 — Scan pathway rows

Iterate over `pathways` rows (plain Python loop via `iter_rows(named=True)`) selecting only the four needed columns: `csv_row_number`, `pathway_id`, `from_stop_id`, `to_stop_id`.

For each row:

```
emitted: set[str] = set()   # at most 2 entries per row

for field_name in ("from_stop_id", "to_stop_id"):
    stop_id = row[field_name]
    if stop_id is None or stop_id == "":
        continue
    if stop_id not in external_map:
        continue
    if stop_id in emitted:
        continue                # dedup: same stop as both endpoints
    emitted.add(stop_id)
    emit notice(csv_row_number, external_map[stop_id], pathway_id, stop_id)
```

The `emitted` set scoped per row ensures that when `from_stop_id == to_stop_id` and that stop is in the external-access map, only one notice is produced.

### Why plain Python iteration instead of a pure Polars join

The deduplication requirement (one notice per unique `stop_id` per pathway row) is trivially expressed with the `emitted` set. A pure join approach produces two rows for the same pathway when both endpoints map to the same external-access stop, requiring a follow-up `unique()` or `group_by()`. Since `pathways.txt` is typically small (hundreds to low thousands of rows), the row-by-row approach is both simpler and adequate.

## 5. Registry entry

Add to `VALIDATOR_REGISTRY` in `src/gtfs_validator/validators/__init__.py`:

```python
from gtfs_validator.validators.pathway_stop_access import validate_pathway_stop_access

ValidatorEntry(
    name="pathway_stop_access",
    fn=validate_pathway_stop_access,
    requires=["stops", "pathways"],
),
```

Place it near the other `pathway_*` entries (after `pathway_reachable_location`).

## 6. Test plan

Test file: `tests/test_validators/test_pathway_stop_access.py`

All tests build minimal DataFrames inline. The `ctx` fixture uses any valid `ValidationContext`.

---

### `test_to_stop_has_external_access_yields_notice`

**Scenario:** The `to_stop_id` references a stop with `stop_access=1`; `from_stop_id` does not.

**Stops:**

| stop_id | stop_access | platform_code |
|---|---|---|
| `"stop1"` | `0` | `"platform1"` |
| `"stop2"` | `1` | `"platform2"` |

**Pathways:**

| csv_row_number | pathway_id | from_stop_id | to_stop_id |
|---|---|---|---|
| `12` | `"pathway12"` | `"stop1"` | `"stop2"` |

**Expected:** exactly 1 notice with:
- `code == "pathway_to_stop_with_access_outside_of_station_pathways"`
- `severity == Severity.ERROR`
- `fields["csvRowNumber"] == 12`
- `fields["platformCode"] == "platform2"`
- `fields["pathwayId"] == "pathway12"`
- `fields["stopId"] == "stop2"`

---
