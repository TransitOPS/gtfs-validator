# Implementation: ServiceGapValidator

## 1. Module Location

**Validator file:** `src/gtfs_validator/validators/service_gap.py`

No new shared utilities are needed. The interval set logic is self-contained within this module. The validator reads `calendar.txt` and optionally `calendar_dates.txt` from the feed dict.

## 3. Notice Definitions

### `big_gap_in_service` — Severity: INFO

Emitted once per gap that exceeds `MAX_GAP_DAYS` (i.e., 14 or more inactive days between two consecutive active service intervals).

```python
Notice(
    code="big_gap_in_service",
    severity=Severity.INFO,
    fields={
        "service_id": <str>,         # The service_id from calendar.txt
        "gap_start_date": <str>,     # YYYY-MM-DD: last active day before the gap (= prev_end)
        "gap_end_date": <str>,       # YYYY-MM-DD: first active day after the gap (= next_start)
        "gap_duration_days": <int>,  # Length of the inactive span (strictly > 13)
    },
)
```

Date fields are formatted as `YYYY-MM-DD` strings using `date.isoformat()`.

`gap_start_date` and `gap_end_date` are the **bounding active dates** around the gap, not the internal gap boundaries:
- `gap_start_date` = `prev_end` (the last active day before the inactive span)
- `gap_end_date` = `next_start` (the first active day after the inactive span)

## 4. Implementation Approach

### Data structures

```python
@dataclass
class DateInterval:
    start: date
    end: date  # inclusive

    def length_in_days(self) -> int:
        return (self.end - self.start).days + 1
```

A `ServiceIntervalSet` wraps a `list[DateInterval]` kept in ascending order by `start`. Because the number of intervals per service is small (at most a few hundred), linear-scan merge and split are acceptable. The normalization invariant is: no two intervals overlap, no two intervals are adjacent, all intervals are non-empty.

### Helper functions (module-level, pure)

**`_weekly_pattern`** — converts the seven day columns to a 7-bit integer (bit 0 = Monday, ..., bit 6 = Sunday):

```
def _weekly_pattern(mon, tue, wed, thu, fri, sat, sun) -> int:
    days = [mon, tue, wed, thu, fri, sat, sun]
    pattern = 0
    for i, d in enumerate(days):
        pattern |= (int(d) & 1) << i
    return pattern
```

**`_is_active_day`** — checks bit for a date's weekday (Python `date.weekday()` returns 0 = Monday):

```
def _is_active_day(d: date, pattern: int) -> bool:
    return bool((pattern >> d.weekday()) & 1)
```

**`_add_interval`** — merges a new `[new_start, new_end]` into the sorted interval list, absorbing overlapping or adjacent entries:

```
Pseudocode:
  new_interval = DateInterval(new_start, new_end)
  find all existing intervals that overlap or are adjacent to new_interval
  merge them all into a single extended interval covering the full union
  replace the absorbed entries with the merged result
```

Two intervals `A` and `B` overlap or are adjacent if `A.end + 1 day >= B.start` and `B.end + 1 day >= A.start`.

**`_add_date`** — adds a single date as a one-day interval; delegates to `_add_interval(d, d, ...)`.

**`_remove_date`** — removes a single date from the interval list:

```
Pseudocode:
  find the interval I that contains the date d (if any); if none, no-op
  if d == I.start and d == I.end: remove I entirely
  elif d == I.start: set I.start = d + 1 day
  elif d == I.end:   set I.end   = d - 1 day
  else: split I into [I.start, d - 1 day] and [d + 1 day, I.end]
```

**`_apply_calendar_row`** — walks a date range using the weekly pattern and emits contiguous active-day runs as intervals merged into the set:

```
Pseudocode:
  if pattern == 0: return   # no active days
  run_start = None
  current = start_date
  while current <= end_date:
      if _is_active_day(current, pattern):
          if run_start is None:
              run_start = current
      else:
          if run_start is not None:
              _add_interval(run_start, current - 1 day, intervals)
              run_start = None
      current += 1 day
  if run_start is not None:
      _add_interval(run_start, end_date, intervals)
```

**`_build_service_intervals`** — Phase 1 + Phase 2:

```
Pseudocode:
  intervals: dict[str, list[DateInterval]] = {}

  # Phase 1: calendar.txt weekly patterns
  for row in calendar.iter_rows(named=True):
      sid = row["service_id"]
      pattern = _weekly_pattern(row["monday"], ..., row["sunday"])
      if sid not in intervals:
          intervals[sid] = []
      _apply_calendar_row(row["start_date"], row["end_date"], pattern, intervals[sid])

  # Phase 2: calendar_dates.txt exceptions (only for service_ids seen in calendar)
  if calendar_dates is not None and not calendar_dates.is_empty():
      for row in calendar_dates.iter_rows(named=True):
          sid = row["service_id"]
          if sid not in intervals:
              continue  # service not driven by calendar.txt — skip
          if row["exception_type"] == 1:   # SERVICE_ADDED
              _add_date(row["date"], intervals[sid])
          elif row["exception_type"] == 2:  # SERVICE_REMOVED
              _remove_date(row["date"], intervals[sid])

  return intervals
```

Note: `calendar_dates.txt` exceptions are only applied to services already keyed in `intervals` (i.e., those that appeared in `calendar.txt`). Services appearing only in `calendar_dates.txt` are silently ignored, matching the Java behavior.

**`_get_gaps`** — returns the list of inactive spans between consecutive active intervals:

```
def _get_gaps(active_intervals: list[DateInterval]) -> list[DateInterval]:
    if len(active_intervals) < 2:
        return []
    gaps = []
    for i in range(1, len(active_intervals)):
        prev_end   = active_intervals[i - 1].end
        next_start = active_intervals[i].start
        gap_start  = prev_end + timedelta(days=1)
        gap_end    = next_start - timedelta(days=1)
        if gap_start <= gap_end:
            gaps.append(DateInterval(gap_start, gap_end))
    return gaps
```

### Main validator algorithm

```
Pseudocode:
  if "calendar" not in feed or feed["calendar"].is_empty():
      return []

  calendar = feed["calendar"].select(
      ["service_id", "start_date", "end_date",
       "monday", "tuesday", "wednesday", "thursday", "friday", "saturday", "sunday"]
  )
  calendar_dates = None
  if "calendar_dates" in feed and not feed["calendar_dates"].is_empty():
      calendar_dates = feed["calendar_dates"].select(
          ["service_id", "date", "exception_type"]
      )

  service_intervals = _build_service_intervals(calendar, calendar_dates)

  notices: list[Notice] = []

  for service_id, intervals in service_intervals.items():
      if len(intervals) < 2:
          continue
      for gap in _get_gaps(intervals):
          gap_length = gap.length_in_days()
          if gap_length > MAX_GAP_DAYS:
              # gap.start = prev_end + 1 day; gap.end = next_start - 1 day
              prev_end   = gap.start - timedelta(days=1)
              next_start = gap.end   + timedelta(days=1)
              notices.append(Notice(
                  code="big_gap_in_service",
                  severity=Severity.INFO,
                  fields={
                      "service_id": service_id,
                      "gap_start_date": prev_end.isoformat(),
                      "gap_end_date": next_start.isoformat(),
                      "gap_duration_days": gap_length,
                  },
              ))

  return notices
```

### Polars vs. plain Python

Per the analysis spec (section 7) and the AGENTS.md rule permitting plain Python for "interval logic when clearer and safer than forcing Polars":

- **Polars** is used only for the initial column selection (`df.select(...)`) and row iteration (`iter_rows(named=True)`).
- **Plain Python** handles all interval merge, split, and gap computation. The algorithm is inherently sequential and stateful and cannot be naturally vectorized.
- Do not attempt to implement `_add_interval` or `_remove_date` as Polars expressions.

### Column types after load-time cast

From `schemas.py` (`CALENDAR` and `CALENDAR_DATES`):
- `start_date`, `end_date`, `date` columns are typed `_DATE` → loaded as `datetime.date` Python objects after two-phase cast.
- `monday`–`sunday`, `exception_type` are typed `_ENUM` → loaded as Python `int` values.
- `service_id` → `str`.

No additional type coercion is needed inside the validator.

## 5. Registry Entry

Add the import to `src/gtfs_validator/validators/__init__.py` in the import block:

```python
from gtfs_validator.validators.service_gap import validate_service_gap
```

Append the entry to `VALIDATOR_REGISTRY`:

```python
ValidatorEntry(
    name="service_gap",
    fn=validate_service_gap,
    requires=["calendar"],
),
```

`requires=["calendar"]` is correct: `calendar_dates` is optional and its absence is handled gracefully inside the validator. The runner will skip this validator only if `calendar` is absent from the feed; presence of `calendar_dates` is irrelevant to dispatch.

Place the entry after the existing `expired_calendar` entry (which also depends on `calendar` and `calendar_dates`) to keep calendar-related validators grouped.
