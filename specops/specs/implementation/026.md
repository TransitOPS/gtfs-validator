# Implementation: InconsistentRouteTypeForInSeatTransferValidator

## 1. Module Location

**Validator:** `src/gtfs_validator/validators/inconsistent_route_type_for_in_seat_transfer.py`

This is a cross-table validator that joins `transfers.txt` with `routes.txt` (twice) to detect in-seat transfers (`transfer_type=4`) connecting routes with different `route_type` values. The check is fully vectorizable with Polars double-join and filter.

## 2. Function Signature

```python
from __future__ import annotations

import polars as pl

from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Notice, Severity


def validate_inconsistent_route_type_for_in_seat_transfer(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

No internal helpers are needed; the logic is a single filter-join-join-filter pipeline.

## 3. Notice Definitions

### `inconsistent_route_type_for_in_seat_transfer`

Severity: **WARNING**

Emitted when an in-seat transfer (`transfer_type=4`) connects two routes that have different `route_type` values.

```python
Notice(
    code="inconsistent_route_type_for_in_seat_transfer",
    severity=Severity.WARNING,
    fields={
        "csv_row_number": <int>,      # row number from transfers.txt
        "from_route_id": <str>,       # the from_route_id of the transfer
        "to_route_id": <str>,         # the to_route_id of the transfer
        "from_route_type": <int>,     # route_type of the from-route
        "to_route_type": <int>,       # route_type of the to-route
    },
)
```

## 4. Implementation Approach

### Strategy: Polars filter + double inner join

This validator is well-suited to a fully vectorized Polars implementation using two inner joins. The inner joins naturally exclude transfers whose `from_route_id` or `to_route_id` do not exist in `routes.txt`, matching the Java `Optional.ifPresent()` behavior. FK violations are handled elsewhere.

### Algorithm

```
1.  transfers = feed.get("transfers")
2.  routes = feed.get("routes")
3.  if transfers is None or routes is None:
4.      return []
5.  if transfers.is_empty() or routes.is_empty():
6.      return []
7.  for col in ("from_route_id", "to_route_id", "transfer_type"):
8.      if col not in transfers.columns:
9.          return []
10.
11. # Filter to in-seat transfers only (transfer_type == 4)
12. in_seat = transfers.filter(pl.col("transfer_type") == "4")
13. if in_seat.is_empty():
14.     return []
15.
16. route_lookup = routes.select("route_id", "route_type")
17.
18. # Join twice: once for from_route_id, once for to_route_id
19. joined = (
20.     in_seat.select("csvRowNumber", "from_route_id", "to_route_id")
21.     .join(
22.         route_lookup.rename({"route_id": "from_route_id", "route_type": "from_route_type"}),
23.         on="from_route_id",
24.         how="inner",
25.     )
26.     .join(
27.         route_lookup.rename({"route_id": "to_route_id", "route_type": "to_route_type"}),
28.         on="to_route_id",
29.         how="inner",
30.     )
31. )
32.
33. # Filter to rows where route types differ
34. bad = joined.filter(pl.col("from_route_type") != pl.col("to_route_type"))
35.
36. # Emit one notice per mismatched transfer
37. notices = []
38. for row in bad.iter_rows(named=True):
39.     notices.append(Notice(
40.         code="inconsistent_route_type_for_in_seat_transfer",
41.         severity=Severity.WARNING,
42.         fields={
43.             "csv_row_number": row["csvRowNumber"],
44.             "from_route_id": row["from_route_id"],
45.             "to_route_id": row["to_route_id"],
46.             "from_route_type": int(row["from_route_type"]),
47.             "to_route_type": int(row["to_route_type"]),
48.         },
49.     ))
50. return notices
```

### Handling missing tables and columns

- If `transfers` or `routes` is absent from the feed dict, the runner skips this validator entirely via the `requires` list (never called). The function also guards against `None` defensively.
- If `transfers` is present but lacks any of `from_route_id`, `to_route_id`, or `transfer_type` columns, return early with no notices.
- If `transfers` or `routes` is empty, return early with no notices.
- Transfers whose `from_route_id` or `to_route_id` do not match any route are excluded by the inner join (FK violations are handled by load-time FK infrastructure).

### Key design decisions

- The `transfer_type` column is compared as the string `"4"` since the loading phase reads CSV columns as Utf8 before type casting. If the schema casts `transfer_type` to integer, use integer comparison `== 4` instead. Check the actual dtype at implementation time and adjust accordingly.
- The `iter_rows` loop over bad rows is acceptable because the number of mismatched in-seat transfers is expected to be very small.
- The column rename approach avoids ambiguity when joining `routes` twice on different keys.
- `route_type` values in notice fields are cast to `int` for consistency with the analysis spec.
- Only `transfer_type=4` (IN_SEAT_TRANSFER_ALLOWED) triggers this validator. Other transfer types (0=RECOMMENDED, 1=TIMED, 2=MINIMUM_TIME, 3=IMPOSSIBLE, 5=IN_SEAT_TRANSFER_NOT_ALLOWED) are ignored.

## 5. Registry Entry

In `src/gtfs_validator/validators/__init__.py`, add the import:

```python
from gtfs_validator.validators.inconsistent_route_type_for_in_seat_transfer import (
    validate_inconsistent_route_type_for_in_seat_transfer,
)
```

Append the entry to `VALIDATOR_REGISTRY`:

```python
ValidatorEntry(
    name="inconsistent_route_type_for_in_seat_transfer",
    fn=validate_inconsistent_route_type_for_in_seat_transfer,
    requires=["transfers", "routes"],
),
```

Both `transfers` and `routes` are listed in `requires` because the validator needs both tables to perform the joins. If either is absent, the runner will skip it.

def make_routes(rows: list[tuple[str, str]]) -> pl.DataFrame:
    """Each row is (route_id, route_type)."""
    return pl.DataFrame(
        {"route_id": [r[0] for r in rows], "route_type": [r[1] for r in rows]}
    )


def make_transfers(rows: list[tuple[str, str, str]], row_start: int = 2) -> pl.DataFrame:
    """Each row is (from_route_id, to_route_id, transfer_type).

    csvRowNumber starts at row_start (default 2, since row 1 is the header).
    """
    return pl.DataFrame(
        {
            "csvRowNumber": list(range(row_start, row_start + len(rows))),
            "from_route_id": [r[0] for r in rows],
            "to_route_id": [r[1] for r in rows],
            "transfer_type": [r[2] for r in rows],
        }
    )
