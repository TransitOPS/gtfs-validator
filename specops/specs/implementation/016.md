# Implementation: FareTransferRuleDurationLimitTypeValidator

## 1. Module Location

**Validator:** `src/gtfs_validator/validators/fare_transfer_rule_duration_limit_type.py`

No new shared utilities are needed. Both notice codes are specific to this
validator and are not shared with any existing notice.

The schema constant `FARE_TRANSFER_RULES` is already defined in `schemas.py`
(line 403). The relevant columns are:

- `fare_transfer_rules.txt`: `duration_limit` (optional positive integer, part
  of composite PK), `duration_limit_type` (conditionally required enum),
  `csv_row_number` (injected by the loading pipeline).

The `csv_row_number` column is already present on the DataFrame at validator
dispatch time — the loading pipeline attaches it. Do not derive it via
`with_row_index`.

## 3. Notice Definitions

### `fare_transfer_rule_duration_limit_without_type`

Severity: **ERROR**

Emitted when a row in `fare_transfer_rules.txt` has `duration_limit` set (not
null) but `duration_limit_type` is absent (null). The duration value is
meaningless without knowing how it is measured.

```python
Notice(
    code="fare_transfer_rule_duration_limit_without_type",
    severity=Severity.ERROR,
    fields={
        "csv_row_number": <int>,  # csv_row_number of the offending row
    },
)
```

---

### `fare_transfer_rule_duration_limit_type_without_duration_limit`

Severity: **ERROR**

Emitted when a row in `fare_transfer_rules.txt` has `duration_limit_type` set
(not null) but `duration_limit` is absent (null). A duration limit type is
meaningless without an actual duration value.

```python
Notice(
    code="fare_transfer_rule_duration_limit_type_without_duration_limit",
    severity=Severity.ERROR,
    fields={
        "csv_row_number": <int>,  # csv_row_number of the offending row
    },
)
```

---

**Null semantics:** After the two-phase load (raw string → typed cast), a
missing or empty CSV cell for an optional integer or enum column is represented
as `null` in Polars. `is_null()` / `is_not_null()` map directly to the Java
`hasDurationLimit()` / `hasDurationLimitType()` semantics.

**Per-row, per-notice:** Each violating row produces exactly one notice. The
two checks are independent; they cannot both fire for the same row because
each checks the opposite presence combination.

## 4. Implementation Approach

```
function validate_fare_transfer_rule_duration_limit_type(feed, ctx):

    # --- Skip guard ---
    if "fare_transfer_rules" not in feed or feed["fare_transfer_rules"].is_empty():
        return []

    df = feed["fare_transfer_rules"]
    notices = []

    # --- Check 1: duration_limit present, duration_limit_type absent ---
    has_limit_no_type = df.filter(
        pl.col("duration_limit").is_not_null() & pl.col("duration_limit_type").is_null()
    )
    for row in has_limit_no_type.iter_rows(named=True):
        notices.append(Notice(
            code="fare_transfer_rule_duration_limit_without_type",
            severity=Severity.ERROR,
            fields={"csv_row_number": row["csv_row_number"]},
        ))

    # --- Check 2: duration_limit_type present, duration_limit absent ---
    has_type_no_limit = df.filter(
        pl.col("duration_limit_type").is_not_null() & pl.col("duration_limit").is_null()
    )
    for row in has_type_no_limit.iter_rows(named=True):
        notices.append(Notice(
            code="fare_transfer_rule_duration_limit_type_without_duration_limit",
            severity=Severity.ERROR,
            fields={"csv_row_number": row["csv_row_number"]},
        ))

    return notices
```

**Key design decisions:**

- **Two independent filter passes.** Each check runs as a separate Polars
  vectorized filter over the full `duration_limit` and `duration_limit_type`
  columns. This matches the Java `SingleEntityValidator` pattern of two
  independent conditionals per row.

- **No cross-row or cross-table state.** The validator reads only
  `fare_transfer_rules`. No joins, no lookups, no accumulators across rows.

- **`iter_rows` on filtered result only.** Python-level iteration is confined
  to the (typically very small) subsets of violating rows. The filter
  expressions themselves are fully vectorized Polars operations over the
  entire column.

- **Notice ordering.** All `fare_transfer_rule_duration_limit_without_type`
  notices appear before all
  `fare_transfer_rule_duration_limit_type_without_duration_limit` notices, in
  CSV row order within each group. This is a natural consequence of the two
  sequential filter passes.

- **No column-presence guard needed.** The schema defines `duration_limit` and
  `duration_limit_type` as columns of `fare_transfer_rules.txt`. The loading
  pipeline ensures both columns are present when the table is loaded, even if
  the CSV omits them (in which case they are all-null). The validator may
  therefore reference both columns unconditionally once the skip guard has
  passed.

- **Load-time checks not duplicated.** The following are handled at load time
  and must not be re-checked here: `duration_limit` positive integer
  constraint, `duration_limit_type` valid enum range (0–3), `fare_transfer_type`
  required, FK checks for `from_leg_group_id`, `to_leg_group_id`, and
  `fare_product_id`, composite PK uniqueness.

- **`ctx` unused.** The validator does not inspect the validation date or
  country code. The parameter is accepted to satisfy the `ValidatorFn` type
  alias.

```python
from datetime import date

from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Severity
from gtfs_validator.validators.fare_transfer_rule_duration_limit_type import (
    validate_fare_transfer_rule_duration_limit_type,
)

CTX = ValidationContext(country_code="US", date_for_validation=date(2024, 1, 1))


def make_fare_transfer_rules(rows: list[dict]) -> pl.DataFrame:
    """Build a fare_transfer_rules DataFrame from a list of dicts.

    Keys: duration_limit (int | None), duration_limit_type (int | None),
    csv_row_number (int). Other columns are omitted unless explicitly needed.
    """
    return pl.DataFrame(
        {
            "duration_limit": pl.Series(
                [r.get("duration_limit") for r in rows], dtype=pl.Int64
            ),
            "duration_limit_type": pl.Series(
                [r.get("duration_limit_type") for r in rows], dtype=pl.Int64
            ),
            "csv_row_number": [r["csv_row_number"] for r in rows],
        }
    )
```
