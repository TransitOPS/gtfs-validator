# Implementation: FareMediaNameValidator

## 1. Module Location

**Validator:** `src/gtfs_validator/validators/fare_media_name.py`

No new shared utilities are needed. The notice code `missing_recommended_field`
is generic and shared across validators. It is produced as a plain `Notice`
dataclass instance with `code="missing_recommended_field"` and
`severity=Severity.WARNING`.

The schema constant `FARE_MEDIA` is already defined in `schemas.py` at line 354.
The relevant columns are `fare_media_id` (required, PK), `fare_media_name`
(optional, text), and `fare_media_type` (required, enum).

## 3. Notice Definitions

### `missing_recommended_field`

Severity: **WARNING**

Emitted when `fare_media_type` is `TRANSIT_CARD` (2) or `MOBILE_APP` (4) and
`fare_media_name` is absent (null or empty string).

```python
Notice(
    code="missing_recommended_field",
    severity=Severity.WARNING,
    fields={
        "filename": "fare_media.txt",
        "csv_row_number": <int>,   # 0-based row index from with_row_index
        "field_name": "fare_media_name",
    },
)
```

**`csv_row_number` sourcing:** The `fare_media.txt` schema in `schemas.py` does
not declare a `csv_row_number` column. The value must be derived at load time
using `with_row_index`. Follow the same convention used by other validators in
the project: attach a 0-based integer index column named `"_row_idx"` via
`df.with_row_index("_row_idx")` and expose it as `csv_row_number` in the
notice `fields`. Do not hardcode 1-based offsets unless the project-wide
loading convention is confirmed to produce 1-based values. If the loading
pipeline already attaches a `csv_row_number` column to every DataFrame, use
that column directly without re-deriving it.

**`filename` wire format:** The literal string `"fare_media.txt"`, matching
`GtfsFareMedia.FILENAME` in the Java source.

**`field_name` wire format:** The literal string `"fare_media_name"`, matching
the Java field reference.

## 4. Implementation Approach

```
function validate_fare_media_name(feed, ctx):

    # --- Skip guard ---
    if "fare_media" not in feed or feed["fare_media"].is_empty():
        return []

    df = feed["fare_media"].with_row_index("_row_idx")

    # --- Vectorized violation filter ---
    # Types that require a name: TRANSIT_CARD=2, MOBILE_APP=4
    # Null fare_media_type never matches is_in([2, 4]), so null types
    # are safely treated as "no name required" (Java default: return false).
    requires_name = pl.col("fare_media_type").is_in([2, 4])

    # Treat both null and empty string as "absent"
    name_absent = pl.col("fare_media_name").is_null() | (pl.col("fare_media_name") == "")

    violations = df.filter(requires_name & name_absent)

    # --- Emit one notice per violating row ---
    notices = [
        Notice(
            code="missing_recommended_field",
            severity=Severity.WARNING,
            fields={
                "filename": "fare_media.txt",
                "csv_row_number": row["_row_idx"],
                "field_name": "fare_media_name",
            },
        )
        for row in violations.iter_rows(named=True)
    ]
    return notices
```

**Key design decisions:**

- **Fully vectorized pre-filter.** Both the type check (`is_in([2, 4])`) and
  the absence check (`is_null() | (col == "")`) are composed as Polars
  expressions. Only the (typically very small) set of violating rows is
  iterated in Python via `iter_rows(named=True)`. This matches the approach
  used in `duplicate_fare_media.py` and `fare_attribute_agency_id.py`.

- **Integer comparison for enum type.** `fare_media_type` is loaded as an
  integer column after load-time casting. The validator compares against
  integer literals `2` (TRANSIT_CARD) and `4` (MOBILE_APP) directly. No
  string comparison or named constant aliasing is required at the validator
  level unless the project defines a Python enum for `GtfsFareMediaType`.

- **Null `fare_media_type` treated as "no name required."** `pl.col("fare_media_type").is_in([2, 4])`
  evaluates to `false` for null values in Polars, which correctly skips null
  types without any explicit null guard. This matches Java's `default: return
  false` branch in `requiresFareMediaName`.

- **Empty string vs. null for `fare_media_name`.** Both are treated as absent.
  The compound predicate `is_null() | (col == "")` matches Java's
  `hasFareMediaName()` returning false for both null and the empty-string
  sentinel.

- **Single-table validator.** No joins, no cross-table lookups. The `ctx`
  argument is accepted but unused.

- **No guard for column existence.** `fare_media_name` and `fare_media_type`
  are declared in the `FARE_MEDIA` schema. If the CSV omits them entirely,
  the loading layer will handle that as a missing-column error before the
  validator runs. No defensive column-existence check is needed inside this
  validator.

- **Notice ordering.** Notices are emitted in ascending `_row_idx` order
  because `with_row_index` assigns indices in original row order and
  `df.filter` preserves row order.


Add to `VALIDATOR_REGISTRY` after the `"fare_leg_join_rule"` entry (alphabetical
by `name`):

```python
ValidatorEntry(
    name="fare_media_name",
    fn=validate_fare_media_name,
    requires=["fare_media"],
),
```

The `requires` list contains only `"fare_media"` because this is a
single-table validator. The skip guard in the function body handles the table
being absent or empty.
