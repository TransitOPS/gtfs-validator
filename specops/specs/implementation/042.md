# Implementation: PathwayLoopValidator

## 1. Module location

`src/gtfs_validator/validators/pathway_loop.py`

The validator is co-located with other pathway validators. The existing `pathways.py` module hosts `validate_bidirectional_exit_gate`; this new validator is simple enough to warrant its own file, matching the one-concern-per-file pattern used by the other pathway validators (`pathway_dangling_generic_node.py`, `pathway_endpoint_type.py`).

## 2. Function signature

```python
def validate_pathway_loop(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

`ctx` is accepted for interface consistency but is not used by this validator.

## 3. Notice definitions

### `pathway_loop`

- **Code:** `"pathway_loop"`
- **Severity:** `Severity.WARNING`
- **Fields dict:**

```python
{
    "csvRowNumber": int,   # csv_row_number from pathways.txt row
    "pathwayId":   str,   # pathway_id value from pathways.txt
    "stopId":      str,   # from_stop_id value (equal to to_stop_id when notice fires)
}
```

`stopId` is populated from `from_stop_id`, not `to_stop_id`. Both values are identical when the notice fires, and the Java constructor reads `pathway.fromStopId()` explicitly.

## 4. Implementation approach

Use a single vectorized Polars filter followed by a row iteration to emit notices. No joins or cross-table lookups are needed.

### Algorithm pseudocode

```
def validate_pathway_loop(feed, ctx):
    if "pathways" not in feed:
        return []

    pathways = feed["pathways"]

    if pathways.is_empty():
        return []

    violations = pathways.filter(
        from_stop_id is not null
        AND to_stop_id is not null
        AND from_stop_id == to_stop_id
    )

    notices = []
    for row in violations.select(["csv_row_number", "pathway_id", "from_stop_id"]).iter_rows(named=True):
        notices.append(
            Notice(
                code="pathway_loop",
                severity=Severity.WARNING,
                fields={
                    "csvRowNumber": row["csv_row_number"],
                    "pathwayId":    row["pathway_id"],
                    "stopId":       row["from_stop_id"],
                },
            )
        )
    return notices
```

### Null handling

Both `from_stop_id` and `to_stop_id` are `@Required` in the `PATHWAYS` schema, so they will ordinarily be non-null after loading. The `is_not_null()` guards replicate the Java `hasFromStopId()` / `hasToStopId()` checks, which return `False` for fields absent or empty in the CSV. Rows with a null endpoint are silently skipped; no notice is emitted.

### Ordering guarantee

The Polars filter preserves input row order. Notices are emitted in ascending `csv_row_number` order, matching the order rows appear in `pathways.txt`.

### Column requirements

From `pathways.txt`: `csv_row_number`, `pathway_id`, `from_stop_id`, `to_stop_id`.

## 5. Registry entry

Add the import to `src/gtfs_validator/validators/__init__.py` alongside the other pathway validator imports:

```python
from gtfs_validator.validators.pathway_loop import validate_pathway_loop
```

Add the entry to `VALIDATOR_REGISTRY` after the `pathway_endpoint_type` entry to keep pathway validators grouped:

```python
ValidatorEntry(
    name="pathway_loop",
    fn=validate_pathway_loop,
    requires=["pathways"],
),
```

## 6. Test plan

Test file: `tests/test_validators/test_pathway_loop.py`

### Shared fixtures

```python
CTX = ValidationContext(country_code="US", date_for_validation=date(2026, 3, 8))

PATHWAYS_SCHEMA = {
    "csv_row_number": pl.Int64,
    "pathway_id":     pl.Utf8,
    "from_stop_id":   pl.Utf8,
    "to_stop_id":     pl.Utf8,
}
```

Helper `make_feed(rows)`: accepts a list of dicts and returns `{"pathways": pl.DataFrame(rows, schema=PATHWAYS_SCHEMA)}`.

---

### `test_loop_yields_notice`

- Pathway: `csv_row_number=2`, `pathway_id="pw1"`, `from_stop_id="platform1"`, `to_stop_id="platform1"`.
- Expected: exactly one notice.
  - `code == "pathway_loop"`.
  - `severity == Severity.WARNING`.
  - `fields == {"csvRowNumber": 2, "pathwayId": "pw1", "stopId": "platform1"}`.
- Confirms: identical endpoint IDs on both sides triggers the notice; `stopId` is taken from `from_stop_id`.

---

### `test_no_loop_yields_no_notice`

- Pathway: `csv_row_number=2`, `pathway_id="pw1"`, `from_stop_id="platform1"`, `to_stop_id="entrance2"`.
- Expected: `[]`.
- Confirms: distinct endpoint IDs are valid; no notice emitted.

---

### `test_no_endpoints_yields_no_notice`

- Pathway: `csv_row_number=2`, `pathway_id="pw1"`, `from_stop_id=None`, `to_stop_id=None`.
- Expected: `[]`.
- Confirms: null endpoint fields cause the check to be skipped entirely.

---

### `test_null_from_stop_id_yields_no_notice`

### `test_multiple_loop_rows_yield_one_notice_each`

  - Row 3: `pw2`, `from="s1"`, `to="s2"` (no loop).

- Expected: exactly 2 notices.
  - Notice 0: `{csvRowNumber: 2, pathwayId: "pw1", stopId: "s1"}`.
  - Notice 1: `{csvRowNumber: 4, pathwayId: "pw3", stopId: "s3"}`.
- Confirms: one notice per offending row; non-loop rows are skipped; emission order follows `csv_row_number`.

### `test_pathways_absent_yields_no_notice`

- Expected: `[]`.

### `test_pathways_empty_yields_no_notice`

- Feed: `{"pathways": pl.DataFrame(schema=PATHWAYS_SCHEMA)}` (empty DataFrame).
- Expected: `[]`.
- Confirms: no notices when `pathways.txt` is present but has no rows.
