# Implementation: StopNameValidator

## 1. Module location

```
src/gtfs_validator/validators/stop_name.py
```

## 2. Function signature

```python
def validate_stop_name(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

`ctx` is accepted but unused; the validator is a single-table check over `stops.txt` only.

## 3. Notice definitions

### `missing_stop_name` — ERROR

Emitted when a stop, station, or entrance (location_type 0, 1, or 2) has no `stop_name`.

```python
Notice(
    code="missing_stop_name",
    severity=Severity.ERROR,
    fields={
        "csv_row_number": int,   # 1-based row number from stops.csv_row_number
        "stop_id":        str,   # stops.stop_id
        "location_type":  int,   # stops.location_type; always 0, 1, or 2
    },
)
```

Filter condition: `location_type IN (0, 1, 2) AND (stop_name IS NULL OR stop_name == "")`.

### `same_name_and_description_for_stop` — WARNING

Emitted when `stop_desc` duplicates `stop_name` (case-insensitive).

```python
Notice(
    code="same_name_and_description_for_stop",
    severity=Severity.WARNING,
    fields={
        "csv_row_number": int,   # 1-based row number from stops.csv_row_number
        "stop_id":        str,   # stops.stop_id
        "stop_desc":      str,   # stops.stop_desc (the duplicating description)
    },
)
```

Filter condition: `stop_name IS NOT NULL AND stop_name != "" AND stop_desc IS NOT NULL AND stop_desc != "" AND lower(stop_name) == lower(stop_desc)`.

Note: `stop_name` is intentionally not included in the `same_name_and_description_for_stop`
fields. Only `csv_row_number`, `stop_id`, and `stop_desc` are recorded — matching the Java
notice constructor signature.

### Enum reference

| `location_type` value | Name |
|---|---|
| 0 | STOP (default when column is absent from the row) |
| 1 | STATION |
| 2 | ENTRANCE/EXIT |
| 3 | GENERIC_NODE |
| 4 | BOARDING_AREA |
| any other | UNRECOGNIZED |

## 4. Implementation approach

### Guard clauses (return `[]` immediately if)

1. `"stops" not in feed` — `stops.txt` is absent from the feed.
2. `feed["stops"].is_empty()` — file is present but contains no data rows.
3. Both `"stop_name"` and `"location_type"` are absent from `stops.columns` — the
   column-level guard. The validator still runs when at least one of these two columns
   is present. This mirrors the Java `shouldCallValidate` behavior.

### Algorithm (Polars, two independent filter passes)

Both checks are independent vectorized filter passes. `iter_rows` is used only to
construct notices from the already-filtered subset, not for the filtering logic itself.

```
CONSTANT REQUIRED_NAME_LOCATION_TYPES = {0, 1, 2}  # STOP, STATION, ENTRANCE

# --- Guard clauses ---
IF "stops" not in feed:
    RETURN []

stops = feed["stops"]

IF stops.is_empty():
    RETURN []

IF "stop_name" not in stops.columns AND "location_type" not in stops.columns:
    RETURN []

notices = []

# --- Check A: missing_stop_name ---
# Only run when both stop_name and location_type columns are present.
IF "stop_name" in stops.columns AND "location_type" in stops.columns:
    missing_name = stops.filter(
        pl.col("location_type").is_in(list(REQUIRED_NAME_LOCATION_TYPES))
        & (pl.col("stop_name").is_null() | (pl.col("stop_name") == ""))
    )
    FOR row IN missing_name.iter_rows(named=True):
        EMIT Notice(
            code="missing_stop_name",
            severity=ERROR,
            fields={
                "csv_row_number": row["csv_row_number"],
                "stop_id":        row["stop_id"],
                "location_type":  row["location_type"],
            },
        )

# --- Check B: same_name_and_description_for_stop ---
# Only run when both stop_name and stop_desc columns are present.
IF "stop_name" in stops.columns AND "stop_desc" in stops.columns:
    same_name_desc = stops.filter(
        pl.col("stop_name").is_not_null()
        & (pl.col("stop_name") != "")
        & pl.col("stop_desc").is_not_null()
        & (pl.col("stop_desc") != "")
        & (
            pl.col("stop_name").str.to_lowercase()
            == pl.col("stop_desc").str.to_lowercase()
        )
    )
    FOR row IN same_name_desc.iter_rows(named=True):
        EMIT Notice(
            code="same_name_and_description_for_stop",
            severity=WARNING,
            fields={
                "csv_row_number": row["csv_row_number"],
                "stop_id":        row["stop_id"],
                "stop_desc":      row["stop_desc"],
            },
        )

RETURN notices
```

### Null semantics for `stop_name`

The Java `stop.hasStopName()` check returns `false` when `stop_name` is null/unset.
The Java `stop.stopName().isEmpty()` check returns `true` when `stop_name` is an empty
string. The Python loading layer should normalize empty strings to null at load time;
however, Check A uses `pl.col("stop_name").is_null() | (pl.col("stop_name") == "")` as
a safety net in case empty strings are preserved.

Check B uses the same dual guard on both `stop_name` and `stop_desc` for consistency.

### Case-insensitive comparison

The Java `isValidStopDesc` method uses `stopDesc.equalsIgnoreCase(stopName)`. The Polars
equivalent is:

```python
pl.col("stop_name").str.to_lowercase() == pl.col("stop_desc").str.to_lowercase()
```

### Default `location_type`

When `location_type` is omitted from a row, the schema applies a default of `0` (STOP)
at load time. The validator assumes this default has already been applied. A null
`location_type` in the DataFrame after loading would not be caught by the `is_in(...)` filter
and would silently skip; load-time default handling prevents this case.

### Independence of Check A and Check B

Check A and Check B are fully independent. Both are performed regardless of the other's
outcome. In practice a row cannot trigger both simultaneously: Check B requires `stop_name`
to be non-null and non-empty, while Check A fires only when `stop_name` is null or empty.

### Guard clause ordering

The following order must be preserved:

1. `"stops" not in feed` → return `[]`
2. `stops.is_empty()` → return `[]`
3. Neither `"stop_name"` nor `"location_type"` in `stops.columns` → return `[]`
4. Perform Check A only if both `"stop_name"` and `"location_type"` columns are present.
5. Perform Check B only if both `"stop_name"` and `"stop_desc"` columns are present.

## 5. Registry entry

Add to `VALIDATOR_REGISTRY` in `src/gtfs_validator/validators/__init__.py`:

```python
from gtfs_validator.validators.stop_name import validate_stop_name

# In VALIDATOR_REGISTRY list:
ValidatorEntry(
    name="stop_name",
    fn=validate_stop_name,
    requires=["stops"],
),
```

The `requires` list contains only `"stops"`. No other tables are consulted.

Place the entry near the other `stops`-only validators such as `location_type_single_entity`,
`parent_station`, and `stop_access`.

```python
import polars as pl
import pytest
from gtfs_validator.context import ValidationContext

from gtfs_validator.validators.stop_name import validate_stop_name

CTX = ValidationContext(country_code="US", date_for_validation=date(2024, 1, 1))

BASE_SCHEMA = {
    "csv_row_number": pl.Int64,
    "stop_id": pl.Utf8,
    "stop_name": pl.Utf8,
    "stop_desc": pl.Utf8,
    "location_type": pl.Int64,
}

def make_feed(rows: list[dict], schema: dict | None = None) -> dict[str, pl.DataFrame]:
    """Build a minimal feed dict with a stops DataFrame."""
    s = schema or BASE_SCHEMA
    if not rows:
        return {"stops": pl.DataFrame(schema=s)}
    return {"stops": pl.DataFrame(rows).cast(s)}
```
