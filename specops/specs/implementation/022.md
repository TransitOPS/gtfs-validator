# Implementation: GeoJsonGeometryValidator

## 1. Module Location

**Validator:** `src/gtfs_validator/validators/geojson_geometry.py`

Although the Java implementation is a load-time utility class called from `GeoJsonFileLoader`, the Python migration adapts this to the standard validator framework. The validator operates on a `locations_geojson` entry in the `feed` dict, which the GeoJSON loader populates during the loading phase as a list of parsed feature dicts (not a Polars DataFrame).

The `feed` dict convention is extended: `feed["locations_geojson"]` holds a Python list of feature dicts rather than a `pl.DataFrame`, since GeoJSON features with nested coordinate arrays do not map naturally to tabular form. The validator function still receives the standard `(feed, ctx)` signature. If `locations_geojson` is absent from `feed`, the validator returns an empty list.

**New dependency:** `shapely` must be added to the project dependencies. Shapely wraps GEOS (the same geometry engine underlying Java's JTS) and provides equivalent polygon construction and topological validation.

```python
def _validate_polygon(
    rings: list[list[list[float]]],
    feature_id: str,
    feature_index: int,
    geometry_type: str,

    """Construct and validate a MultiPolygon from GeoJSON coordinate arrays.

    Returns (MultiPolygon, []) on success or (None, [notices]) on failure.
    """
```

## 3. Notice Definitions

### `invalid_geometry`

Severity: **ERROR**

Emitted when a Polygon or MultiPolygon geometry fails GEOS topological validation or raises an exception during construction.

```python
Notice(
    code="invalid_geometry",
    severity=Severity.ERROR,
    fields={
        "feature_id": <str>,        # The "id" of the GeoJSON feature
        "feature_index": <int>,     # 0-based index in the features array
        "geometry_type": <str>,     # "Polygon" or "MultiPolygon"
        "message": <str>,           # Validation error detail from Shapely
    },
)
```

Conditions that trigger this notice:

- Self-intersecting ring (bowtie/figure-8 shape)
- Ring with fewer than 4 coordinates (3 distinct + closing point)
- Ring not closed (first and last coordinate differ)
- Hole outside shell (interior ring extends beyond exterior ring)
- Nested/crossing holes (interior rings overlap each other)
- Overlapping polygons in MultiPolygon (interiors intersect)
- Degenerate geometry (polygon collapses to a line or point)

## 4. Implementation Approach

### Strategy: Plain Python with Shapely

This validator requires computational geometry that cannot be expressed as Polars tabular operations. Use Shapely for polygon construction and topological validation, matching the Java implementation's use of JTS.

```python
from shapely.geometry import Polygon, MultiPolygon
from shapely.validation import explain_validity
from shapely.errors import GEOSException
```

### Data representation

The GeoJSON loader stores parsed features in `feed["locations_geojson"]` as a Python list of dicts. Each feature dict has the structure:

```python
{
    "id": str,               # feature id
    "index": int,            # 0-based position in the features array
    "geometry_type": str,    # "Polygon" or "MultiPolygon"
    "coordinates": list,     # nested coordinate arrays per GeoJSON spec
}
```

If the loader has not been implemented yet, the validator simply returns `[]` when the key is missing. This keeps it forward-compatible with future GeoJSON loading work.

### Skip conditions

```python
if "locations_geojson" not in feed:
    return []

features = feed["locations_geojson"]
if not features:
    return []
```

### Algorithm: `_validate_polygon(rings, feature_id, feature_index, geometry_type)`

```
1. try:
2.     shell = rings[0]       # exterior ring coordinates
3.     holes = rings[1:] if len(rings) > 1 else None
4.     polygon = Polygon(shell, holes)
5. except (GEOSException, ValueError) as exc:
6.     return (None, [Notice("invalid_geometry", ERROR, {
7.         "feature_id": feature_id,
8.         "feature_index": feature_index,
9.         "geometry_type": geometry_type,
10.        "message": str(exc),
11.    })])
12. if not polygon.is_valid:
13.     return (None, [Notice("invalid_geometry", ERROR, {
14.        "feature_id": feature_id,
15.        "feature_index": feature_index,
16.        "geometry_type": geometry_type,
17.        "message": explain_validity(polygon),
18.    })])
19. return (polygon, [])
```

### Algorithm: `_validate_multi_polygon(polygons_coords, feature_id, feature_index)`

```
1. sub_polygons = []
2. all_notices = []
3. for p, poly_rings in enumerate(polygons_coords):
4.     polygon, notices = _validate_polygon(
5.         poly_rings, feature_id, p, "MultiPolygon"
6.     )
7.     if notices:
8.         return (None, notices)   # short-circuit on first invalid sub-polygon
9.     sub_polygons.append(polygon)
10. try:
11.     multi = MultiPolygon(sub_polygons)
12. except (GEOSException, ValueError) as exc:
13.     return (None, [Notice("invalid_geometry", ERROR, {
14.         "feature_id": feature_id,
15.         "feature_index": feature_index,
16.         "geometry_type": "MultiPolygon",
17.         "message": str(exc),
18.     })])
19. if not multi.is_valid:
20.     return (None, [Notice("invalid_geometry", ERROR, {
21.         "feature_id": feature_id,
22.         "feature_index": feature_index,
23.         "geometry_type": "MultiPolygon",
24.         "message": explain_validity(multi),
25.     })])
26. return (multi, [])
```

### Algorithm: `validate_geojson_geometry(feed, ctx)`

```
1. if "locations_geojson" not in feed or not feed["locations_geojson"]:
2.     return []
3. notices = []
4. for feature in feed["locations_geojson"]:
5.     feature_id = feature["id"]
6.     feature_index = feature["index"]
7.     geom_type = feature["geometry_type"]
8.     coords = feature["coordinates"]
9.     if geom_type == "Polygon":
10.        _, feat_notices = _validate_polygon(
11.            coords, feature_id, feature_index, "Polygon"
12.        )
13.    elif geom_type == "MultiPolygon":
14.        _, feat_notices = _validate_multi_polygon(
15.            coords, feature_id, feature_index
16.        )
17.    else:
18.        continue  # unsupported types handled elsewhere
19.    notices.extend(feat_notices)
20. return notices
```

### Coordinate interpretation

GeoJSON coordinates are `[longitude, latitude]`. Shapely interprets them as `(x, y)` where `x = longitude` and `y = latitude`, matching the Java/JTS convention. No coordinate reordering is needed.

### What is NOT checked here

- Whether `locations.geojson` is present (handled by the loader)
- Whether required GeoJSON fields (`id`, `type`, `geometry`, `properties`) exist (handled by GeoJSON loader)
- Whether the geometry type is supported (handled by loader; emits `unsupported_geometry_type`)
- Whether coordinates are near the origin or poles (separate validator concern)
- Duplicate JSON keys, unknown elements, missing required elements (all handled by GeoJSON loader)

## 5. Registry Entry

In `src/gtfs_validator/validators/__init__.py`, add the import:

```python
from gtfs_validator.validators.geojson_geometry import validate_geojson_geometry
```

Append the entry to `VALIDATOR_REGISTRY`:

```python
ValidatorEntry(
    name="geojson_geometry",
    fn=validate_geojson_geometry,
    requires=["locations_geojson"],
),
```

The `requires=["locations_geojson"]` entry causes the runner to skip this validator when `locations.geojson` was not present in the feed (i.e., the key is absent from the `feed` dict). This is consistent with how other validators are skipped when their required tables are missing.

## 6. Test Plan

Test file: `tests/test_validators/test_geojson_geometry.py`

All tests construct minimal `feed` dicts with feature lists and call `validate_geojson_geometry` directly. Shapely is used in tests only to verify that valid inputs produce no notices -- the validator itself uses Shapely internally.
