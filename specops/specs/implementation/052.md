# Implementation: ServiceHasNoActiveDayOfTheWeekValidator

## 1. Module Location

**Validator file:** `src/gtfs_validator/validators/service_no_active_day.py`

This validator is self-contained. It reads only `calendar.txt` from the feed dict and requires no shared utilities beyond the standard imports.

## 3. Notice Definitions

### `service_has_no_active_day_of_the_week` — Severity: WARNING

Emitted once per `calendar.txt` row where `service_id` is non-null/non-empty and all seven day-of-week columns (`monday` through `sunday`) hold `0` (NOT_AVAILABLE).

```python
Notice(
    code="service_has_no_active_day_of_the_week",
    severity=Severity.WARNING,
    fields={
        "csvRowNumber": <int>,   # 1-based row number of the offending calendar row
        "serviceId": <str>,      # value of calendar.service_id for that row
    },
)
```

Field name conventions follow the camelCase pattern used throughout the existing notice registry (`csvRowNumber`, `serviceId`).

One notice per offending row. If the PK constraint is somehow violated and multiple rows share a `service_id`, each row is checked independently and may independently produce a notice.

---

## 4. Implementation Approach

### Strategy: pure Polars filter + collect

The check is a straightforward vectorized predicate — no graph traversal, no interval arithmetic, no stateful accumulation. A single `pl.all_horizontal` expression identifies all offending rows in one pass.

### Module-level constant and helper

```python
_DAY_COLUMNS: list[str] = [
    "monday", "tuesday", "wednesday", "thursday", "friday", "saturday", "sunday"
]
_NOT_AVAILABLE: int = 0


def _all_days_inactive() -> pl.Expr:
    """Boolean expression: True when every day column equals NOT_AVAILABLE (0).

    fill_null(0) replicates Java's enum default of NOT_AVAILABLE for missing
    required fields. Nulls in day columns should already produce a load-time
    notice; treating them as 0 here is a safe defensive fallback that does not
    change observable output.
    """
    return pl.all_horizontal(
        [pl.col(day).fill_null(_NOT_AVAILABLE).eq(_NOT_AVAILABLE) for day in _DAY_COLUMNS]
    )
```

### Main validator pseudocode

```
def validate_service_no_active_day(feed, ctx):
    # Guard: table absent or empty
    if "calendar" not in feed or feed["calendar"].is_empty():
        return []

    df = feed["calendar"]

    # Filter to rows where service_id is non-null AND all day columns are 0
    offending = df.filter(
        pl.col("service_id").is_not_null() & _all_days_inactive()
    )

    if offending.is_empty():
        return []

    notices: list[Notice] = []
    for row in offending.select(["csv_row_number", "service_id"]).iter_rows(named=True):
        notices.append(
            Notice(
                code="service_has_no_active_day_of_the_week",
                severity=Severity.WARNING,
                fields={
                    "csvRowNumber": row["csv_row_number"],
                    "serviceId": row["service_id"],
                },
            )
        )
    return notices
```

### Column types after load-time cast

From `schemas.py` (`CALENDAR` definition):
- `service_id` — `_ID` → `pl.Utf8`
- `monday` through `sunday` — `_ENUM` → `pl.Int64` (values 0 or 1)
- `csv_row_number` — injected by the loader as `pl.Int64`, 1-based

No additional type coercion is needed inside the validator beyond the `fill_null(0)` defensive null handling inside `_all_days_inactive`.

### Why `pl.all_horizontal` over a manual fold

`pl.all_horizontal` produces a clean, readable single expression and is idiomatic Polars for "all of these boolean columns are true". It avoids a Python-level loop over column names at expression-build time while staying equally correct.

### `calendar_dates.txt` is not consulted

This validator is scoped strictly to the weekly-pattern columns of `calendar.txt`. Exception dates in `calendar_dates.txt` are irrelevant — a service with all-zero day columns is flagged regardless of whether `calendar_dates.txt` has SERVICE_ADDED rows for it.

Add the import to the import block in `src/gtfs_validator/validators/__init__.py`:

```python
from gtfs_validator.validators.service_no_active_day import validate_service_no_active_day
```

Append the entry to `VALIDATOR_REGISTRY` (place it near the existing `service_gap` entry to keep calendar-related validators grouped):

```python
ValidatorEntry(
    name="service_no_active_day",
    fn=validate_service_no_active_day,
    requires=["calendar"],
),
```

`requires=["calendar"]` is the complete dependency list. The runner will skip this validator if `calendar` is absent from the feed; `calendar_dates` plays no role here.

## 6. Test Plan

**Test file:** `tests/test_validators/test_service_no_active_day.py`

All tests construct minimal Polars DataFrames and call `validate_service_no_active_day` directly.

### Shared helpers

```python
from __future__ import annotations

import polars as pl
import pytest

from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Severity
from gtfs_validator.validators.service_no_active_day import validate_service_no_active_day

CTX = ValidationContext(country_code="US", date_for_validation=__import__("datetime").date(2024, 1, 1))

_CALENDAR_SCHEMA = {
    "csv_row_number": pl.Int64,
    "service_id": pl.Utf8,
    "monday": pl.Int64,
    "tuesday": pl.Int64,
    "wednesday": pl.Int64,
    "thursday": pl.Int64,
    "friday": pl.Int64,
    "saturday": pl.Int64,
    "sunday": pl.Int64,
}

_ALL_ZERO = {"monday": 0, "tuesday": 0, "wednesday": 0, "thursday": 0,
             "friday": 0, "saturday": 0, "sunday": 0}

_ALL_ONE = {"monday": 1, "tuesday": 1, "wednesday": 1, "thursday": 1,
            "friday": 1, "saturday": 1, "sunday": 1}


def make_calendar(rows: list[dict]) -> pl.DataFrame:
    """Build a calendar DataFrame from row dicts. Returns empty frame when rows=[]."""
    if not rows:
        return pl.DataFrame(schema=_CALENDAR_SCHEMA)
    return pl.DataFrame(rows, schema=_CALENDAR_SCHEMA)
```
