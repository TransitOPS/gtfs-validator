## 1. Module location

`src/gtfs_validator/validators/pickup_drop_off_window.py`

## 2. Function signature

```python
def validate_pickup_drop_off_window(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

## 3. Notice definitions

### `forbidden_arrival_or_departure_time`

- **Code**: `"forbidden_arrival_or_departure_time"`
- **Severity**: `Severity.ERROR`
- **Fields dict structure**:

```python
{
    "csv_row_number": int,                       # stop_times.csv_row_number
    "arrival_time": int | None,                  # seconds-since-midnight, or None if absent/null
    "departure_time": int | None,                # seconds-since-midnight, or None if absent/null
    "start_pickup_drop_off_window": int | None,  # seconds-since-midnight, or None if absent/null
    "end_pickup_drop_off_window": int | None,    # seconds-since-midnight, or None if absent/null
}
```

Emitted when at least one of `start_pickup_drop_off_window` or `end_pickup_drop_off_window` is non-null on the same row as a non-null `arrival_time` or `departure_time`. GTFS prohibits both timing approaches on a single stop-time record. All four time fields are carried into the notice at their raw loaded values (integers, or `None` if the column is absent from the header or null for that row).

### `missing_pickup_or_drop_off_window`

- **Code**: `"missing_pickup_or_drop_off_window"`
- **Severity**: `Severity.ERROR`
- **Fields dict structure**:

```python
{
    "csv_row_number": int,                       # stop_times.csv_row_number
    "start_pickup_drop_off_window": int | None,  # value from row, or None if absent/null
    "end_pickup_drop_off_window": int | None,    # value from row, or None if absent/null
}
```

Emitted when exactly one of `start_pickup_drop_off_window` or `end_pickup_drop_off_window` is non-null — i.e., both fields must be provided together, but one is missing. The present window field carries its value; the absent or null one carries `None`.

### `invalid_pickup_drop_off_window`

- **Code**: `"invalid_pickup_drop_off_window"`
- **Severity**: `Severity.ERROR`
- **Fields dict structure**:

```python
{
    "csv_row_number": int,           # stop_times.csv_row_number
    "start_pickup_drop_off_window": int,  # always non-null (check C only runs when both present)
    "end_pickup_drop_off_window": int,    # always non-null
}
```

Emitted when both window fields are present and non-null but `end_pickup_drop_off_window` is not strictly greater than `start_pickup_drop_off_window` (i.e., end <= start). Both fields are always non-null when this notice is emitted because check C is only reached when both are present.

## 4. Implementation approach

**Approach**: Polars vectorized filter passes, then row iteration for notice construction.

Three sequential filter passes are made over the `windowed` subset (rows where at least one window field is non-null). Check A and check B are independent filter passes over `windowed`. Check C operates on a partition of `windowed` that is mutually exclusive with check B — specifically the rows where both windows are present. This naturally enforces the "check B causes early return, so check C is skipped for those rows" semantics from the Java implementation without any explicit branching.

**Pseudocode**:

```
function validate_pickup_drop_off_window(feed, ctx):

    # Guard: stop_times must be in feed
    if "stop_times" not in feed:
        return []

    df = feed["stop_times"]
    cols = set(df.columns)

    has_start = "start_pickup_drop_off_window" in cols
    has_end   = "end_pickup_drop_off_window" in cols

    # Guard: at least one window column must be present in the header
    if not has_start and not has_end:
        return []

    # Build window_expr: at least one window field is non-null for this row
    window_expr = pl.lit(False)
    if has_start:
        window_expr = window_expr | pl.col("start_pickup_drop_off_window").is_not_null()
    if has_end:
        window_expr = window_expr | pl.col("end_pickup_drop_off_window").is_not_null()

    # Subset: rows where at least one window field is non-null
    windowed = df.filter(window_expr)

    notices = []

    # ---- Check A: arrival_time or departure_time present alongside window fields ----

    has_arrival   = "arrival_time" in cols
    has_departure = "departure_time" in cols

    time_expr = pl.lit(False)
    if has_arrival:
        time_expr = time_expr | pl.col("arrival_time").is_not_null()
    if has_departure:
        time_expr = time_expr | pl.col("departure_time").is_not_null()

    check_a_violations = windowed.filter(time_expr)
    for row in check_a_violations.iter_rows(named=True):
        notices.append(Notice(
            code="forbidden_arrival_or_departure_time",
            severity=Severity.ERROR,
            fields={
                "csv_row_number": row["csv_row_number"],
                "arrival_time": row.get("arrival_time"),
                "departure_time": row.get("departure_time"),
                "start_pickup_drop_off_window": row.get("start_pickup_drop_off_window"),
                "end_pickup_drop_off_window": row.get("end_pickup_drop_off_window"),
            },
        ))

    # ---- Check B: exactly one window present (missing the other) ----

    # both_windows_expr: True only when ALL present window columns are non-null
    both_windows_expr = pl.lit(True)
    if has_start:
        both_windows_expr = both_windows_expr & pl.col("start_pickup_drop_off_window").is_not_null()
    if has_end:
        both_windows_expr = both_windows_expr & pl.col("end_pickup_drop_off_window").is_not_null()

    check_b_violations = windowed.filter(~both_windows_expr)
    for row in check_b_violations.iter_rows(named=True):
        notices.append(Notice(
            code="missing_pickup_or_drop_off_window",
            severity=Severity.ERROR,
            fields={
                "csv_row_number": row["csv_row_number"],
                "start_pickup_drop_off_window": row.get("start_pickup_drop_off_window"),
                "end_pickup_drop_off_window": row.get("end_pickup_drop_off_window"),
            },
        ))

    # ---- Check C: end window not strictly after start window ----
    # Only evaluated for rows where both windows are present (complement of check B rows)

    check_c_candidates = windowed.filter(both_windows_expr)
    check_c_violations = check_c_candidates.filter(
        pl.col("end_pickup_drop_off_window") <= pl.col("start_pickup_drop_off_window")
    )
    for row in check_c_violations.iter_rows(named=True):
        notices.append(Notice(
            code="invalid_pickup_drop_off_window",
            severity=Severity.ERROR,
            fields={
                "csv_row_number": row["csv_row_number"],
                "start_pickup_drop_off_window": row["start_pickup_drop_off_window"],
                "end_pickup_drop_off_window": row["end_pickup_drop_off_window"],
            },
        ))

    return notices
```

**Check interaction and mutual exclusivity**:

- `check_b_violations` = rows in `windowed` where NOT both windows are present.
- `check_c_candidates` = rows in `windowed` where both windows ARE present.
- These two sets are a partition of `windowed`; a row can appear in one or the other, never both. This implements the Java "check B causes early return, check C is skipped" semantics without explicit per-row branching.
- A row can produce at most two notices: one from check A and one from either check B or check C (never both B and C).

**Column presence handling**:

- If neither `arrival_time` nor `departure_time` is in `df.columns`, `time_expr` remains `pl.lit(False)` and `check_a_violations` is empty — check A emits nothing.
- If only `arrival_time` is present (no `departure_time`), `time_expr` checks only that column.
- If only `start_pickup_drop_off_window` is present (no `end_pickup_drop_off_window`): `both_windows_expr` checks only `start_pickup_drop_off_window`. Any row with a non-null start fires check B (missing end). Check C never runs because `both_windows_expr` cannot be true if `end_pickup_drop_off_window` is absent from the header.
- Symmetrically for only `end_pickup_drop_off_window` present.
- Use `row.get(col_name)` (not `row[col_name]`) when building notice fields for optionally-present columns so that absent columns yield `None` rather than raising `KeyError`. The `invalid_pickup_drop_off_window` notice fields use `row["..."]` (bracket access) since check C only runs when both columns are confirmed present.

**Time field representation**:

After loading, `arrival_time`, `departure_time`, `start_pickup_drop_off_window`, and `end_pickup_drop_off_window` are stored as integers (seconds since midnight) per the `_TIME` field type in `schemas.py`. The check C comparison `end <= start` is a direct integer comparison that correctly implements the Java `isAfter()` / `equals()` semantics. No time parsing or conversion is needed in the validator.

**`both_windows_expr` when only one window column exists in header**:

When only `start_pickup_drop_off_window` is in the header (no `end_pickup_drop_off_window` column), `both_windows_expr` evaluates to `start_pickup_drop_off_window.is_not_null()`. A row with a non-null start would pass this test, but check C would then attempt to reference `end_pickup_drop_off_window`, which doesn't exist. This case is safe because `both_windows_expr` was built without the end column, so a row can only reach `check_c_candidates` if the start is non-null — but since the end column is absent, the end comparison in check C cannot execute. In practice this scenario (one window column absent from the header entirely) is handled correctly: `both_windows_expr` will require both columns to be non-null only when both columns exist; if one is absent from the header, the expression built from only the present column will still pass some rows to `check_c_candidates`, so an extra guard is needed.

**Clarification — both columns must exist for check C to be safe**:

Before executing `check_c_violations`, explicitly guard that both window columns are present in `df.columns`. If only one window column exists in the header, skip check C entirely (the missing column means all rows with any window set will have already fired check B, so check C would have no valid candidates anyway):

```
if has_start and has_end:
    check_c_candidates = windowed.filter(both_windows_expr)
    check_c_violations = check_c_candidates.filter(
        pl.col("end_pickup_drop_off_window") <= pl.col("start_pickup_drop_off_window")
    )
    for row in check_c_violations.iter_rows(named=True):
        ...
```

### `test_only_start_column_in_header_missing_end_fires_check_b`

Setup:
- `stop_times` DataFrame constructed with columns `csv_row_number`, `arrival_time`, `departure_time`, `start_pickup_drop_off_window` (no `end_pickup_drop_off_window` column at all).
- Row: `csv_row_number=9`, `arrival_time=None`, `departure_time=None`, `start_pickup_drop_off_window=3600`.

Expected:
- Exactly 1 notice with `code == "missing_pickup_or_drop_off_window"`.
- `notice.fields["start_pickup_drop_off_window"] == 3600`.
- `notice.fields["end_pickup_drop_off_window"] is None`.

Explanation: Header guard passes (start column present). Entry condition passes (start non-null). `both_windows_expr` requires `start.is_not_null()` only (end column absent), so it evaluates True for this row — but check C is guarded by `if has_start and has_end`, which is False, so check C is skipped. Check B fires because `~both_windows_expr` ... wait: `both_windows_expr` is True when only `has_start` is True and `start_pickup_drop_off_window` is non-null. So `~both_windows_expr` is False and check B does not fire. Check C is skipped by the `has_start and has_end` guard. Net result: 0 notices.

**Correction**: When only `start_pickup_drop_off_window` is in the header, `both_windows_expr = pl.col("start_pickup_drop_off_window").is_not_null()`. A row with a non-null start satisfies `both_windows_expr`, so it does NOT appear in `check_b_violations`. And since `has_end` is False, check C is skipped by the explicit guard. Therefore this row produces no notices. This is correct GTFS behavior: when the end column is absent from the header entirely, the feed predates the window feature and should not be penalized for missing-end.

**Revised expected**: `[]`.
