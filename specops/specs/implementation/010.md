# Implementation: DuplicateRouteNameValidator

## 1. Module Location

**Validator:** `src/gtfs_validator/validators/duplicate_route_name.py`

No shared utilities needed. This is a single-table validator operating
only on `routes.txt` with no cross-table joins or date logic.

## 3. Notice Definitions

All notices have severity **WARNING**.

### `duplicate_route_name`

Emitted when two distinct routes within the same agency share the same
`(route_short_name, route_long_name, route_type, agency_id)` tuple.
Each duplicate row after the first produces a separate notice paired
with the first occurrence.

```python
Notice(
    code="duplicate_route_name",
    severity=Severity.WARNING,
    fields={
        "csv_row_number_1": <int>,       # row number of first occurrence
        "route_id_1": <str>,             # ID of first occurrence
        "csv_row_number_2": <int>,       # row number of duplicate
        "route_id_2": <str>,             # ID of duplicate
        "route_short_name": <str>,       # shared short name
        "route_long_name": <str>,        # shared long name
        "route_type_value": <int>,       # shared route type as integer
        "agency_id": <str>,              # shared agency ID
    },
)
```

Referenced file: `routes.txt`.

## 4. Implementation Approach

```
function validate_duplicate_route_name(feed, ctx):
    # 1. Guard: table must exist and be non-empty
    if "routes" not in feed or feed["routes"].is_empty():
        return []

    df = feed["routes"]

    # 2. Add 1-based csv_row_number from row order
    df = df.with_row_index("_idx").with_columns(
        (pl.col("_idx") + 2).alias("csv_row_number")
    )

    # 3. Fill null string fields with empty string to match Java
    #    default-getter semantics (null -> "")
    df = df.with_columns(
        pl.col("route_short_name").fill_null("").alias("route_short_name"),
        pl.col("route_long_name").fill_null("").alias("route_long_name"),
        pl.col("agency_id").fill_null("").alias("agency_id"),
    )

    # 4. Group by composite key and collect row numbers and IDs as lists
    #    Filter to groups with more than one row (duplicates)
    groups = (
        df.sort("csv_row_number")
        .group_by("route_short_name", "route_long_name", "route_type", "agency_id")
        .agg(
            pl.col("csv_row_number"),
            pl.col("route_id"),
        )
        .filter(pl.col("csv_row_number").list.len() > 1)
    )

    # 5. Emit notices: pair first row with each subsequent row
    notices = []
    for row in groups.iter_rows(named=True):
        row_numbers = row["csv_row_number"]
        route_ids = row["route_id"]
        short_name = row["route_short_name"]
        long_name = row["route_long_name"]
        route_type = row["route_type"]
        agency_id = row["agency_id"]

        first_row_number = row_numbers[0]
        first_route_id = route_ids[0]

        for i in range(1, len(row_numbers)):
            notices.append(
                Notice(
                    code="duplicate_route_name",
                    severity=Severity.WARNING,
                    fields={
                        "csv_row_number_1": first_row_number,
                        "route_id_1": first_route_id,
                        "csv_row_number_2": row_numbers[i],
                        "route_id_2": route_ids[i],
                        "route_short_name": short_name,
                        "route_long_name": long_name,
                        "route_type_value": route_type,
                        "agency_id": agency_id,
                    },
                )
            )

    return notices
```

**Key design decisions:**

- **`+ 2` for csv_row_number.** The `with_row_index` gives a 0-based
  index. Adding 2 yields the 1-based csv_row_number that accounts for
  the header row, matching the Java convention where row 1 is the
  header and data starts at row 2.
- **`fill_null("")` on route_short_name, route_long_name, and
  agency_id.** Matches Java default-getter semantics where missing
  values are returned as empty strings. This ensures two routes with
  null short names (and matching long name, type, agency) are grouped
  together as duplicates.
- **`sort("csv_row_number")` before `group_by`.** Polars `group_by`
  does not guarantee intra-group ordering. Sorting first ensures the
  first element in each aggregated list is always the earliest row,
  giving deterministic pairing semantics.
- **Polars `group_by` + `agg` with list collection.** Groups by the
  four-column composite key and collects row numbers and IDs as lists.
  Filtering to `list.len() > 1` discards unique entries efficiently.
- **Direct tuple comparison instead of hashing.** The Java
  implementation uses FarmHash64 for the composite key. The Python
  implementation uses Polars group-by on the actual column values,
  which avoids hash collision false positives and is idiomatic.
- **Python iteration for notice emission.** Routes tables are typically
  small (hundreds to low thousands of rows), so iterating over
  duplicate groups in Python is appropriate. The first element of each
  list is always the "left" side of the notice.

## 5. Registry Entry

In `src/gtfs_validator/validators/__init__.py`, add the import and
registry entry:

```python
from gtfs_validator.validators.duplicate_route_name import validate_duplicate_route_name

# Add to VALIDATOR_REGISTRY list:
ValidatorEntry(
    name="duplicate_route_name",
    fn=validate_duplicate_route_name,
    requires=["routes"],
),
```

The `requires` list specifies `"routes"` as the sole required table.
The runner will skip this validator if `routes.txt` is not present in
the feed.
