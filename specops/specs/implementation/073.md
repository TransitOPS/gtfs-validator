## 3. Notice definitions

### `missing_required_field` (ERROR)

Emitted once per missing conditionally-required stop ID field on a non-in-seat
transfer row. Both fields are checked independently; a single row may produce
zero, one, or two notices.

```python
Notice(
    code="missing_required_field",
    severity=Severity.ERROR,
    fields={
        "filename": "transfers.txt",           # literal string, always this value
        "csv_row_number": int,                 # from transfers.csv_row_number
        "field_name": "from_stop_id",          # or "to_stop_id"
    },
)
```

Conditions for emission (all three must hold):

- `transfer_type` IS NOT NULL, AND
- `transfer_type` NOT IN {4, 5} (i.e., not an in-seat transfer), AND
- the named field (`from_stop_id` or `to_stop_id`) IS NULL

The two field checks (`from_stop_id`, `to_stop_id`) are always performed
independently. A row missing both fields produces exactly two notices, one
for each field, with `field_name` set accordingly.

## 4. Implementation approach

**Strategy**: vectorized Polars. Filter the transfers DataFrame once to the
applicable (non-in-seat, non-null transfer_type) rows, then perform a
separate null-check pass for each of the two stop ID fields. No row-by-row
Python iteration over the full table is needed.

### Guard clauses

Return `[]` immediately if any of the following are true:

1. `"transfers"` not in `feed`
2. `feed["transfers"].is_empty()`
3. Any of the required columns (`"transfer_type"`, `"from_stop_id"`,
   `"to_stop_id"`, `"csv_row_number"`) is absent from `feed["transfers"].columns`

These guards match the Java `shouldCallValidate` conditions. In particular,
if `transfer_type` is absent the column guard fires and no notices are
emitted (not even for rows that have null stop IDs), which is the correct
behavior.

### Column type note

After load-time casting, `transfer_type` is stored as a nullable integer
(`Int64` or `Int32`) in the feed DataFrame. A null value means the column
was absent or unparseable for that row. The Polars expression
`pl.col("transfer_type").is_not_null()` handles this correctly.

The `from_stop_id` and `to_stop_id` columns are `Utf8` (string); a null
value means the field was absent or empty in the CSV.

### Pseudocode

```python
def validate_transfer_stop_ids_conditional(feed, ctx):
    if "transfers" not in feed:
        return []

    transfers = feed["transfers"]

    if transfers.is_empty():
        return []

    required_cols = {"transfer_type", "from_stop_id", "to_stop_id", "csv_row_number"}
    if not required_cols.issubset(transfers.columns):
        return []

    # Filter once to rows that are subject to the stop ID requirement:
    # transfer_type must be non-null AND not an in-seat type (4 or 5).
    non_in_seat = transfers.filter(
        pl.col("transfer_type").is_not_null()
        & ~pl.col("transfer_type").is_in([4, 5])
    )

    notices: list[Notice] = []

    # Check each stop ID field independently.
    # from_stop_id is checked before to_stop_id to preserve Java field order.
    for field_name in ("from_stop_id", "to_stop_id"):
        missing = non_in_seat.filter(pl.col(field_name).is_null())
        for row in missing.select(["csv_row_number"]).iter_rows(named=True):
            notices.append(
                Notice(
                    code="missing_required_field",
                    severity=Severity.ERROR,
                    fields={
                        "filename": "transfers.txt",
                        "csv_row_number": row["csv_row_number"],
                        "field_name": field_name,
                    },
                )
            )

    return notices
```

### Notice ordering

The outer loop processes `from_stop_id` before `to_stop_id`. Within each
field, notices are emitted in the order rows appear in the filtered
DataFrame (which reflects CSV row order). This means all `from_stop_id`
notices precede all `to_stop_id` notices across the full output list. This
is acceptable: the Java implementation processes one row at a time (checking
`from_stop_id` then `to_stop_id` per row), but since both orderings are
behaviorally equivalent for validation purposes and the spec does not require
interleaved per-row ordering, the two-pass Polars approach is correct.

## 6. Test plan

Test file: `tests/test_validators/test_transfer_stop_ids_conditional.py`

All tests build minimal DataFrames inline. Integer columns use Python `int`
(or `None`); string columns use Python `str` (or `None`). Polars infers
dtypes from Python values. Assertions check exact notice count, `code`,
`severity`, and key `fields` values.

### Helper factories (suggested)

