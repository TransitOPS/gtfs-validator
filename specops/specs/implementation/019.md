# Implementation: FeedExpirationDateValidator

## 1. Module Location

**Validator:** `src/gtfs_validator/validators/feed_expiration_date.py`

No new shared utilities are required. The validator reads only
`feed_info.txt` and uses `ctx.date_for_validation` directly.

## 2. Function Signature

```python
from __future__ import annotations

from datetime import timedelta

import polars as pl

from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Notice, Severity


def validate_feed_expiration_date(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

`ctx.date_for_validation` is a `datetime.date` object (frozen field on
`ValidationContext`). No additional context fields are needed.

## 3. Notice Definitions

Both notices have severity **WARNING**. The two are mutually exclusive:
at most one is emitted per `feed_info.txt` row.

### `feed_expiration_date_7_days`

Emitted when `feed_end_date < current_date + 7 days` (strict less-than).
Applies when the feed expires in 6 days or fewer, or has already expired.

```python
Notice(
    code="feed_expiration_date_7_days",
    severity=Severity.WARNING,
    fields={
        "csv_row_number": <int>,           # CSV row number of the row
        "current_date": <str>,             # YYYYMMDD, the validation date
        "feed_end_date": <str>,            # YYYYMMDD, the declared end date
        "suggested_expiration_date": <str>,# YYYYMMDD, current_date + 7 days
    },
)
```

### `feed_expiration_date_30_days`

Emitted when `feed_end_date >= current_date + 7 days` AND
`feed_end_date < current_date + 30 days` (strict less-than). Applies
when the feed expires in 7–29 days inclusive.

```python
Notice(
    code="feed_expiration_date_30_days",
    severity=Severity.WARNING,
    fields={
        "csv_row_number": <int>,           # CSV row number of the row
        "current_date": <str>,             # YYYYMMDD, the validation date
        "feed_end_date": <str>,            # YYYYMMDD, the declared end date
        "suggested_expiration_date": <str>,# YYYYMMDD, current_date + 30 days
    },
)
```

All date fields are formatted as `YYYYMMDD` strings using
`date.strftime("%Y%m%d")`, matching the Java notice output format.

## 4. Implementation Approach

### Skip conditions

```python
if "feed_info" not in feed or feed["feed_info"].is_empty():
    return []
```

If `feed_end_date` is null for a given row, that row is skipped
silently (no notice). This is handled by filtering the DataFrame to
non-null `feed_end_date` rows before iteration.

### Algorithm

```
current_date = ctx.date_for_validation          # datetime.date
plus_7       = current_date + timedelta(days=7)
plus_30      = current_date + timedelta(days=30)

df = feed["feed_info"].filter(pl.col("feed_end_date").is_not_null())

for row in df.iter_rows(named=True):
    end_date   = row["feed_end_date"]   # datetime.date after load-time cast
    row_number = row["csv_row_number"]  # int

    if end_date < plus_7:
        emit feed_expiration_date_7_days(
            csv_row_number=row_number,
            current_date=current_date.strftime("%Y%m%d"),
            feed_end_date=end_date.strftime("%Y%m%d"),
            suggested_expiration_date=plus_7.strftime("%Y%m%d"),
        )
        continue   # 30-day check is skipped for this row

    if end_date < plus_30:
        emit feed_expiration_date_30_days(
            csv_row_number=row_number,
            current_date=current_date.strftime("%Y%m%d"),
            feed_end_date=end_date.strftime("%Y%m%d"),
            suggested_expiration_date=plus_30.strftime("%Y%m%d"),
        )
```

The `continue` after emitting `feed_expiration_date_7_days` enforces
mutual exclusivity: the 30-day check is never evaluated for the same
row that triggered the 7-day notice.

### Date arithmetic

Use `datetime.timedelta` for offset arithmetic, which correctly handles
month and year rollovers (matching Java's `LocalDate.plusDays`).

The Java test uses `TEST_NOW = 2021-01-25` because adding 7 days rolls
to February 1 (month boundary) and adding 30 days rolls to February 24.
Python `date + timedelta` handles this identically.

### Why `iter_rows` is acceptable here

`feed_info.txt` is declared `single_row=True` in `schemas.py`, so the
loader enforces at most one data row. There is no performance concern
with row-by-row iteration over a single-row table.

### Boundary semantics

Both comparisons are strict less-than (`<`). The boundary values
themselves (`current_date + 7` and `current_date + 30`) do NOT trigger
a notice. A `feed_end_date` exactly equal to `current_date + 30`
produces no notice.

### What is not checked here

The following are handled at load time and must not be duplicated:

- Type validation of `feed_end_date` (valid YYYYMMDD date string).
- End-range check: `feed_start_date <= feed_end_date` (enforced by
  `load_validators.py` via the `end_range` annotation in `FEED_INFO`).
- Single-row enforcement for `feed_info.txt`.
- Required field presence checks for `feed_publisher_name`,
  `feed_publisher_url`, `feed_lang`.

### Schema reference

`FEED_INFO` in `src/gtfs_validator/schemas.py` (lines 546–561):

- `feed_end_date` is typed `_DATE` (parsed to `datetime.date` by the
  two-phase loader) and annotated `_REC` (recommended).
- `csv_row_number` is injected by the loader as an `Int64` column on
  every loaded table.
- No schema changes are needed.

Place this entry after the existing `feed_contact` entry (which also
`requires=["feed_info"]`) to keep `feed_info`-dependent validators
grouped together.

## 6. Test Plan

Test file: `tests/test_validators/test_feed_expiration_date.py`

All tests construct minimal `feed` dicts with Polars DataFrames and
call `validate_feed_expiration_date` directly. Use a fixed
`TEST_NOW = date(2021, 1, 25)` matching the Java test suite to cover
the month-boundary rollover (plus 7 = Feb 1, plus 30 = Feb 24).

### Shared test fixtures

```python

    """Return a minimal feed dict with a single feed_info row."""
    row = {
        "feed_publisher_name": ["Test Publisher"],
        "feed_publisher_url": ["https://example.com"],
        "feed_lang": ["en"],
        "feed_end_date": [feed_end_date],
        "csv_row_number": [1],
    }
    return {"feed_info": pl.DataFrame(row)}
```
