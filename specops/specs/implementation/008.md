# Implementation: DateTripsValidator

## 1. Module Location

**Validator:** `src/gtfs_validator/validators/date_trips.py`

**Shared utilities (new):** `src/gtfs_validator/trip_calendar_utils.py`

The `calendar_utils.py` module already provides `build_service_date_map()`,
which handles step 3a (building the service_id-to-dates mapping). Two new
reusable helpers are needed in a new `trip_calendar_utils.py` module:

- `count_trips_per_service_date()` -- counts effective trips per calendar
  date, accounting for frequency-based expansion.
- `compute_majority_service_coverage()` -- computes the majority service
  window (start/end date interval) from trip-count-per-date data.

These helpers are placed in a separate module (not inside the validator)
because `FeedExpirationDateValidator` (validator #19) will also need them.

```python
from __future__ import annotations

from datetime import date

import polars as pl


def count_trips_per_service_date(
    feed: dict[str, pl.DataFrame],
    service_date_map: dict[str, set[date]],
) -> dict[date, int]:
    """Count effective trips running on each service date.

    For each trip, determines its effective count (1 for non-frequency
    trips, expanded count for frequency-based trips), aggregates by
    service_id, then distributes across each service_id's active dates.

    Returns a mapping from date to total trip count.
    """


def compute_majority_service_coverage(
    date_trip_counts: dict[date, int],
) -> tuple[date, date] | None:
    """Compute the majority service window from per-date trip counts.

    Returns (majority_start, majority_end) or None if no trips exist.
    """
```

## 3. Notice Definitions

All notices have severity **WARNING**.

### `trip_coverage_not_active_for_next_7_days`

Emitted when the majority service window does not fully cover the next
7 days from the validation date. At most one notice per feed.

```python
Notice(
    code="trip_coverage_not_active_for_next_7_days",
    severity=Severity.WARNING,
    fields={
        "current_date": <str>,               # YYYYMMDD format
        "service_window_start_date": <str>,   # YYYYMMDD format
        "service_window_end_date": <str>,     # YYYYMMDD format
    },
)
```

Date fields are formatted as `YYYYMMDD` strings (e.g. `"20221201"`) to
match the Java notice output format, using `date.strftime("%Y%m%d")`.

### Helper: `count_trips_per_service_date`

```
function count_trips_per_service_date(feed, service_date_map):
    # 1. Compute effective trip count per trip_id
    if "trips" not in feed or feed["trips"].is_empty():
        return {}

    trips = feed["trips"].select("trip_id", "service_id")

    # 2. Expand frequency-based trips
    if "frequencies" in feed and not feed["frequencies"].is_empty():
        freqs = feed["frequencies"].select(
            "trip_id", "start_time", "end_time", "headway_secs"
        )

        # For each frequency row, compute expanded trip count:
        #   1 + floor((end_time - start_time - 1) / headway_secs)
        # but only when headway_secs > 0; otherwise count as 1.
        #
        # start_time and end_time are Duration types (GTFS TIME fields).
        # Convert to total seconds for arithmetic.
        freq_counts = freqs.with_columns([
            (pl.col("end_time").dt.total_seconds()
             - pl.col("start_time").dt.total_seconds()).alias("span_secs"),
        ]).with_columns(
            pl.when(pl.col("headway_secs") > 0)
            .then(1 + ((pl.col("span_secs") - 1) // pl.col("headway_secs")))
            .otherwise(1)
            .cast(pl.Int64)
            .alias("freq_trip_count")
        )

        # Sum freq_trip_count per trip_id
        freq_per_trip = freq_counts.group_by("trip_id").agg(
            pl.col("freq_trip_count").sum().alias("effective_count")
        )

        # Left join trips with freq counts; trips not in frequencies get count=1
        trips = trips.join(freq_per_trip, on="trip_id", how="left").with_columns(
            pl.col("effective_count").fill_null(1)
        )
    else:
        trips = trips.with_columns(pl.lit(1).alias("effective_count"))

    # 3. Aggregate trip counts per service_id
    service_counts = trips.group_by("service_id").agg(
        pl.col("effective_count").sum().alias("trip_count")
    )

    # 4. Distribute counts across service dates
    date_counts: dict[date, int] = {}
    for row in service_counts.iter_rows(named=True):
        sid = row["service_id"]
        count = row["trip_count"]
        for d in service_date_map.get(sid, set()):
            date_counts[d] = date_counts.get(d, 0) + count

    return date_counts
```

**Design note:** Steps 1-3 use Polars for joining trips with frequencies
and aggregating. Step 4 distributes counts across dates using plain
Python iteration over the service date map, which is natural since the
map is already a Python dict of sets.

### Helper: `compute_majority_service_coverage`

```
function compute_majority_service_coverage(date_trip_counts):
    if not date_trip_counts:
        return None

    # 1. Sort all trip counts
    sorted_counts = sorted(date_trip_counts.values())
    n = len(sorted_counts)

    # 2. Determine "typical max" index, avoiding outliers
    index = max(int(0.90 * n), n - 30)
    # Clamp to valid range
    index = max(0, min(index, n - 1))
    typical_max = sorted_counts[index]

    if typical_max == 0:
        return None

    # 3. Compute majority threshold
    threshold = int(0.75 * typical_max)

    # 4. Find first and last dates meeting the threshold
    sorted_dates = sorted(date_trip_counts.keys())
    majority_start = None
    majority_end = None

    for d in sorted_dates:
        if date_trip_counts[d] >= threshold:
            if majority_start is None:
                majority_start = d
            majority_end = d

    if majority_start is None or majority_end is None:
        return None

    return (majority_start, majority_end)
```

### Validator: `validate_date_trips`

```
function validate_date_trips(feed, ctx):
    # 1. Build service date map (reuse existing helper)
    from gtfs_validator.calendar_utils import build_service_date_map
    service_date_map = build_service_date_map(feed)

    # 2. Count trips per service date
    date_trip_counts = count_trips_per_service_date(feed, service_date_map)

    # 3. Compute majority service window
    coverage = compute_majority_service_coverage(date_trip_counts)
    if coverage is None:
        return []

    majority_start, majority_end = coverage

    # 4. Check 7-day coverage
    validation_date = ctx.date_for_validation
    required_end = validation_date + timedelta(days=7)

    # No notice if: majority_start <= validation_date AND majority_end >= required_end
    if majority_start <= validation_date and majority_end >= required_end:
        return []

    # 5. Emit notice
    return [
        Notice(
            code="trip_coverage_not_active_for_next_7_days",
            severity=Severity.WARNING,
            fields={
                "current_date": validation_date.strftime("%Y%m%d"),
                "service_window_start_date": majority_start.strftime("%Y%m%d"),
                "service_window_end_date": majority_end.strftime("%Y%m%d"),
            },
        )
    ]
```

**Key design decisions:**

- **Reuse `build_service_date_map` from `calendar_utils.py`.** This
  function already implements the full calendar + calendar_dates merge
  logic needed for step 3a.
- **Polars for trip/frequency aggregation, plain Python for date
  distribution.** The trip-count-per-service-id aggregation is a natural
  Polars pipeline (join + group_by). Distributing counts across dates is
  iterative over a Python dict-of-sets, which is cleaner than trying to
  explode the date sets into a DataFrame.
- **Separate helpers for reuse.** `count_trips_per_service_date` and
  `compute_majority_service_coverage` are standalone functions that
  `FeedExpirationDateValidator` can call directly with different
  day-count thresholds (30 days instead of 7).
- **`compute_majority_service_coverage` is threshold-agnostic.** It
  returns the raw window; the 7-day check is in the validator itself.
  The feed expiration validator can reuse the same window and apply its
  own 30-day check.
- **TIME column handling.** GTFS TIME fields (`start_time`, `end_time`
  in frequencies) are loaded as `pl.Duration` by the loader. The
  arithmetic uses `.dt.total_seconds()` to get integer seconds for the
  headway expansion formula.
- **Integer truncation.** Both `int(0.90 * n)` and `int(0.75 * count)`
  use Python's `int()` which truncates toward zero, matching Java's
  `(int)` cast behavior for positive values.

## 5. Registry Entry

In `src/gtfs_validator/validators/__init__.py`, add the import and
registry entry:

```python
from gtfs_validator.validators.date_trips import validate_date_trips

# Add to VALIDATOR_REGISTRY list:
ValidatorEntry(
    name="date_trips",
    fn=validate_date_trips,
    requires=["trips"],
),
```

The `requires` list specifies `"trips"` as the minimum required table.
The validator gracefully handles missing `calendar`, `calendar_dates`,
and `frequencies` tables internally (via `build_service_date_map` and
the frequency expansion guard).
