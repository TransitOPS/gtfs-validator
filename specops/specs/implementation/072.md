## 3. Notice definitions

### `transfer_distance_too_large`

```python
Notice(
    code="transfer_distance_too_large",
    severity=Severity.WARNING,
    fields={
        "csv_row_number": int,   # from transfers.csv_row_number
        "from_stop_id": str,     # from transfers.from_stop_id
        "to_stop_id": str,       # from transfers.to_stop_id
        "distance_km": float,    # computed: distance_meters / 1_000
    },
)
```

Condition: `distance_meters > 10_000` (strict greater-than; exactly 10,000 m
does NOT trigger this notice).

Severity: WARNING.

At most one notice per transfer row. Mutually exclusive with
`transfer_distance_above_2_km` — when this notice fires, the INFO notice is
not additionally emitted for the same row.

### `transfer_distance_above_2_km`

```python
Notice(
    code="transfer_distance_above_2_km",
    severity=Severity.INFO,
    fields={
        "csv_row_number": int,   # from transfers.csv_row_number
        "from_stop_id": str,     # from transfers.from_stop_id
        "to_stop_id": str,       # from transfers.to_stop_id
        "distance_km": float,    # computed: distance_meters / 1_000
    },
)
```

Condition: `distance_meters > 2_000 AND distance_meters <= 10_000` (strict
lower bound; exactly 2,000 m does NOT trigger this notice).

Severity: INFO.

At most one notice per transfer row. Mutually exclusive with
`transfer_distance_too_large`.

## 4. Implementation approach

**Strategy**: Build a Python dict index over `stops.txt` once, then iterate
`transfers.txt` row-by-row in Python. Per-row parent-chain traversal and
haversine computation are applied inside the loop.

Using plain Python for the inner loop is appropriate because:
- The coordinate resolution requires per-row parent-chain graph traversal (up
  to 3 hops) that cannot be cleanly vectorized in Polars.
- Transfer tables are small in practice.
- The existing `shape_increasing_distance.py` establishes this same precedent
  for geometry computation.

### Constants

```python
EARTH_RADIUS_METERS: float = 6_371_010.0
```

This is the S2Earth mean radius. Do NOT use `6_371_000.0` or `6_371.0 * 1000`.
The test contracts lock in exact `distance_km` values computed with
`6_371_010.0`; any other value will produce incorrect results.

The constant is already defined in
`src/gtfs_validator/validators/shape_increasing_distance.py`. Import or
redefine it locally — do not rely on cross-module internal imports unless a
shared utility module is extracted.

### Helper: `_resolve_stop_latlng`

```python
def _resolve_stop_latlng(
    stop_id: str,
    stops_index: dict[str, tuple[float | None, float | None, str | None]],
) -> tuple[float, float]:
    """
    Resolve a stop_id to (lat, lon) by walking the parent_station chain.

    stops_index maps stop_id -> (stop_lat, stop_lon, parent_station).

    Returns (0.0, 0.0) if no coordinates are found within 3 hops, or if the
    stop_id is not present in the index. This matches the Java S2LatLng.CENTER
    fallback behavior exactly (including the known bug where an unresolvable
    stop produces a spurious distance computation from the origin rather than
    being skipped — do not fix this).
    """
    for _ in range(3):
        entry = stops_index.get(stop_id)
        if entry is None:
            return (0.0, 0.0)
        lat, lon, parent = entry
        if lat is not None and lon is not None:
            return (lat, lon)
        if parent is not None:
            stop_id = parent
        else:
            break
    return (0.0, 0.0)
```

The loop runs at most 3 times, supporting the boarding area → stop → station
chain. A parent cycle is implicitly terminated after 3 iterations.

### Helper: `_haversine_meters`

```python
import math

def _haversine_meters(
    lat1: float, lon1: float, lat2: float, lon2: float
) -> float:
    """Great-circle distance in metres using the haversine formula (S2Earth)."""
    phi1, phi2 = math.radians(lat1), math.radians(lat2)
    dphi = math.radians(lat2 - lat1)
    dlambda = math.radians(lon2 - lon1)
    a = (
        math.sin(dphi / 2) ** 2
        + math.cos(phi1) * math.cos(phi2) * math.sin(dlambda / 2) ** 2
    )
    return 2 * math.atan2(math.sqrt(a), math.sqrt(max(0.0, 1.0 - a))) * EARTH_RADIUS_METERS
```

The `max(0.0, 1.0 - a)` guard prevents a negative argument to `sqrt` from
floating-point rounding when the two points are antipodal.

### Guard clauses (applied before any iteration)

Return `[]` immediately if any of the following are true:

1. `"transfers"` not in `feed`
2. `"stops"` not in `feed`
3. `"from_stop_id"` not in `feed["transfers"].columns`
4. `"to_stop_id"` not in `feed["transfers"].columns`
5. `feed["transfers"].is_empty()`

These map directly to the Java `shouldCallValidate` conditions.

### Stops index construction

Build `stops_index` once from the `stops` DataFrame before the transfer loop:

```python
stops_index: dict[str, tuple[float | None, float | None, str | None]] = {}
for row in stops.select(["stop_id", "stop_lat", "stop_lon", "parent_station"]).iter_rows(named=True):
    stops_index[row["stop_id"]] = (
        row["stop_lat"],
        row["stop_lon"],
        row.get("parent_station"),
    )
```

If `parent_station` is not a column in `stops`, `row.get("parent_station")`
returns `None` safely and the parent-chain traversal is effectively a no-op.

### Pseudocode for main function

```
def validate_transfer_distance(feed, ctx):
    # Guard clauses
    if "transfers" not in feed or "stops" not in feed:
        return []

    transfers = feed["transfers"]
    stops = feed["stops"]

    if "from_stop_id" not in transfers.columns or "to_stop_id" not in transfers.columns:
        return []

    if transfers.is_empty():
        return []

    # Build stop coordinate + parent index once
    stops_index = {}
    for row in stops.select(["stop_id", "stop_lat", "stop_lon", "parent_station"]).iter_rows(named=True):
        stops_index[row["stop_id"]] = (row["stop_lat"], row["stop_lon"], row.get("parent_station"))

    notices = []

    for row in transfers.iter_rows(named=True):
        from_stop_id = row["from_stop_id"]
        to_stop_id = row["to_stop_id"]

        # Skip rows where either stop ID is null
        if from_stop_id is None or to_stop_id is None:
            continue

        from_lat, from_lon = _resolve_stop_latlng(from_stop_id, stops_index)
        to_lat, to_lon = _resolve_stop_latlng(to_stop_id, stops_index)

        distance_m = _haversine_meters(from_lat, from_lon, to_lat, to_lon)

        if distance_m > 10_000:
            notices.append(Notice(
                code="transfer_distance_too_large",
                severity=Severity.WARNING,
                fields={
                    "csv_row_number": row["csv_row_number"],
                    "from_stop_id": from_stop_id,
                    "to_stop_id": to_stop_id,
                    "distance_km": distance_m / 1_000,
                },
            ))
        elif distance_m > 2_000:
            notices.append(Notice(
                code="transfer_distance_above_2_km",
                severity=Severity.INFO,
                fields={
                    "csv_row_number": row["csv_row_number"],
                    "from_stop_id": from_stop_id,
                    "to_stop_id": to_stop_id,
                    "distance_km": distance_m / 1_000,
                },
            ))

    return notices
```

The `if / elif` structure ensures exactly one notice per row at most (or none).
A distance above 10 km emits only the WARNING; the INFO is not additionally
emitted.

### Handling `parent_station` column absence in `stops`

If `stops` does not have a `parent_station` column, the `.select(...)` call
will raise a `ColumnNotFoundError`. Guard defensively:

```python
select_cols = ["stop_id", "stop_lat", "stop_lon"]
if "parent_station" in stops.columns:
    select_cols.append("parent_station")

for row in stops.select(select_cols).iter_rows(named=True):
    stops_index[row["stop_id"]] = (
        row["stop_lat"],
        row["stop_lon"],
        row.get("parent_station"),  # None when column absent
    )
```

## 6. Test plan

Test file: `tests/test_validators/test_transfer_distance.py`

All tests build minimal DataFrames. Integer columns use Python `int` (or
`None`); float columns use Python `float` (or `None`); string columns use
Python `str` (or `None`). Polars infers dtypes from the Python values.
Assertions check exact notice count, `code`, `severity`, and key `fields`
values.

Helper factory (suggested):

```python
def _make_stops(rows: list[dict]) -> pl.DataFrame:
    """Build a stops DataFrame from a list of dicts with stop_id, stop_lat, stop_lon, parent_station."""
    return pl.DataFrame({
        "stop_id": [r["stop_id"] for r in rows],
        "stop_lat": [r.get("stop_lat") for r in rows],
        "stop_lon": [r.get("stop_lon") for r in rows],
        "parent_station": [r.get("parent_station") for r in rows],

def _make_transfers(rows: list[dict]) -> pl.DataFrame:
    """Build a transfers DataFrame from a list of dicts with from_stop_id, to_stop_id, csv_row_number."""
    return pl.DataFrame({
        "from_stop_id": [r.get("from_stop_id") for r in rows],
        "to_stop_id": [r.get("to_stop_id") for r in rows],
        "csv_row_number": [r.get("csv_row_number", 1) for r in rows],
    })
```
