
Standard validator signature per AGENTS.md. `ctx` is accepted but not used.

## 3. Notice definitions

### `missing_required_field` (ERROR)

Reuses the existing `Notice` dataclass with `code="missing_required_field"`. Emitted when `from_trip_id` or `to_trip_id` is absent on a row where `transfer_type` is 4 or 5.

```python
Notice(
    code="missing_required_field",
    severity=Severity.ERROR,
    fields={
        "filename": "transfers.txt",   # literal string
        "csv_row_number": int,         # from transfers row
        "field_name": "from_trip_id",  # or "to_trip_id"
    },
)
```

Conditions:
- `transfer_type` IS NOT NULL, AND
- `transfer_type` IN {4, 5}, AND
- `from_trip_id` IS NULL → one notice with `field_name="from_trip_id"`
- `to_trip_id` IS NULL → one notice with `field_name="to_trip_id"`

Both fields are checked independently. A single row may produce zero, one, or two notices of this type.

---

### `transfer_with_invalid_stop_location_type` (ERROR)

Emitted when `from_stop_id` or `to_stop_id` on an in-seat transfer row references a stop whose `location_type` is STATION (1). This notice is also emitted by `TransfersStopTypeValidator` (073) for non-in-seat types. It must be defined once in a shared location and imported by both validators.

```python
Notice(
    code="transfer_with_invalid_stop_location_type",
    severity=Severity.ERROR,
    fields={
        "csv_row_number": int,          # from transfers row
        "stop_id_field_name": str,      # "from_stop_id" or "to_stop_id"
        "stop_id": str,                 # the referenced stop ID
        "location_type_value": int,     # numeric value (e.g., 1)
        "location_type_name": str,      # name (e.g., "STATION")
    },
)
```

Conditions:
- `transfer_type` IN {4, 5}, AND
- Stop ID is non-null and resolves in `stops.txt`, AND
- `location_type == 1` (STATION).

Note: For in-seat transfers, only `location_type == 0` (STOP) is valid. STATION (1) is specifically forbidden. Values 2, 3, 4 are not flagged by this validator; they are handled by `TransfersStopTypeValidator` for non-in-seat types.

---

### `transfer_with_suspicious_mid_trip_in_seat` (WARNING)

Emitted when the transfer stop is not at the expected terminal position in the trip's stop-times sequence: `from_stop_id` must be the last stop of the from-trip; `to_stop_id` must be the first stop of the to-trip.

```python
Notice(
    code="transfer_with_suspicious_mid_trip_in_seat",
    severity=Severity.WARNING,
    fields={
        "csv_row_number": int,          # from transfers row
        "trip_id_field_name": str,      # "from_trip_id" or "to_trip_id"
        "trip_id": str,                 # the referenced trip ID
        "stop_id_field_name": str,      # "from_stop_id" or "to_stop_id"
        "stop_id": str,                 # the referenced stop ID
    },
)
```

Conditions:
- `transfer_type` IN {4, 5}, AND
- Stop ID resolves in `stops.txt`, AND
- Stop ID appears somewhere in the trip's stop-times (otherwise deferred to `TransfersTripReferenceValidator`), AND
- For FROM direction: `from_stop_id` is NOT the last stop-time in the trip (ordered by `stop_sequence`).
- For TO direction: `to_stop_id` is NOT the first stop-time in the trip (ordered by `stop_sequence`).

Both directions are checked independently; a single row may produce zero, one, or two notices of this type.

## 4. Implementation approach

**Strategy**: Pre-build Python dicts from `stops` and `stop_times` DataFrames (built once, O(n)), then iterate the filtered in-seat transfer rows in Python (row-by-row). The outer loop over transfer rows is inherently multi-table and position-sensitive, making plain Python clearer than forcing a vectorized join approach. Per AGENTS.md: "Use plain Python algorithms for graph/geometry/interval logic when clearer and safer than forcing Polars."

### Guard clauses

Return `[]` immediately if any of the following hold:

1. `"transfers"` not in `feed`
2. `feed["transfers"].is_empty()`
3. `"transfer_type"` not in `feed["transfers"].columns`

The stop and stop_times tables are optional inputs; their absence is handled by building empty dicts, which causes the relevant checks to be silently skipped (deferred to FK validators).

### Pre-build lookup structures

```python
# stops lookup: stop_id -> location_type (int or None)
stops_df = feed.get("stops")
stops_by_id: dict[str, int | None] = {}
if stops_df is not None and "stop_id" in stops_df.columns and "location_type" in stops_df.columns:
    for row in stops_df.select(["stop_id", "location_type"]).iter_rows(named=True):
        stops_by_id[row["stop_id"]] = row["location_type"]

# stop_times lookup: trip_id -> list[str] of stop_ids ordered by stop_sequence
trip_stops: dict[str, list[str]] = {}
stop_times_df = feed.get("stop_times")
if stop_times_df is not None:
    required_st_cols = {"trip_id", "stop_id", "stop_sequence"}
    if required_st_cols.issubset(stop_times_df.columns):
        sorted_st = stop_times_df.sort("stop_sequence").select(["trip_id", "stop_id"])
        for row in sorted_st.iter_rows(named=True):
            trip_stops.setdefault(row["trip_id"], []).append(row["stop_id"])
```

`stop_sequence` values in the loaded DataFrame are typed integers (or null). Null `stop_sequence` rows are included by `.sort()` and will sort first; this matches the Java behavior where null sequences are treated as present but unordered. Since FK validators handle missing/malformed sequences, this validator does not need to filter them out.

### Filtering in-seat rows

```python
in_seat = transfers.filter(
    pl.col("transfer_type").is_not_null()
    & pl.col("transfer_type").is_in([4, 5])
)
```

After the load-time casting, `transfer_type` is a nullable integer column. String comparison is wrong; compare against integer literals.

### Direction iteration

For each in-seat transfer row, process FROM direction then TO direction. The FROM/TO pairs are:

| Direction | trip_id field    | stop_id field    | Expected position |
|-----------|------------------|------------------|-------------------|
| FROM      | `from_trip_id`   | `from_stop_id`   | last stop         |
| TO        | `to_trip_id`     | `to_stop_id`     | first stop        |

### Check ordering within each direction

For each direction, per row:

1. **Check 1 — trip ID presence**: if `trip_id` IS NULL, emit `missing_required_field`. Continue to stop checks regardless.
2. **Check 2 — stop location type**: look up `stop_id` in `stops_by_id`. If not found, skip to next direction. If `location_type == 1`, emit `transfer_with_invalid_stop_location_type`.
3. **Check 3 — stop in trip's stop-times**: look up `trip_id` in `trip_stops`. If trip has no stop-times OR `stop_id` not in the trip's stop list, skip position check (deferred to `TransfersTripReferenceValidator`).
4. **Check 4 — stop at terminal position**: compare stop at expected index (last for FROM, first for TO) against `stop_id`. If they differ, emit `transfer_with_suspicious_mid_trip_in_seat`.

### Pseudocode

```python
DIRECTIONS = [
    ("from_trip_id", "from_stop_id", "last"),
    ("to_trip_id",   "to_stop_id",   "first"),
]

notices: list[Notice] = []

for row in in_seat.iter_rows(named=True):
    csv_row_number = row["csv_row_number"]

    for trip_field, stop_field, position in DIRECTIONS:
        trip_id = row.get(trip_field)
        stop_id = row.get(stop_field)

        # Check 1: trip_id required for in-seat transfers
        if trip_id is None:
            notices.append(Notice(
                code="missing_required_field",
                severity=Severity.ERROR,
                fields={
                    "filename": "transfers.txt",
                    "csv_row_number": csv_row_number,
                    "field_name": trip_field,
                },
            ))

        # Stop checks: only if stop_id is non-null and resolves in stops
        if stop_id is None or stop_id not in stops_by_id:
            continue  # FK validation deferred

        location_type = stops_by_id[stop_id]

        # Check 2: station is forbidden for in-seat transfers
        if location_type == 1:
            notices.append(Notice(
                code="transfer_with_invalid_stop_location_type",
                severity=Severity.ERROR,
                fields={
                    "csv_row_number": csv_row_number,
                    "stop_id_field_name": stop_field,
                    "stop_id": stop_id,
                    "location_type_value": 1,
                    "location_type_name": "STATION",
                },
            ))

        # Check 3: verify stop appears in trip's stop-times
        if trip_id is None or trip_id not in trip_stops:
            continue  # cross-reference deferred

        stops_in_trip = trip_stops[trip_id]
        if stop_id not in stops_in_trip:
            continue  # FK absence deferred

        # Check 4: positional check
        expected_stop = stops_in_trip[-1] if position == "last" else stops_in_trip[0]
        if expected_stop != stop_id:
            notices.append(Notice(
                code="transfer_with_suspicious_mid_trip_in_seat",
                severity=Severity.WARNING,
                fields={
                    "csv_row_number": csv_row_number,
                    "trip_id_field_name": trip_field,
                    "trip_id": trip_id,
                    "stop_id_field_name": stop_field,
                    "stop_id": stop_id,
                },
            ))

return notices
```

### Column presence for iteration

Before iterating `in_seat`, verify that `from_trip_id`, `to_trip_id`, `from_stop_id`, `to_stop_id`, and `csv_row_number` are present in the transfers columns. If any is absent, return `[]`. Use `.get()` on the row dict or check columns once up front.

Recommended: check up front with a set intersection guard:

```python
required_cols = {"transfer_type", "from_trip_id", "to_trip_id",
                 "from_stop_id", "to_stop_id", "csv_row_number"}
if not required_cols.issubset(set(transfers.columns)):
    return []
```

### Notice ordering guarantee

Per the analysis spec, the FROM direction is processed before TO for each row, and within each direction `missing_required_field` is emitted before the stop-type and position notices. The pseudocode above satisfies this ordering because Check 1 runs first (trip ID), then Checks 2–4 (stop-related). FROM direction completes fully before TO direction begins.

### Helper factories (suggested)

```python
from datetime import date
import polars as pl
from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Severity

def _ctx() -> ValidationContext:
    return ValidationContext(country_code="US", date_for_validation=date(2024, 1, 1))

def _make_transfers(rows: list[dict]) -> pl.DataFrame:
    return pl.DataFrame({
        "transfer_type":  [r.get("transfer_type") for r in rows],
        "from_stop_id":   [r.get("from_stop_id") for r in rows],
        "to_stop_id":     [r.get("to_stop_id") for r in rows],
        "from_trip_id":   [r.get("from_trip_id") for r in rows],
        "to_trip_id":     [r.get("to_trip_id") for r in rows],
        "csv_row_number": [r.get("csv_row_number", 2) for r in rows],
    })

def _make_stops(rows: list[dict]) -> pl.DataFrame:
    return pl.DataFrame({
        "stop_id":       [r["stop_id"] for r in rows],
        "location_type": [r.get("location_type", 0) for r in rows],
    })

def _make_stop_times(rows: list[dict]) -> pl.DataFrame:
    return pl.DataFrame({
        "trip_id":       [r["trip_id"] for r in rows],
        "stop_id":       [r["stop_id"] for r in rows],
        "stop_sequence": [r["stop_sequence"] for r in rows],
    })
```
