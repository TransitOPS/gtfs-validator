# Implementation: InconsistentRouteTypeForBlockIdValidator

## 1. Module Location

**Validator:** `src/gtfs_validator/validators/inconsistent_route_type_for_block_id.py`

This is a cross-table validator that joins `trips.txt` with `routes.txt` to detect blocks containing trips with mixed route types. The check is fully vectorizable with Polars group-by aggregation.

## 2. Function Signature

```python
from __future__ import annotations

import polars as pl

from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Notice, Severity


def validate_inconsistent_route_type_for_block_id(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

No internal helpers are needed; the logic is a single join-group-filter pipeline.

## 3. Notice Definitions

### `inconsistent_route_type_for_block_id`

Severity: **WARNING**

Emitted when trips sharing the same `block_id` are associated with routes that have more than one distinct `route_type` value.

```python
Notice(
    code="inconsistent_route_type_for_block_id",
    severity=Severity.WARNING,
    fields={
        "block_id": <str>,       # the block_id with inconsistent route types
        "route_ids": <str>,      # comma-separated distinct route_id values (sorted)
        "route_types": <str>,    # comma-separated distinct route_type values (sorted)
    },
)
```

## 4. Implementation Approach

### Strategy: Polars join + group-by aggregation

This validator is well-suited to a fully vectorized Polars implementation. The inner join on `route_id` naturally excludes trips whose route is not found (FK violations are handled elsewhere). The group-by on `block_id` with `n_unique` aggregation identifies inconsistent blocks in a single pass.

### Algorithm

```
1.  trips = feed.get("trips")
2.  routes = feed.get("routes")
3.  if trips is None or routes is None:
4.      return []
5.  if trips.is_empty() or routes.is_empty():
6.      return []
7.  if "block_id" not in trips.columns:
8.      return []
9.
10. # Join trips with routes to attach route_type
11. joined = trips.select("block_id", "route_id").join(
12.     routes.select("route_id", "route_type"),
13.     on="route_id",
14.     how="inner",  # drops trips with unmatched route_id
15. )
16.
17. # Filter out rows where block_id is null or empty
18. filtered = joined.filter(
19.     pl.col("block_id").is_not_null()
20.     & (pl.col("block_id") != "")
21. )
22.
23. if filtered.is_empty():
24.     return []
25.
26. # Group by block_id and aggregate distinct route info
27. agg = filtered.group_by("block_id").agg(
28.     pl.col("route_type").n_unique().alias("n_types"),
29.     pl.col("route_id").unique().alias("route_ids"),
30.     pl.col("route_type").unique().alias("route_types"),
31. )
32.
33. # Keep only blocks with more than one distinct route_type
34. bad = agg.filter(pl.col("n_types") > 1)
35.
36. # Emit one notice per inconsistent block
37. notices = []
38. for row in bad.iter_rows(named=True):
39.     notices.append(Notice(
40.         code="inconsistent_route_type_for_block_id",
41.         severity=Severity.WARNING,
42.         fields={
43.             "block_id": row["block_id"],
44.             "route_ids": ", ".join(str(r) for r in sorted(row["route_ids"])),
45.             "route_types": ", ".join(str(t) for t in sorted(row["route_types"])),
46.         },
47.     ))
48. return notices
```

### Handling missing tables and columns

- If `trips` or `routes` is absent from the feed dict, the runner skips this validator entirely via the `requires` list (never called).
- If `trips` is present but has no `block_id` column, return early with no notices.
- If `trips` or `routes` is empty, return early with no notices.
- Trips whose `route_id` does not match any route are excluded by the inner join (FK violations are handled by the load-time FK infrastructure).
- Rows with null or empty-string `block_id` are filtered out before grouping.

### Key design decisions

- The `iter_rows` loop over bad blocks is acceptable because the number of inconsistent blocks is expected to be very small relative to total data size.
- Comma-separated values in notice fields are sorted for deterministic output and test stability.
- `route_type` values are rendered as their string representation (the raw integer/enum value from the CSV).

## 5. Registry Entry

In `src/gtfs_validator/validators/__init__.py`, add the import:

```python
from gtfs_validator.validators.inconsistent_route_type_for_block_id import (
    validate_inconsistent_route_type_for_block_id,
)
```

Append the entry to `VALIDATOR_REGISTRY`:

```python
ValidatorEntry(
    name="inconsistent_route_type_for_block_id",
    fn=validate_inconsistent_route_type_for_block_id,
    requires=["trips", "routes"],
),
```

Both `trips` and `routes` are listed in `requires` because the validator needs both tables to perform the join. If either is absent, the runner will skip it.

```python
def make_routes(rows: list[tuple[str, str]]) -> pl.DataFrame:
    """Each row is (route_id, route_type)."""
    return pl.DataFrame(
        {"route_id": [r[0] for r in rows], "route_type": [r[1] for r in rows]}
    )


def make_trips(rows: list[tuple[str, str, str | None]]) -> pl.DataFrame:
    """Each row is (trip_id, route_id, block_id)."""
    return pl.DataFrame(
        {
            "trip_id": [r[0] for r in rows],
            "route_id": [r[1] for r in rows],
            "block_id": [r[2] for r in rows],
        }
    )
```

**Test 1: `test_same_route_type_for_block_id_no_notice`**

- routes: `("r0", "3")`, `("r1", "3")` (both BUS)
- trips: `("t0", "r0", "b0")`, `("t1", "r1", "b0")`
- Expected: 0 notices

**Test 2: `test_different_route_type_for_block_id_generates_notice`**
