## 3. Notice definitions

### `fast_travel_between_consecutive_stops`

```python
Notice(
    code="fast_travel_between_consecutive_stops",

        "stop_sequence1": int,        # stop_times.stop_sequence for start stop
        "stop_id1": str,              # stop_times.stop_id for start stop
        "stop_name1": str,            # stops.stop_name for start stop

        "csv_row_number2": int,       # stop_times.csv_row_number for end stop
        "stop_sequence2": int,        # stop_times.stop_sequence for end stop
        "stop_id2": str,              # stop_times.stop_id for end stop

        "arrival_time2": str,         # "HH:MM:SS" arrival time at end stop

```

Emitted when implied speed between two adjacent stop times exceeds the max speed for the
route type. Both stops must have resolvable coordinates. The start stop must have
`departure_time` and the end stop must have `arrival_time`.

### `fast_travel_between_far_stops`

```python
Notice(
    code="fast_travel_between_far_stops",
    severity=Severity.WARNING,
    fields={
        "trip_csv_row_number": int,   # trips.csv_row_number
        "trip_id": str,
        "route_id": str,
        "speed_kph": float,
        "distance_km": float,         # accumulated sum of consecutive distances
        "csv_row_number1": int,
        "stop_sequence1": int,
        "stop_id1": str,
        "stop_name1": str,
        "departure_time1": str,
        "csv_row_number2": int,
        "stop_sequence2": int,
        "stop_id2": str,
        "stop_name2": str,
        "arrival_time2": str,
    },
)
```

Emitted when implied speed between any two stops (using accumulated consecutive distances)
exceeds the max speed AND the accumulated distance is greater than 10.0 km. At most one
such notice is emitted per trip. Both stops must exist in `stops.txt`. The start stop must
have `departure_time` and the end stop must have `arrival_time`.

Fields are structurally identical to `fast_travel_between_consecutive_stops`. The
`distance_km` field holds the sum of straight-line consecutive segment distances, not a
direct geodesic from start to end.

## 4. Implementation approach

**Strategy**: Polars for joining and grouping; plain Python for per-trip geometry traversal.

### 4.2 `get_max_speed_kph(route_type: int) -> float`

```
return MAX_SPEED_KPH.get(route_type, DEFAULT_MAX_SPEED_KPH)
```

### 4.3 `haversine_km(lat1, lon1, lat2, lon2) -> float`

Pure Python haversine using `math`. Returns great-circle distance in km.

```
R = 6371.0  # Earth radius in km
dlat = radians(lat2 - lat1)
dlon = radians(lon2 - lon1)
a = sin(dlat/2)**2 + cos(radians(lat1)) * cos(radians(lat2)) * sin(dlon/2)**2
return R * 2 * asin(sqrt(a))
```

### 4.4 `resolve_stop_latlng(stop_id, stops_index) -> tuple[float, float] | None`

```
stops_index: dict[str, dict]  — pre-built from stops DataFrame, keyed by stop_id

for hop in range(MAX_PARENT_HOPS):
    row = stops_index.get(stop_id)
    if row is None:
        return None
    lat = row["stop_lat"]
    lon = row["stop_lon"]
    if lat is not None and lon is not None:
        return (lat, lon)
    parent = row.get("parent_station")
    if not parent:
        return None
    stop_id = parent
return None
```

### 4.5 `get_time_between_stops_secs(departure_secs, arrival_secs) -> int`

```
raw = arrival_secs - departure_secs
if raw <= 0:
    return 60
if arrival_secs % 60 == 0 and departure_secs % 60 == 0:
    return raw + 60
return raw
```

### 4.6 `get_speed_kph(distance_km, departure_secs, arrival_secs) -> float`

```
return distance_km * 3600 / get_time_between_stops_secs(departure_secs, arrival_secs)
```

Converts integer seconds-since-midnight to `"HH:MM:SS"` string for notice fields.

### 4.8 Main validator pseudocode

```
def validate_stop_time_travel_speed(feed, ctx):
    # Guard clauses
    for table in ["stop_times", "trips", "routes", "stops"]:
        if table not in feed or feed[table].is_empty():
            return []

    stop_times = feed["stop_times"]
    trips = feed["trips"]
    routes = feed["routes"]
    stops = feed["stops"]

    # Build stops lookup dict keyed on stop_id
    stops_index = {
        row["stop_id"]: row
        for row in stops.select(
            ["stop_id", "stop_lat", "stop_lon", "stop_name", "parent_station"]
        ).iter_rows(named=True)
    }

    # Join stop_times -> trips -> routes to get route_type and trip metadata
    # trips: keep trip_id, route_id, csv_row_number (alias trip_csv_row_number)
    trips_slim = trips.select([
        pl.col("trip_id"),
        pl.col("route_id"),
        pl.col("csv_row_number").alias("trip_csv_row_number"),
    ])
    routes_slim = routes.select([
        pl.col("route_id"),
        pl.col("route_type"),
    ])
    joined = (
        stop_times
        .join(trips_slim, on="trip_id", how="left")
        .join(routes_slim, on="route_id", how="left")
        .filter(pl.col("route_type").is_not_null())
        .sort(["trip_id", "stop_sequence"])
    )

    if joined.is_empty():
        return []

    notices: list[Notice] = []

    # Per-trip iteration
    for trip_df in joined.partition_by("trip_id", maintain_order=True):
        rows = trip_df.iter_rows(named=True)  # list for indexing
        rows = list(rows)
        if len(rows) < 2:
            continue

        route_type = rows[0]["route_type"]
        max_speed = get_max_speed_kph(route_type)
        trip_id = rows[0]["trip_id"]
        route_id = rows[0]["route_id"]
        trip_csv_row_number = rows[0]["trip_csv_row_number"]

        # Pre-compute consecutive distances for far-stop check
        distances_km = []  # distances_km[i] = distance between rows[i] and rows[i+1]
        for i in range(len(rows) - 1):
            start_latlng = resolve_stop_latlng(rows[i]["stop_id"], stops_index)
            end_latlng = resolve_stop_latlng(rows[i+1]["stop_id"], stops_index)
            if start_latlng is None or end_latlng is None:
                distances_km.append(0.0)
            else:
                distances_km.append(haversine_km(*start_latlng, *end_latlng))

        # Run consecutive-stop check
        notices.extend(
            _check_consecutive_stops(rows, distances_km, max_speed,
                                     trip_id, route_id, trip_csv_row_number,
                                     stops_index)
        )

        # Run far-stop check
        notices.extend(
            _check_far_stops(rows, distances_km, max_speed,
                             trip_id, route_id, trip_csv_row_number,
                             stops_index)
        )

    return notices
```

### 4.9 `_check_consecutive_stops` pseudocode

```
def _check_consecutive_stops(rows, distances_km, max_speed,
                              trip_id, route_id, trip_csv_row_number,
                              stops_index):
    notices = []
    start = rows[0]
    for i in range(1, len(rows)):
        end = rows[i]

        # Resolve coordinates; compute distance
        start_latlng = resolve_stop_latlng(start["stop_id"], stops_index)
        end_latlng = resolve_stop_latlng(end["stop_id"], stops_index)

        if start_latlng is None or end_latlng is None:
            # Do NOT advance start; continue with same start
            continue

        # Advance start (both coords resolved)
        distance_km = haversine_km(*start_latlng, *end_latlng)

        # Guard: both times must be present
        if start["departure_time"] is None or end["arrival_time"] is None:
            start = end
            continue

        speed = get_speed_kph(distance_km, start["departure_time"],
                              end["arrival_time"])

        if speed > max_speed:
            notices.append(Notice(
                code="fast_travel_between_consecutive_stops",
                severity=Severity.WARNING,
                fields=_build_notice_fields(
                    trip_csv_row_number, trip_id, route_id,
                    speed, distance_km, start, end, stops_index,
                ),
            ))

        start = end

    return notices
```

Key rule: `start` advances to `end` only when both stops have resolvable coordinates. When
`resolve_stop_latlng` returns `None` for either stop, `continue` executes without assigning
`start = end`, so the next iteration still uses the original `start`. This matches the Java
behavior where `getDistanceKm` returning `Optional.empty` triggers `continue` before
`start = end`.

### 4.10 `_check_far_stops` pseudocode

```
def _check_far_stops(rows, distances_km, max_speed,
                     trip_id, route_id, trip_csv_row_number,
                     stops_index):
    n = len(rows)
    for end_idx in range(n):
        end = rows[end_idx]

        # Outer guard: end must have arrival_time
        if end["arrival_time"] is None:
            continue

        # Outer guard: end stop must exist in stops table
        if stops_index.get(end["stop_id"]) is None:
            return []  # abort entire far-stop check for this trip

        distance_to_end = 0.0

        for start_idx in range(end_idx - 1, -1, -1):
            # Accumulate distance for this segment
            distance_to_end += distances_km[start_idx]

            start = rows[start_idx]

            # start must have departure_time
            if start["departure_time"] is None:
                continue

            speed = get_speed_kph(distance_to_end, start["departure_time"],
                                  end["arrival_time"])

            if speed <= max_speed:
                continue

            # Speed violation found; check distance threshold
            if distance_to_end <= FAR_STOP_DISTANCE_THRESHOLD_KM:
                continue  # near pair, handled by consecutive check

            # start stop must exist in stops table
            if stops_index.get(start["stop_id"]) is None:
                return []  # abort entire far-stop check for this trip

            # Emit one notice and return immediately
            return [Notice(
                code="fast_travel_between_far_stops",
                severity=Severity.WARNING,
                fields=_build_notice_fields(
                    trip_csv_row_number, trip_id, route_id,
                    speed, distance_to_end, start, end, stops_index,
                ),
            )]

    return []
```

### 4.11 `_build_notice_fields` helper

Constructs the shared fields dict. Looks up `stop_name` from `stops_index` for each stop;
falls back to `""` if the stop has no `stop_name`. Converts integer seconds to `"HH:MM:SS"`
strings via `secs_to_hhmmss`.

```python
def _build_notice_fields(
    trip_csv_row_number: int,
    trip_id: str,
    route_id: str,
    speed_kph: float,
    distance_km: float,
    start: dict,
    end: dict,
    stops_index: dict,
) -> dict:
    start_stop = stops_index.get(start["stop_id"]) or {}
    end_stop = stops_index.get(end["stop_id"]) or {}
    return {
        "trip_csv_row_number": trip_csv_row_number,
        "trip_id": trip_id,
        "route_id": route_id,
        "speed_kph": round(speed_kph, 2),
        "distance_km": round(distance_km, 4),
        "csv_row_number1": start["csv_row_number"],
        "stop_sequence1": start["stop_sequence"],
        "stop_id1": start["stop_id"],
        "stop_name1": start_stop.get("stop_name") or "",
        "departure_time1": secs_to_hhmmss(start["departure_time"]),
        "csv_row_number2": end["csv_row_number"],
        "stop_sequence2": end["stop_sequence"],
        "stop_id2": end["stop_id"],
        "stop_name2": end_stop.get("stop_name") or "",
        "arrival_time2": secs_to_hhmmss(end["arrival_time"]),
    }
```

### 4.12 Deduplication note

The Java fingerprint deduplication (grouping trips by identical route/stops/times) is
omitted for simplicity. Each trip is validated independently, which is correct by the
notice contract (one notice per trip). If feed size makes this a performance concern,
implement fingerprint grouping as a dict keyed on
`(route_id, tuple(stop_ids), tuple(arrival_secs), tuple(departure_secs))`.
