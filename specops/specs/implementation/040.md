# Implementation: PathwayDanglingGenericNodeValidator

## 1. Module location

`src/gtfs_validator/validators/pathway_dangling_generic_node.py`

The existing pathway validator lives in `src/gtfs_validator/validators/pathways.py`. This validator is sufficiently distinct — it involves a two-table graph check rather than a single-table predicate — and warrants its own module to keep concerns separated and file sizes manageable.

## 2. Function signature

```python
def validate_pathway_dangling_generic_node(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

`ctx` is accepted for signature consistency but is not used by this validator.

## 3. Notice definitions

### `pathway_dangling_generic_node` — WARNING

Emitted when a stop with `location_type == 3` (GENERIC_NODE) has exactly one distinct neighbor in the pathway graph (treating all edges as undirected).

```python
Notice(
    code="pathway_dangling_generic_node",
    severity=Severity.WARNING,
    fields={
        "csvRowNumber": <int>,          # csvRowNumber of the dangling GENERIC_NODE row in stops.txt
        "stopId": <str>,                # stop_id of the dangling GENERIC_NODE
        "stopName": <str | None>,       # stop_name of the dangling GENERIC_NODE; null passed through
        "parentStation": <str | None>,  # parent_station of the dangling GENERIC_NODE; null passed through
    },
)
```

| Field | Type | Source | Description |
|---|---|---|---|
| `csvRowNumber` | `int` | `stops.txt` row | Row number of the dangling generic node |
| `stopId` | `str` | `stops.stop_id` | ID of the dangling generic node |
| `stopName` | `str \| None` | `stops.stop_name` | Name of the dangling generic node; null passed through as-is |
| `parentStation` | `str \| None` | `stops.parent_station` | Parent station ID of the dangling node; null passed through as-is |

Severity: `Severity.WARNING`.

## 4. Implementation approach

**Plain Python with a prebuilt adjacency-set dict.** The per-node neighbor-set computation is a graph problem that maps poorly to vectorized Polars expressions. AGENTS.md explicitly permits this pattern: "Use plain Python algorithms for graph/geometry/interval logic when clearer and safer than forcing Polars."

The DataFrames are still loaded via Polars; only the neighbor-accumulation loop is plain Python.

### Module-level constant

```python
_GENERIC_NODE: int = 3
```

### Algorithm (pseudocode)

```
def validate_pathway_dangling_generic_node(feed, ctx):
    stops = feed.get("stops")
    if stops is None or stops.is_empty():
        return []

    # Filter to GENERIC_NODE rows only
    generic_nodes = stops.filter(pl.col("location_type") == _GENERIC_NODE)
    if generic_nodes.is_empty():
        return []

    # Initialise neighbor sets for every GENERIC_NODE stop_id
    # Keys are exactly the generic-node stop IDs; values start as empty sets.
    neighbors: dict[str, set[str]] = {
        row["stop_id"]: set()
        for row in generic_nodes.iter_rows(named=True)
    }

    # Walk every pathway row and accumulate undirected neighbors
    pathways = feed.get("pathways")
    if pathways is not None and not pathways.is_empty():
        for row in pathways.select(["from_stop_id", "to_stop_id"]).iter_rows(named=True):
            from_id = row["from_stop_id"]
            to_id   = row["to_stop_id"]
            if from_id in neighbors:
                neighbors[from_id].add(to_id)
            if to_id in neighbors:
                neighbors[to_id].add(from_id)

    # Emit a notice for each GENERIC_NODE that has exactly one distinct neighbor
    notices: list[Notice] = []
    for row in generic_nodes.iter_rows(named=True):
        if len(neighbors[row["stop_id"]]) == 1:
            notices.append(Notice(
                code="pathway_dangling_generic_node",
                severity=Severity.WARNING,
                fields={
                    "csvRowNumber":  row["csvRowNumber"],
                    "stopId":        row["stop_id"],
                    "stopName":      row.get("stop_name"),
                    "parentStation": row.get("parent_station"),
                },
            ))

    return notices
```

### Key implementation notes

- **`csvRowNumber` column name**: the loader injects a camelCase `csvRowNumber` column (1-based integer). Access it as `row["csvRowNumber"]`.
- **Output ordering**: `generic_nodes` is a filtered slice of `stops`, which preserves the original row order from `stops.txt`. Iterating over `generic_nodes` in order produces notices sorted by `csvRowNumber` without an explicit `.sort()` call, matching Java iteration order.
- **`stop_name` and `parent_station` nullability**: both fields are optional in the GTFS spec. Use `row.get("stop_name")` and `row.get("parent_station")` so that null values are passed through as Python `None` rather than raising a `KeyError`.
- **Isolated nodes (zero neighbors)**: neighbor set size == 0; no notice emitted. Only exactly-one-neighbor triggers the notice.
- **Missing `pathways` table**: when `pathways` is absent or empty, all neighbor sets remain empty (size == 0), so no notices are emitted. No special branch is required beyond the `if pathways is not None and not pathways.is_empty()` guard.
- **Dangling FK references in pathways**: if a pathway's `from_stop_id` or `to_stop_id` references a stop not in `stops.txt`, that pathway still contributes the opposite endpoint to any GENERIC_NODE's neighbor set. FK violations are handled by separate load-time validators.
- **Deduplication**: the neighbor collection is a Python `set`, so multiple pathway edges to the same neighbor count as one distinct neighbor. This correctly handles the case where `(G → A)` and `(A → G)` both exist — the neighbor set for G is still `{A}`, size 1.
- **Non-GENERIC_NODE stops**: the initial filter to `location_type == 3` ensures all other stop types (STOP, STATION, ENTRANCE, BOARDING_AREA) are never keys in `neighbors` and are never iterated in the notice-emission loop.

## 5. Registry entry

Add the following import to `src/gtfs_validator/validators/__init__.py`, grouped with the other `p*` imports:

```python
from gtfs_validator.validators.pathway_dangling_generic_node import (
    validate_pathway_dangling_generic_node,
)
```

Add the following entry to `VALIDATOR_REGISTRY`. Alphabetically this falls after `"parent_station"` and before `"trip_service_id_foreign_key"`. The existing `"bidirectional_exit_gate"` entry uses `requires=["pathways"]`; this new entry requires both `"stops"` and `"pathways"`:

```python
ValidatorEntry(
    name="pathway_dangling_generic_node",
    fn=validate_pathway_dangling_generic_node,
    requires=["stops", "pathways"],
),
```

`requires=["stops", "pathways"]` causes the runner's `should_skip` logic to bypass this validator automatically when either `stops.txt` or `pathways.txt` is absent from the feed. Per the analysis spec, an absent `pathways` table means all generic nodes are isolated (neighbor set size == 0) and would produce no notices anyway, so skipping is safe and consistent.

```python
from datetime import date

import polars as pl

from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Severity
from gtfs_validator.validators.pathway_dangling_generic_node import (
    validate_pathway_dangling_generic_node,

CTX = ValidationContext(country_code="US", date_for_validation=date(2026, 3, 8))

STOPS_SCHEMA = {
    "csvRowNumber": pl.Int64,
    "stop_id":       pl.Utf8,
    "stop_name":     pl.Utf8,
    "location_type": pl.Int64,
    "parent_station": pl.Utf8,
}

    "from_stop_id": pl.Utf8,
    "to_stop_id":   pl.Utf8,

# Shared stop rows used by most tests

# Row 11: STOP,         stop_id="stop11", parent="stop10"
# Row 12: GENERIC_NODE, stop_id="stop12", parent="stop10"

BASE_STOPS = pl.DataFrame(
    {
        "csvRowNumber":   [10, 11, 12, 13],

        "location_type":  [1, 0, 3, 2],
        "parent_station": [None, "stop10", "stop10", "stop10"],
    },
    schema=STOPS_SCHEMA,
)


def make_pathways(*edges: tuple[str, str]) -> pl.DataFrame:
    """Build a pathways DataFrame from (from_stop_id, to_stop_id) tuples."""
    return pl.DataFrame(
        {
            "from_stop_id": [e[0] for e in edges],
            "to_stop_id":   [e[1] for e in edges],
        },
        schema=PATHWAYS_SCHEMA,
    )
```

#### `test_multiple_generic_nodes_mixed`

Verifies that exactly the dangling subset is reported when multiple GENERIC_NODE rows are present.

- Feed:
  - `stops`: rows:
    - row 1: STATION `"sta"`, location_type=1
    - row 2: GENERIC_NODE `"gn_dangling"`, location_type=3, csvRowNumber=2
    - row 3: GENERIC_NODE `"gn_passthrough"`, location_type=3, csvRowNumber=3

  - `pathways`:
    - `("sta", "gn_dangling")` — gn_dangling has 1 neighbor

- Expected: exactly 1 notice, `fields["stopId"] == "gn_dangling"`.

#### `test_output_order_matches_stops_row_order`

Verifies that notices are emitted in `stops.txt` row order (ascending `csvRowNumber`).

- Feed:
  - `stops`: three GENERIC_NODE rows at csvRowNumbers 30, 20, 10 (intentionally out of order in the DataFrame to confirm the loader-provided order is preserved)
  - `pathways`: one edge giving each GENERIC_NODE exactly one neighbor
- Expected: 3 notices, with `csvRowNumber` values in the order they appear in the DataFrame — 30, 20, 10 — not sorted. This confirms the implementation does not re-sort and instead respects the order already present in the DataFrame.

> Note: If the loader always loads rows in CSV file order (`csvRowNumber` ascending), this test effectively verifies ascending order. The key property being tested is that the implementation does not introduce independent sorting — it relies on the DataFrame's existing order, which matches the Java behavior of iterating the stop table in load order.

#### `test_dangling_via_reverse_edge_only`

Verifies that `to_stop_id` direction also contributes to a GENERIC_NODE's neighbor set.

- Feed:
  - `stops`: GENERIC_NODE `"gn"` at row 5, one other stop `"other"` at row 6
  - `pathways`: edge `("other", "gn")` only (gn appears as `to_stop_id`, not `from_stop_id`)
- Expected: 1 notice. `gn` has neighbor set `{"other"}`, size == 1.

#### `test_pathway_referencing_non_generic_node_stop`

Verifies that pathway edges where the endpoint is not a GENERIC_NODE are handled without error, and do not cause false positives for unrelated stops.

- Feed:
  - `stops`: STOP `"stop_a"` and STOP `"stop_b"` only (no GENERIC_NODE)
  - `pathways`: edge `("stop_a", "stop_b")`
- Expected: 0 notices. No GENERIC_NODE rows; validator exits early after `generic_nodes.is_empty()`.

#### `test_pathway_with_unknown_stop_id_still_counts_as_neighbor`

Verifies that an FK-dangling pathway endpoint still contributes to the GENERIC_NODE's neighbor set (FK validation is out-of-scope for this validator).

- Feed:
  - `stops`: GENERIC_NODE `"gn"` at row 1 (the only stop)
  - `pathways`: edge `("gn", "nonexistent_stop")` where `"nonexistent_stop"` has no row in `stops`
- Expected: 1 notice. Neighbor set for `"gn"` = `{"nonexistent_stop"}`, size == 1. The dangling FK reference still increments the neighbor count.
