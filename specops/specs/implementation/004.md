## 1. Module Location

`src/gtfs_validator/validators/bikes_allowance.py`

## 3. Notice Definitions

### `missing_bike_allowance` (WARNING)

Emitted when a trip on a ferry route (`route_type == 4`) has a
`bikes_allowed` value that is null, 0 (UNKNOWN), or any integer not in
the valid set {1, 2}. Ferries commonly transport bikes, so explicit
allowance information is expected.

```python
Notice(
    code="missing_bike_allowance",
    severity=Severity.WARNING,
    fields={
        "csv_row_number": <int>,   # 1-based row number of the trip record
        "route_id": <str>,         # route_id of the ferry route
        "trip_id": <str>,          # trip_id of the offending trip
    },
)
```

## 4. Implementation Approach

```
function validate_bikes_allowance(feed, ctx):
    # 1. Guard: both tables must exist
    if "routes" not in feed or "trips" not in feed:
        return []

    routes = feed["routes"]
    trips = feed["trips"]

    # 2. Guard: empty tables
    if routes.is_empty() or trips.is_empty():
        return []

    # 3. Find ferry route IDs (route_type == 4)
    ferry_route_ids = routes.filter(
        pl.col("route_type") == 4
    ).select("route_id")

    # 4. Guard: no ferry routes
    if ferry_route_ids.is_empty():
        return []

    # 5. Semi-join trips against ferry route IDs
    ferry_trips = trips.join(ferry_route_ids, on="route_id", how="semi")

    # 6. Filter for violations: bikes_allowed NOT IN {1, 2}
    #    This catches null, 0, and any unrecognized integer uniformly.
    #    In Polars, null.is_in([1, 2]) returns null, and ~null evaluates
    #    to null, which is excluded by filter — so we use an explicit
    #    null-aware condition.
    violations = ferry_trips.filter(
        ~pl.col("bikes_allowed").is_in([1, 2]) | pl.col("bikes_allowed").is_null()
    )

    # 7. Emit notices
    notices = []
    for row in violations.iter_rows(named=True):
        notices.append(
            Notice(
                code="missing_bike_allowance",
                severity=Severity.WARNING,
                fields={
                    "csv_row_number": row["csv_row_number"],
                    "route_id": row["route_id"],
                    "trip_id": row["trip_id"],
                },
            )
        )

    return notices
```

**Key Polars idioms used:**

- `df.filter(pl.col("route_type") == 4)` to isolate ferry routes.
- `.join(..., how="semi")` to efficiently restrict trips to those on
  ferry routes without duplicating columns.
- `~pl.col("bikes_allowed").is_in([1, 2]) | pl.col("bikes_allowed").is_null()`
  to catch null, 0, and unrecognized values. The explicit `is_null()` OR
  is needed because Polars `is_in` returns null (not false) for null
  inputs, and `~null` is still null, which `filter` drops. The OR clause
  ensures null rows are included in the violation set.
- `iter_rows(named=True)` to emit per-row notices (acceptable because
  only violating rows are iterated, which is typically a small subset).

**Null handling:** The `bikes_allowed` column is optional in the GTFS
schema (`Presence.OPTIONAL`), so null values are expected. The loading
layer parses the field as an integer enum; missing/empty values become
null. The filter logic treats null identically to 0 (UNKNOWN).

**Column-existence safety:** `route_type` is a required field on
`routes.txt` and `bikes_allowed` is a defined column on `trips.txt`. The
loader ensures both columns exist when the respective tables are present
in the feed. The `route_id` and `trip_id` columns are required fields on
their respective tables.
