# Implementation: MissingLevelIdValidator

## 1. Module location

`src/gtfs_validator/validators/missing_level_id.py`

## 2. Function signature

```python
def validate_missing_level_id(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

`ctx` is accepted for signature consistency but is not used by this validator.

## 3. Notice definitions

### `missing_level_id` — ERROR

Emitted when a stop that serves as an endpoint of at least one elevator pathway (`pathway_mode == 5`) does not have `level_id` defined (i.e., `level_id` is null) in `stops.txt`.

```python
Notice(
    code="missing_level_id",
    severity=Severity.ERROR,
    fields={
        "csvRowNumber": <int>,
        "stopId": <str>,
        "stopName": <str | None>,
    },
)
```

| Field | Type | Description |
|---|---|---|
| `csvRowNumber` | `int` | 1-based CSV row number of the stop record in `stops.txt` (header = row 1, first data row = row 2). Read from the `csvRowNumber` column added by the loader. |
| `stopId` | `str` | The `stop_id` of the stop that is missing `level_id`. |
| `stopName` | `str \| None` | The `stop_name` of that stop; `None` if the column is absent or the value is null. |

One notice is emitted per distinct stop, regardless of how many elevator pathways reference it.

## 4. Implementation approach

Polars joins are used for the cross-table lookup. Plain Python guard clauses precede all Polars operations.

**Algorithm (pseudocode):**

```
if "pathways" not in feed or "stops" not in feed:
    return []

pathways = feed["pathways"]
stops    = feed["stops"]

# Step 1: filter to elevator pathways only (pathway_mode == 5)
elevators = pathways.filter(pl.col("pathway_mode") == 5)
if elevators.is_empty():
    return []

# Step 2: collect unique stop IDs from both endpoint columns, deduplicated
from_ids        = elevators.select(pl.col("from_stop_id").alias("stop_id"))
to_ids          = elevators.select(pl.col("to_stop_id").alias("stop_id"))
elevator_stop_ids = pl.concat([from_ids, to_ids]).unique()

# Step 3: inner-join against stops to get stop metadata
#         (stops not in stops.txt are silently skipped — dangling FK is
#          handled by the FK validator separately)
joined = elevator_stop_ids.join(
    stops.select(["stop_id", "level_id", "stop_name", "csvRowNumber"]),
    on="stop_id",
    how="inner",
)

# Step 4: keep only stops where level_id is null
missing = joined.filter(pl.col("level_id").is_null())

# Step 5: emit one notice per remaining row
for row in missing.iter_rows(named=True):
    emit Notice(
        code="missing_level_id",
        severity=Severity.ERROR,
        fields={
            "csvRowNumber": row["csvRowNumber"],
            "stopId":       row["stop_id"],
            "stopName":     row.get("stop_name"),
        },
    )
```

**Key implementation notes:**

- `pathway_mode` is an integer column after load-time casting; the filter uses `== 5` (integer literal).
- The `level_id` column in `stops.txt` is an optional `Utf8` field. The loader normalizes empty strings to null for optional string fields, so `is_null()` correctly captures both absent and empty-string cases. If there is any doubt whether normalization has run, add `| (pl.col("level_id") == "")` to the filter predicate as a defensive fallback.
- If `stops.txt` does not include a `level_id` column at all (the column is entirely absent), the join select on `"level_id"` will raise. Guard this by checking `"level_id" in stops.columns`; if absent, treat every stop in the joined result as missing `level_id`.
- `iter_rows` on the final `missing` DataFrame is acceptable because the number of offending stops is expected to be small. The join and filter steps use vectorized Polars operations.
- The `stop_name` column may be absent from a minimal feed. Use `row.get("stop_name")` (or check column presence before joining) to avoid `KeyError`; emit `None` for `stopName` when the value is unavailable.
- Output ordering is not guaranteed; the notice list may be in any order.

## 5. Registry entry

Add to `VALIDATOR_REGISTRY` in `src/gtfs_validator/validators/__init__.py`. Insert it alphabetically among the `missing_*` entries — after `missing_feed_info` and before any later entry:

```python
from gtfs_validator.validators.missing_level_id import validate_missing_level_id

ValidatorEntry(
    name="missing_level_id",
    fn=validate_missing_level_id,
    requires=["pathways", "stops"],
)
```

`requires` lists both tables consumed by the validator. The runner uses this list to skip dispatch when neither table is present, which also satisfies the "pathways absent → no notices" and "stops absent → no notices" edge cases for free. Because both keys are in `requires`, the validator is only dispatched when at least one of the tables is in the feed; the in-function guards handle the case where the other table is missing.

Note: using `requires=["pathways", "stops"]` causes the runner to skip the validator entirely when *both* tables are absent. The in-body guard `if "pathways" not in feed or "stops" not in feed: return []` handles the case where exactly one of the two tables is present.

    rows: list[tuple[str, str | None, str | None]],
    row_start: int = 2,
) -> pl.DataFrame:
    """Build a stops DataFrame. Each row is (stop_id, stop_name, level_id)."""
    return pl.DataFrame(
        {
            "csvRowNumber": list(range(row_start, row_start + len(rows))),
            "stop_id":      [r[0] for r in rows],
            "stop_name":    [r[1] for r in rows],
            "level_id":     [r[2] for r in rows],
        },
        schema={
            "csvRowNumber": pl.Int64,
            "stop_id":      pl.Utf8,
            "stop_name":    pl.Utf8,

    )

    rows: list[tuple[str, str, int]],
