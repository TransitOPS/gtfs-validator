# Implementation: MissingStopsFileValidator

## 1. Module location

`src/gtfs_validator/validators/missing_stops_file.py`

## 2. Function signature

```python
def validate_missing_stops_file(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

`ctx` is accepted for signature consistency but is not used by this validator.

## 3. Notice definitions

### `missing_required_file` — ERROR

Emitted when neither `stops.txt` nor `locations.geojson` is present in the feed.

```python
Notice(
    code="missing_required_file",
    severity=Severity.ERROR,
    fields={"filename": "stops.txt"},
)
```

| Field | Type | Value |
|---|---|---|
| `filename` | `str` | `"stops.txt"` — hardcoded regardless of which file(s) are absent. |

This notice code is shared with other validators (e.g., `missing_feed_info.py`). No new notice type is needed.

Exactly one notice is emitted per feed when the condition is met; zero notices otherwise.

### Double-emit check

`loading.py`'s `_handle_missing` emits `missing_required_file` only for tables with `TableRequirement.REQUIRED`. `stops.txt` is defined with `TableRequirement.CONDITIONALLY_REQUIRED` (`_TCR`) in `schemas.py`, so `loading.py` emits only `missing_recommended_file` (WARNING) when `stops.txt` is absent. This validator is therefore the sole emitter of the `missing_required_file` ERROR for the missing-stops scenario, and there is no double-emit risk.

## 4. Implementation approach

No Polars operations are needed. The check is a pure key-presence test on the feed dict.

The feed dict uses short keys without `.txt` extensions (consistent with all other validators in this codebase). `stops.txt` maps to `"stops"` and `locations.geojson` maps to `"locations_geojson"`.

**Algorithm (pseudocode):**

```
stops_present   = "stops" in feed
geojson_present = "locations_geojson" in feed

if not stops_present and not geojson_present:
    return [Notice(code="missing_required_file", severity=ERROR, fields={"filename": "stops.txt"})]

return []
```

The validator must run even when both files are absent. The `requires=[]` registry entry (section 5) ensures the runner never skips this validator on the basis of missing tables.

**Full implementation:**

```python
"""Validator: MissingStopsFileValidator."""

from __future__ import annotations

from typing import TYPE_CHECKING

from gtfs_validator.notices import Notice, Severity

if TYPE_CHECKING:
    import polars as pl

    from gtfs_validator.context import ValidationContext


def validate_missing_stops_file(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
    """Emit an error when neither stops.txt nor locations.geojson is present."""
    stops_present = "stops" in feed
    geojson_present = "locations_geojson" in feed
    if not stops_present and not geojson_present:
        return [
            Notice(
                code="missing_required_file",
                severity=Severity.ERROR,
                fields={"filename": "stops.txt"},
            )
        ]
    return []
```

## 5. Registry entry

Add an import and a `ValidatorEntry` to `src/gtfs_validator/validators/__init__.py`. Insert the import with the other `missing_*` imports and place the entry alphabetically among the `missing_*` entries — after `missing_feed_info` and before `missing_level_id`.

```python
from gtfs_validator.validators.missing_stops_file import validate_missing_stops_file
```

```python
ValidatorEntry(
    name="missing_stops_file",
    fn=validate_missing_stops_file,
    requires=[],
),
```

`requires=[]` is mandatory. If either `"stops"` or `"locations_geojson"` were listed in `requires`, the runner's `should_skip` logic would skip the validator when that table's status is `MISSING_FILE` — defeating the purpose of this check. With `requires=[]`, the validator is always dispatched and performs its own presence guards.

Confirm with the actual loader implementation; if the feed stores it as a DataFrame or another type, adjust the fixture accordingly. The key presence check (`"locations_geojson" in feed`) is independent of the value type.
