**Validator:** `src/gtfs_validator/validators/fare_product_default_rider_categories.py`

No new shared utilities are needed. The notice code
`fare_product_with_multiple_default_rider_categories` is specific to this
validator and is not shared with any existing notice.

## 3. Notice Definitions

### `fare_product_with_multiple_default_rider_categories`

Severity: **ERROR**

Emitted once per `fare_product_id` that is associated with two or more
distinct `rider_category_id` values that each have `is_default_fare_category
== 1` (IS_DEFAULT). The notice references only the first two distinct
offending rider categories in CSV row order.

```python
Notice(
    code="fare_product_with_multiple_default_rider_categories",
    severity=Severity.ERROR,
    fields={
        "fare_product_id": <str>,        # the violating fare product
        "csv_row_number1": <int>,        # csv_row_number of the first distinct default rider category row in fare_products.txt
        "csv_row_number2": <int>,        # csv_row_number of the second distinct default rider category row in fare_products.txt
        "rider_category_id1": <str>,     # rider_category_id of the first distinct default rider category
        "rider_category_id2": <str>,     # rider_category_id of the second distinct default rider category
    },
)
```

**`csv_row_number` sourcing:** Both row numbers refer to rows in
`fare_products.txt`. The `csv_row_number` column is already present on the
`fare_products` DataFrame when the validator runs (injected by the loading
pipeline). Read it directly — do not derive it with `with_row_index`.

**De-duplication semantics:** A `(fare_product_id, rider_category_id)` pair
is counted only once regardless of how many `fare_products.txt` rows carry
that pair (e.g., rows with different `fare_media_id`). The first row by
`csv_row_number` order for each unique pair is the one whose row number
appears in the notice.

**Three or more distinct defaults:** When a product has three or more distinct
default rider categories, exactly one notice is still emitted — referencing
only the first and second distinct occurrences. The third and beyond are not
referenced in any notice.

## 4. Implementation Approach

```
function validate_fare_product_default_rider_categories(feed, ctx):

    # --- Skip guards ---
    if "rider_categories" not in feed or feed["rider_categories"].is_empty():
        return []
    if "fare_products" not in feed or feed["fare_products"].is_empty():
        return []

    df_fp = feed["fare_products"]
    df_rc = feed["rider_categories"].select(["rider_category_id", "is_default_fare_category"])

    # --- Step 1: join to bring is_default_fare_category into fare_products rows ---
    # Left join preserves all fare_products rows; non-matching rider_category_id
    # yields null for is_default_fare_category.
    joined = df_fp.join(df_rc, on="rider_category_id", how="left")

    # --- Step 2: filter to IS_DEFAULT rows only (is_default_fare_category == 1) ---
    # Null is_default_fare_category (no matching rider category) evaluates to
    # false in == comparison, so unresolved FK rows are silently dropped here.
    defaults = joined.filter(pl.col("is_default_fare_category") == 1)

    # --- Step 3: de-duplicate (fare_product_id, rider_category_id) pairs ---
    # Sort by csv_row_number first to ensure "first" means earliest CSV row.
    # unique(keep="first") retains the earliest row per pair after sort.
    # Re-sort after unique to restore global csv_row_number order.
    deduped = (
        defaults
        .sort("csv_row_number")
        .unique(subset=["fare_product_id", "rider_category_id"], keep="first")
        .sort("csv_row_number")
    )

    # --- Step 4: group by fare_product_id, emit notice if group size > 1 ---
    notices = []
    for (fare_product_id,), group in deduped.group_by(["fare_product_id"]):
        group_sorted = group.sort("csv_row_number")
        if len(group_sorted) < 2:
            continue
        rows = list(group_sorted.iter_rows(named=True))
        r1 = rows[0]
        r2 = rows[1]
        notices.append(Notice(
            code="fare_product_with_multiple_default_rider_categories",
            severity=Severity.ERROR,
            fields={
                "fare_product_id": fare_product_id,
                "csv_row_number1": r1["csv_row_number"],
                "csv_row_number2": r2["csv_row_number"],
                "rider_category_id1": r1["rider_category_id"],
                "rider_category_id2": r2["rider_category_id"],
            },
        ))
    return notices
```

**Key design decisions:**

- **Left join, not inner join.** A left join is used so that `fare_products`
  rows with a `rider_category_id` that does not exist in `rider_categories.txt`
  produce a null `is_default_fare_category`. The `== 1` filter then drops
  those rows silently. This matches the Java behavior where a missing FK
  target returns an empty Optional and the row is skipped.

- **`is_default_fare_category == 1` filter handles nulls safely.** In Polars,
  `null == 1` evaluates to `null` (falsy), so null values from unresolved FKs
  are excluded without an explicit null guard.

- **De-duplication before grouping.** The `unique(subset=["fare_product_id",
  "rider_category_id"], keep="first")` call after sorting by `csv_row_number`
  exactly replicates the Java de-duplication logic: the same `rider_category_id`
  appearing multiple times for the same `fare_product_id` (e.g., across
  different `fare_media_id` values) is counted only once.

- **Sort-then-unique-then-sort.** Polars `unique` does not guarantee output
  row order. Sorting by `csv_row_number` before `unique` ensures `keep="first"`
  retains the earliest row, then re-sorting after `unique` restores ascending
  CSV order for subsequent group iteration.

- **Group iteration in Python.** `group_by` in Polars does not guarantee group
  order. Notice ordering across multiple violating products is therefore
  non-deterministic, which matches the Java HashMap iteration behavior. Within
  each group, `sort("csv_row_number")` guarantees `r1` is always the earlier
  row and `r2` is always the second-earliest.

- **Only first two rows referenced.** Even for groups with three or more rows,
  only `rows[0]` and `rows[1]` are used. This matches Java's use of indices
  0 and 1 from its accumulator lists.

- **Fully vectorized before Python iteration.** The join, filter, de-duplicate,
  and sort steps are all Polars operations. Python iteration (`iter_rows`) only
  runs on the (typically very small) per-product groups that contain violating
  rows.

- **`rider_category_id` may be null in fare_products.** Rows where
  `rider_category_id` is null will join to null and then be filtered out by
  `== 1`. No explicit null guard on `rider_category_id` is needed before the
  join.

- **`ctx` unused.** The validator does not inspect the validation date or
  country code. The parameter is accepted to satisfy the `ValidatorFn` type
  alias.

handle the case where either table is absent or empty; the `requires` list
is informational for dependency tracking and documentation only.

import polars as pl
from datetime import date

from gtfs_validator.context import ValidationContext
from gtfs_validator.notices import Severity
from gtfs_validator.validators.fare_product_default_rider_categories import (
    validate_fare_product_default_rider_categories,
)

CTX = ValidationContext(country_code="US", date_for_validation=date(2024, 1, 1))


def make_rider_categories(rows: list[dict]) -> pl.DataFrame:
    """Build a rider_categories DataFrame from a list of dicts.

    Keys: rider_category_id (str), is_default_fare_category (int).
    """
    return pl.DataFrame({
        "rider_category_id": [r["rider_category_id"] for r in rows],
        "is_default_fare_category": [r["is_default_fare_category"] for r in rows],
    })


def make_fare_products(rows: list[dict]) -> pl.DataFrame:
    """Build a fare_products DataFrame from a list of dicts.

    Keys: fare_product_id (str), rider_category_id (str | None),
    csv_row_number (int). fare_media_id is omitted unless needed.
    """
    return pl.DataFrame({
        "fare_product_id": [r["fare_product_id"] for r in rows],
        "rider_category_id": [r.get("rider_category_id") for r in rows],
        "csv_row_number": [r["csv_row_number"] for r in rows],
    })
