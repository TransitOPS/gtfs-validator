# Analysis: StopAccessValidator

## 1. Purpose

Validate that `stops.stop_access` is only specified for stops (location_type = 0) that
are associated with a parent station; flag any row where `stop_access` is set on a
non-stop location type or on a stop that lacks a `parent_station` value.

## 2. Input tables

| Table | Columns used |
|---|---|
| `stops.txt` | `csv_row_number`, `stop_id`, `stop_name`, `stop_access`, `location_type`, `parent_station` |

This is a single-table, single-entity validator. No cross-table joins are performed.

### Column semantics

- `stop_access` — optional enum column; values are `0` (ACCESSIBLE_VIA_PATHWAYS) or
  `1` (NOT_ACCESSIBLE_VIA_PATHWAYS). When this column is absent from the file header
  entirely the validator skips all rows (guard clause on column presence).
- `location_type` — enum column; values are `0` (STOP), `1` (STATION), `2`
  (ENTRANCE/EXIT), `3` (GENERIC_NODE), `4` (BOARDING_AREA). Defaults to `0` (STOP)
  when omitted.
- `parent_station` — optional ID referencing `stops.stop_id`; present (non-null,
  non-empty) indicates the stop belongs to a parent station.

## 3. Validation logic

The validator is applied independently to each row of `stops.txt`.

### Step 1: Guard — skip if stop_access is null

If `stop_access` is null/absent for a row, skip that row entirely. No notice is
emitted for stops that do not specify `stop_access`.

### Step 2: Branch on location_type

**Branch A — location_type == STOP (0):**

Check whether `parent_station` is populated. In Java this is `entity.hasParentStation()`
which returns true when `parent_station` is a non-null, non-empty string.

- If `parent_station` is absent/null/empty: emit
  `stop_access_specified_for_stop_with_no_parent_station`.
- If `parent_station` is present: no notice — this is the valid usage of `stop_access`.

**Branch B — location_type is anything other than STOP (1, 2, 3, 4):**

`stop_access` is forbidden for all non-stop location types. Emit
`stop_access_specified_for_incorrect_location` unconditionally (regardless of whether
`parent_station` is present).

### Decision table

| location_type | parent_station present | stop_access null | Result |
|---|---|---|---|
| any | any | yes (null) | No notice |
| STOP (0) | yes | no | No notice (valid) |
| STOP (0) | no | no | `stop_access_specified_for_stop_with_no_parent_station` |
| STATION (1) | any | no | `stop_access_specified_for_incorrect_location` |
| ENTRANCE (2) | any | no | `stop_access_specified_for_incorrect_location` |
| GENERIC_NODE (3) | any | no | `stop_access_specified_for_incorrect_location` |
| BOARDING_AREA (4) | any | no | `stop_access_specified_for_incorrect_location` |

### Column-level guard

The Java `shouldCallValidate` method checks `header.hasColumn(GtfsStop.STOP_ACCESS_FIELD_NAME)`.
When the `stop_access` column is not present in the file header at all, the validator
does not execute for any row. In Python this translates to: if the `stop_access` column
is not present in the `stops` DataFrame, return `[]` immediately.

## 4. Notices emitted

### `stop_access_specified_for_stop_with_no_parent_station` (ERROR)

Emitted when a row with `location_type == STOP` has `stop_access` set but has no
`parent_station`.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | integer | `stops.csv_row_number` | 1-based row number of the offending row |
| `stop_id` | string | `stops.stop_id` | Identifier of the stop |
| `stop_name` | string | `stops.stop_name` | Human-readable name of the stop |
| `stop_access` | integer (enum) | `stops.stop_access` | The disallowed stop_access value |
| `location_type` | integer (enum) | `stops.location_type` | Will be 0 (STOP) |

Condition: `stop_access IS NOT NULL AND location_type == 0 AND parent_station IS NULL`.

### `stop_access_specified_for_incorrect_location` (ERROR)

Emitted when any row whose `location_type` is not STOP (i.e. is STATION, ENTRANCE,
GENERIC_NODE, or BOARDING_AREA) has `stop_access` set.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | integer | `stops.csv_row_number` | 1-based row number of the offending row |
| `stop_id` | string | `stops.stop_id` | Identifier of the stop |
| `stop_name` | string | `stops.stop_name` | Human-readable name of the stop |
| `stop_access` | integer (enum) | `stops.stop_access` | The disallowed stop_access value |
| `location_type` | integer (enum) | `stops.location_type` | The non-STOP location type |

Condition: `stop_access IS NOT NULL AND location_type != 0`.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `stops.txt` absent from feed | Return `[]`; no notices. |
| `stops.txt` present but empty | Return `[]`; no notices. |
| `stop_access` column not in file header | Return `[]` immediately (column-level guard). |
| `stop_access` is null for a row | Skip that row; no notice. |
| `location_type` omitted (defaults to 0, STOP) | Treated as STOP; triggers `no_parent_station` notice if `parent_station` is also absent and `stop_access` is set. |
| `location_type == STOP` with `parent_station` and `stop_access` set | No notice; this is valid usage. |
| `location_type == STATION` with `parent_station` set and `stop_access` set | `stop_access_specified_for_incorrect_location` still emitted; parent_station is irrelevant for non-STOP locations. |
| Multiple offending rows | One notice per offending row. |
| `stop_name` is null | Java passes null into the notice as-is; Python should pass `None`/null faithfully. |

## 6. Test contracts

### `stopLocationWithoutParentStation_generatesNotice`

- Input: one stop row with `csv_row_number=7`, `stop_id="S1"`,
  `location_type=STOP (0)`, `stop_name="Stop 1"`,
  `stop_access=NOT_ACCESSIBLE_VIA_PATHWAYS (1)`, no `parent_station`.
- Expected: exactly one `StopAccessSpecifiedForStopWithNoParentStationNotice`:
  - `csv_row_number = 7`
  - `stop_id = "S1"`
  - `stop_name = "Stop 1"`
  - `stop_access = NOT_ACCESSIBLE_VIA_PATHWAYS (1)`
  - `location_type = STOP (0)`

### `nonStopLocationWithStopAccess_generatesIncorrectLocationNotice`

- Input: one stop row with `csv_row_number=9`, `stop_id="S2"`,
  `location_type=STATION (1)`, `stop_name="Stop 2"`,
  `stop_access=NOT_ACCESSIBLE_VIA_PATHWAYS (1)`.
- Expected: exactly one `StopAccessSpecifiedForIncorrectLocationNotice`:
  - `csv_row_number = 9`
  - `stop_id = "S2"`
  - `stop_name = "Stop 2"`
  - `stop_access = NOT_ACCESSIBLE_VIA_PATHWAYS (1)`
  - `location_type = STATION (1)`

The test suite does not include:
- A valid case (STOP + parent_station + stop_access — no notice).
- Null `stop_access` producing no notice.
- Absent `stop_access` column producing no notices.
- ENTRANCE, GENERIC_NODE, BOARDING_AREA location types (only STATION is tested, but
  the else-branch in the Java code covers all non-STOP types).

## 7. Implementation notes

### Polars approach

Both notice conditions are independent vectorized filters over the `stops` DataFrame.
Implement as two separate filter passes rather than row-by-row iteration.

```python
import polars as pl
from gtfs_validator.notices import Notice
from gtfs_validator.context import ValidationContext

STOP_LOCATION_TYPE = 0

def validate_stop_access(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
    if "stops" not in feed:
        return []
    stops = feed["stops"]
    if stops.is_empty():
        return []
    if "stop_access" not in stops.columns:
        return []

    # Only consider rows where stop_access is set
    with_access = stops.filter(pl.col("stop_access").is_not_null())
    if with_access.is_empty():
        return []

    notices: list[Notice] = []

    # Case 1: STOP location with no parent_station
    no_parent = with_access.filter(
        (pl.col("location_type") == STOP_LOCATION_TYPE)
        & pl.col("parent_station").is_null()
    )
    for row in no_parent.iter_rows(named=True):
        notices.append(
            Notice(
                code="stop_access_specified_for_stop_with_no_parent_station",
                severity="ERROR",
                fields={
                    "csv_row_number": row["csv_row_number"],
                    "stop_id": row["stop_id"],
                    "stop_name": row["stop_name"],
                    "stop_access": row["stop_access"],
                    "location_type": row["location_type"],
                },
            )
        )

    # Case 2: Non-STOP location with stop_access set
    wrong_type = with_access.filter(
        pl.col("location_type") != STOP_LOCATION_TYPE
    )
    for row in wrong_type.iter_rows(named=True):
        notices.append(
            Notice(
                code="stop_access_specified_for_incorrect_location",
                severity="ERROR",
                fields={
                    "csv_row_number": row["csv_row_number"],
                    "stop_id": row["stop_id"],
                    "stop_name": row["stop_name"],
                    "stop_access": row["stop_access"],
                    "location_type": row["location_type"],
                },
            )
        )

    return notices
```

### Null semantics for parent_station

In GTFS, `parent_station` is an optional string ID field. At load time it will be null
when omitted or empty. The check `pl.col("parent_station").is_null()` is the correct
Polars equivalent of `!entity.hasParentStation()` in Java, which tests for null/empty.
If the loading layer normalizes empty strings to null (as it should), this is
sufficient. If empty strings are preserved, add `.or_(pl.col("parent_station") == "")`.

### Default location_type

When `location_type` is omitted from a row, the schema default is `0` (STOP). Ensure
the loading layer applies this default before the validator runs; otherwise null
`location_type` values would not match the STOP filter and would fall into the
"incorrect location" branch incorrectly.

### Guard clause ordering

1. `"stops"` not in feed → return `[]`
2. `stops.is_empty()` → return `[]`
3. `"stop_access"` not in `stops.columns` → return `[]`
4. Filter to rows where `stop_access` is not null (the per-row null guard)

### Notice code mapping

| Java class | Python notice code |
|---|---|
| `StopAccessSpecifiedForStopWithNoParentStationNotice` | `stop_access_specified_for_stop_with_no_parent_station` |
| `StopAccessSpecifiedForIncorrectLocationNotice` | `stop_access_specified_for_incorrect_location` |
