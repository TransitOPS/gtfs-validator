# Analysis: UniqueGeographyIdValidator

## 1. Purpose

Validates that the `id` values from `locations.geojson` features do not collide with `stop_id` values from `stops.txt` or `location_group_id` values from `location_groups.txt`; all three ID namespaces must be globally unique.

## 2. Input tables

| Source | Feed key | Columns used |
|---|---|---|
| `stops.txt` | `"stops"` | `stop_id`, `csv_row_number` |
| `location_groups.txt` | `"location_groups"` | `location_group_id`, `csv_row_number` |
| `locations.geojson` | `"locations_geojson"` | feature `id`, feature `index` |

### Notes on locations.geojson

`locations.geojson` is not a CSV file; in the Python implementation it is loaded as a list of dicts under `feed["locations_geojson"]`. Each dict has at least keys `"id"` (the feature ID string) and `"index"` (the zero-based feature position within the file, equivalent to Java's `featureIndex`). The existing Python implementation at `src/gtfs_validator/validators/unique_geography_id.py` currently uses the key `"geojson_features"` and a column model, which is inconsistent with the rest of the codebase; it should use `"locations_geojson"` (a list of dicts) to match the pattern used by `geojson_geometry.py`, `location_id_foreign_key.py`, and `overlapping_pickup_drop_off_zone.py`.

### Schema reference

`stops.txt` (`STOPS`):

| Column | Type | Constraint |
|---|---|---|
| `stop_id` | string | Required, Primary Key |
| `csv_row_number` | int | Internal tracking column |

`location_groups.txt` (`LOCATION_GROUPS`):

| Column | Type | Constraint |
|---|---|---|
| `location_group_id` | string | Required, Primary Key |
| `csv_row_number` | int | Internal tracking column |

`locations.geojson` (list of dicts):

| Key | Type | Description |
|---|---|---|
| `"id"` | string | GeoJSON Feature `id` property |
| `"index"` | int | Zero-based position of the feature in the file |

## 3. Validation logic

### Skip conditions

- If all three sources are absent or empty, no checks are performed and no notices are emitted.
- If only one source is non-empty, collision is structurally impossible; no notices are emitted.

### Algorithm

The Java implementation merges all ID entries from all three sources into a single list, groups by ID, and then for each group that spans more than one distinct source file, emits one notice. Groups where all entries come from the same file are silently ignored (i.e., duplicate `stop_id` values within `stops.txt` are not the responsibility of this validator; those are caught by PK validation at load time).

```
entries = []

for each stop in stops.txt:
    entries.append((stop.stop_id, "stops.txt", stop.csv_row_number))

for each group in location_groups.txt:
    entries.append((group.location_group_id, "location_groups.txt", group.csv_row_number))

for each feature in locations.geojson:
    entries.append((feature.id, "locations.geojson", feature.index))

group entries by id:
    for each id, group_list:
        unique_sources = distinct sources in group_list
        if len(unique_sources) == 1:
            skip  # same-file duplicates are ignored by this validator
        if len(group_list) > 1 AND len(unique_sources) > 1:
            emit duplicate_geography_id(
                geography_id = id,
                csv_row_number_stops = row_number from "stops.txt" entry (or None),
                csv_row_number_location_groups = row_number from "location_groups.txt" entry (or None),
                feature_index = row_number from "locations.geojson" entry (or None),
            )
```

### Key observations

1. **Cross-source only**: A single `stop_id` duplicated within `stops.txt` alone does not trigger this validator. The same `id` appearing in `stops.txt` AND `location_groups.txt` does trigger it.
2. **Three-way collision**: If the same ID appears in all three sources, one notice is emitted with all three row numbers populated.
3. **Two-way collision**: If the same ID appears in exactly two sources, one notice is emitted with the two relevant row numbers and `None` for the third.
4. **First-occurrence row numbers**: The Java `getRowNumber` uses `findFirst()`, so only the first row number per source file is captured in the notice. If `stop_id = "x"` appears twice in `stops.txt`, only the first row number is reported.
5. **No deduplication across notices**: The validator emits one notice per colliding ID, not per colliding pair.

## 4. Notices emitted

### `duplicate_geography_id`

Severity: **ERROR**

Emitted when the same ID string appears in more than one of `stops.txt`, `location_groups.txt`, or `locations.geojson`.

| Field | Type | Description |
|---|---|---|
| `geography_id` | string | The duplicate ID |
| `csv_row_number_stops` | int or None | CSV row number in `stops.txt` (None if stops.txt does not contain this ID) |
| `csv_row_number_location_groups` | int or None | CSV row number in `location_groups.txt` (None if not present there) |
| `feature_index` | int or None | Zero-based feature index in `locations.geojson` (None if not present there) |

**Notice code derivation:**
- Java class: `DuplicateGeographyIdNotice`
- Python notice code: `duplicate_geography_id`

**Java field mapping:**

| Java field | Python field | Note |
|---|---|---|
| `geographyId` | `geography_id` | The colliding ID |
| `csvRowNumberA` | `csv_row_number_stops` | Row from stops.txt |
| `csvRowNumberB` | `csv_row_number_location_groups` | Row from location_groups.txt |
| `featureIndex` | `feature_index` | Index in locations.geojson |

## 5. Edge cases

- **All three sources absent**: Return `[]` immediately.
- **Only stops.txt present**: No collision possible across sources; return `[]`.
- **Only locations.geojson present**: No collision possible across sources; return `[]`.
- **stops.txt empty (header only)**: Treat as if absent for this check.
- **location_groups.txt absent**: `csv_row_number_location_groups` is `None` in any notice emitted.
- **locations.geojson absent**: `feature_index` is `None` in any notice emitted.
- **Null feature `id` in locations.geojson**: Skip features where `id` is `None` or missing.
- **Null `stop_id` in stops.txt**: Skip rows where `stop_id` is `None` (load-time validation should catch required-field violations, but the validator must not crash).
- **Null `location_group_id` in location_groups.txt**: Same as above; skip null values.
- **Same ID in same source more than once**: Not reported by this validator (only cross-source collisions matter). The single-source guard `if len(unique_sources) == 1: return` handles this.
- **Same ID in all three sources**: One notice emitted with all three row fields populated.
- **Multiple distinct colliding IDs**: One notice per colliding ID.

## 7. Implementation notes

### Existing Python implementation

A Python implementation already exists at `/Users/ryanmahoney/Documents/gtfs-validator/src/gtfs_validator/validators/unique_geography_id.py`. It is functionally correct in logic but has two issues:

1. **Wrong feed key for GeoJSON**: Uses `"geojson_features"` (a DataFrame model) instead of `"locations_geojson"` (a list of dicts), which is inconsistent with all other validators that consume GeoJSON data.
2. **Not registered**: The validator is not yet added to `VALIDATOR_REGISTRY` in `validators/__init__.py`.

### Validator type

Cross-source ID collision check. The data is naturally small enough (one row per stop/group/feature) that a plain Python dict grouping approach is appropriate. A Polars-based union approach is also viable but adds complexity for minimal gain.

### Validator signature

```python
def validate_unique_geography_id(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

Note: `feed["locations_geojson"]` is `list[dict[str, Any]]`, not a `pl.DataFrame`.

### Corrected GeoJSON access pattern

```python
# Correct pattern (matches other validators):
geojson_features: list[dict] = feed.get("locations_geojson") or []
for feature in geojson_features:
    fid = feature.get("id")
    feature_index = feature.get("index")
    if fid is not None:
        entries.append({"id": fid, "source": "locations.geojson", "row_number": feature_index})
```

### Implementation strategy

Plain Python grouping is preferred over Polars here because the data is inherently multi-source with heterogeneous row representations. The algorithm is:

1. Iterate `stops` DataFrame rows, collect `(stop_id, "stops.txt", csv_row_number)`.
2. Iterate `location_groups` DataFrame rows, collect `(location_group_id, "location_groups.txt", csv_row_number)`.
3. Iterate `locations_geojson` list, collect `(feature["id"], "locations.geojson", feature["index"])`.
4. Group all entries by ID using a `dict[str, list[dict]]`.
5. For each group, compute `unique_sources`. If `len(unique_sources) > 1`, emit one notice.

### Notice codes (Python)

| Java notice class | Python notice code | Severity |
|---|---|---|
| `DuplicateGeographyIdNotice` | `duplicate_geography_id` | ERROR |

### Relationship to load-time validation

Load-time validation handles:
- `stop_id` type (required string) and PK uniqueness within `stops.txt`.
- `location_group_id` type and PK uniqueness within `location_groups.txt`.
- GeoJSON feature ID presence and type validation.

This validator specifically handles cross-source namespace collision, which cannot be expressed as a single-table constraint.

### Validator registration

The validator should be added to `VALIDATOR_REGISTRY` in `validators/__init__.py`. Because it needs `stops`, `location_groups`, and `locations_geojson` — and any of them can be absent — it should not gate on all three being present. The validator itself handles partial presence.

```python
ValidatorEntry(
    name="unique_geography_id",
    fn=validate_unique_geography_id,
    requires=[],  # handles absent tables internally
),
```

Alternatively, if the registry supports optional requires, gate only on at least one of the three being present to avoid unnecessary invocations on feeds with none of these.
