# Analysis: ParentStationValidator

## 1. Purpose

Validates that every `parent_station` reference in `stops.txt` points to a record with the correct `location_type`, and that every station (`location_type=1`) is actually used as the parent of at least one stop/platform (`location_type=0`).

## 2. Input tables

| Table | Columns used |
|---|---|
| `stops.txt` | `stop_id`, `stop_name`, `location_type`, `parent_station` |

This is a single-table validator. No cross-table joins are required.

### Location type integer values

| Integer | Enum name | Meaning |
|---|---|---|
| 0 | `STOP` | Stop / platform |
| 1 | `STATION` | Station |
| 2 | `ENTRANCE` | Entrance / exit |
| 3 | `GENERIC_NODE` | Generic pathway node |
| 4 | `BOARDING_AREA` | Boarding area |
| any other | `UNRECOGNIZED` | Unknown / invalid |

### Allowed parent location types per child type

| Child `location_type` | Expected parent `location_type` |
|---|---|
| 0 (STOP) | 1 (STATION) |
| 2 (ENTRANCE) | 1 (STATION) |
| 3 (GENERIC_NODE) | 1 (STATION) |
| 4 (BOARDING_AREA) | 0 (STOP) |
| 1 (STATION) | No parent allowed (handled by another validator) |
| Other (UNRECOGNIZED) | No check performed |

## 3. Validation logic

Two independent checks are performed in a single pass over the stops table.

### Check A: wrong parent location type

For each row in `stops.txt`:

1. If the row has `location_type == STATION` (1), record its `stop_id` in a `stations` set and skip further processing for this row.
2. If the row has no `parent_station` value (null or empty), skip it.
3. Look up the parent record by `parent_station` value. If the parent `stop_id` is not found in the table, skip it (broken foreign-key reference is reported by a separate validator).
4. If the row's `location_type == STOP` (0), record the parent's `stop_id` in a `stations_with_stops` set.
5. Compute the `expected_parent_location_type` for the child's `location_type`:
   - STOP, ENTRANCE, or GENERIC_NODE → expected parent is STATION (1)
   - BOARDING_AREA → expected parent is STOP (0)
   - UNRECOGNIZED → no check (skip)
6. If the parent's actual `location_type` does not equal the expected type, emit `wrong_parent_location_type`.

### Check B: unused station

After processing all rows:

7. Compute `unused_stations = stations - stations_with_stops`.
8. For each `stop_id` in `unused_stations`, look up the stop record and emit `unused_station`.

Note: "used" in this context means having at least one child row with `location_type == STOP` (0) that references it. A station that is only the parent of ENTRANCEs, GENERIC_NODEs, or BOARDING_AREAs is still considered unused.

## 4. Notices emitted

### `wrong_parent_location_type` (ERROR)

Emitted when a stop's `parent_station` points to a record whose `location_type` is not the expected type for that child's `location_type`.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | integer | child row | Row number of the child record |
| `stop_id` | string | child `stop_id` | ID of the child stop |
| `stop_name` | string | child `stop_name` | Name of the child stop |
| `location_type` | integer | child `location_type` (raw integer) | Actual location type of the child |
| `parent_csv_row_number` | integer | parent row | Row number of the parent record |
| `parent_station` | string | child `parent_station` | ID of the parent station |
| `parent_stop_name` | string | parent `stop_name` | Name of the parent stop |
| `parent_location_type` | integer | parent `location_type` (raw integer) | Actual location type of the parent |
| `expected_location_type` | integer | computed | Expected location type for the parent |

Severity: ERROR.

Java class: `WrongParentLocationTypeNotice`.

### `unused_station` (INFO)

Emitted when a record has `location_type == STATION` (1) but no stop with `location_type == STOP` (0) references it via `parent_station`.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | integer | station row | Row number of the unused station |
| `stop_id` | string | station `stop_id` | ID of the unused station |
| `stop_name` | string | station `stop_name` | Name of the unused station |

Severity: INFO.

Java class: `UnusedStationNotice`.

Note: `UnusedParentStationNotice` is a deprecated predecessor of `unused_station`, renamed in version 7.0.0. The Python implementation should use `unused_station` only.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `stops.txt` absent from feed | Return immediately, no notices. |
| `stops.txt` present but empty | No rows to process; no notices. |
| Stop has `parent_station` set but the referenced `stop_id` does not exist | Skip (broken FK is caught by a separate FK validator); no notice from this validator. |
| Stop has `location_type` that is UNRECOGNIZED | `expected_parent_location_type` returns UNRECOGNIZED; the type check is skipped; no `wrong_parent_location_type` notice. |
| Station (`location_type=1`) has a `parent_station` field | The station is added to the `stations` set and processing continues to the next row; the parent check is not performed on it here (checked by another validator). |
| Station is the parent of only ENTRANCE, GENERIC_NODE, or BOARDING_AREA children | It is NOT added to `stations_with_stops`; it will appear in `unused_stations`; an `unused_station` notice is emitted. |
| Station is the parent of at least one STOP (0) child | Added to `stations_with_stops`; removed from `unused_stations`; no `unused_station` notice. |
| `stop_name` is null | Null is passed through to notice fields as-is. |
| Multiple stops share the same `parent_station` | Each child is checked independently; the parent is recorded in `stations_with_stops` at the first STOP child and stays there. |
| Station appears in a `parent_station` field but has no corresponding row (dangling reference) | The station is never added to the `stations` set; it cannot appear in `unused_stations`; no `unused_station` notice. |
| BOARDING_AREA child with STATION parent | Emits `wrong_parent_location_type` (expected STOP=0, got STATION=1). The STATION is also not marked as used (since no STOP references it), so an `unused_station` notice is also emitted for the same station. Both notices fire. |

## 6. Test contracts

### `stopParent`

- STOP child with STATION parent: valid. No notices.
- STOP child with ENTRANCE parent: emits `wrong_parent_location_type`. Fields: child row=1, `stop_id="child"`, `stop_name="Child location"`, `location_type=0` (STOP), parent row=2, `parent_station="parent"`, `parent_stop_name="Parent location"`, `parent_location_type=2` (ENTRANCE), `expected_location_type=1` (STATION).

### `entranceParent`

- ENTRANCE child with STATION parent: valid type, but station has no STOP children; emits `unused_station` for the parent (row=2, `stop_id="parent"`, `stop_name="Parent location"`).
- ENTRANCE child with STOP parent: emits `wrong_parent_location_type`. Expected parent type = STATION (1), actual = STOP (0).

### `genericNodeParent`

- GENERIC_NODE child with STATION parent: valid type, but station has no STOP children; emits `unused_station`.
- GENERIC_NODE child with STOP parent: emits `wrong_parent_location_type`. Expected = STATION (1), actual = STOP (0).

### `boardingAreaParent`

- BOARDING_AREA child with STOP parent: valid. No notices.
- BOARDING_AREA child with STATION parent: emits both `wrong_parent_location_type` (expected STOP=0, got STATION=1) AND `unused_station` (station has no STOP children).

### `noParent`

- STOP, ENTRANCE, GENERIC_NODE, BOARDING_AREA rows with no `parent_station` set: all produce no notices. Validator ignores non-station rows without a parent reference.
- Note: a lone STATION with no `parent_station` also produces no `unused_station` notice in this test because the `validateNoParent` helper tests only the child types.

### `unusedStation`

- Three rows: one STOP (child, `parent_station="used_station"`), one STATION `"unused_station"`, one STATION `"used_station"`.
- Expected: exactly one `unused_station` notice for `"unused_station"` (row=2). No notice for `"used_station"` because it has a STOP child.

### `foreignKeyViolation_handledGracefully`

- One STOP row with `parent_station="parent"`, but no row with `stop_id="parent"` exists.
- Expected: no notices. The validator silently skips unresolvable `parent_station` references.

## 7. Implementation notes

### Algorithm choice

This validator involves two related passes over the stops table. The Java uses a single row loop plus two set operations. In Python:

- **Option A (pure Polars):** Use Polars joins and filter expressions for both checks. This is cleaner and avoids Python loops on large feeds.
- **Option B (Python loop):** Collect to Python dicts and iterate. Acceptable for small feeds but not preferred per AGENTS.md.

Recommended: Polars for both checks since the logic maps cleanly to set operations and joins.

### Polars implementation sketch

**Check A (wrong parent location type):**

```python
# Join stops to itself: child on the left, parent on the right
child = stops.filter(
    pl.col("location_type").is_in([0, 2, 3, 4]) & pl.col("parent_station").is_not_null()
)
joined = child.join(
    stops.select(["stop_id", "stop_name", "location_type"]).rename({
        "stop_id": "parent_station",
        "stop_name": "parent_stop_name",
        "location_type": "parent_location_type",
    }),
    on="parent_station",
    how="inner",  # inner join drops unresolvable references (FK violations handled elsewhere)
)
# Map expected parent type
expected_map = {0: 1, 2: 1, 3: 1, 4: 0}  # child_type -> expected_parent_type
# Add expected_location_type column and filter mismatches
```

Since `location_type` is an integer column, use `pl.col("location_type").replace(expected_map)` or a `when/then` chain for the mapping, then filter where `parent_location_type != expected_location_type`.

**Check B (unused station):**

```python
stations = stops.filter(pl.col("location_type") == 1).select(["stop_id", "stop_name", "csv_row_number"])
stop_parents = stops.filter(
    (pl.col("location_type") == 0) & pl.col("parent_station").is_not_null()
).select(pl.col("parent_station").alias("stop_id"))
unused = stations.join(stop_parents, on="stop_id", how="anti")
# Each row in `unused` produces an unused_station notice
```

### Location type mapping

Use a `when/then/otherwise` chain in Polars or a plain Python dict lookup. The `UNRECOGNIZED` case (no check) is handled by an inner join (unrecognized child types produce no expected type mapping and are simply not included in the filter).

Alternatively, filter to only recognized child types before the join:

```python
CHILD_TYPES = {0, 2, 3, 4}
EXPECTED_PARENT = {0: 1, 2: 1, 3: 1, 4: 0}
```

### Notice fields

Both notices use `csv_row_number` (integer row counter from the CSV, 1-based). The loader must preserve this as a column. Confirm the feed DataFrame has a `csv_row_number` column (added during loading).

`location_type` and `parent_location_type` in the `wrong_parent_location_type` notice are the raw integer values, not enum names.

### Guard for missing table

```python
stops = feed.get("stops")
if stops is None or stops.is_empty():
    return []
```

If the `parent_station` column does not exist in the DataFrame (feed did not include it), treat all rows as having no parent and proceed directly to the unused station check.

### Notice codes

- `"wrong_parent_location_type"` (from Java `WrongParentLocationTypeNotice`)
- `"unused_station"` (from Java `UnusedStationNotice`; replaces deprecated `"unused_parent_station"`)

### Feed dict key

- `"stops"` — `stops.txt`

### Validator registration

Requires: `["stops"]`.

### Determinism

Both checks are independent and their output order depends on iteration order. Emit `wrong_parent_location_type` notices in the order child rows appear in the stops table. Emit `unused_station` notices in the order stations appear in the stops table. (Java emits them in hash-set iteration order, which is not guaranteed; the Python implementation should use stable ordering by `csv_row_number` for predictability.)
