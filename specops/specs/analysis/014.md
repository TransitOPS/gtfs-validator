# Analysis: FareMediaNameValidator

## 1. Purpose

Validates each row of `fare_media.txt` for a single conditional recommendation: when `fare_media_type` indicates a physical or digital card that riders need to identify by name (transit card or mobile app), then `fare_media_name` should be present. Absence of the name for those types is reported as a WARNING.

For fare media types that do not require a distinguishing name (`NONE`, `PAPER_TICKET`, `CONTACTLESS_EMV`), the field is genuinely optional and no notice is emitted regardless of whether a name is supplied or not.

This validator has no cross-table dependencies. It operates on individual `fare_media.txt` rows only.

## 2. Input tables

| Table | Columns used |
|---|---|
| `fare_media.txt` | `fare_media_type`, `fare_media_name`, `csv_row_number` |

### Schema reference

`fare_media.txt` (`GtfsFareMediaSchema`):

| Column | Type | Constraint |
|---|---|---|
| `fare_media_id` | ID (string) | Required, primary key |
| `fare_media_name` | string | Optional (recommended for types 2 and 4) |
| `fare_media_type` | enum (`GtfsFareMediaType`) | Required |

`GtfsFareMediaType` enum values:

| Name | Integer value | Requires name? |
|---|---|---|
| `NONE` | 0 | No |
| `PAPER_TICKET` | 1 | No |
| `TRANSIT_CARD` | 2 | Yes |
| `CONTACTLESS_EMV` | 3 | No |
| `MOBILE_APP` | 4 | Yes |

## 3. Validation logic

### Skip condition

Run if `fare_media.txt` is present in the feed and non-empty. If the table is absent or empty, return no notices immediately.

In Python:

```python
if "fare_media" not in feed or feed["fare_media"].is_empty():
    return []
```

### Per-row check

For each row in `fare_media.txt`:

1. Determine whether the `fare_media_type` value requires a name. Only types `TRANSIT_CARD` (2) and `MOBILE_APP` (4) require a name.
2. If the type requires a name AND `fare_media_name` is absent (null or empty string): emit one `missing_recommended_field` notice (WARNING).
3. Otherwise: no notice.

The check is one-directional. Providing a name for a type that does not require one (e.g., `PAPER_TICKET` with a name) never produces a notice.

### Pseudocode

```
for each row in fare_media:
    if fare_media_type in {TRANSIT_CARD, MOBILE_APP}:
        if fare_media_name is null or empty:
            emit missing_recommended_field(
                filename="fare_media.txt",
                csv_row_number=row.csv_row_number,
                field_name="fare_media_name"
            )
```

### What is NOT checked here

- Whether `fare_media_id` is unique (primary key; handled at load time).
- Whether `fare_media_type` is a valid enum value (handled at load time).
- Whether `fare_media_name` is non-empty when it IS present (no length or format constraint imposed by this validator).

## 4. Notices emitted

### `missing_recommended_field`

Severity: **WARNING**

Emitted when `fare_media_type` is `TRANSIT_CARD` (2) or `MOBILE_APP` (4) and `fare_media_name` is absent.

| Field | Type | Description |
|---|---|---|
| `filename` | string | `"fare_media.txt"` |
| `csv_row_number` | int | Row number of the offending record |
| `field_name` | string | `"fare_media_name"` |

This is a generic notice shared across multiple validators. In the Java implementation it is `MissingRecommendedFieldNotice` with severity `WARNING`.

## 5. Edge cases

- **`fare_media.txt` absent**: Skip entirely; no notices.
- **`fare_media.txt` present but empty**: Skip entirely; no notices.
- **`fare_media_type` = `TRANSIT_CARD`, `fare_media_name` absent**: Emit one `missing_recommended_field` notice.
- **`fare_media_type` = `TRANSIT_CARD`, `fare_media_name` present**: No notice.
- **`fare_media_type` = `MOBILE_APP`, `fare_media_name` absent**: Emit one `missing_recommended_field` notice.
- **`fare_media_type` = `MOBILE_APP`, `fare_media_name` present**: No notice.
- **`fare_media_type` = `PAPER_TICKET`, `fare_media_name` absent**: No notice (name not required).
- **`fare_media_type` = `PAPER_TICKET`, `fare_media_name` present**: No notice.
- **`fare_media_type` = `NONE`, `fare_media_name` absent**: No notice.
- **`fare_media_type` = `CONTACTLESS_EMV`, `fare_media_name` absent**: No notice.
- **Unknown/unrecognized `fare_media_type` value**: Falls through the switch default case in Java, which returns `false` (no name required). The Python implementation should treat unknown enum values as "no name required" (consistent with the Java `default: return false` branch).
- **Empty string vs. null for `fare_media_name`**: Java's `hasFareMediaName()` returns `false` for both null and the empty-string sentinel. The Python implementation must treat both null and empty string as "absent".
- **Multiple rows, mixed types**: Each row is evaluated independently; each emits its own notice if applicable.

## 7. Implementation notes

### Validator type

Single-table (row-level) validator. Operates only on `fare_media.txt`. No cross-table joins required.

### Validator signature

```python
def validate_fare_media_name(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

### Skip logic

```python
if "fare_media" not in feed or feed["fare_media"].is_empty():
    return []
```

### Polars implementation strategy

The check is fully vectorizable. Build a boolean mask for rows that require a name but lack one, then iterate only over the (typically small) violation set to emit notices.

Recommended approach:

```python
df = feed["fare_media"]
# Types that require a name: TRANSIT_CARD=2, MOBILE_APP=4
requires_name = df["fare_media_type"].is_in([2, 4])
name_absent = df["fare_media_name"].is_null() | (df["fare_media_name"] == "")
violations = df.filter(requires_name & name_absent)
notices = [
    Notice(
        code="missing_recommended_field",
        severity=Severity.WARNING,
        fields={
            "filename": "fare_media.txt",
            "csv_row_number": row["csv_row_number"],
            "field_name": "fare_media_name",
        },
    )
    for row in violations.iter_rows(named=True)
]
return notices
```

The violation set is expected to be small (most feeds will have very few fare media rows), so iterating over it in Python after the Polars filter is acceptable.

### Notice codes (Python)

| Java notice class | Python notice code | Severity |
|---|---|---|
| `MissingRecommendedFieldNotice` | `missing_recommended_field` | WARNING |

`missing_recommended_field` is a generic notice shared across multiple validators. It should already be producible using the existing `Notice` dataclass in `notices.py` with `code="missing_recommended_field"` and `severity=Severity.WARNING`.

### Enum value representation in Python

The Python schema for `fare_media.txt` should store `fare_media_type` as an integer column after load-time casting. The validator compares against integer literals `2` (TRANSIT_CARD) and `4` (MOBILE_APP) directly, or against named constants if the Python schema defines them.

If `fare_media_type` fails enum validation at load time (unrecognized integer), the row may be excluded from the typed DataFrame or have a null `fare_media_type`. The validator should treat null `fare_media_type` as "not requiring a name" (consistent with Java's `default: return false`), which the `is_in([2, 4])` expression handles correctly since null never matches.

### Relationship to load-time validation

The following are handled at load time and must not be duplicated in this validator:

- `fare_media_id` presence and uniqueness (required field + primary key).
- `fare_media_type` is a valid enum value (domain/enum check).

This validator only adds the conditional recommendation check on `fare_media_name` that depends on the value of `fare_media_type`.
