# Analysis: PathwayStopAccessValidator

## 1. Purpose

Validates that no pathway links to a stop with `stop_access == 1` (NOT_ACCESSIBLE_VIA_PATHWAYS), since such stops are accessible from the street and are independent of the station's internal pathway network.

## 2. Input tables

| Table | Columns used |
|---|---|
| `stops.txt` | `stop_id`, `stop_access`, `platform_code` |
| `pathways.txt` | `csv_row_number`, `pathway_id`, `from_stop_id`, `to_stop_id` |

Both tables are required. The validator guards on `stop_access` column presence: if `stops.txt` is absent or does not include a `stop_access` column, the validator skips entirely.

## 3. Validation logic

### Step 1: Guard on `stop_access` column presence

The Java `shouldCallValidate()` returns `false` if `stopTable` is null or if the `stop_access` column is not present in the header. In Python this translates to: if `"stops"` is not in the feed dict, or if the `stops` DataFrame does not contain a `stop_access` column, return an empty notice list immediately.

### Step 2: Build the external-access stop map

Iterate over all rows in `stops.txt`. For each row where `stop_access` is non-null and equals `1` (NOT_ACCESSIBLE_VIA_PATHWAYS), add an entry to a lookup map:

```
external_access_stops: dict[str, str | None]
  key:   stop_id
  value: platform_code (may be null/None)
```

If no stops with `stop_access == 1` exist, return early with no notices.

### Step 3: Scan pathways for violations

For each row in `pathways.txt`:

1. Initialise a per-pathway set `emitted_stop_ids` (max 2 entries) to deduplicate notices within a single pathway.
2. Check `from_stop_id`:
   - If `from_stop_id` is non-null, non-blank, present in `external_access_stops`, and has not yet been emitted for this pathway, emit a notice using the pathway's `csv_row_number`, the stop's `platform_code`, the `pathway_id`, and `from_stop_id`. Add `from_stop_id` to `emitted_stop_ids`.
3. Check `to_stop_id`:
   - Same check as above using `to_stop_id`. If `to_stop_id == from_stop_id` and a notice was already emitted for that stop ID in this pathway, skip (the `emitted_stop_ids` set prevents a duplicate).

The `emitted_stop_ids` guard means that if a pathway somehow has the same `stop_id` as both `from_stop_id` and `to_stop_id`, only one notice is emitted.

## 4. Notices emitted

### `pathway_to_stop_with_access_outside_of_station_pathways` (ERROR)

Emitted when a pathway endpoint (`from_stop_id` or `to_stop_id`) refers to a stop that has `stop_access == 1`.

| Field | Type | Source | Description |
|---|---|---|---|
| `csvRowNumber` | integer | `pathways.csv_row_number` | Row number of the offending pathway record |
| `platformCode` | string or null | `stops.platform_code` of the referenced stop | Platform code of the stop with external access |
| `pathwayId` | string | `pathways.pathway_id` | ID of the offending pathway |
| `stopId` | string | `pathways.from_stop_id` or `to_stop_id` | The stop ID that has `stop_access == 1` |

Severity: ERROR.

Java class: `PathwayToStopWithAccessOutsideOfStationPathwaysNotice`.

Referenced files: `pathways.txt`, `stops.txt`.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `stops.txt` absent | Guard in `shouldCallValidate` returns false; no notices. |
| `stop_access` column absent from `stops.txt` header | Guard returns false; no notices. |
| `pathways.txt` absent or empty | No pathway rows to scan; no notices. |
| No stop has `stop_access == 1` | `external_access_stops` map is empty; early return; no notices. |
| `from_stop_id` is null or blank | Skipped (null/blank check before map lookup). |
| `to_stop_id` is null or blank | Skipped (same check). |
| `from_stop_id == to_stop_id` and the stop has `stop_access == 1` | Only one notice per pathway — `emitted_stop_ids` set prevents the second duplicate. |
| `stop_access` is null for a stop | Stop is not added to the external-access map; no notice for pathways referencing it. |
| `platform_code` is null for an external-access stop | Notice is emitted with `platformCode` field set to null. |
| A stop_id in `from_stop_id`/`to_stop_id` does not exist in `stops.txt` | Not present in the map; no notice (FK violation handled separately). |
| `stop_access == 0` (ACCESSIBLE_VIA_PATHWAYS) | Stop not added to map; no notice. |

## 6. Test contracts

### `toStopHasExternalAccess_yieldsNotice`

Setup:
- Stop 1: `stop_id="stop1"`, `stop_access=0` (ACCESSIBLE_VIA_PATHWAYS), `platform_code="platform1"`
- Stop 2: `stop_id="stop2"`, `stop_access=1` (NOT_ACCESSIBLE_VIA_PATHWAYS), `platform_code="platform2"`
- Pathway: `pathway_id="pathway12"`, `from_stop_id="stop1"`, `to_stop_id="stop2"`, `csv_row_number=12`

Expected: exactly 1 notice with `csvRowNumber=12`, `platformCode="platform2"`, `pathwayId="pathway12"`, `stopId="stop2"`.

Explanation: Only `to_stop_id` refers to an external-access stop; `from_stop_id` does not.

### `noStopsHaveExternalAccess_yieldNotice` (misleadingly named — actually expects no notices)

Setup:
- Stop 1: `stop_access=0`, Stop 2: `stop_access=0`
- Pathway linking stop1 → stop2

Expected: no notices. Neither stop has `stop_access == 1`, so the map is empty and the validator returns early.

## 7. Implementation notes

### Algorithm choice

The algorithm is naturally a two-phase lookup:
1. Build a Python dict from `stops` with `stop_access == 1`.
2. Iterate pathway rows and emit notices for matching stop IDs.

Both phases work well with Polars for filtering and column access. The per-pathway dedup set is a minor Python-level concern. Prefer Polars for the bulk filtering; do the per-row dedup in Python only if the same stop could appear as both endpoints (a rare edge case).

### Recommended Polars approach

```python
# Phase 1: build external-access stop map
external = (
    feed["stops"]
    .filter(pl.col("stop_access") == 1)
    .select(["stop_id", "platform_code"])
)
if external.is_empty():
    return []
external_map: dict[str, str | None] = dict(
    zip(external["stop_id"].to_list(), external["platform_code"].to_list())
)

# Phase 2: join pathways against external stops for from_stop_id
# and to_stop_id, union results, dedup within each pathway
```

For the dedup-within-pathway case (same stop as both endpoints), a simple join-union approach produces two rows for the same pathway + same stop_id; these should be deduplicated by `(csv_row_number, stop_id)` before emitting notices.

### Feed dict keys

- `"stops"` — `stops.txt`
- `"pathways"` — `pathways.txt`

### Required columns

From `stops.txt`: `stop_id`, `stop_access`, `platform_code`.

From `pathways.txt`: `csv_row_number`, `pathway_id`, `from_stop_id`, `to_stop_id`.

### Null semantics

- A stop with `stop_access` null is treated as not having external access — it must be explicitly `== 1`.
- `platform_code` may be null; pass it through as null in the notice.
- `from_stop_id` and `to_stop_id` null or empty string are skipped.

### `stop_access` enum values

| Name | Integer |
|---|---|
| ACCESSIBLE_VIA_PATHWAYS | 0 |
| NOT_ACCESSIBLE_VIA_PATHWAYS | 1 |

After loading, `stop_access` will be an integer column (or null). The trigger value is `1`.

### Notice code mapping

| Java class | Python notice code |
|---|---|
| `PathwayToStopWithAccessOutsideOfStationPathwaysNotice` | `pathway_to_stop_with_access_outside_of_station_pathways` |

### Validator registration

Requires tables: `["stops", "pathways"]`.

Soft guard: skip if `stops` DataFrame is missing or has no `stop_access` column.
