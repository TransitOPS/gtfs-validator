# Analysis: UrlConsistencyValidator

## 1. Purpose

Validates that `route_url` values in `routes.txt` and `stop_url` values in `stops.txt` do not duplicate any `agency_url` in `agency.txt`, and that `stop_url` values do not duplicate any `route_url` in `routes.txt`; URL comparisons are case-insensitive.

## 2. Input tables

| Source | Feed key | Columns used |
|---|---|---|
| `agency.txt` | `"agency"` | `agency_url`, `agency_name`, `csv_row_number` |
| `routes.txt` | `"routes"` | `route_id`, `route_url`, `csv_row_number` |
| `stops.txt` | `"stops"` | `stop_id`, `stop_url`, `csv_row_number` |

### Schema reference

`agency.txt`:

| Column | Type | Constraint |
|---|---|---|
| `agency_url` | string | Optional for lookup (agencies without a URL are excluded from the map) |
| `agency_name` | string | Reported in notices |
| `csv_row_number` | int | Internal tracking column |

`routes.txt`:

| Column | Type | Constraint |
|---|---|---|
| `route_id` | string | Required, Primary Key |
| `route_url` | string | Optional (routes without a URL are skipped) |
| `csv_row_number` | int | Internal tracking column |

`stops.txt`:

| Column | Type | Constraint |
|---|---|---|
| `stop_id` | string | Required, Primary Key |
| `stop_url` | string | Optional (stops without a URL are skipped) |
| `csv_row_number` | int | Internal tracking column |

## 3. Validation logic

### Overview

Three independent checks are performed:

1. For each route that has a `route_url`, emit a notice for every agency whose `agency_url` matches (case-insensitively).
2. For each stop that has a `stop_url`, emit a notice for every agency whose `agency_url` matches (case-insensitively).
3. For each stop that has a `stop_url`, emit a notice for every route whose `route_url` matches (case-insensitively).

### Step-by-step algorithm

```
# Build lookup maps (lowercase keys, multiple values per key via list-multimap)

agency_by_url = {}  # lowercase url -> list of agencies
for each agency in agency.txt:
    if agency.agency_url is not None:
        key = agency.agency_url.lower()
        agency_by_url.setdefault(key, []).append(agency)

route_by_url = {}  # lowercase url -> list of routes
for each route in routes.txt:
    if route.route_url is not None:
        key = route.route_url.lower()
        route_by_url.setdefault(key, []).append(route)

# Check 1: route_url vs agency_url
for each route in routes.txt:
    if route.route_url is None:
        continue
    key = route.route_url.lower()
    for each agency in agency_by_url.get(key, []):
        emit same_route_and_agency_url(route, agency)

# Check 2: stop_url vs agency_url
# Check 3: stop_url vs route_url
for each stop in stops.txt:
    if stop.stop_url is None:
        continue
    key = stop.stop_url.lower()
    for each agency in agency_by_url.get(key, []):
        emit same_stop_and_agency_url(stop, agency)
    for each route in route_by_url.get(key, []):
        emit same_stop_and_route_url(stop, route)
```

### Key observations

1. **Case-insensitive comparison**: All URL comparisons are performed after lowercasing both sides. The Java implementation uses `Ascii.toLowerCase()` from Guava, which performs ASCII-only lowercasing (not full Unicode). Python's `str.lower()` is equivalent for valid URLs (which are ASCII-constrained).
2. **One notice per matching pair**: If a route URL matches two agencies, two notices are emitted (one per agency). There is no deduplication.
3. **Null/absent URLs are skipped**: Rows without a URL value are not added to lookup maps and not iterated for comparison. Null entries never produce notices.
4. **No cross-route check**: The validator does not check whether two routes share the same `route_url`; that would be a separate concern. It only checks cross-table collisions.
5. **No agency-to-agency check**: Duplicate `agency_url` within `agency.txt` is not the responsibility of this validator.

## 5. Edge cases

- **`agency.txt` absent or empty**: The agency lookup map is empty. Checks 1 and 2 produce no notices; check 3 (stop vs route) still runs.
- **`routes.txt` absent or empty**: The route lookup map is empty. Check 1 produces no notices; check 3 produces no notices; check 2 (stop vs agency) still runs.
- **`stops.txt` absent or empty**: Checks 2 and 3 produce no notices; check 1 (route vs agency) still runs.
- **All three tables absent or empty**: No notices emitted; return `[]`.
- **`agency_url` is null**: That agency is not added to the lookup map and never generates a match.
- **`route_url` is null**: That route is skipped both when building the route lookup map and during check 1 iteration.
- **`stop_url` is null**: That stop is skipped entirely during checks 2 and 3.
- **Multiple agencies share the same `agency_url`**: All matching agencies are stored in the list-multimap. Each produces a separate notice when matched.
- **Multiple routes share the same `route_url`**: All are stored in the map. Each route is also iterated in check 1.
- **Case variation**: `"www.MobilityData.org"` and `"www.mobilitydata.org"` are treated as equal. The notice stores the original un-lowercased URL from the primary record (route or stop).
- **Route with null `route_url` and non-null `agency_url`**: No `same_route_and_agency_url` notice (null URL guard fires).
- **Agency with null `agency_url`**: Not in the map; never matched.

## 7. Implementation notes

### Validator type

Cross-table URL duplication check. Data volumes are moderate (agency is typically small, routes and stops are medium). A Polars join approach is natural and preferred over explicit Python loops.

### Validator signature

```python
def validate_url_consistency(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

### Implementation strategy

Two approaches are viable:

**Option A: Polars joins (preferred)**

```python
# Check 1: route_url vs agency_url
agency = feed.get("agency")
routes = feed.get("routes")
stops = feed.get("stops")

if agency is not None and routes is not None:
    agency_urls = (
        agency
        .filter(pl.col("agency_url").is_not_null())
        .with_columns(pl.col("agency_url").str.to_lowercase().alias("_url_key"))
    )
    route_urls = (
        routes
        .filter(pl.col("route_url").is_not_null())
        .with_columns(pl.col("route_url").str.to_lowercase().alias("_url_key"))
    )
    matches = route_urls.join(agency_urls, on="_url_key", how="inner")
    # iterate matches to emit notices

# Check 2 and 3 follow the same pattern with stops.
```

**Option B: Plain Python dicts**

Build `agency_by_url` and `route_by_url` maps (as the Java does), then iterate. This is simpler to read but slower for large tables. Acceptable given the small number of agencies.

### Case normalization

Use `str.lower()` for key computation. The Java uses `Ascii.toLowerCase()` which is equivalent for all valid URL characters (ASCII only). Do not store the lowercased value in the notice; store the original value from the primary record (the route or stop side, matching Java behavior for `routeUrl` and `stopUrl` fields).

### Notice field: `route_url` vs `stop_url`

The notices store the original URL from the left-side table (route or stop), not the normalized lowercase key. This preserves the exact string from the feed for user-facing reporting.

### Notice field: `agency_name`

Both `same_route_and_agency_url` and `same_stop_and_agency_url` include `agency_name` from the matching agency row. This field is required in `agency.txt`, so it should always be present after load-time validation.

### Notice codes (Python)

| Java notice class | Python notice code | Severity |
|---|---|---|
| `SameRouteAndAgencyUrlNotice` | `same_route_and_agency_url` | WARNING |
| `SameStopAndAgencyUrlNotice` | `same_stop_and_agency_url` | WARNING |
| `SameStopAndRouteUrlNotice` | `same_stop_and_route_url` | WARNING |

### Relationship to load-time validation

Load-time validation handles:
- Type checks and required fields for all three tables.
- `route_url`, `stop_url`, and `agency_url` URL format validation (if any).

This validator specifically handles cross-table URL collision, which cannot be expressed as a single-table constraint.

### Suggested file location

`src/gtfs_validator/validators/url_consistency.py`

### Validator registration

```python
ValidatorEntry(
    name="url_consistency",
    fn=validate_url_consistency,
    requires=[],  # handles absent tables internally
),
```

At least one of `agency`, `routes`, or `stops` must be present and have relevant URL fields for any notice to fire. The validator should handle all absent-table combinations gracefully without raising errors.
