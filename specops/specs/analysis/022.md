# Analysis: GeoJsonGeometryValidator

## 1. Purpose

Validates that Polygon and MultiPolygon geometries in `locations.geojson` are topologically valid according to the OGC Simple Features Specification (section 6.1.11), emitting an error notice for any polygon that is malformed, self-intersecting, or otherwise geometrically invalid.

## 2. Input tables

| Table | Columns / fields used |
|---|---|
| `locations.geojson` | Per-feature: `id`, `geometry.type`, `geometry.coordinates` |

### Data model

This is not a CSV table. The input is a GeoJSON `FeatureCollection` file parsed into individual `GtfsGeoJsonFeature` objects during load time. Each feature has:

- `featureId` (string) -- the `id` field of the GeoJSON feature
- `featureIndex` (int) -- the 0-based position of the feature in the `features` array
- `geometryType` (enum: `Polygon` | `MultiPolygon`)
- `coordinates` -- nested array of coordinate rings

### External dependencies

- **JTS Topology Suite** (Java): Used via `GeometryFactory` and `IsValidOp` to construct and validate polygon geometry. The Python equivalent is **Shapely**, which wraps the same underlying GEOS library.

## 3. Validation logic

### Context

`GeoJsonGeometryValidator` is a **utility class** (not a standalone validator registered in the validator registry). It is called from `GeoJsonFileLoader.extractFeature()` during the load phase, not during the cross-table validation phase. The loader calls `createPolygon()` or `createMultiPolygon()` depending on the feature's geometry type.

### Algorithm: `createPolygon(rings, feature, featureIndex)`

1. Parse the coordinate rings from the JSON array:
   - `rings[0]` is the exterior ring (shell).
   - `rings[1..n]` are interior rings (holes), if any.
   - Each ring is an array of `[longitude, latitude]` coordinate pairs.
2. Create a JTS `LinearRing` from the exterior ring coordinates.
3. If there are interior rings (`rings.length > 1`), create `LinearRing` objects for each.
4. Construct a JTS `Polygon` from the exterior ring and optional interior rings.
5. Validate the polygon using `IsValidOp.isValid(polygon)`:
   - If **invalid**: emit `invalid_geometry` notice with the JTS validation error message, return `null`.
   - If **valid**: return the polygon.
6. If an `IllegalArgumentException` is thrown during construction (e.g., ring has fewer than 4 points, ring is not closed): emit `invalid_geometry` notice with the exception message, return `null`.

### Algorithm: `createMultiPolygon(polygons, feature, featureIndex)`

1. For each polygon entry in the polygons array, call `createPolygon()`.
2. If any individual polygon is invalid (returns `null`), immediately return `null` for the entire MultiPolygon. The notice for the invalid sub-polygon was already emitted by `createPolygon()`.
3. Construct a JTS `MultiPolygon` from all the valid polygon objects.
4. Validate the MultiPolygon using `IsValidOp.isValid(multiPolygon)`:
   - If **invalid**: emit `invalid_geometry` notice, return `null`.
   - If **valid**: return the MultiPolygon.
5. If an `IllegalArgumentException` is thrown during construction: emit `invalid_geometry` notice, return `null`.

### JTS/GEOS validity rules (OGC SFA 6.1.11)

A polygon is valid if and only if:
- The exterior ring is closed (first point equals last point).
- The exterior ring has at least 4 coordinates (3 distinct points + closing point).
- The ring does not self-intersect.
- Interior rings (holes) are contained within the exterior ring.
- Interior rings do not cross each other.
- Interior rings may touch the exterior ring or each other at a single point but not along an edge.

A MultiPolygon is valid if:
- Each constituent polygon is valid.
- Polygons do not overlap (their interiors do not intersect).
- Polygons may touch at a finite number of points.

### What is NOT checked here

- Whether `locations.geojson` is present (handled by the loader framework).
- Whether required GeoJSON fields (`id`, `type`, `geometry`, `properties`) are present (handled by `GeoJsonFileLoader.extractFeature()`).
- Whether the geometry type is `Polygon` or `MultiPolygon` vs. unsupported types (handled by `GeoJsonFileLoader`; emits `unsupported_geometry_type` notice).
- Whether coordinates are near the origin or poles (handled by `GeoJsonFileLoader.validateCoordinates()`; emits `point_near_origin` / `point_near_pole` notices).
- Duplicate JSON keys, unknown elements, missing required elements (all handled by `GeoJsonFileLoader`).

## 4. Notices emitted

### `invalid_geometry`

Severity: **ERROR**

Emitted when a Polygon or MultiPolygon geometry fails JTS/GEOS topological validation or throws an exception during construction.

| Field | Type | Description |
|---|---|---|
| `featureId` | string | The `id` of the GeoJSON feature containing the invalid geometry |
| `featureIndex` | int | The 0-based index of the feature (or sub-polygon for MultiPolygon) in the collection |
| `geometryType` | string | `"Polygon"` or `"MultiPolygon"` |
| `message` | string | The validation error detail from JTS `IsValidOp` or the exception message |

#### Conditions that trigger this notice

- **Self-intersecting ring**: A ring crosses itself (e.g., a bowtie/figure-8 shape).
- **Too few points**: A ring has fewer than 4 coordinates (3 distinct + closing).
- **Ring not closed**: First and last coordinate of a ring differ.
- **Hole outside shell**: An interior ring extends beyond the exterior ring.
- **Nested holes**: Interior rings cross or overlap each other.
- **Overlapping polygons in MultiPolygon**: Two constituent polygons share interior area (not just touching at points).
- **Degenerate geometry**: A polygon collapses to a line or point.

## 5. Edge cases

- **`locations.geojson` absent**: The loader never instantiates `GeoJsonGeometryValidator`. No notices from this class.
- **Empty features array**: No features to validate. No calls to `createPolygon`/`createMultiPolygon`.
- **Polygon with only exterior ring (no holes)**: `createInteriorRings()` returns `null` when `polygonRings.length == 1`. The polygon is created with no interior rings.
- **Polygon with holes**: Interior rings are parsed from `rings[1..n]` and passed to the polygon constructor.
- **MultiPolygon with one invalid sub-polygon**: The first invalid sub-polygon emits a notice and causes the entire `createMultiPolygon()` to return `null` immediately, short-circuiting validation of remaining polygons.
- **MultiPolygon where individual polygons are valid but collectively invalid**: Each polygon passes `createPolygon()`, but the assembled MultiPolygon fails `IsValidOp` (e.g., overlapping polygons). A single `invalid_geometry` notice is emitted for the MultiPolygon.
- **`featureIndex` semantics for MultiPolygon**: When `createPolygon()` is called from within `createMultiPolygon()`, the `featureIndex` parameter is the sub-polygon index `p` (0-based within the MultiPolygon), NOT the feature index in the collection. This means the notice's `featureIndex` refers to the sub-polygon position.
- **IllegalArgumentException during construction**: Caught and converted to a notice rather than propagating. This handles cases like malformed coordinate arrays that JTS rejects before validation.

## 7. Implementation notes

### Validator type

This is a **load-time utility** rather than a post-load cross-table validator. In the Python architecture, GeoJSON geometry validation should be integrated into the GeoJSON loading/parsing phase.

### Implementation strategy: Plain Python with Shapely

This validator requires computational geometry (polygon construction and topological validation). It cannot be expressed as Polars tabular operations. Use **Shapely** (Python wrapper around GEOS, the same geometry engine underlying JTS) for direct equivalence.

```python
from shapely.geometry import Polygon, MultiPolygon
from shapely.validation import explain_validity
```

Shapely's `is_valid` property and `explain_validity()` function provide the same checks as JTS `IsValidOp`.

### Key Shapely equivalences

| Java (JTS) | Python (Shapely) |
|---|---|
| `geometryFactory.createLinearRing(coords)` | Implicit in `Polygon(shell, holes)` |
| `geometryFactory.createPolygon(shell, holes)` | `Polygon(shell_coords, [hole1_coords, ...])` |
| `geometryFactory.createMultiPolygon(polygons)` | `MultiPolygon([poly1, poly2, ...])` |
| `IsValidOp.isValid(geom)` | `geom.is_valid` |
| `IsValidOp(geom).getValidationError().getMessage()` | `explain_validity(geom)` |
| `IllegalArgumentException` on construction | `shapely.errors.GEOSException` or `ValueError` |

### Coordinate interpretation

GeoJSON coordinates are `[longitude, latitude]`. The validator passes them directly to JTS/GEOS as `(x, y)` where `x = longitude` and `y = latitude`. Shapely uses the same convention.

### Suggested integration point

Since this is a load-time utility, it should be called during GeoJSON file parsing in the loading module. If GeoJSON loading is implemented as a dedicated loader in `src/gtfs_validator/loading.py` or a separate `geojson.py` module, the geometry validation logic belongs there.

### Suggested helper function

```python
def validate_geojson_polygon(
    rings: list[list[list[float]]],
    feature_id: str,
    feature_index: int,
    geometry_type: str,
) -> tuple[Polygon | None, list[Notice]]:
    """Construct and validate a Polygon from GeoJSON coordinate rings.

    Returns the valid Polygon and an empty notice list, or None and
    a list containing an invalid_geometry notice.
    """
```

### Dependencies

- **Shapely** must be added to the project dependencies. It is a well-established Python geometry library with no heavy transitive dependencies (uses bundled GEOS).
