# Analysis: TripAndShapeDistanceValidator

## 1. Purpose

For each trip that has an associated shape, validates that the last stop time's `shape_dist_traveled` value does not exceed the maximum `shape_dist_traveled` of the shape's points; when it does, the severity is determined by the actual geographic distance between the last shape point and the last stop.

---

## 2. Input tables

| Table | Columns used |
|---|---|
| `trips.txt` | `trip_id`, `shape_id` |
| `stop_times.txt` | `trip_id`, `stop_id`, `stop_sequence`, `shape_dist_traveled` |
| `stops.txt` | `stop_id`, `stop_lat`, `stop_lon` |
| `shapes.txt` | `shape_id`, `shape_pt_lat`, `shape_pt_lon`, `shape_pt_sequence`, `shape_dist_traveled` |

### Column semantics

- `trips.shape_id` — optional string; links a trip to a shape. Trips without a shape_id are not skipped explicitly, but the shape lookup will return no rows and the validator will skip them.
- `stop_times.shape_dist_traveled` — optional float; cumulative distance from the start of the shape at this stop. Only the last stop time's value is used.
- `shapes.shape_dist_traveled` — optional float; cumulative distance along the shape at each point. The validator takes the max across all shape points for a given `shape_id`.
- `stops.stop_lat`, `stops.stop_lon` — geographic coordinates of the stop; used only to compute the geographic distance from the endpoint of the shape to the last stop's position.
- `shapes.shape_pt_lat`, `shapes.shape_pt_lon` — geographic coordinates of the shape point with the maximum `shape_dist_traveled`; used only for the geographic distance calculation.

---

## 3. Validation logic

For each trip in `trips.txt`:

### Step 1: Resolve the last stop time

```
stop_times_for_trip = stop_times WHERE trip_id == trip.trip_id
                      ORDER BY stop_sequence (implied by Java list ordering)
if stop_times_for_trip is empty:
    skip this trip   # no stop times at all
last_stop_time = stop_times_for_trip[-1]   # last element
```

### Step 2: Resolve the last stop's geographic position

```
stop = stops WHERE stop_id == last_stop_time.stop_id
if stop not found:
    skip this trip   # defensive guard; referential integrity checked elsewhere
```

### Step 3: Resolve the maximum shape distance

```
shape_points = shapes WHERE shape_id == trip.shape_id
max_shape_point = shape_points.max_by(shape_dist_traveled)
if max_shape_point not found (i.e., shape_id absent from shapes.txt):
    skip this trip
max_shape_dist = max_shape_point.shape_dist_traveled
if max_shape_dist == 0:
    skip this trip   # shape has no distance information; no meaningful comparison
```

### Step 4: Compare distances

```
max_stop_time_dist = last_stop_time.shape_dist_traveled

if max_stop_time_dist > max_shape_dist:
    geo_distance_meters = haversine_distance(
        (max_shape_point.shape_pt_lat, max_shape_point.shape_pt_lon),
        (stop.stop_lat, stop.stop_lon)
    )
    if geo_distance_meters > 11.1:
        emit TripDistanceExceedsShapeDistanceNotice (ERROR)
    else:
        emit TripDistanceExceedsShapeDistanceBelowThresholdNotice (WARNING)
```

### Distance calculation details

The Java implementation uses Google's S2 geometry library via `S2Earth.getDistanceMeters(S2LatLng, S2LatLng)`, which computes the great-circle distance using Earth's mean radius of 6,371,010 m. This is equivalent to the Haversine formula at this precision level. In Python, `math`-based Haversine or `geopy.distance.great_circle` with radius 6371010 m will reproduce this behavior. The threshold is a hard constant: **11.1 meters**.

## 4. Notices emitted

### `trip_distance_exceeds_shape_distance` (ERROR)

The last stop time's `shape_dist_traveled` is greater than the maximum `shape_dist_traveled` of any shape point AND the geographic distance between that last shape point and the last stop is greater than or equal to 11.1 m.

| Field | Type | Source | Description |
|---|---|---|---|
| `trip_id` | string | `trips.trip_id` | The trip that has the discrepancy |
| `shape_id` | string | `trips.shape_id` | The shape associated with this trip |
| `max_trip_distance_traveled` | float | `stop_times.shape_dist_traveled` (last stop) | The distance claimed by the last stop time |
| `max_shape_distance_traveled` | float | `shapes.shape_dist_traveled` (max per shape) | The maximum distance on record in the shape |
| `geo_distance_to_shape` | float | computed | Great-circle distance in meters between the last shape point and the last stop |

Severity: **ERROR**.

Conditions:
- Trip has at least one stop time.
- The last stop's `stop_id` resolves to a row in `stops.txt`.
- The trip's `shape_id` resolves to at least one row in `shapes.txt`.
- `max_shape_dist > 0`.
- `last_stop_time.shape_dist_traveled > max_shape_dist`.
- `geo_distance_meters > 11.1`.

---

### `trip_distance_exceeds_shape_distance_below_threshold` (WARNING)

The last stop time's `shape_dist_traveled` is greater than the maximum shape distance AND the geographic distance between the last shape point and the last stop is at most 11.1 m (the discrepancy is minor and may be a rounding artifact).

| Field | Type | Source | Description |
|---|---|---|---|
| `trip_id` | string | `trips.trip_id` | The trip that has the discrepancy |
| `shape_id` | string | `trips.shape_id` | The shape associated with this trip |
| `max_trip_distance_traveled` | float | `stop_times.shape_dist_traveled` (last stop) | The distance claimed by the last stop time |
| `max_shape_distance_traveled` | float | `shapes.shape_dist_traveled` (max per shape) | The maximum distance on record in the shape |
| `geo_distance_to_shape` | float | computed | Great-circle distance in meters between the last shape point and the last stop |

Severity: **WARNING**.

Conditions: identical to the ERROR case except `geo_distance_meters <= 11.1`.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `trips.txt` absent or empty | Validator is not invoked (runner guard) or returns `[]` immediately. |
| `shapes.txt` absent or empty | For every trip, the shape lookup returns no rows; all trips are skipped. Return `[]`. |
| `stop_times.txt` absent or empty | `stop_times_for_trip` is empty for every trip; all trips are skipped. Return `[]`. |
| Trip has `shape_id` that is absent from `shapes.txt` | `max_shape_point` lookup returns nothing; trip is skipped silently. |
| Trip has no `shape_id` (null) | Shape lookup on a null key returns no rows; trip is skipped silently. |
| Last stop time's `stop_id` not in `stops.txt` | Stop lookup returns nothing; trip is skipped silently (referential integrity is checked by FK validators elsewhere). |
| `max_shape_dist == 0` | Trip skipped — avoids divide-by-zero and false positives when shape has no distance data. |
| `max_stop_time_dist == 0` | Condition `max_stop_time_dist > max_shape_dist` is false if `max_shape_dist >= 0`; no notice emitted. |
| `shape_dist_traveled` is null/missing on last stop time | Java's `lastStopTime.shapeDistTraveled()` returns `0.0` by default when unset; comparison still runs with 0.0 vs max shape distance. No notice unless 0.0 > max_shape_dist (which cannot happen if max_shape_dist > 0). |
| `shape_dist_traveled` is null/missing on shape points | Java's default is 0.0; the max across shape points becomes 0.0; the `maxShapeDist == 0` guard fires and the trip is skipped. |
| Trip has exactly one stop time | That single stop time is treated as the "last" stop time. Logic proceeds normally. |
| Geographic distance exactly equal to 11.1 m | The condition is `distanceInMeters > DISTANCE_THRESHOLD`, so exactly 11.1 m falls into the WARNING path (below-threshold). |
| Multiple trips with the same shape_id | Each trip is evaluated independently. Both may emit notices if each trip's last stop time exceeds the shared shape's max distance. |
| `stop_times` rows for a trip are not sorted by `stop_sequence` in the feed | Java uses `stopTimeTable.byTripId(tripId)` which returns a list sorted by `stop_sequence` (implied by table container semantics). Python must sort by `stop_sequence` before selecting the last row. |

## 6. Test contracts

All three tests use the same helper pattern:
- `createTripTable(n)` creates n trips: `trip_id="t0".."t{n-1}"`, `shape_id="s0".."s{n-1}"`.
- `createStopTimesTable(n, base_dist)` creates n stop times with `trip_id="t0".."t{n-1}"`, `stop_id="st0".."st{n-1}"`, `shape_dist_traveled = base_dist + i`.
- `createShapeTable(n, base_dist, lonLat)` creates n shapes with `shape_id="s0".."s{n-1}"`, `shape_pt_lat=lonLat`, `shape_pt_lon=lonLat`, `shape_dist_traveled = base_dist + i`.
- `createStopTable(n)` creates n stops with `stop_id="st0".."st{n-1}"`, `stop_lat=0.0`, `stop_lon=0.0`.

### `testTripDistanceExceedsShapeDistance`

Setup:
- 2 trips (`t0`, `t1`), 1 stop time (`t0`, `shape_dist_traveled=10.0`), 1 shape (`s0`, `shape_dist_traveled=9.0`, `lat/lon=10.0`), 1 stop (`st0`, `lat/lon=0.0`).
- For trip `t0`: `max_stop_time_dist=10.0 > max_shape_dist=9.0`. Geographic distance between shape point `(10.0, 10.0)` and stop `(0.0, 0.0)` ≈ 1,571 km, well above 11.1 m threshold.
- Trip `t1` has no stop times (stop time list has only 1 row for `t0`).

Expected: at least one `TripDistanceExceedsShapeDistanceNotice` (ERROR) is found. Confirms the ERROR path fires when geo distance is large.

### `testTripDistanceExceedsShapeDistanceNoShapeDistance`

Setup:
- Same as above but shape `shape_dist_traveled=0.0` (so `base_dist + 0 = 0.0`).
- `max_shape_dist == 0` guard fires.

Expected: no `TripDistanceExceedsShapeDistanceNotice`. Confirms the zero-shape-distance guard silences the validator.

### `testTripDistanceExceedsShapeDistanceWarning`

Setup:
- 2 trips, 1 stop time (`t0`, `shape_dist_traveled=10.0`), 1 shape (`s0`, `shape_dist_traveled=9.0`, `lat/lon=0.000001`), 1 stop (`st0`, `lat/lon=0.0`).
- `max_stop_time_dist=10.0 > max_shape_dist=9.0`. Geographic distance between shape point `(0.000001, 0.000001)` and stop `(0.0, 0.0)` ≈ 0.16 m, below 11.1 m threshold.

Expected: at least one `TripDistanceExceedsShapeDistanceBelowThresholdNotice` (WARNING) is found. Confirms the WARNING path fires when geo distance is tiny (rounding artifact scenario).

### What is NOT covered by the Java test suite

- `trips.txt` absent or empty.
- `shapes.txt` absent or empty.
- `stop_times.txt` absent or empty.
- Trip with no `shape_id` (null shape_id).
- Last stop's `stop_id` not present in `stops.txt`.
- `shape_dist_traveled` null on shape or stop time rows.
- Multiple trips all producing notices in one run.
- Geographic distance exactly equal to 11.1 m (boundary condition).
- Trip has more than one stop time (multi-stop-time ordering correctness).

## 7. Implementation notes

### Algorithm strategy

The validator is trip-centric: iterate over every trip, skip on any missing dependency (stop times, stop, shape, max shape dist), compute whether the last stop time's distance exceeds the shape's extent, then branch on geographic distance. This is a cross-table join that is most naturally expressed in Polars as a series of joins followed by a per-trip computation.

**Recommended Polars approach:**

1. Compute `max_shape_dist` and the corresponding `(shape_pt_lat, shape_pt_lon)` per `shape_id` from `shapes.txt` — use `group_by("shape_id").agg(pl.max("shape_dist_traveled"), ... )`. Because we need the lat/lon of the max-distance point (not just the max value), use `sort("shape_dist_traveled", descending=True).group_by("shape_id").first()` to get the full row of the max-distance point per shape.

2. Compute `last_stop_time` per `trip_id` from `stop_times.txt` — use `sort("stop_sequence").group_by("trip_id").last()` to get the final stop time row per trip (including `stop_id` and `shape_dist_traveled`).

3. Join `trips` → `last_stop_time` on `trip_id`. Drop trips with no stop time (inner join or left join + drop nulls).

4. Join result → `stops` on `stop_id`. Drop rows where stop not found.

5. Join result → `max_shape_row` on `shape_id`. Drop rows where shape not found.

6. Filter: `max_shape_dist > 0` AND `last_stop_time.shape_dist_traveled > max_shape_dist`.

7. For remaining rows, compute geographic distance in Python using a UDF or `.map_elements()`. Since this is only called for rows that have already violated the numeric threshold, the list will typically be small — plain Python element-wise iteration over the filtered result is acceptable here.

8. Branch rows by `geo_distance_meters > 11.1` and emit the appropriate notice for each row.

### Geographic distance

The Java implementation uses `S2Earth.getDistanceMeters(S2LatLng a, S2LatLng b)` which computes:

```
great_circle_angle = a.getDistance(b)   # S1Angle in radians
distance_meters = angle_radians * 6_371_010.0
```

This is the standard spherical great-circle formula (Haversine). In Python:

```python
import math

EARTH_RADIUS_METERS = 6_371_010.0

def haversine_meters(lat1: float, lon1: float, lat2: float, lon2: float) -> float:
    phi1, phi2 = math.radians(lat1), math.radians(lat2)
    dphi = math.radians(lat2 - lat1)
    dlam = math.radians(lon2 - lon1)
    a = math.sin(dphi / 2) ** 2 + math.cos(phi1) * math.cos(phi2) * math.sin(dlam / 2) ** 2
    return 2 * math.asin(math.sqrt(a)) * EARTH_RADIUS_METERS
```

This matches the S2 library's mean Earth radius exactly.

### Stop time ordering

Java's `stopTimeTable.byTripId(tripId)` returns a list already sorted by `stop_sequence`. In Polars, always sort `stop_times` by `stop_sequence` before taking the last row per trip to ensure correctness:

```python
stop_times.sort("stop_sequence").group_by("trip_id").last()
```

### Threshold constant

`DISTANCE_THRESHOLD = 11.1` meters. The comparison is **strictly greater than** (`>`), meaning a geo distance of exactly 11.1 m falls into the WARNING (below-threshold) path.

### Null handling for `shape_dist_traveled`

- If `shape_dist_traveled` is null on a stop time row, treat it as `0.0` (matching Java's default getter behavior). A trip with a null last stop time distance will always satisfy `0 <= max_shape_dist` when `max_shape_dist > 0`, so no notice is emitted.
- If all `shape_dist_traveled` values for a shape are null, the max will be null. Treat null max shape distance as 0 (or filter it out the same way as `max_shape_dist == 0`), causing the trip to be skipped.

### Guard clauses

```python
def validate_trip_and_shape_distance(
    feed: dict[str, pl.DataFrame], ctx: ValidationContext
) -> list[Notice]:
    if "trips" not in feed or "stop_times" not in feed:
        return []
    if "shapes" not in feed or "stops" not in feed:
        return []
    trips = feed["trips"]
    stop_times = feed["stop_times"]
    shapes = feed["shapes"]
    stops = feed["stops"]
    if trips.is_empty() or stop_times.is_empty() or shapes.is_empty():
        return []
```

### Polars vs plain Python

| Operation | Approach |
|---|---|
| Max shape distance + coordinates per `shape_id` | Polars: `sort + group_by + first()` |
| Last stop time per `trip_id` | Polars: `sort + group_by + last()` |
| Cross-table joins (trips × stop_times × stops × shapes) | Polars joins (inner or left + filter nulls) |
| Numeric threshold filter (`shape_dist_traveled > max_shape_dist`) | Polars filter expression |
| Geographic distance calculation | Plain Python `haversine_meters()` called via `.map_elements()` or iterating the small filtered result |
| Notice branching (ERROR vs WARNING) | Plain Python loop over the filtered result rows |

### Required tables for registry

Primary tables: `["trips", "stop_times", "stops", "shapes"]`. All four must be present; if any is missing, return `[]`. No feature flag or special context dependency required.

### Known behavioral subtlety

The Java code retrieves the last stop time using `stopTimeTable.byTripId(tripId).get(nbStopTimes - 1)` where the list is already ordered by `stop_sequence`. The stop for that last stop time is then looked up to get its geographic position. The geographic distance check uses the actual latitude/longitude of the last stop (not a `shape_dist_traveled` position on the shape). This means the geographic distance is between the last shape point (by distance value) and the actual GPS location of the last stop — a cross-domain comparison intended to detect whether the discrepancy is due to a rounding error (tiny geo distance) or a real data error (large geo distance).
