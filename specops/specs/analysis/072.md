# Analysis: TransferDistanceValidator

## 1. Purpose

Validates that the geographic distance between the `from_stop_id` and
`to_stop_id` of each transfer is not unreasonably large, emitting an INFO
notice above 2 km and a WARNING notice above 10 km.

## 2. Input tables

| Table | Columns used |
|---|---|
| `transfers.txt` | `from_stop_id`, `to_stop_id`, `csv_row_number` |
| `stops.txt` | `stop_id`, `stop_lat`, `stop_lon`, `parent_station` |

### Column semantics

- `from_stop_id` — optional string; foreign key into `stops.stop_id`. The
  validator only processes a transfer row if both `from_stop_id` and
  `to_stop_id` are non-null.
- `to_stop_id` — optional string; foreign key into `stops.stop_id`.
- `stop_lat` / `stop_lon` — the geographic coordinates of a stop. May be
  absent on child stops (e.g. entrance or boarding-area nodes) that inherit
  location from their `parent_station`.
- `parent_station` — optional string; when a stop has no coordinates, the
  validator walks up the parent chain (up to 3 levels) to find coordinates.
- `csv_row_number` — row number from `transfers.txt`; carried into notices.

## 3. Validation logic

The validator iterates every row of `transfers.txt`. For each row where both
`from_stop_id` and `to_stop_id` are non-null, it computes the great-circle
distance between the two stops and applies two threshold checks.

### Guard — both stop IDs must be present

```
for each transfer in transfers:
    if transfer.from_stop_id IS NULL or transfer.to_stop_id IS NULL:
        skip row
```

Rows where either stop ID is null are silently skipped.

### Coordinate resolution — `getStopOrParentLatLng`

Before computing the distance, each stop ID is resolved to a latitude/longitude
pair via `StopUtil.getStopOrParentLatLng`. The resolution algorithm:

```
function resolve_latlng(stop_id):
    for i in range(3):          # max 3 levels to avoid infinite parent cycles
        stop = stops_table.by_stop_id(stop_id)
        if stop is None:
            return (0.0, 0.0)   # S2LatLng.CENTER fallback
        if stop has stop_lat AND stop_lon:
            return (stop.stop_lat, stop.stop_lon)
        if stop has parent_station:
            stop_id = stop.parent_station
        else:
            break
    return (0.0, 0.0)           # S2LatLng.CENTER fallback
```

Key behaviors:
- The parent chain is walked at most 3 times (supports: boarding area →
  stop → station).
- If the stop is not found in the stops table, `(0.0, 0.0)` is returned
  (the geographic center of the S2 sphere, i.e. coordinates on the equator at
  the prime meridian).
- If no coordinates are found anywhere in the parent chain, `(0.0, 0.0)` is
  returned. This means an unresolvable stop silently produces a spurious
  distance computation from `(0, 0)` rather than being skipped. The Java code
  has a TODO comment acknowledging this is a known bug.

### Distance computation — S2Earth great-circle distance

The Java implementation uses the S2 geometry library's great-circle distance:

```
distance_meters = arc_angle_radians(from_point, to_point) * EARTH_RADIUS_METERS
EARTH_RADIUS_METERS = 6_371_010.0
```

This is mathematically equivalent to the haversine formula using Earth radius
`6_371_010.0` metres (the S2Earth mean radius, distinct from the commonly used
`6_371_000.0`).

### Check 1 — Distance above 10 km (WARNING)

```
if distance_meters > 10_000:
    emit TransferDistanceTooLargeNotice(transfer, distance_km=distance_meters / 1_000)
```

The threshold is strict greater-than. Exactly 10,000 m does not trigger this
notice.

### Check 2 — Distance above 2 km (INFO)

```
else if distance_meters > 2_000:
    emit TransferDistanceAbove_2KmNotice(transfer, distance_km=distance_meters / 1_000)
```

This is an `else if`: only one notice is emitted per transfer row. A distance
above 10 km emits only the WARNING; the INFO is not additionally emitted for
the same row.

### shouldCallValidate guard

The validator's `shouldCallValidate` method returns `false` (skipping all
validation) if:
- `transfers.txt` is absent or its table container is null, OR
- `stops.txt` is absent or its table container is null, OR
- `transfers.txt` does not have a `from_stop_id` column in its header, OR
- `transfers.txt` does not have a `to_stop_id` column in its header.

In the Python implementation this maps to: return `[]` immediately if
`"transfers"` or `"stops"` is absent from the feed dict, or if
`"from_stop_id"` or `"to_stop_id"` is not in the `transfers` DataFrame
columns.

## 4. Notices emitted

### `transfer_distance_too_large` (WARNING)

Emitted when the computed distance between the two stops exceeds 10 km.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | int | `transfers.csv_row_number` | Row number of the offending transfer |
| `from_stop_id` | string | `transfers.from_stop_id` | ID of the origin stop |
| `to_stop_id` | string | `transfers.to_stop_id` | ID of the destination stop |
| `distance_km` | float | computed | Distance in kilometres (meters / 1000) |

Severity: WARNING.

Condition: `distance_meters > 10_000`.

At most one notice per transfer row (mutually exclusive with
`transfer_distance_above_2_km`).

### `transfer_distance_above_2_km` (INFO)

Emitted when the computed distance between the two stops exceeds 2 km but
does not exceed 10 km.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | int | `transfers.csv_row_number` | Row number of the offending transfer |
| `from_stop_id` | string | `transfers.from_stop_id` | ID of the origin stop |
| `to_stop_id` | string | `transfers.to_stop_id` | ID of the destination stop |
| `distance_km` | float | computed | Distance in kilometres (meters / 1000) |

Severity: INFO.

Condition: `distance_meters > 2_000 AND distance_meters <= 10_000`.

At most one notice per transfer row (mutually exclusive with
`transfer_distance_too_large`).

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `transfers.txt` absent from feed | Return `[]` immediately (guard). |
| `stops.txt` absent from feed | Return `[]` immediately (guard). |
| `transfers.txt` has no `from_stop_id` column | Return `[]` immediately (guard). |
| `transfers.txt` has no `to_stop_id` column | Return `[]` immediately (guard). |
| `transfers.txt` present but empty (zero rows) | Return `[]` (no rows to iterate). |
| Transfer row missing `from_stop_id` (null) | Row is skipped; no notice. |
| Transfer row missing `to_stop_id` (null) | Row is skipped; no notice. |
| `from_stop_id` not found in stops table | Coordinates resolve to `(0.0, 0.0)`; distance computed from origin, may produce spurious notice. |
| Stop has no coordinates but has `parent_station` | Walk parent chain up to 3 levels; use first ancestor with coordinates. |
| Parent chain longer than 3 levels | Stop beyond 3 hops is treated as having no coordinates; falls back to `(0.0, 0.0)`. |
| Stop coordinates found but stop has parent cycle | Loop terminates after at most 3 iterations; uses `(0.0, 0.0)` if cycle prevents coordinate resolution. |
| Distance exactly 2,000 m | No notice (condition is strict greater-than). |
| Distance exactly 10,000 m | No notice (condition is strict greater-than). |
| Distance > 10,000 m | One `transfer_distance_too_large` WARNING only; INFO not additionally emitted. |
| Distance between 2,001 m and 10,000 m | One `transfer_distance_above_2_km` INFO only. |
| Distance <= 2,000 m | No notice. |
| Both stops at same location | Distance = 0; no notice. |
| Transfer is self-referential (`from_stop_id == to_stop_id`) | Distance = 0; no notice (this validator does not check self-transfers). |

## 6. Test contracts

The Java test file contains three test methods.

### `testDistanceAbove10KmGeneratesWarning`

- Two stops: `s0` at `(0.0, 0.0)` and `s1` at `(0.0, 0.1)`.
- Transfer: row 1, `from_stop_id="s0"`, `to_stop_id="s1"`.
- Expected: exactly one `TransferDistanceTooLargeNotice` with
  `distance_km = 11.119510117748394`.
- This confirms the exact Earth radius and distance formula used:
  at the equator, 0.1° of longitude ≈ 11.12 km using radius 6,371,010 m.

### `testDistanceAbove2KmGeneratesNotice`

- Two stops: `s0` at `(0.0, 0.0)` and `s1` at `(0.0, 0.02)`.
- Transfer: row 1, `from_stop_id="s0"`, `to_stop_id="s1"`.
- Expected: exactly one `TransferDistanceAbove_2KmNotice` with
  `distance_km = 2.2239020235496785`.
- Confirms the INFO notice and the 2 km threshold.

### `testDistanceBellow2KmYieldsNoNotice`

- Two stops: `s0` at `(0.0, 0.0)` and `s1` at `(0.0, 0.01)`.
- Transfer: row 1, `from_stop_id="s0"`, `to_stop_id="s1"`.
- Expected: no notices.
- Confirms the clean pass for short-distance transfers.

### What is NOT covered by the Java test suite

- Missing `from_stop_id` or `to_stop_id` (null guard behavior).
- `transfers.txt` or `stops.txt` absent from feed.
- Stop ID not found in stops table (fallback to `(0.0, 0.0)`).
- Stop with coordinates missing but parent with coordinates present.
- Parent chain traversal (multiple levels of indirection).
- Transfer with distance exactly at the 2,000 m or 10,000 m threshold.
- Feed with multiple transfer rows producing mixed notices.

## 7. Implementation notes

### Algorithm strategy

The Java validator is a row-by-row `FileValidator`. The Python implementation
should:

1. Apply header-column and table-presence guards up front.
2. Build a coordinate resolution lookup from `stops.txt` (considering parent
   chains) before iterating transfers.
3. Iterate the transfers DataFrame rows in Python to apply the parent-chain
   resolution per stop ID, compute the distance, and bucket into the
   appropriate notice.

Using plain Python for the inner loop is appropriate here because:
- The distance computation requires per-row parent-chain lookups that are
  not naturally vectorized.
- The coordinate resolution logic is graph traversal (up to 3 hops), which
  is cleaner as plain Python than forced into Polars expressions.
- Transfer tables are small in practice.

### Earth radius

Use `EARTH_RADIUS_METERS = 6_371_010.0` (the S2Earth value). Do NOT use
`6_371_000.0` or `6_371.0 * 1000`. The test contracts lock in distance values
computed with `6_371_010.0`; using a different radius will produce incorrect
`distance_km` values in notices.

The `shape_increasing_distance.py` module already defines this constant
correctly as `EARTH_RADIUS_METERS = 6_371_010.0`. Reuse or import it rather
than duplicating.

### Coordinate resolution helper

The Python equivalent of `StopUtil.getStopOrParentLatLng` should be a
standalone helper function:

```python
def resolve_stop_latlng(
    stop_id: str,
    stops_index: dict[str, tuple[float | None, float | None, str | None]],
) -> tuple[float, float]:
    """
    Resolve a stop_id to (lat, lon) by walking the parent_station chain.
    Returns (0.0, 0.0) if no coordinates are found (matching Java fallback).
    stops_index maps stop_id -> (stop_lat, stop_lon, parent_station).
    """
    for _ in range(3):
        entry = stops_index.get(stop_id)
        if entry is None:
            return (0.0, 0.0)
        lat, lon, parent = entry
        if lat is not None and lon is not None:
            return (lat, lon)
        if parent is not None:
            stop_id = parent
        else:
            break
    return (0.0, 0.0)
```

Build `stops_index` once before the transfer loop from the `stops` DataFrame
using `.to_dicts()` or `.iter_rows(named=True)`.

### Distance function

Use the haversine formula with `EARTH_RADIUS_METERS = 6_371_010.0`. The
existing `_geodesic_distance_meters` function in
`src/gtfs_validator/validators/shape_increasing_distance.py` is correct
and can serve as a reference or be extracted to a shared utility module.

```python
import math

EARTH_RADIUS_METERS: float = 6_371_010.0

def haversine_meters(lat1: float, lon1: float, lat2: float, lon2: float) -> float:
    phi1, phi2 = math.radians(lat1), math.radians(lat2)
    dphi = math.radians(lat2 - lat1)
    dlambda = math.radians(lon2 - lon1)
    a = math.sin(dphi / 2) ** 2 + math.cos(phi1) * math.cos(phi2) * math.sin(dlambda / 2) ** 2
    return 2 * math.atan2(math.sqrt(a), math.sqrt(max(0.0, 1.0 - a))) * EARTH_RADIUS_METERS
```

### Recommended Polars + Python approach

```python
def validate_transfer_distance(
    feed: dict[str, pl.DataFrame], ctx: ValidationContext
) -> list[Notice]:
    if "transfers" not in feed or "stops" not in feed:
        return []

    transfers = feed["transfers"]
    stops = feed["stops"]

    if "from_stop_id" not in transfers.columns or "to_stop_id" not in transfers.columns:
        return []

    if transfers.is_empty():
        return []

    # Build stop coordinate + parent index once
    stops_index: dict[str, tuple[float | None, float | None, str | None]] = {}
    for row in stops.select(["stop_id", "stop_lat", "stop_lon", "parent_station"]).iter_rows(named=True):
        stops_index[row["stop_id"]] = (row["stop_lat"], row["stop_lon"], row.get("parent_station"))

    notices: list[Notice] = []

    for row in transfers.iter_rows(named=True):
        from_stop_id = row["from_stop_id"]
        to_stop_id = row["to_stop_id"]

        if from_stop_id is None or to_stop_id is None:
            continue

        from_lat, from_lon = resolve_stop_latlng(from_stop_id, stops_index)
        to_lat, to_lon = resolve_stop_latlng(to_stop_id, stops_index)

        distance_m = haversine_meters(from_lat, from_lon, to_lat, to_lon)

        if distance_m > 10_000:
            notices.append(
                TransferDistanceTooLargeNotice(
                    csv_row_number=row["csv_row_number"],
                    from_stop_id=from_stop_id,
                    to_stop_id=to_stop_id,
                    distance_km=distance_m / 1_000,
                )
            )
        elif distance_m > 2_000:
            notices.append(
                TransferDistanceAbove2KmNotice(
                    csv_row_number=row["csv_row_number"],
                    from_stop_id=from_stop_id,
                    to_stop_id=to_stop_id,
                    distance_km=distance_m / 1_000,
                )
            )

    return notices
```

### Feed dict keys

- `"transfers"` — `transfers.txt`
- `"stops"` — `stops.txt`

### Validator registration

Required tables: `["transfers", "stops"]`. The validator self-guards on both
table presence and the `from_stop_id` / `to_stop_id` column presence.

Feature flag: none.

### Cross-table join

This validator requires a lookup from `stops.txt` by `stop_id`. Build a plain
Python dict index from the stops DataFrame rather than doing a Polars join,
because the coordinate-resolution logic involves up to 3 levels of parent
traversal that cannot be cleanly expressed as a single Polars join.

### Notice code naming

The Java notice `TransferDistanceAbove_2KmNotice` maps to code
`transfer_distance_above_2_km` (the underscore before `2` is converted to
standard snake_case). Verify this matches the existing notice registry before
implementing.

### Known Java limitation (do not fix)

The Java `getStopOrParentLatLng` falls back to `S2LatLng.CENTER` (lat=0,
lon=0) when a stop ID is missing from the table. The Python implementation
must replicate this behavior exactly (return `(0.0, 0.0)`) so that notices
produced for feeds with missing stop references are behaviorally equivalent.
The Java source has a `TODO` comment noting this can cause bugs; do not
"fix" it in the Python port — the spec requires behavioral equivalence.
