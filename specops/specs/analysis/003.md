# Analysis: BidirectionalExitGateValidator

## 1. Purpose

Validates that exit gates (`pathway_mode=7`) in `pathways.txt` are not marked as bidirectional (`is_bidirectional=1`).

## 2. Input tables

| Table | Columns used |
|---|---|
| `pathways.txt` | `pathway_mode`, `is_bidirectional` |

Only the `pathways` table is read. No cross-table joins are needed.

## 3. Validation logic

This is a single-entity (row-level) validator. For each row in `pathways.txt`:

1. Check if `pathway_mode` equals `7` (EXIT_GATE).
2. Check if `is_bidirectional` equals `1` (BIDIRECTIONAL).
3. If **both** conditions are true, emit a `BidirectionalExitGateNotice`.

No guard clause or header check is needed beyond the standard requirement that both `pathway_mode` and `is_bidirectional` are required fields in the schema (enforced at load time).

### Relevant enums

**`pathway_mode`**:
| Value | Name |
|---|---|
| 1 | WALKWAY |
| 2 | STAIRS |
| 3 | MOVING_SIDEWALK |
| 4 | ESCALATOR |
| 5 | ELEVATOR |
| 6 | FARE_GATE |
| 7 | EXIT_GATE |

**`is_bidirectional`**:
| Value | Name |
|---|---|
| 0 | UNIDIRECTIONAL |
| 1 | BIDIRECTIONAL |

## 4. Notices emitted

### `bidirectional_exit_gate`

- **Severity**: ERROR
- **Condition**: A row in `pathways.txt` where `pathway_mode == 7` AND `is_bidirectional == 1`.
- **Fields**:
  | Field | Type | Description |
  |---|---|---|
  | `csv_row_number` | int | The 1-based row number of the faulty record |
  | `pathway_mode` | int | The pathway mode value (always 7 when this notice fires) |
  | `is_bidirectional` | int | The is_bidirectional value (always 1 when this notice fires) |

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `pathways.txt` is missing from feed | Validator is never called; no notices emitted |
| `pathways.txt` is empty (no data rows) | No rows to iterate; no notices emitted |
| `pathway_mode` is 7 but `is_bidirectional` is 0 | No notice (exit gate is unidirectional, which is valid) |
| `pathway_mode` is not 7 and `is_bidirectional` is 1 | No notice (bidirectional is fine for non-exit-gate pathways) |
| `pathway_mode` or `is_bidirectional` is null/missing | Both fields are required; load-time validation catches missing values before this validator runs |

## 6. Test contracts

### `isBidirectionalExitGateShouldGenerateNotice`
- **Input**: pathway_mode=7, is_bidirectional=BIDIRECTIONAL (1), csvRowNumber=1
- **Expected**: Exactly one `BidirectionalExitGateNotice` is emitted.

### `isNotBidirectionalExitGateShouldNotGenerateNotice`
- **Input**: pathway_mode=7, is_bidirectional=UNIDIRECTIONAL (0), csvRowNumber=1
- **Expected**: No notices emitted.

## 7. Implementation notes

### Polars vs plain Python

This is a straightforward vectorized filter: select rows where `pathway_mode == 7` AND `is_bidirectional == 1`. A single Polars `filter` expression is ideal:

```python
violations = pathways.filter(
    (pl.col("pathway_mode") == 7) & (pl.col("is_bidirectional") == 1)
)
```

Then iterate the (typically tiny) result to emit notices. No graph, geometry, or interval logic is needed.

### Utility dependencies

None. This validator uses no shared utility classes beyond the standard notice and context types.

### Notice code derivation

The Java class `BidirectionalExitGateNotice` maps to snake_case notice code `bidirectional_exit_gate`.
