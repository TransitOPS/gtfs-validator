# Analysis: MatchingFeedAndAgencyLangValidator

## 1. Purpose

Validates that `agency.agency_lang` values in `agency.txt` match `feed_info.feed_lang` in `feed_info.txt`, with a special exemption when `feed_lang` is `mul` (multilingual).

## 2. Input tables

| Table | Columns used |
|---|---|
| `feed_info.txt` | `feed_lang` |
| `agency.txt` | `agency_id`, `agency_name`, `agency_lang`, `csvRowNumber` |

### Key relationships

- `feed_info.txt` is expected to contain at most one row (singleton entity).
- `agency.txt` may contain multiple rows.
- `agency_lang` is optional; agencies without it are skipped.
- `feed_lang` is a BCP-47 language tag; the special value `mul` (ISO 639-2 for "multiple languages") exempts the feed from this check entirely.

## 3. Validation logic

1. **Guard: no feed_info rows** -- If `feed_info.txt` is missing or has zero rows, skip validation entirely. No notices.
2. **Guard: feed_lang not set** -- If the single `feed_info` row has no `feed_lang` value (null/empty), skip validation. No notices.
3. **Guard: feed_lang is `mul`** -- If `feed_lang` equals `mul`, skip validation. A multilingual feed may legitimately have agencies with different languages. No notices.
4. **For each agency row**:
   a. If `agency_lang` is not set (null/empty), skip this agency. No notice.
   b. If `agency_lang` differs from `feed_lang`, emit `feed_info_lang_and_agency_lang_mismatch` (WARNING).

### Language comparison

The Java code uses `java.util.Locale` for comparison. This means language tags are parsed and compared structurally (e.g., `fr-FR` does not equal `fr-CA` even though both are French). The comparison is locale-aware, not plain string equality. In Python, the simplest equivalent is case-insensitive string comparison of the normalized BCP-47 tags (lowercased), since the loading layer should already produce well-formed tags.

## 4. Notices emitted

### `feed_info_lang_and_agency_lang_mismatch` (WARNING)

Files `agency.txt` and `feed_info.txt` define mismatching `agency.agency_lang` and `feed_info.feed_lang`. When `feed_lang` is not `mul`, all agencies with a specified `agency_lang` should match `feed_lang`.

| Field | Type | Description |
|---|---|---|
| `csvRowNumber` | int | Row number of the agency record |
| `agencyId` | string | The `agency_id` of the mismatched agency |
| `agencyName` | string | The `agency_name` of the mismatched agency |
| `agencyLang` | string | The `agency_lang` value (BCP-47 tag) |
| `feedLang` | string | The `feed_lang` value (BCP-47 tag) |

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `feed_info.txt` missing or empty | No notices (early return) |
| `feed_lang` is null/empty | No notices (early return) |
| `feed_lang` is `mul` | No notices (early return, any mix of agency languages allowed) |
| `feed_lang` is `mul` with a single agency | No notices (still valid) |
| `agency_lang` is null/empty on some agencies | Those agencies are skipped; no notice for them |
| `agency_lang` matches `feed_lang` exactly | No notice |
| `agency_lang` is a regional variant (e.g., `fr-CA`) and `feed_lang` is a different variant (e.g., `fr-FR`) | WARNING emitted -- they are distinct locales |
| Multiple agencies, some matching and some not | One notice per mismatched agency |
| `agency.txt` is empty | No notices (no agencies to iterate) |

## 6. Test contracts

### `noFeedInfoShouldNotGenerateNotice`
- **Setup**: Both agency and feed_info tables are empty.
- **Expected**: No notices.

### `noFeedLangShouldNotGenerateNotice`
- **Setup**: Two agencies with `agency_lang` set (English, France), feed_info row with `feed_lang=null`.
- **Expected**: No notices. When feed_lang is unset, no comparison is made.

### `languageMismatch`
- **Setup**: Three agencies -- `fr-CA` (row 2), `fr-FR` (row 3), and one with null `agency_lang` (row 4). Feed lang is `fr-FR`.
- **Expected**: Exactly one notice for the `fr-CA` agency (row 2): `FeedInfoLangAndAgencyLangMismatchNotice(csvRowNumber=2, agencyId="agencyCa", agencyName="agencyCa name", agencyLang="fr-CA", feedLang="fr-FR")`.
- **Key point**: The `fr-FR` agency matches and produces no notice. The null-lang agency is skipped.

### `multilanguageFeedDifferentAgencies`
- **Setup**: Two agencies with different languages (English, France). Feed lang is `mul`.
- **Expected**: No notices. The `mul` language tag exempts the feed from mismatch checks.

### `multilanguageFeedSingleAgency`
- **Setup**: One agency with English lang. Feed lang is `mul`.
- **Expected**: No notices. Even a single agency is valid when feed_lang is `mul`.

## 7. Implementation notes

### Polars approach

This validator is straightforward and can be implemented with minimal Polars operations since it is a cross-table check between a singleton (`feed_info`) and a small table (`agency`).

1. **Extract feed_lang**: Read the first (and only) row of `feed_info.txt`. If the table is missing, empty, or `feed_lang` is null, return early with no notices.
2. **Check for `mul`**: If `feed_lang` equals `"mul"` (case-insensitive), return early.
3. **Filter agencies**: From `agency.txt`, filter rows where `agency_lang` is non-null AND `agency_lang != feed_lang`.
4. **Emit notices**: For each filtered row, emit a notice with `csvRowNumber`, `agency_id`, `agency_name`, `agency_lang`, and the `feed_lang` value.

### Considerations

- **Language tag comparison**: The Java code uses `java.util.Locale` equality. `Locale.FRANCE` is `fr-FR` and `Locale.CANADA_FRENCH` is `fr-CA` -- these are not equal. In Python, compare the raw BCP-47 tag strings after lowercasing (or use exact case if the loading layer normalizes them consistently). The key point is that regional variants are considered distinct.
- **Null vs empty semantics**: In Java, `hasFeedLang()` and `hasAgencyLang()` return false for both null and empty. The loading layer should normalize empty strings to null so that a simple `.is_null()` check suffices.
- **No join needed**: The feed_lang is a single scalar value extracted from feed_info. It is compared against each agency row via a simple column filter expression, not a join.
- **Plain Python is fine**: Given that `feed_info` is always a single row and `agency` is typically very small (rarely more than a few dozen rows), plain Python iteration over collected rows is perfectly acceptable. A Polars filter expression is also clean and idiomatic.
