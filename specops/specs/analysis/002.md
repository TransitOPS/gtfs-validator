# Analysis: AttributionWithoutRoleValidator

## 1. Purpose

Validates that each row in `attributions.txt` has at least one role assigned (`is_producer`, `is_operator`, or `is_authority` set to 1).

## 2. Input tables

| Table | Columns used |
|---|---|
| `attributions.txt` | `attribution_id`, `is_producer`, `is_operator`, `is_authority` |

Only the `attributions` table is read. No cross-table joins are needed.

## 3. Validation logic

This is a single-entity (row-level) validator. For each row in `attributions.txt`:

1. **Guard clause (shouldCallValidate)**: If none of the three role columns (`is_producer`, `is_operator`, `is_authority`) are present in the file headers, skip this validator entirely. If at least one of the three columns exists in the header, proceed.

2. **Per-row check**: A row "has a role" if any of `is_producer`, `is_operator`, or `is_authority` equals `1` (the ASSIGNED enum value). The default/missing value for these fields is `0` (NOT_ASSIGNED).

3. If a row has no role assigned (all three are either missing/null or `0`), emit an `AttributionWithoutRoleNotice`.

The role enum has two values:
- `0` = NOT_ASSIGNED (default)
- `1` = ASSIGNED

## 4. Notices emitted

### `attribution_without_role`

- **Severity**: WARNING
- **Condition**: A row in `attributions.txt` where none of `is_producer`, `is_operator`, `is_authority` equals `1`.
- **Fields**:
  | Field | Type | Description |
  |---|---|---|
  | `csv_row_number` | int | The 1-based row number of the faulty record |
  | `attribution_id` | str | The `attribution_id` of the faulty record (may be empty string) |

## 5. Edge cases

- **Missing `attributions.txt` table**: The validator is not invoked (the framework only calls it when the table exists). In Python, the validator function should return an empty list if `"attributions"` is not in `feed`.
- **None of the three role columns present in the file**: The `shouldCallValidate` guard returns false, skipping the validator. In the Python implementation, if none of the three columns exist in the DataFrame, return early with no notices.
- **One or two role columns present**: The validator still runs. Missing columns should be treated as having the default value `0` (NOT_ASSIGNED). If a present column has value `1`, the row passes.
- **Null/missing `attribution_id`**: The notice is still emitted with an empty string for `attribution_id`. The id field is optional per the schema (it is the PK but not marked `@Required`).
- **Empty DataFrame (table exists but has no data rows)**: No rows to validate, no notices emitted.

## 6. Test contracts

### Test 1: `attributionWithoutRoleShouldGenerateNotice`
- **Input**: One attribution row (csvRowNumber=2, attributionId="attr-1") with no roles set (all default to NOT_ASSIGNED).
- **Expected**: Exactly one `attribution_without_role` notice with csvRowNumber=2, attributionId="attr-1".

### Test 2: `attributionWithoutRoleAndNoIdShouldGenerateNotice`
- **Input**: One attribution row (csvRowNumber=2, attributionId="") with no roles set.
- **Expected**: Exactly one `attribution_without_role` notice with csvRowNumber=2, attributionId="".

### Test 3: `attributionWithRoleShouldNotGenerateNotice`
- **Input**: Three separate attribution rows, each with exactly one role set to ASSIGNED:
  - Row with only `is_authority` = 1
  - Row with only `is_operator` = 1
  - Row with only `is_producer` = 1
- **Expected**: No notices for any of the three cases.

### Test 4: `attributionWithAllRolesShouldNotGenerateNotice`
- **Input**: One attribution row with all three roles set to ASSIGNED (is_authority=1, is_operator=1, is_producer=1).
- **Expected**: No notices.

### Additional Python test cases to add
- **Missing table**: `feed` dict has no `"attributions"` key. Expected: empty list.
- **Empty DataFrame**: `attributions` table exists but has zero rows. Expected: empty list.
- **Missing role columns**: DataFrame has `attribution_id` and `organization_name` but none of the three role columns. Expected: empty list (guard clause).
- **Partial columns**: Only `is_producer` column exists, set to 0. Expected: notice emitted.

## 7. Implementation notes

- **Use Polars expressions**: This is a straightforward row-level filter. Use a Polars expression to find rows where none of the three role columns equals 1, then emit a notice per matching row.
- **Column existence check**: Before filtering, check which of the three role columns (`is_producer`, `is_operator`, `is_authority`) exist in the DataFrame. If none exist, return early. For missing columns, either add them with default value 0 or adjust the filter to only check present columns.
- **Default value handling**: The schema defines these as enum columns with default 0 (NOT_ASSIGNED). After loading, null values in these columns should already be filled with the default. If not, treat null as NOT_ASSIGNED (0).
- **No utility functions needed**: This validator is self-contained. No new helpers required.
- **Validator signature**: `(feed: dict[str, pl.DataFrame], ctx: ValidationContext) -> list[Notice]`
- **Notice code**: `"attribution_without_role"`
- **Registry**: Add to `VALIDATOR_REGISTRY` in `validators/__init__.py`.
