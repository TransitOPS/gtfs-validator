# Analysis: StopTimeArrivalAndDepartureTimeValidator

## 1. Purpose

For every stop time row in `stop_times.txt`, verify that `arrival_time` and
`departure_time` are either both present or both absent; and for each trip, verify that
no stop's `arrival_time` is earlier than the preceding stop's `departure_time`.

## 2. Input tables

| Table | Columns used |
|---|---|
| `stop_times.txt` | `csv_row_number`, `trip_id`, `stop_sequence`, `arrival_time`, `departure_time` |

This is a single-table validator operating on `stop_times.txt` only. No cross-table joins
are performed.

### Column semantics

- `trip_id` — string; used to group stop times into per-trip sequences.
- `stop_sequence` — integer; defines the ordering of stop times within a trip.
- `arrival_time` — optional time (seconds since midnight); null when not provided in the
  feed row.
- `departure_time` — optional time (seconds since midnight); null when not provided in
  the feed row.
- `csv_row_number` — 1-based integer row position in the raw CSV file.

## 3. Validation logic

The Java validator is a `FileValidator` that operates over all rows of `stop_times.txt`.
It groups rows by `trip_id` (using `table.byTripIdMap()`), then iterates each trip's stop
times in stop-sequence order. Two independent checks are performed.

### Check 1: Arrival/departure time pairing

For each row in `stop_times.txt`:

- If exactly one of `arrival_time` or `departure_time` is present (but not the other),
  emit `stop_time_with_only_arrival_or_departure_time` (ERROR).
- The `specifiedField` is set to the name of whichever field IS present:
  - If only `arrival_time` is present: `specifiedField = "arrival_time"`.
  - If only `departure_time` is present: `specifiedField = "departure_time"`.
- If both are present, or both are absent: no notice.

### Check 2: Arrival before previous departure (within a trip)

For each trip, iterate its stop times in stop-sequence order, tracking the most recent
stop that had a `departure_time`. Let that stop be called "previous departure stop". For
each subsequent stop that has an `arrival_time`:

- If `current.arrival_time < previous_departure_stop.departure_time`: emit
  `stop_time_with_arrival_before_previous_departure_time` (ERROR).
- "Previous departure stop" is updated whenever a stop with a `departure_time` is
  encountered — it always refers to the most recently seen stop that carried a
  `departure_time`, not merely the immediately preceding row.
- The comparison is strictly "less than" (`isBefore`). Equal times do not trigger the
  notice.

### Interaction between the two checks

Both checks run independently in the same loop pass. A row that has only one of
`arrival_time`/`departure_time` will trigger Check 1; if it also has an `arrival_time`
it will also participate in Check 2. A row with neither time will trigger neither check.

### Decision table for Check 1

| arrival_time | departure_time | Result |
|---|---|---|
| null | null | No notice |
| present | present | No notice |
| null | present | `stop_time_with_only_arrival_or_departure_time`, specifiedField = `"departure_time"` |
| present | null | `stop_time_with_only_arrival_or_departure_time`, specifiedField = `"arrival_time"` |

### Algorithm for Check 2 (per trip)

```
previous_departure_idx = -1
for i, stop_time in enumerate(trip_stop_times_in_sequence_order):
    if stop_time has arrival_time:
        if previous_departure_idx != -1:
            if stop_time.arrival_time < trip_stop_times[previous_departure_idx].departure_time:
                emit stop_time_with_arrival_before_previous_departure_time
    if stop_time has departure_time:
        previous_departure_idx = i
```

## 4. Notices emitted

### `stop_time_with_only_arrival_or_departure_time` (ERROR)

Emitted when a `stop_times.txt` row has exactly one of `arrival_time` or `departure_time`
defined (both or neither are expected per GTFS spec).

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | integer | `stop_times.csv_row_number` | 1-based row number of the offending row |
| `trip_id` | string | `stop_times.trip_id` | Trip identifier for the offending row |
| `stop_sequence` | integer | `stop_times.stop_sequence` | Stop sequence number of the offending row |
| `specified_field` | string | derived | Name of the field that IS present: `"arrival_time"` or `"departure_time"` |

Condition: `(arrival_time IS NULL) XOR (departure_time IS NULL)`.

### `stop_time_with_arrival_before_previous_departure_time` (ERROR)

Emitted when a stop's `arrival_time` is earlier than the `departure_time` of the most
recently preceding stop (within the same trip) that had a `departure_time`.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | integer | `stop_times.csv_row_number` | 1-based row number of the current (offending) stop time |
| `prev_csv_row_number` | integer | `stop_times.csv_row_number` | 1-based row number of the previous stop time whose departure is used |
| `trip_id` | string | `stop_times.trip_id` | Shared trip identifier |
| `arrival_time` | time | `stop_times.arrival_time` | Arrival time of the current stop (seconds since midnight) |
| `departure_time` | time | `stop_times.departure_time` | Departure time of the previous stop (seconds since midnight) |

Condition: `current.arrival_time < previous_stop.departure_time` (within same trip,
where previous stop is the most-recently-seen stop that had a departure_time).

### Notice code mapping

| Java class | Python notice code |
|---|---|
| `StopTimeWithOnlyArrivalOrDepartureTimeNotice` | `stop_time_with_only_arrival_or_departure_time` |
| `StopTimeWithArrivalBeforePreviousDepartureTimeNotice` | `stop_time_with_arrival_before_previous_departure_time` |

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `stop_times.txt` absent from feed | Return `[]`; no notices. |
| `stop_times.txt` present but empty | Return `[]`; no notices. |
| Row with both `arrival_time` and `departure_time` absent | No notice from either check. |
| Row with both `arrival_time` and `departure_time` present | No notice from Check 1; Check 2 comparison still occurs. |
| Trip with a single stop time | Check 2 never compares (no previous departure); no `stop_time_with_arrival_before_previous_departure_time` notice possible. |
| Stop time where `departure_time` is absent but `arrival_time` is present | The stop participates in Check 2 as a potential current stop; it does not update `previous_departure_idx`. |
| Stop time where `arrival_time` is absent but `departure_time` is present | Triggers Check 1 notice; updates `previous_departure_idx` for future Check 2 comparisons. |
| Current arrival equals previous departure exactly | No notice (strictly less-than comparison). |
| Multiple trips in feed | Checks are scoped per-trip; no cross-trip comparison. |
| Multiple offending rows in a trip | One notice per offending row for each applicable check. |
| Stop times not in stop-sequence order in raw CSV | Java groups via `byTripIdMap()` which sorts by stop_sequence; Python must also sort by `stop_sequence` within each trip group before applying Check 2. |

### Missing from test suite

The Java tests do not cover:

- Empty `stop_times.txt`.
- A trip with a single stop time (no previous departure; Check 2 should not fire).
- Stop times where the `arrival_time` exactly equals the previous `departure_time`
  (boundary: no notice expected).
- Stops where `departure_time` is absent (does not update `previous_departure_idx`)
  followed by a later stop whose `arrival_time` would be before a yet-earlier departure.
- Multiple trips in the same feed where each trip is checked independently.
- Stop times provided out of `stop_sequence` order in the raw CSV.
- Rows that trigger both Check 1 and Check 2 simultaneously.

## 7. Implementation notes

### Approach for Check 1 (vectorized)

Check 1 is naturally vectorized. Filter rows where exactly one of `arrival_time` and
`departure_time` is null:

```python
has_arrival = pl.col("arrival_time").is_not_null()
has_departure = pl.col("departure_time").is_not_null()
offenders = stop_times.filter(has_arrival != has_departure)
```

For each offending row, `specified_field` is `"arrival_time"` if `arrival_time` is not
null, else `"departure_time"`.

### Approach for Check 2 (plain Python over groups)

Check 2 requires ordered, stateful traversal within each trip group. Per AGENTS.md
guidelines, plain Python algorithms are preferred over forced Polars for
graph/interval/stateful logic.

Group `stop_times` by `trip_id` and sort each group by `stop_sequence`. Then run the
tracking algorithm described in Section 3.

Avoid calling `.to_pandas()` or row-by-row `.iter_rows()` on large DataFrames when
possible. Prefer `partition_by("trip_id", maintain_order=True)` after sorting by
`stop_sequence` globally, then iterate over the resulting list of per-trip DataFrames.

```python
# Sort once globally
sorted_st = stop_times.sort(["trip_id", "stop_sequence"])

for trip_df in sorted_st.partition_by("trip_id", maintain_order=True):
    rows = trip_df.select(
        ["csv_row_number", "trip_id", "stop_sequence", "arrival_time", "departure_time"]
    ).iter_rows(named=True)
    prev_dep_row = None
    for row in rows:
        arrival = row["arrival_time"]
        departure = row["departure_time"]
        if arrival is not None and prev_dep_row is not None:
            if arrival < prev_dep_row["departure_time"]:
                # emit notice
                ...
        if departure is not None:
            prev_dep_row = row
```

### Time representation

In the Java validator, times are `GtfsTime` objects with an `isBefore` method (comparing
seconds since midnight). In the Python loading layer, `arrival_time` and `departure_time`
should be loaded as integer seconds since midnight (or null), enabling direct integer
comparisons (`<`). Values can exceed 86400 for trips running past midnight.

### Guard clause ordering

1. `"stop_times"` not in feed — return `[]`.
2. `stop_times` DataFrame is empty — return `[]`.
3. Run Check 1 (vectorized filter).
4. Sort and group by `trip_id` for Check 2.
5. Return all collected notices.

### Column absence

If `arrival_time` or `departure_time` column is absent from the file header entirely,
the loading layer will produce a null-filled column. This is consistent with all rows
being treated as having no arrival/departure time, which is valid (both absent = no
notice). No special handling is needed beyond what the loading layer provides.

- `"stop_times"` — `stop_times.txt`

Activation condition: `stop_times.txt` is present.
