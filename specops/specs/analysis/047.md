# Analysis: PickupDropOffWindowValidator

## 1. Purpose

Validates that `start_pickup_drop_off_window` and `end_pickup_drop_off_window` fields in `stop_times.txt` do not coexist with `arrival_time` or `departure_time`, that both window fields are always present together when either is used, and that the end window is strictly later than the start window.

## 2. Input tables

| Table | Columns used |
|---|---|
| `stop_times.txt` | `csv_row_number`, `arrival_time`, `departure_time`, `start_pickup_drop_off_window`, `end_pickup_drop_off_window` |

Only `stop_times.txt` is read. All five columns are optional; the validator guards on the presence of the window columns in the header before running.

## 3. Validation logic

### Step 1: Guard — skip unless at least one window column is present

`shouldCallValidate()` returns `false` (skip entirely) unless `stop_times.txt` has at least one of `start_pickup_drop_off_window` or `end_pickup_drop_off_window` in its header.

In Python: if `"stop_times"` is not in the feed dict, or the `stop_times` DataFrame has neither `start_pickup_drop_off_window` nor `end_pickup_drop_off_window` as a column, return `[]` immediately.

### Step 2: For each row where at least one window field is non-null, run three sequential checks

The Java implementation iterates per row. The entry condition for all checks on a given row is that at least one of `start_pickup_drop_off_window` or `end_pickup_drop_off_window` is set (non-null). Rows where neither window field is set are skipped entirely (early return at the top of `validate()`).

#### Check A — forbidden arrival or departure time

Trigger condition (both must be true for this row):

- At least one of `start_pickup_drop_off_window` or `end_pickup_drop_off_window` is non-null.
- `arrival_time` is non-null OR `departure_time` is non-null.

If triggered, emit `forbidden_arrival_or_departure_time` with:

- `csvRowNumber`: the row number of this `stop_times` record.
- `arrivalTime`: the value of `arrival_time` for this row (null if that field is absent/unset).
- `departureTime`: the value of `departure_time` for this row (null if that field is absent/unset).
- `startPickupDropOffWindow`: the value of `start_pickup_drop_off_window` for this row (null if absent/unset).
- `endPickupDropOffWindow`: the value of `end_pickup_drop_off_window` for this row (null if absent/unset).

Important: Check A does NOT cause an early return. After emitting (or not emitting) for check A, execution continues to check B.

#### Check B — missing start or end pickup/drop-off window

Trigger condition (both must be true for this row):

- At least one of `start_pickup_drop_off_window` or `end_pickup_drop_off_window` is non-null (same entry condition).
- NOT both of `start_pickup_drop_off_window` and `end_pickup_drop_off_window` are non-null — i.e., exactly one of them is present and the other is null.

If triggered, emit `missing_pickup_or_drop_off_window` with:

- `csvRowNumber`: the row number of this `stop_times` record.
- `startPickupDropOffWindow`: the value of `start_pickup_drop_off_window` (null if absent).
- `endPickupDropOffWindow`: the value of `end_pickup_drop_off_window` (null if absent).

Important: Check B causes an early return for the row. If check B fires, check C is NOT evaluated.

#### Check C — invalid pickup/drop-off window (end not strictly after start)

This check is only reached when both `start_pickup_drop_off_window` and `end_pickup_drop_off_window` are non-null (check B did not fire).

Trigger condition:

- `start_pickup_drop_off_window >= end_pickup_drop_off_window` (i.e., start is equal to or after end).

If triggered, emit `invalid_pickup_drop_off_window` with:

- `csvRowNumber`: the row number of this `stop_times` record.
- `startPickupDropOffWindow`: the value of `start_pickup_drop_off_window`.
- `endPickupDropOffWindow`: the value of `end_pickup_drop_off_window`.

### Summary of check interactions per row

| Condition | Check A | Check B | Check C |
|---|---|---|---|
| No window fields set | skip entire row | — | — |
| Only one window set, no times | no | yes, return | — |
| Only one window set, with times | yes | yes, return | — |
| Both windows set, with times, valid window | yes | no | no |
| Both windows set, with times, invalid window | yes | no | yes |
| Both windows set, no times, start >= end | no | no | yes |
| Both windows set, no times, start < end | no | no | no (valid) |

## 4. Notices emitted

### `forbidden_arrival_or_departure_time` (ERROR)

Emitted when `arrival_time` or `departure_time` is set on the same row as `start_pickup_drop_off_window` or `end_pickup_drop_off_window`. GTFS prohibits both timing approaches on a single stop time record.

| Field | Type | Source | Description |
|---|---|---|---|
| `csvRowNumber` | integer | `stop_times.csv_row_number` | Row number of the offending record |
| `arrivalTime` | time or null | `stop_times.arrival_time` | Arrival time; null if not set on this row |
| `departureTime` | time or null | `stop_times.departure_time` | Departure time; null if not set on this row |
| `startPickupDropOffWindow` | time or null | `stop_times.start_pickup_drop_off_window` | Start window; null if not set on this row |
| `endPickupDropOffWindow` | time or null | `stop_times.end_pickup_drop_off_window` | End window; null if not set on this row |

Severity: ERROR.

Java class: `ForbiddenArrivalOrDepartureTimeNotice`.

Referenced files: `stop_times.txt`.

Python notice code: `forbidden_arrival_or_departure_time`.

### `missing_pickup_or_drop_off_window` (ERROR)

Emitted when exactly one of `start_pickup_drop_off_window` or `end_pickup_drop_off_window` is present but the other is missing. GTFS requires both fields to be provided together.

| Field | Type | Source | Description |
|---|---|---|---|
| `csvRowNumber` | integer | `stop_times.csv_row_number` | Row number of the offending record |
| `startPickupDropOffWindow` | time or null | `stop_times.start_pickup_drop_off_window` | Start window value; null if that field was absent |
| `endPickupDropOffWindow` | time or null | `stop_times.end_pickup_drop_off_window` | End window value; null if that field was absent |

Severity: ERROR.

Java class: `MissingPickupOrDropOffWindowNotice`.

Referenced files: `stop_times.txt`.

Python notice code: `missing_pickup_or_drop_off_window`.

### `invalid_pickup_drop_off_window` (ERROR)

Emitted when both `start_pickup_drop_off_window` and `end_pickup_drop_off_window` are present but `end_pickup_drop_off_window` is not strictly later than `start_pickup_drop_off_window`. This includes the case where they are equal.

| Field | Type | Source | Description |
|---|---|---|---|
| `csvRowNumber` | integer | `stop_times.csv_row_number` | Row number of the offending record |
| `startPickupDropOffWindow` | time | `stop_times.start_pickup_drop_off_window` | Start of the window |
| `endPickupDropOffWindow` | time | `stop_times.end_pickup_drop_off_window` | End of the window (must be strictly greater than start) |

Severity: ERROR.

Java class: `InvalidPickupDropOffWindowNotice`.

Referenced files: `stop_times.txt`.

Python notice code: `invalid_pickup_drop_off_window`.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `stop_times.txt` absent from feed | Guard returns false; no notices emitted. |
| Neither `start_pickup_drop_off_window` nor `end_pickup_drop_off_window` column in header | Guard returns false; no notices emitted. |
| `stop_times.txt` empty (no rows) | No rows to evaluate; no notices. |
| Row has both window columns null | Row skipped at entry guard; no notices for that row. |
| Only `start_pickup_drop_off_window` is non-null (end is null) | Entry guard passes; check B fires (missing end); early return from row; check C not evaluated. |
| Only `end_pickup_drop_off_window` is non-null (start is null) | Entry guard passes; check B fires (missing start); early return from row; check C not evaluated. |
| Both windows set, start < end, no arrival/departure time | No notices (valid case). |
| Both windows set, start == end | Check A skipped (no arrival/departure times); check B skipped (both present); check C fires (`invalid_pickup_drop_off_window`). |
| Both windows set, start > end | Same as equal — check C fires. |
| Arrival time set with both windows | Check A fires; check B not triggered (both windows present); check C evaluated (fires if start >= end). |
| Departure time set with both windows | Same as above, check A fires. |
| Both arrival and departure time set with one window field | Check A fires; check B fires (missing other window); early return, check C not evaluated. |
| `arrival_time` column absent from DataFrame | Treat as null for check A; check A only fires if `departure_time` is non-null. |
| `departure_time` column absent from DataFrame | Treat as null for check A; check A only fires if `arrival_time` is non-null. |
| A row can produce at most two notices: one from check A and one from either check B or check C (never both B and C, since B causes early return before C). |

## 6. Test contracts

### `shouldGenerateForbiddenArrivalOrDepartureTimeNotice`

Setup:
- `csv_row_number=1`, `arrival_time="00:00:00"`, `departure_time="00:00:01"`, `start_pickup_drop_off_window="00:00:02"`, `end_pickup_drop_off_window="00:00:03"`.

Expected: exactly 1 notice of type `ForbiddenArrivalOrDepartureTimeNotice`.

Explanation: Entry guard passes (both windows set). Check A fires (both arrival and departure times are present). Check B does not fire (both windows present). Check C does not fire (end > start). Net result: one notice.

### `shouldGenerateMissingPickupOrDropOffWindowNotice_missingStart`

Setup:
- `csv_row_number=1`, `end_pickup_drop_off_window="00:00:03"` only (no start, no arrival/departure times).

Expected: exactly 1 notice of type `MissingPickupOrDropOffWindowNotice`.

Explanation: Entry guard passes (end window set). Check A does not fire (no arrival/departure times). Check B fires (start window absent); early return. Check C not evaluated. The notice fields carry `startPickupDropOffWindow=null`, `endPickupDropOffWindow="00:00:03"`.

### `shouldGenerateMissingPickupOrDropOffWindowNotice_missingEnd`

Setup:
- `csv_row_number=1`, `start_pickup_drop_off_window="00:00:03"` only (no end, no arrival/departure times).

Expected: exactly 1 notice of type `MissingPickupOrDropOffWindowNotice`.

Explanation: Entry guard passes (start window set). Check A does not fire. Check B fires (end window absent); early return. The notice fields carry `startPickupDropOffWindow="00:00:03"`, `endPickupDropOffWindow=null`.

### `shouldGenerateInvalidPickupDropOffWindowNotice`

Setup:
- `csv_row_number=1`, `start_pickup_drop_off_window="00:00:03"`, `end_pickup_drop_off_window="00:00:02"` (end is before start).

Expected: exactly 1 notice of type `InvalidPickupDropOffWindowNotice`.

Explanation: Entry guard passes (both windows set). Check A does not fire (no arrival/departure times). Check B does not fire (both windows present). Check C fires (start "00:00:03" > end "00:00:02").

Note: There is no explicit Java test for the equal-time case (`start == end`), but the Java source explicitly checks `equals()` as well as `isAfter()`, confirming that `start == end` must also emit `invalid_pickup_drop_off_window`.

## 7. Implementation notes

### Algorithm choice

The logic is per-row and involves three sequential checks with specific early-return semantics. The checks operate only on `stop_times.txt` columns with no cross-table joins required. Polars filter expressions are appropriate for vectorizing each check. The early-return from check B (which prevents check C from running on those rows) can be handled by partitioning the DataFrame at each step.

### Recommended Polars approach

```python
stop_times = feed["stop_times"]

has_start_col = "start_pickup_drop_off_window" in stop_times.columns
has_end_col = "end_pickup_drop_off_window" in stop_times.columns

# Entry guard: at least one window column exists in header (already checked above)
# Row-level entry condition: at least one window value is non-null
window_expr = pl.lit(False)
if has_start_col:
    window_expr = window_expr | pl.col("start_pickup_drop_off_window").is_not_null()
if has_end_col:
    window_expr = window_expr | pl.col("end_pickup_drop_off_window").is_not_null()

# Subset of rows where at least one window field is set
windowed = stop_times.filter(window_expr)

# Check A: arrival_time or departure_time present alongside window fields
has_arrival_col = "arrival_time" in windowed.columns
has_departure_col = "departure_time" in windowed.columns
time_expr = pl.lit(False)
if has_arrival_col:
    time_expr = time_expr | pl.col("arrival_time").is_not_null()
if has_departure_col:
    time_expr = time_expr | pl.col("departure_time").is_not_null()
check_a_violations = windowed.filter(time_expr)
# emit forbidden_arrival_or_departure_time for each row in check_a_violations

# Check B: exactly one window present (missing the other)
both_windows_expr = pl.lit(True)
if has_start_col:
    both_windows_expr = both_windows_expr & pl.col("start_pickup_drop_off_window").is_not_null()
if has_end_col:
    both_windows_expr = both_windows_expr & pl.col("end_pickup_drop_off_window").is_not_null()

check_b_violations = windowed.filter(~both_windows_expr)
# emit missing_pickup_or_drop_off_window for each row in check_b_violations

# Check C: only rows where both windows are present; end <= start
check_c_candidates = windowed.filter(both_windows_expr)
check_c_violations = check_c_candidates.filter(
    pl.col("end_pickup_drop_off_window") <= pl.col("start_pickup_drop_off_window")
)
# emit invalid_pickup_drop_off_window for each row in check_c_violations
```

This approach respects the early-return semantics: check B and check C are mutually exclusive by construction (check B applies to rows missing at least one window, check C only applies to rows with both windows).

### Time field comparison

In the Python schema, `start_pickup_drop_off_window` and `end_pickup_drop_off_window` are loaded as `_TIME` (integer seconds since midnight, as defined in `schemas.py`). Numeric comparison (`<=`) directly implements the Java `isAfter()` / `equals()` check. No special time utility is needed.

Similarly, `arrival_time` and `departure_time` are `_TIME` columns; their null-ness is the only property needed for check A.

### Notice field null semantics

- `arrivalTime` in `forbidden_arrival_or_departure_time`: carry raw row value; will be null if `arrival_time` column is absent or null for that row.
- `departureTime` in `forbidden_arrival_or_departure_time`: same treatment.
- `startPickupDropOffWindow` in `missing_pickup_or_drop_off_window`: will be null when the column is absent or the value is null.
- `endPickupDropOffWindow` in `missing_pickup_or_drop_off_window`: same.
- `startPickupDropOffWindow` and `endPickupDropOffWindow` in `invalid_pickup_drop_off_window`: both are always non-null (check C only runs when both are present).
