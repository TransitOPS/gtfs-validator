# Analysis: StopTimesGeographyIdPresenceValidator

## 1. Purpose

Validates that each record in `stop_times.txt` has exactly one of `stop_id`,
`location_group_id`, or `location_id` defined — not zero, and not more than one.

## 2. Input tables

| Table | Columns used |
|---|---|
| `stop_times.txt` | `stop_id`, `location_group_id`, `location_id`, `csv_row_number` |

### Column semantics

- `stop_id` — optional string; identifies a fixed stop. Presence means the row references
  a traditional stop.
- `location_group_id` — optional string; identifies a location group (flexible service).
  Presence means the row references a group of locations.
- `location_id` — optional string; identifies a GeoJSON location (flex service). Presence
  means the row references a GeoJSON-defined area or point.
- `csv_row_number` — integer; the source CSV row number, included in notice payloads for
  diagnostics.

Exactly one of these three columns must have a non-null, non-empty value per row.

## 3. Validation logic

This is a per-row check. For each row in `stop_times.txt`:

1. Count how many of `stop_id`, `location_group_id`, and `location_id` are present
   (non-null and non-empty). Call this `presence_count`.
2. If `presence_count == 0`:
   - Emit `missing_required_field` with `filename = "stop_times.txt"`,
     `csv_row_number = <row>`, `field_name = "stop_id"`.
   - The field reported is always `stop_id` regardless of which other fields are also
     absent, because `stop_id` is the traditional required field for this table.
3. If `presence_count > 1` (i.e., 2 or 3 of the fields are present simultaneously):
   - Emit `forbidden_geography_id` with the row number and the values of whichever of
     `stop_id`, `location_group_id`, `location_id` are present (null for absent ones).
4. If `presence_count == 1`: valid; no notice emitted.

### Guard clause (`shouldCallValidate`)

The Java validator only runs at all if at least one of `stop_id`, `location_group_id`, or
`location_id` appears as a column header in `stop_times.txt`. If none of those three
columns exist in the file, validation is skipped entirely and no `missing_required_field`
notice is emitted (that would be a load-time schema error caught elsewhere).

In the Python implementation, this translates to: if none of the three columns are present
in the DataFrame (all are absent as columns), skip the validator and return `[]`.

## 4. Notices emitted

### `missing_required_field` (ERROR)

Emitted when none of the three geography ID fields are present on a row.

| Field | Type | Source | Description |
|---|---|---|---|
| `filename` | string | constant `"stop_times.txt"` | The file containing the faulty record |
| `csv_row_number` | int | `stop_times.csv_row_number` | CSV row number of the offending row |
| `field_name` | string | constant `"stop_id"` | The name of the missing required field |

Condition: `stop_id` is null/absent AND `location_group_id` is null/absent AND
`location_id` is null/absent.

Note: `missing_required_field` is a shared notice class used across many validators. The
field reported is always `"stop_id"` — this is hardcoded in the Java source.

### `forbidden_geography_id` (ERROR)

Emitted when more than one geography ID field is present on the same row.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | int | `stop_times.csv_row_number` | CSV row number of the offending row |
| `stop_id` | string or null | `stop_times.stop_id` | Value of `stop_id` if present, else null |
| `location_group_id` | string or null | `stop_times.location_group_id` | Value of `location_group_id` if present, else null |
| `location_id` | string or null | `stop_times.location_id` | Value of `location_id` if present, else null |

Condition: two or more of `stop_id`, `location_group_id`, `location_id` are non-null /
non-empty in the same row.

Note: This notice is defined as an inner class of the Java validator
(`StopTimesGeographyIdPresenceValidator.ForbiddenGeographyIdNotice`). In Python it should
be a standalone notice dataclass with code `"forbidden_geography_id"` and severity ERROR.

Important: the Java test for `ForbiddenGeographyIdNotice` is commented out with `// TODO:
Put back when this notice is ready to be published.`. This means the multi-geography-id
check is implemented in the Java code but intentionally not yet active in the published
output. The Python implementation should implement the full logic but be aware this notice
was not yet enabled in the reference implementation at time of migration.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `stop_times.txt` absent | Return `[]` immediately (guard clause). |
| `stop_times.txt` is empty (no rows) | No notices; loop over zero rows produces nothing. |
| None of `stop_id`, `location_group_id`, `location_id` are columns in the file | Per `shouldCallValidate`, skip the validator entirely; return `[]`. |
| Only one of the three columns exists as a column in the file | The other two are treated as absent (null) for all rows; validator still runs for the existing column. |
| A row has `stop_id` only | `presence_count == 1`; valid; no notice. |
| A row has `location_group_id` only | `presence_count == 1`; valid; no notice. |
| A row has `location_id` only | `presence_count == 1`; valid; no notice. |
| A row has `stop_id` and `location_group_id` | `presence_count == 2`; emit `forbidden_geography_id`. |
| A row has `stop_id` and `location_id` | `presence_count == 2`; emit `forbidden_geography_id`. |
| A row has `location_group_id` and `location_id` | `presence_count == 2`; emit `forbidden_geography_id`. |
| A row has all three fields | `presence_count == 3`; emit `forbidden_geography_id` with all three values. |
| A row has all three fields absent/null | `presence_count == 0`; emit `missing_required_field` with `field_name = "stop_id"`. |
| Empty string value in `stop_id` | Treat empty string as absent (consistent with GTFS loading convention where empty CSV cells become null). |

## 6. Test contracts

### `NoGeographyIdShouldGenerateMissingRequiredFieldNotice` (active)

- Input: a `GtfsStopTime` with no `stop_id`, no `location_group_id`, no `location_id`
  (all absent). `csv_row_number = 2`.
- Expected: exactly one `MissingRequiredFieldNotice("stop_times.txt", 2, "stop_id")`.
- Covers: the zero-geography-id case.

Note: This test appears twice in the file (`NoGeographyIdShouldGenerateMissingRequiredFieldNotice`
and `NoGeographyIdShouldGenerateNotice`); both are identical and both are active.

### `OneGeographyIdShouldGenerateNothing` (active)

- Three sub-cases, each with exactly one geography ID set:
  - `stop_id = "stop_id"`, others absent.
  - `location_group_id = "id"`, others absent.
  - `location_id = "id"`, others absent.
- Expected: empty notices list for all three sub-cases.
- Covers: the valid single-geography-id case for all three fields.

### `MultipleGeographyIdShouldGenerateNotice` (commented out, not active)

This test is marked with `// TODO: Put back when this notice is ready to be published.`
and the `@Test` annotation is removed. It is present in the source but does not run.

The test covers four sub-cases:
- `stop_id + location_group_id` → `ForbiddenGeographyIdNotice(2, "stop_id", "location_group_id", "")`.
- `stop_id + location_id` → `ForbiddenGeographyIdNotice(2, "stop_id", "", "location_id")`.
- `location_group_id + location_id` → `ForbiddenGeographyIdNotice(2, "", "location_group_id", "location_id")`.
- All three → `ForbiddenGeographyIdNotice(2, "stop_id", "location_group_id", "location_id")`.

Note: The test uses empty string `""` (not null) for absent fields in the notice payload.
In Python, use `None` for absent fields rather than empty string, as `None` is the natural
sentinel in Polars and Python dataclasses.

### What is NOT covered by the Java test suite

- `stop_times.txt` absent entirely.
- None of the three columns present as file columns (the `shouldCallValidate` path).
- Empty `stop_times.txt` (zero rows).
- Multiple offending rows in the same file (only `csv_row_number = 2` is tested).

## 7. Implementation notes

### Algorithm strategy

The check is naturally vectorized: compute presence flags for all three columns in one
Polars pass, sum them, and filter for violations.

Use Polars expressions:

```python
st = feed["stop_times"]

# Determine which geography columns are present in the DataFrame
has_stop_id_col       = "stop_id" in st.columns
has_location_group_col = "location_group_id" in st.columns
has_location_id_col    = "location_id" in st.columns

# Guard: if none of the three columns exist, skip
if not (has_stop_id_col or has_location_group_col or has_location_id_col):
    return []

# Build presence expressions (True if column exists and value is not null/empty)
flags = []
if has_stop_id_col:
    flags.append(pl.col("stop_id").is_not_null() & (pl.col("stop_id") != ""))
if has_location_group_col:
    flags.append(pl.col("location_group_id").is_not_null() & (pl.col("location_group_id") != ""))
if has_location_id_col:
    flags.append(pl.col("location_id").is_not_null() & (pl.col("location_id") != ""))

# Sum presence flags per row
presence = sum(flags) if flags else pl.lit(0)
```

Then filter for `presence == 0` and `presence > 1` separately to emit the two distinct
notice types.

### Guard clause ordering

1. `"stop_times"` not in feed → return `[]`.
2. `stop_times` is empty (0 rows) → return `[]`.
3. None of `stop_id`, `location_group_id`, `location_id` are columns → return `[]`.

### Polars vs plain Python

This validator is entirely vectorizable. No plain Python loop is needed. Use:
- `pl.col(...).is_not_null()` and `!= ""` for presence detection.
- Arithmetic summation across boolean columns for `presence_count`.
- `.filter(pl.col("presence") == 0)` and `.filter(pl.col("presence") > 1)` to isolate
  the two violation categories.
- `.iter_rows(named=True)` only to construct individual notice objects from the filtered
  results.

### Notice dataclasses

```python
@dataclass
class ForbiddenGeographyIdNotice:
    code: ClassVar[str] = "forbidden_geography_id"
    severity: ClassVar[str] = "ERROR"
    csv_row_number: int
    stop_id: str | None
    location_group_id: str | None
    location_id: str | None
```

The `missing_required_field` notice is already implemented as a shared notice type in the
Python codebase. Reuse it with `filename="stop_times.txt"` and `field_name="stop_id"`.

### Feed dict keys

- `"stop_times"` — `stop_times.txt`

No other tables are required for this validator.

### Validator registration

Required tables: `["stop_times"]`.

No feature flag needed; the validator runs whenever `stop_times.txt` is present.

### Enabled status of `forbidden_geography_id`

The Java code implements `ForbiddenGeographyIdNotice` and emits it in the validate method,
but the test that covers it is commented out pending publication readiness. The Python
implementation should include the full logic; do not suppress the notice. If the project
