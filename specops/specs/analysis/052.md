# Analysis: ServiceHasNoActiveDayOfTheWeekValidator

## 1. Purpose

For every row in `calendar.txt` that has a `service_id`, check whether all seven
day-of-week columns (`monday` through `sunday`) are set to `0` (NOT_AVAILABLE).
If so, the service is effectively inactive on every day of the week, which is
almost certainly a data error, and a WARNING notice is emitted.

## 2. Input tables

| Table | Columns used |
|---|---|
| `calendar.txt` | `service_id`, `monday`, `tuesday`, `wednesday`, `thursday`, `friday`, `saturday`, `sunday` |

No other tables are read. `calendar_dates.txt` is not consulted — the validator
looks only at the weekly pattern columns, not at exception dates.

## 3. Validation logic

### Step 1: Guard

If `calendar.txt` is absent from the feed or the resulting DataFrame is empty,
return immediately with no notices.

### Step 2: Filter rows with a service_id

Retain only rows where `service_id` is non-null and non-empty. In practice,
`service_id` is a required primary-key field in the schema, so null rows should
not appear after load-time validation; the Java guard (`calendar.hasServiceId()`)
is a defensive check.

### Step 3: Check day-of-week columns for each retained row

For each retained row, evaluate whether ALL of the following are true:

```
monday    == 0  (NOT_AVAILABLE)
tuesday   == 0
wednesday == 0
thursday  == 0
friday    == 0
saturday  == 0
sunday    == 0
```

`NOT_AVAILABLE` is the integer value `0`. `AVAILABLE` is `1`. No other values
are valid (domain enforcement is handled at load time).

### Step 4: Emit notice

If the condition in Step 3 is true for a row, emit one
`service_has_no_active_day_of_the_week` notice carrying the CSV row number and
the `service_id` for that row.

One notice is emitted per offending calendar row. If multiple rows share the
same `service_id` (which violates the PK constraint and would already be caught
at load time), each such row would independently produce a notice.

## 4. Notices emitted

### `service_has_no_active_day_of_the_week` (WARNING)

Emitted when a `calendar.txt` row has `service_id` present but all seven
day-of-week columns are `0`.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | integer | `calendar.txt` row index | 1-based row number of the offending row |
| `service_id` | string | `calendar.service_id` | The service identifier |

Java class: `ServiceHasNoActiveDayOfTheWeekNotice`.

Python notice code: `service_has_no_active_day_of_the_week`.

Severity: WARNING.

Referenced files (for notice metadata): `calendar.txt`.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `calendar.txt` absent from feed | Return no notices immediately (guard on missing table key). |
| `calendar.txt` present but empty (zero data rows) | Return no notices immediately (empty DataFrame guard). |
| Row where `service_id` is null / empty | Row is skipped (Java `hasServiceId()` guard). In Python, filter to non-null `service_id` before checking day columns. |
| Row where all seven day columns are `0` | One notice emitted for that row. |
| Row where exactly one day column is `1` | No notice; at least one active day exists. |
| Row where all seven day columns are `1` | No notice. |
| Multiple rows in `calendar.txt`, some fully inactive | One notice per fully-inactive row; active rows produce no notice. |
| `calendar_dates.txt` has SERVICE_ADDED exceptions for an otherwise-inactive service | No effect on this validator; it does not consult `calendar_dates.txt`. |
| Day columns hold null (missing required field) | Load-time validation should already emit a missing-required-field notice. In Python, treat null as `0` (NOT_AVAILABLE) to preserve the spirit of the Java check, which treats the default for a missing `GtfsCalendarService` field as `NOT_AVAILABLE`. |

## 6. Test contracts

### `serviceHasNoActiveDayOfTheWeek`

- Input: two calendar entries.
  - `service_1`: all day columns left at default (`0` / NOT_AVAILABLE); `service_id` = `"service_1"`.
  - `service_2`: `monday` set to `1` (AVAILABLE); remaining days default `0`; `service_id` = `"service_2"`.
- Expected: exactly **1** notice (for `service_1`).
- `service_2` has at least one active day and must not produce a notice.

### `serviceHasAnActiveDayOfTheWeek`

- Input: two calendar entries.
  - `service_1`: `monday` = `1`; remaining days default `0`.
  - `service_2`: `monday` = `1`; remaining days default `0`.
- Expected: **0** notices.

Note: the test file does not include an explicit test for an empty calendar table
or for a row with a missing `service_id`. Python tests should add those edge
cases per AGENTS.md guidelines.

## 7. Implementation notes

### Approach: pure Polars filter + collect

This validator is straightforward vectorized logic with no graph traversal,
interval arithmetic, or stateful accumulation. It is a natural fit for a single
Polars filter expression followed by row collection.

### Polars expression

```python
import polars as pl

DAY_COLUMNS = ["monday", "tuesday", "wednesday", "thursday", "friday", "saturday", "sunday"]
NOT_AVAILABLE = 0

def _all_days_inactive(df: pl.DataFrame) -> pl.Expr:
    """Returns a boolean expression: True if all day columns are NOT_AVAILABLE (0)."""
    exprs = [pl.col(day).fill_null(NOT_AVAILABLE).eq(NOT_AVAILABLE) for day in DAY_COLUMNS]
    combined = exprs[0]
    for e in exprs[1:]:
        combined = combined & e
    return combined
```

Then filter to matching rows and emit one notice per row:

```python
offending = df.filter(
    pl.col("service_id").is_not_null() & _all_days_inactive(df)
)
for row in offending.select(["csv_row_number", "service_id"]).iter_rows(named=True):
    notices.append(
        Notice(
            code="service_has_no_active_day_of_the_week",
            severity=Severity.WARNING,
            fields={
                "csvRowNumber": row["csv_row_number"],
                "serviceId": row["service_id"],
            },
        )
    )
```

Alternatively, use `pl.all_horizontal` over the day columns for a compact single
expression:

```python
all_inactive = pl.all_horizontal(
    [pl.col(day).fill_null(0).eq(0) for day in DAY_COLUMNS]
)
```

### Null handling for day columns

The Java enum default for an unparsed `GtfsCalendarService` field is
`NOT_AVAILABLE` (value `0`). In Python, `fill_null(0)` on integer columns after
load replicates this behavior. Since all day columns are declared `@Required` in
the schema, nulls should already produce a load-time notice; treating nulls as
`0` here is a safe defensive measure that does not change observable notice
output.

|---|---|

### Validator registration

Required tables: `["calendar"]`.

Guard: return `[]` immediately if `"calendar"` is absent from the feed dict or
the DataFrame is empty.

### No dependency on `calendar_dates.txt`

The Java validator is a `FileValidator` scoped to `GtfsCalendarTableContainer`
only. It makes no reference to `calendar_dates.txt`. The Python implementation
must match this: do not consult `calendar_dates.txt` even if a service has added
exceptions that would make it active on some dates.
