# Analysis: TripUsageValidator

## 1. Purpose

Validates that every trip defined in `trips.txt` is referenced by at least one record in `stop_times.txt`. Trips that have no corresponding stop times are considered "unused" and generate a warning.

## 2. Input tables

| Table | Columns used |
|---|---|
| `trips.txt` | `trip_id`, `csv_row_number` |
| `stop_times.txt` | `trip_id` |

### Schema reference

`trips.txt` (`GtfsTripSchema`, Python: `TRIPS`):

| Column | Type | Constraint |
|---|---|---|
| `trip_id` | string | Required, Primary Key |
| `route_id` | string | Required, Foreign Key to `routes.route_id` |
| `service_id` | string | Required, Foreign Key to `calendar.service_id` or `calendar_dates.service_id` |
| ... | ... | ... |

`stop_times.txt` (`GtfsStopTimeSchema`, Python: `STOP_TIMES`):

| Column | Type | Constraint |
|---|---|---|
| `trip_id` | string | Required, Foreign Key to `trips.trip_id` |
| `stop_id` | string | Required, Foreign Key to `stops.stop_id` |
| `stop_sequence` | int | Required, part of composite primary key |
| ... | ... | ... |

## 3. Validation logic

### Skip conditions

- If `trips.txt` is absent or empty, no rows are processed and no notices are emitted.
- If `stop_times.txt` is absent or unparsable, this validator is skipped by dependency gating in the orchestrator.

### Algorithm

The validator iterates over each trip in `trips.txt` and checks whether any stop_time record references that trip:

```
reported_trips = empty set  # to avoid duplicate notices for duplicate trip_ids

for each trip in trips:
    trip_id = trip.trip_id
    
    if trip_id not in reported_trips:
        add trip_id to reported_trips
        
        if no stop_time has this trip_id:
            emit unused_trip(
                trip_id=trip_id,
                csv_row_number=trip.csv_row_number,
            )
```

### Key observations

1. **Deduplication**: The validator uses a `HashSet<String>` to track reported trip IDs, ensuring that even if `trips.txt` contains duplicate `trip_id` values, each unique trip ID generates at most one notice.

2. **Lookup method**: The Java implementation uses `stopTimeTable.byTripId(tripId).isEmpty()` which checks if the collection of stop_times for that trip_id is empty. This implies an index or grouping by trip_id on the stop_times table.

3. **No cross-table state beyond the join**: This is a simple existence check — does trip_id from trips appear in stop_times?

### Pseudocode

```
used_trip_ids = unique set of trip_id values from stop_times

for each unique trip_id in trips:
    if trip_id not in used_trip_ids:
        get first csv_row_number for this trip_id
        emit unused_trip(
            trip_id=trip_id,
            csv_row_number=csv_row_number,
        )
```

## 4. Notices emitted

### `unused_trip`

Severity: **WARNING**

Emitted when a trip defined in `trips.txt` has no corresponding records in `stop_times.txt`.

| Field | Type | Description |
|---|---|---|
| `tripId` | string | The `trip_id` of the unused trip |
| `csvRowNumber` | int | The CSV row number of the trip record in `trips.txt` |

Note: The Java field names use camelCase (`tripId`, `csvRowNumber`). The Python implementation should use snake_case (`trip_id`, `csv_row_number`) for consistency with Python conventions, but the notice code itself is derived from the class name.

**Notice code derivation:**
- Java class: `UnusedTripNotice`
- Python notice code: `unused_trip` (converted from `UnusedTripNotice` → `unused_trip`)

## 5. Edge cases

- **`trips.txt` absent**: No trips to check; no notices emitted.
- **`trips.txt` empty (header only)**: No trips to check; no notices emitted.
- **`stop_times.txt` absent**: Validator is skipped by dependency gating; this validator emits no notices.
- **`stop_times.txt` empty (header only)**: Every trip in `trips.txt` is unused; each unique trip_id generates a notice.
- **Duplicate trip_id in `trips.txt`**: Only one notice is emitted per unique trip_id. The `csv_row_number` will be from the first occurrence encountered during iteration.
- **Trip with stop_times**: No notice emitted for that trip.
- **Trip without stop_times**: Notice emitted.
- **Null trip_id**: If the schema allows null trip_id (it shouldn't for required fields), the validator would still function but may produce unexpected results. Load-time validation should catch null required fields.

## 7. Implementation notes

### Validator type

Cross-table validator using a simple set membership check. Requires:
1. Extract unique `trip_id` values from `stop_times.txt`
2. Find trips in `trips.txt` whose `trip_id` is not in that set

### Validator signature

```python
def validate_trip_usage(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

### Polars implementation strategy

This is an ideal use case for Polars set operations or anti-join:

**Option 1: Anti-join**

```python
import polars as pl
from gtfs_validator.notices import Notice, Severity
from gtfs_validator.context import ValidationContext

def validate_trip_usage(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
    if "trips" not in feed or feed["trips"].is_empty():
        return []
    
    # Get unique trip_ids that have stop_times
    if "stop_times" in feed and not feed["stop_times"].is_empty():
        used_trip_ids = feed["stop_times"].select("trip_id").unique()
    else:
        # No stop_times means all trips are unused
        used_trip_ids = pl.DataFrame({"trip_id": []}).cast({"trip_id": pl.String})
    
    # Find trips not in stop_times (anti-join)
    unused_trips = feed["trips"].join(
        used_trip_ids,
        on="trip_id",
        how="anti",
    )
    
    # Deduplicate by trip_id (keep first occurrence)
    # Polars unique() keeps first occurrence by default when using maintain_order=True
    unused_trips = unused_trips.unique(subset=["trip_id"], maintain_order=True)
    
    notices = []
    for row in unused_trips.iter_rows(named=True):
        notices.append(Notice(
            code="unused_trip",
            severity=Severity.WARNING,
            fields={
                "trip_id": row["trip_id"],
                "csv_row_number": row["csv_row_number"],
            },
        ))
    
    return notices
```

**Option 2: Using is_in expression (alternative)**

```python
def validate_trip_usage(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
    if "trips" not in feed or feed["trips"].is_empty():
        return []
    
    trips_df = feed["trips"]
    
    # Get set of used trip_ids
    if "stop_times" in feed and not feed["stop_times"].is_empty():
        used_trip_ids = feed["stop_times"]["trip_id"].unique()
    else:
        used_trip_ids = pl.Series("trip_id", [], dtype=pl.String)
    
    # Find unused trips
    unused_trips = trips_df.filter(
        ~pl.col("trip_id").is_in(used_trip_ids)
    ).unique(subset=["trip_id"], maintain_order=True)
    
    # ... rest same as Option 1
```

### Performance considerations

- For large feeds, the anti-join approach is typically more efficient than `is_in` for very large datasets.
- Both approaches benefit from Polars' lazy evaluation if needed.
- The unique operation on stop_times trip_id is important to avoid duplicate checking.

### Relationship to load-time validation

The following are handled at load time and must not be duplicated here:

- `trip_id` type validation (string, required)
- `trip_id` uniqueness (primary key constraint)
- Foreign key validation from `stop_times.trip_id` to `trips.trip_id` (this is the reverse check)

This validator specifically checks the "orphan trip" condition: trips that exist but have no stop_times referencing them. This is a best practices warning, not a spec violation.
