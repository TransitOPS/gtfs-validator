# Analysis: MissingLevelIdValidator

## 1. Purpose

Checks that every stop referenced as an endpoint of an elevator pathway (`pathway_mode=5`) has a non-null `level_id` in `stops.txt`.

## 2. Input tables

| Table | Columns used |
|---|---|
| `pathways.txt` | `pathway_mode`, `from_stop_id`, `to_stop_id` |
| `stops.txt` | `stop_id`, `level_id`, `stop_name`, `csv_row_number` (row index) |

The validator reads no other columns. `levels.txt` itself is not read directly; the check is an indirect proxy for whether levels are defined (via `stops.level_id` being populated).

## 3. Validation logic

1. **Collect elevator endpoints**: Iterate over every row in `pathways.txt`. For each row where `pathway_mode == 5` (ELEVATOR), collect both `from_stop_id` and `to_stop_id` into a deduplicated set of stop IDs. Non-elevator pathway modes (1=WALKWAY, 2=STAIRS, 3=MOVING_SIDEWALK, 4=ESCALATOR, 6=FARE_GATE, 7=EXIT_GATE) are completely ignored.

2. **Check each elevator endpoint**: For each stop ID in the elevator endpoint set:
   - Look up the stop record in `stops.txt` by `stop_id`.
   - If the stop exists **and** its `level_id` is null/missing, emit one `missing_level_id` notice for that stop.
   - If the stop exists and has a non-null `level_id`, no notice is emitted.
   - If the stop ID is not found in `stops.txt` (dangling FK), no notice is emitted here — FK validation is handled by a separate validator (`GtfsStopLevelIdForeignKeyValidator`).

3. **Deduplication**: Because elevator endpoints are collected into a set before the stop lookup, each stop that appears as an endpoint in multiple elevator pathways is only checked once and produces at most one notice.

## 4. Notices emitted

### `missing_level_id` (ERROR)

A stop that is an endpoint of an elevator pathway does not have `level_id` defined in `stops.txt`.

| Field | Type | Description |
|---|---|---|
| `csv_row_number` | int | The row number of the stop record in `stops.txt` (1-based, header = row 1). |
| `stop_id` | string | The `stop_id` of the stop missing `level_id`. |
| `stop_name` | string | The `stop_name` of the stop missing `level_id`. |

Conditions: `pathway_mode == 5` in at least one pathway row that references this stop as `from_stop_id` or `to_stop_id`, AND `level_id` is null or absent for this stop.

Severity: ERROR.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `pathways.txt` absent from feed | No elevator endpoints collected; no notices. |
| `pathways.txt` present but empty | No elevator endpoints collected; no notices. |
| `stops.txt` absent from feed | Elevator endpoints collected but no matching stops found; no notices. |
| `stops.txt` present but empty | Same as above — no matching stops; no notices. |
| Stop referenced by elevator pathway is not in `stops.txt` | No notice (dangling FK is handled by FK validator separately). |
| Stop is an endpoint of two different elevator pathways | Deduplicated; at most one notice per stop. |
| Stop is an endpoint of an elevator pathway and also appears in a non-elevator pathway | Only the elevator pathway membership matters; the check still runs (and produces a notice if `level_id` is missing). |
| `pathway_mode` is not 5 (any of WALKWAY, STAIRS, MOVING_SIDEWALK, ESCALATOR, FARE_GATE, EXIT_GATE) | No notice regardless of `level_id` presence or absence. |
| `level_id` is an empty string vs. null | The Java validator uses `hasLevelId()` which is false only for null/missing. An empty string `""` may be treated as present depending on the framework's field parsing conventions. In the Python implementation, treat null as missing (Polars null); a non-null empty string `""` should be considered present to match Java behavior (Java framework reads empty string as empty, not as null for optional string fields, but `hasLevelId()` returns false for empty strings too — see Implementation Notes). |
| `stops.txt` has `level_id` column entirely absent | All stops in elevator endpoints have no `level_id`; every reachable stop emits a notice. |

## 7. Implementation notes

### Approach

This validator crosses two tables. The logic is most naturally expressed using Polars joins:

1. Filter `pathways` to only elevator rows (`pathway_mode == 5`).
2. Collect all unique stop IDs appearing as `from_stop_id` or `to_stop_id` in those rows (union, deduplicated).
3. Join this set of stop IDs against `stops` on `stop_id`.
4. Filter the joined result to rows where `level_id` is null.
5. Emit one notice per remaining row.

```python
def validate_missing_level_id(
    feed: dict[str, pl.DataFrame], ctx: ValidationContext
) -> list[Notice]:
    if "pathways" not in feed or "stops" not in feed:
        return []

    pathways = feed["pathways"]
    stops = feed["stops"]

    # Step 1: filter to elevator pathways only
    elevators = pathways.filter(pl.col("pathway_mode") == 5)
    if elevators.is_empty():
        return []

    # Step 2: collect unique stop IDs from both endpoint columns
    from_ids = elevators.select(pl.col("from_stop_id").alias("stop_id"))
    to_ids = elevators.select(pl.col("to_stop_id").alias("stop_id"))
    elevator_stop_ids = pl.concat([from_ids, to_ids]).unique()

    # Step 3: join against stops
    joined = elevator_stop_ids.join(
        stops.select(["stop_id", "level_id", "stop_name"]),
        on="stop_id",
        how="inner",
    )

    # Step 4: filter to stops missing level_id
    missing = joined.filter(pl.col("level_id").is_null())

    # Step 5: emit notices
    notices: list[Notice] = []
    for row in missing.iter_rows(named=True):
        stop_row = stops.filter(pl.col("stop_id") == row["stop_id"])
        csv_row_number = stop_row[0, "_csv_row_number"] if not stop_row.is_empty() else None
        notices.append(Notice(
            code="missing_level_id",
            severity="ERROR",
            csv_row_number=csv_row_number,
            stop_id=row["stop_id"],
            stop_name=row.get("stop_name"),
        ))
    return notices
```

The `iter_rows` at the end is acceptable here because the number of offending stops is expected to be small. For the join and filter steps, Polars expressions are used for efficiency.

### Empty string vs. null for `level_id`

In the Java framework, `hasLevelId()` returns false when the field has not been set (i.e., was null/absent in CSV) and typically also for empty strings since the framework's string field parsing normalizes empty CSV values to absent. In the Python implementation:

- If `level_id` is loaded as a Polars `Utf8` column, empty strings `""` should be treated as null using a normalization step at load time (replacing `""` with `null` for optional string columns).
- Confirm that `loading.py` already normalizes empty strings to null for optional string fields. If it does, then `is_null()` correctly captures both null and empty-string cases.
- If load-time normalization does not cover this, add `| (pl.col("level_id") == "")` to the filter predicate.

### `csv_row_number` field

The Java notice captures the 1-based CSV row number of the stop record. In the Python implementation, the orchestrator must store row numbers during CSV loading (e.g., as a `_csv_row_number` column added during loading). If the row number is not available, emit the notice without it rather than failing — but prefer preserving it for parity with the Java output.

### Pathway mode enum values

| Name | Integer value |
|---|---|
| WALKWAY | 1 |
| STAIRS | 2 |
| MOVING_SIDEWALK | 3 |
| ESCALATOR | 4 |
| ELEVATOR | 5 |
| FARE_GATE | 6 |
| EXIT_GATE | 7 |

The filter condition is `pathway_mode == 5`. After the schema cast in `loading.py`, `pathway_mode` should already be an integer column.

### No Polars needed for guard clauses

Table-presence guards (`"pathways" not in feed`, `"stops" not in feed`) and the empty-elevators early exit are plain Python and should precede any Polars operations.

### Relationship to other validators

- `GtfsStopLevelIdForeignKeyValidator` separately validates that `stops.level_id` values reference existing `levels.txt` records. This validator does not duplicate that check.
- This validator is the only place that enforces the conditional requirement: `level_id` is required on stops that are elevator endpoints.
