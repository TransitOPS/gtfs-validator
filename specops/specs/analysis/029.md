# Analysis: LocationTypeSingleEntityValidator

## 1. Purpose

Validates that the `parent_station` field in `stops.txt` is present or absent as required by each row's `location_type`.

## 2. Input tables

| Table | Columns used |
|---|---|
| `stops.txt` | `stop_id`, `stop_name`, `location_type`, `parent_station`, `platform_code`, `csvRowNumber` |

### Key relationships

- `location_type` is an enum: STOP (0), STATION (1), ENTRANCE (2), GENERIC_NODE (3), BOARDING_AREA (4).
- `parent_station` is an optional FK reference to another row in `stops.txt`.
- This is a single-entity (row-level) validator -- each row is checked independently.

## 3. Validation logic

For each row in `stops.txt`:

1. **If `parent_station` is present (non-null, non-empty)**:
   a. If `location_type` is STATION (1), emit `station_with_parent_station` (ERROR).
   b. Otherwise, no error -- stations should not have a parent, but all other types may.

2. **If `parent_station` is absent (null or empty)**:
   a. If `location_type` is STOP (0) **and** `platform_code` is non-empty, emit `platform_without_parent_station` (INFO). This is a stop that acts as a platform (has `platform_code`) but lacks a parent station.
   b. If `location_type` is STOP (0) and `platform_code` is empty/null, no notice -- an isolated stop without a parent is valid.
   c. If `location_type` is ENTRANCE (2), GENERIC_NODE (3), or BOARDING_AREA (4), emit `location_without_parent_station` (ERROR). These types always require a parent station.
   d. If `location_type` is STATION (1), no notice -- stations are not expected to have a parent.

## 4. Notices emitted

### `station_with_parent_station` (ERROR)

A station (location_type=1) must not have a `parent_station`.

| Field | Type | Description |
|---|---|---|
| `csvRowNumber` | int | Row number of the faulty record |
| `stopId` | string | The `stop_id` of the station |
| `stopName` | string | The `stop_name` of the station |
| `parentStation` | string | The `parent_station` value that should not be set |

### `location_without_parent_station` (ERROR)

An entrance, generic node, or boarding area is missing the required `parent_station` field.

| Field | Type | Description |
|---|---|---|
| `csvRowNumber` | int | Row number of the faulty record |
| `stopId` | string | The `stop_id` of the location |
| `stopName` | string | The `stop_name` of the location |
| `locationType` | int | The numeric `location_type` value (2, 3, or 4) |

### `platform_without_parent_station` (INFO)

A stop with `platform_code` set (indicating it is a platform) has no `parent_station`. This is less severe than `location_without_parent_station` because a stop without `platform_code` may legitimately be an isolated stop.

| Field | Type | Description |
|---|---|---|
| `csvRowNumber` | int | Row number of the faulty record |
| `stopId` | string | The `stop_id` of the platform |
| `stopName` | string | The `stop_name` of the platform |

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `stops.txt` missing | Validator does not run (no data to iterate) |
| `stops.txt` is empty (no rows) | No notices emitted |
| `location_type` is STOP (0) with no `platform_code` and no `parent_station` | No notice -- valid isolated stop |
| `location_type` is STOP (0) with `platform_code` set and `parent_station` set | No notice -- valid platform with parent |
| `location_type` is STATION (1) with no `parent_station` | No notice -- correct |
| `location_type` is STATION (1) with `parent_station` set | ERROR: `station_with_parent_station` |
| `location_type` is ENTRANCE (2), GENERIC_NODE (3), or BOARDING_AREA (4) with `parent_station` set | No notice -- correct |
| `location_type` is ENTRANCE (2), GENERIC_NODE (3), or BOARDING_AREA (4) without `parent_station` | ERROR: `location_without_parent_station` |
| `location_type` defaults to 0 (STOP) when column is missing or value is empty | Follows STOP logic (check `platform_code`) |
| `platform_code` is null/empty | Treated as empty; stop without platform_code and without parent is valid |

## 6. Test contracts

### `stationWithParentStation`

- **Setup**: A stop with `stop_id="s0"`, `location_type=STATION`, `stop_name="Stop 0"`.
- **Without parent_station**: No notices.
- **With parent_station="parent"**: Exactly one `StationWithParentStationNotice(csvRowNumber=1, stopId="s0", stopName="Stop 0", parentStation="parent")`.

### `platformWithoutParentStation`

- **Setup**: A stop with `stop_id="s0"`, `location_type=STOP`, `stop_name="Stop 0"`, `platform_code="1"`.
- **With parent_station="parent"**: No notices.
- **With parent_station=null**: Exactly one `PlatformWithoutParentStationNotice(csvRowNumber=1, stopId="s0", stopName="Stop 0")`.
- **With platform_code=null and parent_station=null**: No notices (not identified as a platform).

### `locationWithoutParentStationNotice`

- **Setup**: Iterates over ENTRANCE, GENERIC_NODE, BOARDING_AREA.
- **For each, with parent_station="parent"**: No notices.
- **For each, with parent_station=null**: Exactly one `LocationWithoutParentStationNotice(csvRowNumber=1, stopId="s0", stopName="Stop 0", locationType=<numeric value>)`.

## 7. Implementation notes

### Polars approach

This validator is well-suited to vectorized Polars filtering. Rather than iterating row-by-row, the three notice types map to three filtered subsets:

1. **`station_with_parent_station`**: Filter where `location_type == 1` AND `parent_station` is non-null/non-empty.

2. **`platform_without_parent_station`**: Filter where `location_type == 0` AND `parent_station` is null/empty AND `platform_code` is non-null/non-empty.

3. **`location_without_parent_station`**: Filter where `location_type` is in `{2, 3, 4}` AND `parent_station` is null/empty.

Each filtered subset produces one notice per row with the corresponding fields.

### Considerations

- **Null vs empty semantics**: In Java, `hasParentStation()` returns false when the field is unset (null or empty string). In Polars, the loading phase should normalize empty strings to null, so the check becomes a simple `.is_null()` test. Similarly, `platformCode().isEmpty()` should map to a null-or-empty check.
- **location_type default**: Per GTFS spec, when `location_type` is omitted the default is 0 (STOP). The schema/loading layer should handle this default, so the validator can assume the column always has a valid integer.
- **Single-table validator**: This only reads `stops.txt`. No joins are needed.
- **Performance**: Three simple column filters over one table. Very efficient even for large feeds.
