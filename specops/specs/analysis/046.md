# Analysis: PickupDropOffTypeValidator

## 1. Purpose

Validates that the `start_pickup_drop_off_window` and `end_pickup_drop_off_window` fields in `stop_times.txt` are not set when `pickup_type` is `0` (REGULAR) or `3` (ON_REQUEST_TO_DRIVER), and are not set when `drop_off_type` is `0` (REGULAR).

## 2. Input tables

| Table | Columns used |
|---|---|
| `stop_times.txt` | `csv_row_number`, `pickup_type`, `drop_off_type`, `start_pickup_drop_off_window`, `end_pickup_drop_off_window` |

Only `stop_times.txt` is read. All five columns are optional; the validator guards on the presence of the window columns in the header before running.

## 3. Validation logic

### Step 1: Guard — skip unless at least one window column is present

`shouldCallValidate()` returns `false` (skip entirely) unless `stop_times.txt` has at least one of `start_pickup_drop_off_window` or `end_pickup_drop_off_window` in its header.

In Python: if `"stop_times"` is not in the feed dict, or the `stop_times` DataFrame has neither `start_pickup_drop_off_window` nor `end_pickup_drop_off_window` as a column, return `[]` immediately.

### Step 2: For each row in `stop_times.txt`, perform two independent sub-checks

#### Sub-check A — forbidden pickup type with window fields

Trigger condition (all must be true):

- At least one of `start_pickup_drop_off_window` or `end_pickup_drop_off_window` is non-null for this row.
- `pickup_type` equals `0` (REGULAR) or `3` (ON_REQUEST_TO_DRIVER).

If triggered, emit `forbidden_pickup_type` with:

- `csvRowNumber`: the row number of this `stop_times` record.
- `startPickupDropOffWindow`: the value of `start_pickup_drop_off_window` for this row (may be null if only the end window is set).
- `endPickupDropOffWindow`: the value of `end_pickup_drop_off_window` for this row (may be null if only the start window is set).

#### Sub-check B — forbidden drop-off type with window fields

Trigger condition (all must be true):

- At least one of `start_pickup_drop_off_window` or `end_pickup_drop_off_window` is non-null for this row.
- `drop_off_type` equals `0` (REGULAR).

If triggered, emit `forbidden_drop_off_type` with:

- `csvRowNumber`: the row number of this `stop_times` record.
- `startPickupDropOffWindow`: the value of `start_pickup_drop_off_window` for this row.
- `endPickupDropOffWindow`: the value of `end_pickup_drop_off_window` for this row.

Note: Both sub-checks are independent — a single row can trigger two notices (one for pickup, one for drop-off) if both conditions are violated simultaneously.

## 4. Notices emitted

### `forbidden_pickup_type` (ERROR)

Emitted when `start_pickup_drop_off_window` or `end_pickup_drop_off_window` is present on a row where `pickup_type` is REGULAR (0) or ON_REQUEST_TO_DRIVER (3). These pickup type values are incompatible with demand-responsive window fields.

| Field | Type | Source | Description |
|---|---|---|---|
| `csvRowNumber` | integer | `stop_times.csv_row_number` | Row number of the offending record |
| `startPickupDropOffWindow` | time or null | `stop_times.start_pickup_drop_off_window` | Start of the pickup/drop-off window; null if that field is absent or unset |
| `endPickupDropOffWindow` | time or null | `stop_times.end_pickup_drop_off_window` | End of the pickup/drop-off window; null if that field is absent or unset |

Severity: ERROR.

Java class: `ForbiddenPickupTypeNotice`.

Referenced files: `stop_times.txt`.

The notice code in Python should be `forbidden_pickup_type`.

### `forbidden_drop_off_type` (ERROR)

Emitted when `start_pickup_drop_off_window` or `end_pickup_drop_off_window` is present on a row where `drop_off_type` is REGULAR (0). Regular drop-off type is incompatible with demand-responsive window fields.

| Field | Type | Source | Description |
|---|---|---|---|
| `csvRowNumber` | integer | `stop_times.csv_row_number` | Row number of the offending record |
| `startPickupDropOffWindow` | time or null | `stop_times.start_pickup_drop_off_window` | Start of the pickup/drop-off window; null if that field is absent or unset |
| `endPickupDropOffWindow` | time or null | `stop_times.end_pickup_drop_off_window` | End of the pickup/drop-off window; null if that field is absent or unset |

Severity: ERROR.

Java class: `ForbiddenDropOffTypeNotice`.

Referenced files: `stop_times.txt`.

The notice code in Python should be `forbidden_drop_off_type`.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `stop_times.txt` absent from feed | Guard returns false; no notices emitted. |
| Neither `start_pickup_drop_off_window` nor `end_pickup_drop_off_window` column in header | Guard returns false; no notices emitted. |
| `stop_times.txt` empty | No rows to evaluate; no notices. |
| Both window columns present but both null on a row | Neither sub-check fires; no notices for that row. |
| Only `start_pickup_drop_off_window` set (end is null) | `hasStartPickupDropOffWindow()` is true; window condition is satisfied; sub-checks may fire based on type values. Notice fields carry the null `endPickupDropOffWindow`. |
| Only `end_pickup_drop_off_window` set (start is null) | `hasEndPickupDropOffWindow()` is true; window condition is satisfied; sub-checks may fire. Notice fields carry the null `startPickupDropOffWindow`. |
| `pickup_type` is null | Sub-check A does not fire for that row (null does not equal REGULAR or ON_REQUEST_TO_DRIVER). |
| `drop_off_type` is null | Sub-check B does not fire for that row (null does not equal REGULAR). |
| `pickup_type=1` (NOT_AVAILABLE) with window set | Sub-check A does not fire; value 1 is not in the forbidden set {0, 3}. |
| `pickup_type=2` (MUST_PHONE) with window set | Sub-check A does not fire; value 2 is not in the forbidden set {0, 3}. |
| `drop_off_type=1` (NOT_AVAILABLE) with window set | Sub-check B does not fire; only value 0 is forbidden for drop-off. |
| `drop_off_type=2` (MUST_PHONE) with window set | Sub-check B does not fire; only value 0 is forbidden for drop-off. |
| `drop_off_type=3` (ON_REQUEST_TO_DRIVER) with window set | Sub-check B does not fire; only value 0 is forbidden for drop-off. |
| `pickup_type=0` and `drop_off_type=0` with window set | Both sub-checks fire; two distinct notices emitted for that row. |
| `pickup_type=0` and `drop_off_type=1` with window set | Only sub-check A fires; one notice emitted. |
| `pickup_type=3` and `drop_off_type=0` with window set | Sub-check A fires (ON_REQUEST_TO_DRIVER); sub-check B fires (REGULAR drop-off); two notices emitted. |
| Default pickup_type when not set in builder | Java `GtfsStopTime` defaults unset enum fields to ordinal 0 (REGULAR). If the Python schema also defaults missing `pickup_type` to 0, this must be accounted for carefully — or treat null as absent and do not trigger. |

Expected: exactly 1 notice of type `ForbiddenPickupTypeNotice` with `csvRowNumber=3`, `startPickupDropOffWindow="08:00:00"`, `endPickupDropOffWindow="09:00:00"`.

- Stop time row: `csv_row_number=4`, `pickup_type=1` (NOT_AVAILABLE), no window fields set.

## 7. Implementation notes

### Algorithm choice

The logic is per-row and does not require cross-row joins or cross-table lookups. Both sub-checks operate on columns of `stop_times.txt` only. Polars filter expressions are well-suited for vectorized evaluation of both sub-checks independently.

### Recommended Polars approach

Compute the window-present condition first, then apply type filters for each sub-check independently:

```python
stop_times = feed["stop_times"]

# Determine which window columns are actually present
has_start = "start_pickup_drop_off_window" in stop_times.columns
has_end = "end_pickup_drop_off_window" in stop_times.columns

# Window present = at least one window column is non-null
window_expr = pl.lit(False)
if has_start:
    window_expr = window_expr | pl.col("start_pickup_drop_off_window").is_not_null()
if has_end:
    window_expr = window_expr | pl.col("end_pickup_drop_off_window").is_not_null()

# Sub-check A: forbidden pickup type
if "pickup_type" in stop_times.columns:
    pickup_violations = stop_times.filter(
        window_expr
        & pl.col("pickup_type").is_in([0, 3])  # REGULAR or ON_REQUEST_TO_DRIVER
    )
    for row in pickup_violations.iter_rows(named=True):
        notices.append(ForbiddenPickupTypeNotice(...))

# Sub-check B: forbidden drop-off type
if "drop_off_type" in stop_times.columns:
    dropoff_violations = stop_times.filter(
        window_expr
        & pl.col("drop_off_type").eq(0)  # REGULAR only
    )
    for row in dropoff_violations.iter_rows(named=True):
        notices.append(ForbiddenDropOffTypeNotice(...))
```

### Column presence guard

- The gate condition for the whole validator is: `stop_times` is present in the feed AND has at least one of `start_pickup_drop_off_window` or `end_pickup_drop_off_window`.
- If `pickup_type` column is absent from the DataFrame, sub-check A is skipped entirely.
- If `drop_off_type` column is absent from the DataFrame, sub-check B is skipped entirely.
- If a window column is absent, treat it as all-null in the window condition.

### Null semantics

- `pickup_type` null → does not match 0 or 3; sub-check A does not fire.
- `drop_off_type` null → does not match 0; sub-check B does not fire.
- `start_pickup_drop_off_window` null → does not contribute to window-present condition.
- `end_pickup_drop_off_window` null → does not contribute to window-present condition.
- When both window columns are null on a row, the window-present condition is false and neither sub-check fires even if type values are forbidden.
- Notice fields `startPickupDropOffWindow` and `endPickupDropOffWindow` carry the raw row values, which may be null.

### Default value caution for `pickup_type` and `drop_off_type`

In Java, an unset enum field defaults to ordinal 0 (REGULAR). In the Python implementation, the loading layer should represent an absent or unparsed `pickup_type` as null (not 0). This avoids false positives on rows that simply do not set `pickup_type` explicitly. The sub-check should only fire when the integer column value is explicitly 0 or 3 (for pickup) or 0 (for drop-off).

### Time field representation

In Java, the window fields are `GtfsTime` objects. After loading in Python/Polars, these fields will be stored as integer seconds-since-midnight or as string values depending on the schema definition. The notice carries these values as-is (whatever the loaded column holds). No arithmetic on the time values is performed by this validator.

| NOT_AVAILABLE | 1 |

Forbidden pickup types: {0, 3}. Forbidden drop-off type: {0}.
