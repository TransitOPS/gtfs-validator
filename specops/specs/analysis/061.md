# Analysis: StopTimeIncreasingDistanceValidator

## 1. Purpose

For every trip in `stop_times.txt`, verify that `shape_dist_traveled` strictly increases
from one stop time to the next (when rows are ordered by `stop_sequence`), skipping any
stop time rows that lack a `stop_id`.

## 2. Input tables

| Table | Columns used |
|---|---|
| `stop_times.txt` | `csv_row_number`, `trip_id`, `stop_id`, `stop_sequence`, `shape_dist_traveled` |

This is a single-table validator operating on `stop_times.txt` only. No cross-table joins
are performed.

### Column semantics

- `trip_id` — string; used to group stop times into per-trip sequences.
- `stop_id` — optional string; a null value signals a flexible-service or location-based
  row that must be excluded from the distance comparison.
- `stop_sequence` — integer; defines the ordering of stop times within a trip.
- `shape_dist_traveled` — optional float; distance along the shape from the first shape
  point to this stop time. Null when not provided for a row.
- `csv_row_number` — 1-based integer row position in the raw CSV file.

## 3. Validation logic

The Java validator is a `FileValidator` that operates over all rows of `stop_times.txt`.
It groups rows by `trip_id` (using `table.byTripIdMap()`), then iterates each trip's stop
times in `stop_sequence` order (sorted automatically via `@SequenceKey` on the field).

### Guard clause: `shouldCallValidate`

The validator short-circuits and emits nothing if either of these columns is absent from
the file header:

- `stop_id`
- `shape_dist_traveled`

If both columns are present, validation proceeds.

### Per-trip distance ordering check

For each trip (group of rows sharing a `trip_id`), iterate the rows in `stop_sequence`
order, tracking the most recently seen row that is "eligible" (i.e., has a `stop_id`).
Call that tracked row `prev`.

For each row `curr`:

1. **Skip if `curr` has no `stop_id`** — the row is a flexible-service or location-group
   entry. Do not update `prev`, do not compare.
2. If `prev` is not null and both `prev.shape_dist_traveled` and
   `curr.shape_dist_traveled` are non-null, and
   `prev.shape_dist_traveled >= curr.shape_dist_traveled`:
   - Emit `decreasing_or_equal_stop_time_distance` (ERROR).
3. Set `prev = curr` (the current row becomes the new previous, regardless of whether it
   had a `shape_dist_traveled` value).

Key properties of the algorithm:

- The comparison is `>=`, so equal values trigger the notice as well as strictly
  decreasing values.
- Rows without `stop_id` are skipped entirely — they are neither compared nor tracked as
  `prev`. This means two consecutive rows with `stop_id` are compared directly even if
  there are multiple null-`stop_id` rows between them.
- `prev` is updated to `curr` only after the comparison, and only when `curr` has a
  `stop_id`. A row without `stop_id` is never stored as `prev`.
- When `curr` has a `stop_id` but no `shape_dist_traveled`, `prev` is still updated to
  `curr`. However, since the condition requires `prev.hasShapeDistTraveled()` on the
  next iteration, no notice is emitted if the new `prev` lacks a distance value.

### Algorithm (pseudocode)

```
for trip_id, stop_times_in_sequence_order in grouped_by_trip:
    prev = None
    for curr in stop_times_in_sequence_order:
        if curr.stop_id is None:
            continue                   # skip; do not update prev
        if (prev is not None
                and prev.shape_dist_traveled is not None
                and curr.shape_dist_traveled is not None
                and prev.shape_dist_traveled >= curr.shape_dist_traveled):
            emit DecreasingOrEqualStopTimeDistanceNotice(
                trip_id=curr.trip_id,
                stop_id=curr.stop_id,
                csv_row_number=curr.csv_row_number,
                shape_dist_traveled=curr.shape_dist_traveled,
                stop_sequence=curr.stop_sequence,
                prev_csv_row_number=prev.csv_row_number,
                prev_shape_dist_traveled=prev.shape_dist_traveled,
                prev_stop_sequence=prev.stop_sequence,
            )
        prev = curr
```

## 4. Notices emitted

### `decreasing_or_equal_stop_time_distance` (ERROR)

Emitted when two consecutive eligible stop times in a trip (ordered by `stop_sequence`,
excluding null-`stop_id` rows) have a non-increasing `shape_dist_traveled`.

| Field | Type | Source | Description |
|---|---|---|---|
| `trip_id` | string | `stop_times.trip_id` | Trip identifier for the offending pair |
| `stop_id` | string | `stop_times.stop_id` | Stop ID of the current (offending) row |
| `csv_row_number` | integer | `stop_times.csv_row_number` | 1-based row number of the current offending row |
| `shape_dist_traveled` | float | `stop_times.shape_dist_traveled` | Distance value of the current (offending) row |
| `stop_sequence` | integer | `stop_times.stop_sequence` | Stop sequence of the current (offending) row |
| `prev_csv_row_number` | integer | `stop_times.csv_row_number` | 1-based row number of the previous eligible row |
| `prev_shape_dist_traveled` | float | `stop_times.shape_dist_traveled` | Distance value of the previous eligible row |
| `prev_stop_sequence` | integer | `stop_times.stop_sequence` | Stop sequence of the previous eligible row |

Condition: both `stop_id` fields are non-null, both `shape_dist_traveled` values are
non-null, and `prev.shape_dist_traveled >= curr.shape_dist_traveled`.

### Notice code mapping

| Java class | Python notice code |
|---|---|
| `DecreasingOrEqualStopTimeDistanceNotice` | `decreasing_or_equal_stop_time_distance` |

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `stop_times.txt` absent from feed | Return `[]`; no notices. |
| `stop_times.txt` present but empty | Return `[]`; no notices. |
| `stop_id` column absent from file header | `shouldCallValidate()` returns false; return `[]`. |
| `shape_dist_traveled` column absent from file header | `shouldCallValidate()` returns false; return `[]`. |
| Row with `stop_id` present but `shape_dist_traveled` null | Row updates `prev` but the condition `prev.hasShapeDistTraveled()` prevents comparison on the next iteration. No notice. |
| Row with `stop_id` null | Skipped entirely; `prev` is not updated. |
| Two consecutive null-`stop_id` rows between two eligible rows | The two eligible rows are compared directly; the null-`stop_id` rows are invisible to the algorithm. |
| Exactly equal `shape_dist_traveled` between two consecutive eligible rows | Notice IS emitted (condition is `>=`, not `>`). |
| Trip with a single eligible stop time | `prev` is never set before the only row; no comparison possible. No notice. |
| Trip where only one eligible row has `shape_dist_traveled` | Condition requires both `prev` and `curr` to have values; no notice. |
| First eligible row has no `shape_dist_traveled` | `prev` is set to this row; on next eligible row, `prev.hasShapeDistTraveled()` is false so no notice is emitted. |
| Null-`stop_id` row at the very end of a trip | Ignored; does not affect the result. |
| Multiple trips | Checks are scoped per-trip; `prev` is reset to `None` for each new trip. |
| Multiple offending consecutive pairs in one trip | One notice per offending pair. |
| Stop times in raw CSV not in `stop_sequence` order | Java sorts via `@SequenceKey`; Python must sort by `stop_sequence` within each trip group before running the algorithm. |

## 6. Test contracts

### `increasingDistanceAlongShapeShouldNotGenerateNotice`

- Input: three stop times for `"first trip"` with distances 10.0, 45.0, 64.0 and
  sequences 2, 42, 46.
- Expected: no notices.
- Covers: normal strictly increasing case.

### `lastShapeWithDecreasingDistanceAlongShapeShouldGenerateNotice`

- Input: three stop times for `"first trip"` with distances 10.0, 45.0, 4.0 and
  sequences 2, 42, 46.
- Expected: exactly one `DecreasingOrEqualStopTimeDistanceNotice`:
  - `trip_id = "first trip"`, `stop_id = "s2"`, `csv_row_number = 3`,
    `shape_dist_traveled = 4.0`, `stop_sequence = 46`,
    `prev_csv_row_number = 2`, `prev_shape_dist_traveled = 45.0`,
    `prev_stop_sequence = 42`.
- Covers: decreasing distance at the last stop.

### `twoShapesWithTheSameDistanceShouldGenerateNotice`

- Input: three stop times for `"first trip"` with distances 10.0, 45.0, 45.0 and
  sequences 2, 42, 46.
- Expected: exactly one `DecreasingOrEqualStopTimeDistanceNotice`:
  - `trip_id = "first trip"`, `stop_id = "s2"`, `csv_row_number = 3`,
    `shape_dist_traveled = 45.0`, `stop_sequence = 46`,
    `prev_csv_row_number = 2`, `prev_shape_dist_traveled = 45.0`,
    `prev_stop_sequence = 42`.
- Covers: equal (not just strictly decreasing) values also trigger a notice.

### `oneIntermediateShapeWithDecreasingDistanceAlongShapeShouldGenerateNotice`

- Input: three stop times for `"first trip"` with distances 10.0, 8.6, 46.0 and
  sequences 2, 42, 46.
- Expected: exactly one notice for the intermediate row (sequences 2 vs 42):
  - `trip_id = "first trip"`, `stop_id = "s1"`, `csv_row_number = 2`,
    `shape_dist_traveled = 8.6`, `stop_sequence = 42`,
    `prev_csv_row_number = 1`, `prev_shape_dist_traveled = 10.0`,
    `prev_stop_sequence = 2`.
- Covers: the offending row need not be the last; the subsequent recovery does not
  suppress the notice.

### `oneIntermediateShapeWithoutStopShouldBeIgnored`

- Input: four stop times for `"first trip"`, sequences 1–4, distances 0.0, 45.0, 4.0,
  64.0. The third row (`stop_sequence=3`) has `stop_id=null`.
- Expected: no notices.
- Covers: a null-`stop_id` row with a decreasing distance is silently skipped. The fourth
  row (64.0) is compared to the second (45.0), which is increasing.

### `oneIntermediateShapeWithoutStopAndPreviousDecreasingDistanceShouldGenerateNotice`

- Input: four stop times for `"first trip"`, sequences 1–4, distances 0.0, 85.0, 444.0,
  64.0. The third row has `stop_id=null`.
- Expected: exactly one notice for row 4 (64.0) compared to row 2 (85.0):
  - `trip_id = "first trip"`, `stop_id = "s3"`, `csv_row_number = 4`,
    `shape_dist_traveled = 64.0`, `stop_sequence = 4`,
    `prev_csv_row_number = 2`, `prev_shape_dist_traveled = 85.0`,
    `prev_stop_sequence = 2`.
- Covers: null-`stop_id` row in the middle does not reset the tracking of `prev`; the
  previous eligible row (row 2) is still used for comparison.

### `multipleIntermediateShapeWithoutStopAndPreviousDecreasingDistanceShouldGenerateNotice`

- Input: five stop times for `"first trip"`, sequences 1–5, distances 0.0, 85.0, 114.0,
  444.0, 64.0. Rows 3 and 4 have `stop_id=null`.
- Expected: exactly one notice for row 5 (64.0) compared to row 2 (85.0):
  - `trip_id = "first trip"`, `stop_id = "s3"`, `csv_row_number = 5`,
    `shape_dist_traveled = 64.0`, `stop_sequence = 5`,
    `prev_csv_row_number = 2`, `prev_shape_dist_traveled = 85.0`,
    `prev_stop_sequence = 2`.
- Covers: multiple consecutive null-`stop_id` rows are all skipped; `prev` remains at the
  last eligible row.

### `lastShapeWithoutStopShouldBeIgnored`

- Input: six stop times for `"first trip"`, sequences 1–6, distances 0.0, 2.0, 114.0,
  444.0, 3.0, 1.0. Rows 3, 4, and 6 have `stop_id=null`.
- Expected: no notices.
- Covers: row 5 (3.0, has `stop_id`) is compared to row 2 (2.0), which is increasing.
  Row 6 (1.0, no `stop_id`) is skipped entirely. No notice results.

### Missing from the Java test suite

The Java tests do not cover:

- Empty `stop_times.txt`.
- The `shouldCallValidate` guard: feed where `shape_dist_traveled` column is absent.
- The `shouldCallValidate` guard: feed where `stop_id` column is absent.
- A trip with only one eligible stop time (no comparison possible).
- A row where `stop_id` is present but `shape_dist_traveled` is null (updates `prev`
  but does not trigger a notice on the next row).
- Multiple trips in the same feed (per-trip isolation).
- Stop times provided out of `stop_sequence` order in the raw CSV.

## 7. Implementation notes

### Algorithm strategy

The check requires stateful, ordered traversal within each trip group. Per AGENTS.md
guidelines, plain Python is preferred over forced Polars for graph/interval/stateful logic.

The recommended pattern is to sort globally by `["trip_id", "stop_sequence"]`, then use
`partition_by("trip_id", maintain_order=True)` and iterate over per-trip DataFrames with
`iter_rows(named=True)`. This avoids converting the full DataFrame to a Python list while
still supporting per-row state tracking.

```python
sorted_st = stop_times.sort(["trip_id", "stop_sequence"])
for trip_df in sorted_st.partition_by("trip_id", maintain_order=True):
    prev = None
    for row in trip_df.iter_rows(named=True):
        if row["stop_id"] is None:
            continue
        if (
            prev is not None
            and prev["shape_dist_traveled"] is not None
            and row["shape_dist_traveled"] is not None
            and prev["shape_dist_traveled"] >= row["shape_dist_traveled"]
        ):
            # emit notice
            ...
        prev = row
```

### Guard clause ordering

1. `"stop_times"` not in feed — return `[]`.
2. `stop_times` DataFrame is empty — return `[]`.
3. `"stop_id"` column absent from DataFrame — return `[]`.
4. `"shape_dist_traveled"` column absent from DataFrame — return `[]`.
5. Sort globally by `["trip_id", "stop_sequence"]`.
6. Partition by `trip_id` and run per-trip algorithm.
7. Return all collected notices.

### Column absence handling

The Java `shouldCallValidate()` guard checks whether both `stop_id` and
`shape_dist_traveled` are present as columns in the table. In Python, check for column
presence in the DataFrame before proceeding. If the loading layer always produces
null-filled columns for absent optional fields, check whether all values are null as a
proxy — or, preferably, track which columns were actually present in the raw file headers
during loading and expose that information through `ValidationContext`.

### `shape_dist_traveled` type

In the Python loading layer, `shape_dist_traveled` should be loaded as `pl.Float64` (or
left as null when absent). Comparisons are floating-point `>=`.

### Feed dict keys

- `"stop_times"` — `stop_times.txt`

### Validator registration

Required tables: `["stop_times"]`.

Activation condition: `stop_times.txt` is present, and both `stop_id` and
`shape_dist_traveled` columns are present (non-absent from the file header).
