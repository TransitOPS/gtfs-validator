# Analysis: MissingCalendarAndCalendarDateValidator

## 1. Purpose

Validates that at least one of `calendar.txt` or `calendar_dates.txt` is present in the GTFS feed; emits an ERROR if both files are absent.

## 2. Input tables

| Table | Columns used |
|---|---|
| `calendar.txt` | None (only file presence is checked) |
| `calendar_dates.txt` | None (only file presence is checked) |

No column values are read. The validator only inspects whether each file was found in the feed at all.

## 3. Validation logic

1. **Check calendar.txt presence**: Determine whether `calendar.txt` is absent from the feed (i.e., its table status is `MISSING_FILE`).
2. **Check calendar_dates.txt presence**: Determine whether `calendar_dates.txt` is absent from the feed (i.e., its table status is `MISSING_FILE`).
3. **If both are absent**: Emit `missing_calendar_and_calendar_date_files` (ERROR).
4. **Otherwise**: No notices. At least one file being present satisfies the requirement.

### Critical distinction: missing vs. empty

`isMissingFile()` in the Java framework checks strictly for `TableStatus.MISSING_FILE`. A file that is present but has zero data rows (status `PARSABLE_HEADERS_AND_ROWS` with an empty row list) or is completely empty (status `EMPTY_FILE`) does NOT count as missing. Only total absence of the file from the feed triggers this check.

In the Python implementation, the equivalent is checking whether the key is absent from the `feed` dict passed to the validator. An empty DataFrame for a key that is present does not trigger this notice.

## 4. Notices emitted

### `missing_calendar_and_calendar_date_files` (ERROR)

Neither `calendar.txt` nor `calendar_dates.txt` is present in the feed. At least one of the two files must be provided for service schedules to be defined.

| Field | Type | Description |
|---|---|---|
| _(none)_ | — | This notice carries no additional fields. |

Conditions: Fires exactly once when both `calendar.txt` and `calendar_dates.txt` are missing from the feed.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| Both files missing | ERROR notice emitted |
| `calendar.txt` present, `calendar_dates.txt` missing | No notice |
| `calendar.txt` missing, `calendar_dates.txt` present | No notice |
| Both files present | No notice |
| `calendar.txt` present but empty (zero rows, no headers) | No notice — file is present, not missing |
| `calendar.txt` present with headers but zero data rows | No notice — file is present, not missing |
| `calendar_dates.txt` present but empty | No notice — file is present, not missing |
| `calendar.txt` has invalid headers | No notice — file was found, just unparseable |

The guard is purely about file presence. Content, row count, and parse validity are irrelevant to this validator.

## 6. Test contracts

### `bothFilesProvidedShouldNotGenerateNotice`

- **Setup**: `calendar.txt` has one row (service_id="WEEK", weekdays only, 2021-01-04 to 2021-04-10). `calendar_dates.txt` has one row (service_id="WEEK", date=epoch day 24354, exception_type=2).
- **Expected**: No notices.

### `calendarOnlyProvidedShouldNotGenerateNotice`

- **Setup**: `calendar.txt` has one valid row. `calendar_dates.txt` is provided but contains zero entities (empty list, status `PARSABLE_HEADERS_AND_ROWS` with no rows).
- **Expected**: No notices. An empty-but-present `calendar_dates.txt` does not count as missing.

### `calendarDateOnlyProvidedShouldNotGenerateNotice`

- **Setup**: `calendar.txt` is provided with zero entities (empty list). `calendar_dates.txt` has one valid row.
- **Expected**: No notices. An empty-but-present `calendar.txt` does not count as missing.

### `bothMissingFilesShouldGenerateNotice`

- **Setup**: Both tables constructed with `TableStatus.MISSING_FILE` (no file was found in the feed at all).
- **Expected**: Exactly one `MissingCalendarAndCalendarDateFilesNotice`.

## 7. Implementation notes

### Approach

This validator requires no Polars operations. It is a pure presence check on the `feed` dict keys.

```python
def validate_missing_calendar_and_calendar_date(
    feed: dict[str, pl.DataFrame], ctx: ValidationContext
) -> list[Notice]:
    calendar_missing = "calendar" not in feed
    calendar_dates_missing = "calendar_dates" not in feed
    if calendar_missing and calendar_dates_missing:
        return [Notice(code="missing_calendar_and_calendar_date_files", severity="ERROR")]
    return []
```

### Key implementation considerations

- **Key naming**: In the Python feed dict, table keys use the filename stem without `.txt` (e.g., `"calendar"` and `"calendar_dates"`). Confirm the convention matches the rest of the codebase.
- **No column access**: Do not read any columns. Do not attempt to inspect row counts. The check is entirely on key presence.
- **No early return needed**: The logic is a single condition; no multi-stage guard is required.
- **Notice has no fields**: `MissingCalendarAndCalendarDateFilesNotice` is a zero-field notice. The Python dataclass should have only the `code` and `severity` attributes (or inherit them from the base Notice class with no additional fields).
- **Plain Python, no Polars**: No tabular operations are needed. Do not use Polars expressions for this validator.
