# Analysis: LocationHasStopTimesValidator

## 1. Purpose

Validates that stops (location_type=0) have stop times (warning if not), and that non-stop locations (stations, entrances, etc.) do not have stop times (error if they do), accounting for indirect references through location groups.

## 2. Input tables

| Table | Columns used |
|---|---|
| `stops.txt` | `stop_id`, `stop_name`, `location_type` |
| `stop_times.txt` | `stop_id`, `location_group_id` |
| `location_group_stops.txt` | `location_group_id`, `stop_id` |

### Key relationships

- `stop_times.stop_id` references `stops.stop_id` directly.
- `stop_times.location_group_id` references `location_groups.location_group_id`, which maps to stops via `location_group_stops.txt`.
- A stop is considered "referenced" if it appears in `stop_times.stop_id` directly OR if it belongs to a location group that is referenced by `stop_times.location_group_id`.

## 3. Validation logic

1. **Build the set of referenced stop IDs**:
   a. Collect all non-empty `stop_id` values from `stop_times.txt` into a set.
   b. Collect all non-empty `location_group_id` values from `stop_times.txt` into a set.
   c. For each location group ID found in step (b), look up all rows in `location_group_stops.txt` with that `location_group_id` and add their `stop_id` values to the set from step (a).

2. **Check each stop in `stops.txt`**:
   a. If `location_type == 0` (STOP):
      - Look up direct stop time references for this `stop_id` in `stop_times.txt`.
      - If the stop has no direct stop times AND the stop is not in the referenced set (from step 1), emit `stop_without_stop_time` (WARNING).
   b. If `location_type != 0` (STATION=1, ENTRANCE=2, GENERIC_NODE=3, BOARDING_AREA=4):
      - Look up direct stop time references for this `stop_id` in `stop_times.txt`.
      - If the stop has any direct stop times, emit `location_with_unexpected_stop_time` (ERROR).

### location_type values

| Value | Name |
|---|---|
| 0 | STOP (or empty/default) |
| 1 | STATION |
| 2 | ENTRANCE |
| 3 | GENERIC_NODE |
| 4 | BOARDING_AREA |

## 4. Notices emitted

| Code | Severity | Fields | Condition |
|---|---|---|---|
| `stop_without_stop_time` | WARNING | `csv_row_number` (int), `stop_id` (str), `stop_name` (str) | A stop (location_type=0) has no stop times, either directly or via a location group |
| `location_with_unexpected_stop_time` | ERROR | `csv_row_number` (int), `stop_id` (str), `stop_name` (str), `stop_time_csv_row_number` (int) | A non-stop location (location_type != 0) is directly referenced by a stop_time |

### Notice field details

- `csv_row_number`: Row number of the stop in `stops.txt`.
- `stop_id`: The `stop_id` of the offending stop.
- `stop_name`: The `stop_name` of the offending stop.
- `stop_time_csv_row_number`: (only for `location_with_unexpected_stop_time`) Row number of the first offending stop time in `stop_times.txt`.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `stops.txt` missing | Skip validation, no notices |
| `stop_times.txt` missing | Skip validation, no notices |
| `location_group_stops.txt` missing | Treat as empty; location group membership is not considered |
| `stops.txt` empty | No notices (no stops to check) |
| `stop_times.txt` empty | All stops with location_type=0 get a warning |
| `location_group_stops.txt` empty | No location group membership; only direct stop_time references count |
| Stop with location_type=0 referenced only via location group | No warning (the stop is considered referenced) |
| Stop with location_type=0 with both direct and group references | No warning |
| Stop with location_type=0 with no references at all | Warning |
| Station (location_type=1) with direct stop time reference | Error |
| Station (location_type=1) with no stop time reference | No notice |
| Entrance (location_type=2) with direct stop time reference | Error |
| Entrance (location_type=2) with no stop time reference | No notice |
| Non-stop location referenced only via location group (not directly in stop_times) | No error (the validator only checks direct `stop_id` references in stop_times for the error case) |
| Multiple stop times referencing a non-stop location | Only one error notice, using the first stop time's row number |
| `stop_times.location_group_id` column missing | Location group logic is skipped; only direct stop_id references matter |

## 7. Implementation notes

### Polars approach (recommended)

This validator involves set-building logic that is well-suited to Polars joins and anti-joins.

```python
def validate_location_has_stop_times(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
    stops = feed.get("stops")
    stop_times = feed.get("stop_times")
    if stops is None or stop_times is None:
        return []
    if stops.is_empty():
        return []

    location_group_stops = feed.get("location_group_stops")

    # Step 1: Build set of stop_ids referenced in stop_times (directly or via location groups)
    referenced_stop_ids: set[str] = set()
    if "stop_id" in stop_times.columns:
        referenced_stop_ids = set(
            stop_times.select("stop_id").drop_nulls().to_series().to_list()
        )

    if (
        "location_group_id" in stop_times.columns
        and location_group_stops is not None
        and not location_group_stops.is_empty()
    ):
        lg_ids = set(
            stop_times.select("location_group_id").drop_nulls().to_series().to_list()
        )
        if lg_ids:
            lg_stop_ids = (
                location_group_stops
                .filter(pl.col("location_group_id").is_in(list(lg_ids)))
                .select("stop_id")
                .drop_nulls()
                .to_series()
                .to_list()
            )
            referenced_stop_ids.update(lg_stop_ids)

    notices: list[Notice] = []

    # Step 2a: Stops (location_type=0) without any stop time reference
    actual_stops = stops.filter(
        (pl.col("location_type") == 0) | pl.col("location_type").is_null()
    )
    for row in actual_stops.iter_rows(named=True):
        if row["stop_id"] not in referenced_stop_ids:
            notices.append(Notice(
                code="stop_without_stop_time",
                severity=Severity.WARNING,
                csv_row_number=row["csvRowNumber"],
                stop_id=row["stop_id"],
                stop_name=row.get("stop_name", ""),
            ))

    # Step 2b: Non-stop locations with direct stop time references
    non_stops = stops.filter(
        pl.col("location_type").is_not_null() & (pl.col("location_type") != 0)
    )
    if not stop_times.is_empty() and "stop_id" in stop_times.columns:
        # Join non-stop locations with stop_times to find direct references
        bad = non_stops.join(
            stop_times.select("stop_id", "csvRowNumber").rename(
                {"csvRowNumber": "stop_time_csv_row_number"}
            ),
            on="stop_id",
            how="inner",
        )
        # Group by stop to get only the first stop_time row number
        if not bad.is_empty():
            first_bad = bad.group_by("stop_id").agg([
                pl.col("csvRowNumber").first(),
                pl.col("stop_name").first(),
                pl.col("stop_time_csv_row_number").min(),
            ])
            for row in first_bad.iter_rows(named=True):
                notices.append(Notice(
                    code="location_with_unexpected_stop_time",
                    severity=Severity.ERROR,
                    csv_row_number=row["csvRowNumber"],
                    stop_id=row["stop_id"],
                    stop_name=row["stop_name"],
                    stop_time_csv_row_number=row["stop_time_csv_row_number"],
                ))

    return notices
```

### Key considerations

- The Java validator iterates over all stops and checks each one; the Polars approach uses set membership and joins for efficiency.
- For the WARNING case, a stop is exempt if it is referenced either directly in `stop_times.stop_id` OR indirectly through a location group. Both paths must be checked.
- For the ERROR case, only direct `stop_id` references in `stop_times.txt` matter (non-stop locations referenced via `location_group_id` do not trigger this error).
- The Java code uses `stopTimeTable.byStopId()` which indexes by `stop_id` only, not `location_group_id`, confirming the asymmetry in how the two notices are triggered.
- `location_type` defaults to 0 (STOP) when empty/missing in the GTFS spec, so null values should be treated as 0.
- The `location_group_stops.txt` table is optional in GTFS; if absent, treat as empty.
- The `location_group_id` column in `stop_times.txt` is also optional; if absent, skip location group resolution.
- The `iter_rows` loops are acceptable because the number of problematic stops/locations is expected to be small relative to the total dataset.
