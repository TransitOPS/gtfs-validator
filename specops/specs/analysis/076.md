# Analysis: TransfersTripReferenceValidator

## 1. Purpose

Validates that when a `transfers.txt` entry references a trip via `from_trip_id` or `to_trip_id`, any corresponding route ID or stop ID on the same side of the transfer is actually associated with that trip.

## 2. Input tables

| Table | Columns used |
|---|---|
| `transfers.txt` | `from_trip_id`, `to_trip_id`, `from_route_id`, `to_route_id`, `from_stop_id`, `to_stop_id`, `csv_row_number` |
| `trips.txt` | `trip_id`, `route_id` |
| `stop_times.txt` | `trip_id`, `stop_id` |
| `stops.txt` | `stop_id`, `location_type` |

### Column semantics

- `from_trip_id` / `to_trip_id` — optional string foreign keys into `trips.trip_id`; these drive the entire check. If absent/null for a direction, the whole direction is skipped.
- `from_route_id` / `to_route_id` — optional string foreign keys into `routes.route_id`; if present alongside a trip ID, they must match the trip's actual `route_id`.
- `from_stop_id` / `to_stop_id` — optional string foreign keys into `stops.stop_id`; if present alongside a trip ID, they must reference a stop that appears in the trip's stop-times (possibly via a station expansion).
- `csv_row_number` — row number from `transfers.txt`; carried into every notice.
- `trips.route_id` — used to verify that the transfer's route reference matches the trip.
- `stop_times.trip_id` + `stop_times.stop_id` — used to verify that the transfer's stop reference appears in the trip's stop sequence.
- `stops.location_type` — used to handle station expansion: if the referenced stop is a STATION (type 1), child stops (stops with that station as `parent_station`) are also considered valid matches.

## 3. Validation logic

The validator iterates every row of `transfers.txt`. For each row, both directions (FROM and TO) are evaluated independently using identical logic.

```
for each transfer in transfers:
    for direction in [TRANSFER_FROM, TRANSFER_TO]:
        trip_id = transfer.from_trip_id if direction == FROM else transfer.to_trip_id

        if trip_id is absent/null:
            skip this direction entirely

        trip = trips.lookup(trip_id)
        if trip not found:
            # FK absence is validated by GtfsTransferFromTripIdForeignKeyValidator
            # or GtfsTransferToTripIdForeignKeyValidator; skip
            skip this direction

        route_id = transfer.from_route_id if direction == FROM else transfer.to_route_id
        if route_id is present:
            if route_id != trip.route_id:
                emit TransferWithInvalidTripAndRouteNotice(
                    csv_row_number, trip_field_name, trip_id,
                    route_field_name, route_id, expected_route_id=trip.route_id)

        stop_id = transfer.from_stop_id if direction == FROM else transfer.to_stop_id
        if stop_id is present:
            validateTripStopReference(transfer, direction, trip_id, stop_id)
```

### Stop reference validation sub-routine

```
validateTripStopReference(transfer, direction, trip_id, stop_id):
    stop = stops.lookup(stop_id)
    if stop not found:
        # FK absence validated by GtfsTransferFromStopIdForeignKeyValidator
        # or GtfsTransferToStopIdForeignKeyValidator; skip
        return

    candidate_ids = expandStationIfNeeded(stop)
    # candidate_ids is a set of stop_id strings

    stop_times_for_trip = stop_times.byTripId(trip_id)
    if no stop_time in stop_times_for_trip has a stop_id in candidate_ids:
        emit TransferWithInvalidTripAndStopNotice(
            csv_row_number, trip_field_name, trip_id, stop_field_name, stop_id)
```

### Station expansion logic

```
expandStationIfNeeded(stop):
    if stop.location_type == STOP (0):
        return {stop.stop_id}
    elif stop.location_type == STATION (1):
        children = stops.byParentStation(stop.stop_id)
        return {child.stop_id for child in children}
    else:
        # Any other location type (ENTRANCE, GENERIC_NODE, BOARDING_AREA)
        return {}  # empty set — can never match, notice will be emitted
```

### Important ordering and branching details

- Both directions are always checked for every transfer row, independently of each other.
- The FROM direction is evaluated before the TO direction.
- Route check and stop check are both performed when their respective fields are present — they are independent checks within the same direction. A single direction can produce at most one route notice and at most one stop notice.
- The route check does not gate the stop check; both run if both fields are present.
- If the trip is not found in `trips.txt`, neither the route check nor the stop check is performed for that direction.
- If the stop ID is not found in `stops.txt`, the stop check is skipped (FK validator handles missing refs).
- If `expandStationIfNeeded` returns an empty set (non-STOP, non-STATION location type), the `anyMatch` will always fail, so `TransferWithInvalidTripAndStopNotice` is emitted. This is a secondary consequence; the primary validation of invalid location type is handled by `TransfersStopTypeValidator` (075).

## 4. Notices emitted

### `transfer_with_invalid_trip_and_route` (ERROR)

Emitted when a `from_route_id` or `to_route_id` in `transfers.txt` does not match the `route_id` of the corresponding trip in `trips.txt`.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | int | `transfers.csv_row_number` | Row number of the offending transfer |
| `trip_field_name` | string | `"from_trip_id"` or `"to_trip_id"` | Name of the trip ID field for this direction |
| `trip_id` | string | `transfers.from_trip_id` or `to_trip_id` | The referenced trip ID |
| `route_field_name` | string | `"from_route_id"` or `"to_route_id"` | Name of the route ID field with the invalid value |
| `route_id` | string | `transfers.from_route_id` or `to_route_id` | The route ID provided in the transfer row |
| `expected_route_id` | string | `trips.route_id` | The actual route ID associated with the trip |

Severity: ERROR.

Conditions:
- `from_trip_id` (or `to_trip_id`) is present AND found in `trips.txt`, AND
- `from_route_id` (or `to_route_id`) is present AND does not equal the trip's `route_id`.

### `transfer_with_invalid_trip_and_stop` (ERROR)

Emitted when a `from_stop_id` or `to_stop_id` in `transfers.txt` is not served by the corresponding trip's stop-times (considering station expansion).

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | int | `transfers.csv_row_number` | Row number of the offending transfer |
| `trip_field_name` | string | `"from_trip_id"` or `"to_trip_id"` | Name of the trip ID field for this direction |
| `trip_id` | string | `transfers.from_trip_id` or `to_trip_id` | The referenced trip ID |
| `stop_field_name` | string | `"from_stop_id"` or `"to_stop_id"` | Name of the stop ID field with the invalid reference |
| `stop_id` | string | `transfers.from_stop_id` or `to_stop_id` | The referenced stop ID |

Severity: ERROR.

Conditions:
- `from_trip_id` (or `to_trip_id`) is present AND found in `trips.txt`, AND
- `from_stop_id` (or `to_stop_id`) is present AND found in `stops.txt`, AND
- None of the trip's `stop_times` entries have a `stop_id` in the expanded stop set (the stop itself if STOP type, its children if STATION type).

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `transfers.txt` absent from feed | Return `[]` immediately (guard in runner). |
| `transfers.txt` present but empty | Return `[]` (loop body never executes). |
| `trips.txt` absent from feed | All trip lookups return nothing; all rows silently skipped. |
| `stops.txt` absent from feed | All stop lookups return nothing; stop checks silently skipped. |
| `stop_times.txt` absent from feed | Trip has no stop-times; `byTripId` returns empty list; stop check always fails — notice emitted for every transfer row with a trip+stop combination. |
| `from_trip_id` or `to_trip_id` is null/absent | Entire direction skipped (neither route nor stop check runs). |
| Trip ID not found in `trips.txt` | Direction skipped; FK validator handles the missing reference. |
| `from_route_id` / `to_route_id` absent but trip present | Route check skipped; only stop check runs (if stop ID is also present). |
| `from_stop_id` / `to_stop_id` absent but trip present | Stop check skipped; only route check runs (if route ID is also present). |
| Stop ID not found in `stops.txt` | Stop check silently skipped; FK validator handles the missing reference. |
| Stop `location_type` is STOP (0) | Candidate set = `{stop_id}`; matched against trip's stop-times directly. |
| Stop `location_type` is STATION (1) | Candidate set = all child stops with `parent_station == stop_id`; at least one must appear in trip's stop-times. |
| Stop `location_type` is ENTRANCE/GENERIC_NODE/BOARDING_AREA (2/3/4) | Candidate set is empty; `anyMatch` fails; `TransferWithInvalidTripAndStopNotice` is emitted. (Primary location type validation is separate.) |
| Station has no child stops | Candidate set is empty; notice emitted even if stop-times exist. |
| Route matches but stop does not | Only `TransferWithInvalidTripAndStopNotice` emitted. |
| Stop matches but route does not | Only `TransferWithInvalidTripAndRouteNotice` emitted. |
| Both route and stop are invalid for same direction | Both notices emitted; route notice is emitted first (route check runs before stop check in Java). |
| Both FROM and TO directions have errors | Up to four notices can be emitted for a single transfer row (route + stop per direction). |
| Transfer row has only `transfer_type` and no trip IDs | Both directions skipped; no notices. |

## 6. Test contracts

The Java test file (`TransfersTripReferenceValidatorTest.java`) contains two test methods.

### `testValidTripReferences`

Setup:
- Two trips: `t0` with `route_id=r0`, `t1` with `route_id=r1`.
- Three stops: `s0` (default `location_type=STOP`), `s1_stop` with `parent_station=s1_station` (STOP type), `s1_station` with `location_type=STATION`.
- Two stop-time entries: `(t0, s0)` and `(t1, s1_stop)`.
- One transfer row (csv row 2): `from_stop_id=s0`, `from_route_id=r0`, `from_trip_id=t0`, `to_stop_id=s1_station`, `to_route_id=r1`, `to_trip_id=t1`, `transfer_type=IMPOSSIBLE`.

Expected: zero notices.

Key assertions:
- A stop reference via a direct STOP is valid when it appears in the trip's stop-times.
- A stop reference via a STATION is valid when at least one child stop appears in the trip's stop-times (`t1` serves `s1_stop`, which is a child of `s1_station`).
- Matching route IDs produce no error.

### `testInvalidTripReferences`

Setup:
- Two trips: `t0` with `route_id=r0`, `t1` with `route_id=r1`.
- Three stops: `s0`, `s1`, `s2` (all default STOP location type).
- Two stop-time entries: `(t0, s0)` and `(t1, s1)`.
- One transfer row (csv row 2): `from_stop_id=s0`, `from_route_id=DNE` (wrong route), `from_trip_id=t0`, `to_stop_id=s2` (not in t1's stop-times), `to_route_id=r1`, `to_trip_id=t1`, `transfer_type=IMPOSSIBLE`.

Expected: exactly two notices:
1. `TransferWithInvalidTripAndRouteNotice` with direction `TRANSFER_FROM`: `trip_id=t0`, `route_id=DNE`, `expected_route_id=r0`.
2. `TransferWithInvalidTripAndStopNotice` with direction `TRANSFER_TO`: `trip_id=t1`, `stop_id=s2`.

Key assertions:
- A route ID mismatch on the FROM side produces a route notice.
- A stop not in the trip's stop-times on the TO side produces a stop notice.
- Both errors are detected independently; the transfer row produces notices for both.
- Correct route on TO (`r1` matches `t1`) produces no route notice for TO.
- Correct stop on FROM (`s0` is in `t0`'s stop-times) produces no stop notice for FROM.

### What is NOT covered by the Java test suite

- `transfers.txt` absent (guard clause).
- `trips.txt` or `stops.txt` absent.
- `stop_times.txt` absent.
- Null/absent trip ID fields (skip-entire-direction guard).
- Trip ID not found in `trips.txt` (FK-miss skip).
- Stop ID not found in `stops.txt` (FK-miss skip).
- Transfer direction where both route and stop are invalid (generating two notices for one direction).
- Station with no child stops.
- Stop with location_type other than STOP or STATION.
- Multiple transfer rows.

## 7. Implementation notes

### Algorithm strategy

The validator has two distinct sub-checks per direction per row:
1. A route match check: `transfers.route_id == trips.route_id` for the trip.
2. A stop membership check: `transfers.stop_id` (or its station children) in `stop_times` for the trip.

Both sub-checks use lookup tables indexed by `trip_id`. The `stop_times` table can be large, so the most efficient approach is to pre-build a lookup structure indexed by `trip_id`.

Recommended approach (plain Python with pre-built lookups):

1. Guard-return if `"transfers"` is not in `feed`.
2. Build `trips_by_id: dict[str, dict]` mapping `trip_id -> {route_id}` from `trips.txt`.
3. Build `stop_times_by_trip: dict[str, set[str]]` mapping `trip_id -> set of stop_ids` from `stop_times.txt`.
4. Build `stops_by_id: dict[str, dict]` mapping `stop_id -> {location_type}` from `stops.txt`.
5. Build `children_by_station: dict[str, set[str]]` mapping `parent_station -> set of stop_ids` from `stops.txt` (needed for STATION expansion).
6. Iterate each transfer row in Python, checking both directions.

Pre-building `stop_times_by_trip` as a `dict[str, set[str]]` avoids repeated scans of `stop_times.txt` and keeps the membership test O(1).

### Pre-building lookup structures

```python
# trips lookup
trips_df = feed.get("trips")
trips_by_id: dict[str, str] = {}  # trip_id -> route_id
if trips_df is not None:
    for row in trips_df.select(["trip_id", "route_id"]).iter_rows(named=True):
        if row["trip_id"] is not None:
            trips_by_id[row["trip_id"]] = row["route_id"] or ""

# stop_times lookup
stop_times_df = feed.get("stop_times")
stop_times_by_trip: dict[str, set[str]] = {}
if stop_times_df is not None:
    for row in stop_times_df.select(["trip_id", "stop_id"]).iter_rows(named=True):
        if row["trip_id"] is not None and row["stop_id"] is not None:
            stop_times_by_trip.setdefault(row["trip_id"], set()).add(row["stop_id"])

# stops lookup with station expansion
stops_df = feed.get("stops")
stops_location: dict[str, int] = {}       # stop_id -> location_type
children_by_station: dict[str, set[str]] = {}  # parent_station -> set of child stop_ids
if stops_df is not None:
    for row in stops_df.select(["stop_id", "location_type", "parent_station"]).iter_rows(named=True):
        sid = row["stop_id"]
        if sid is not None:
            stops_location[sid] = row["location_type"] or 0
            if row["parent_station"]:
                children_by_station.setdefault(row["parent_station"], set()).add(sid)
```

### Station expansion

```python
def expand_stop(stop_id: str, stops_location: dict[str, int],
                children_by_station: dict[str, set[str]]) -> set[str]:
    loc_type = stops_location.get(stop_id)
    if loc_type is None:
        return set()  # stop not found; FK validator handles this
    if loc_type == 0:  # STOP
        return {stop_id}
    elif loc_type == 1:  # STATION
        return children_by_station.get(stop_id, set())
    else:
        return set()  # ENTRANCE, GENERIC_NODE, BOARDING_AREA
```

### Guard clauses

```python
def validate_transfers_trip_reference(
    feed: dict[str, pl.DataFrame], ctx: ValidationContext
) -> list[Notice]:
    if "transfers" not in feed:
        return []
    transfers = feed["transfers"]
    if transfers.is_empty():
        return []
```

### Polars vs plain Python

The core logic is row-by-row with dictionary lookups. Per project conventions, plain Python iteration is appropriate here because:
- `transfers.txt` is small in practice.
- The stop-times membership check benefits from a pre-built `set` per trip (not a vectorized operation).
- Station expansion is a graph-like lookup, not a tabular join.

Polars is used to efficiently build the lookup dicts (via `iter_rows`) but the validation loop itself is plain Python.

### Feed dict keys

- `"transfers"` — `transfers.txt`
- `"trips"` — `trips.txt`
- `"stop_times"` — `stop_times.txt`
- `"stops"` — `stops.txt`

### Validator registration

Required tables: `["transfers"]`. Presence of `trips`, `stop_times`, and `stops` is handled by graceful fallback (empty lookups) rather than hard preconditions, matching the Java guard pattern. No feature flag required.

### Relationship to other validators

- `GtfsTransferFromTripIdForeignKeyValidator` / `GtfsTransferToTripIdForeignKeyValidator`: validate that `from_trip_id` / `to_trip_id` reference existing trips. This validator defers to them by skipping any unresolvable trip ID.
- `GtfsTransferFromStopIdForeignKeyValidator` / `GtfsTransferToStopIdForeignKeyValidator`: validate that `from_stop_id` / `to_stop_id` reference existing stops. This validator defers to them by skipping any unresolvable stop ID.
- `TransfersStopTypeValidator` (075): validates that `from_stop_id` / `to_stop_id` have valid location types (STOP or STATION). When a stop has an invalid location type, `expandStationIfNeeded` returns an empty set, causing `TransferWithInvalidTripAndStopNotice` to also fire — this is a secondary effect, not the primary responsibility of this validator.
