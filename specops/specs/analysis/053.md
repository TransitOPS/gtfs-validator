# Analysis: ShapeIncreasingDistanceValidator

## 1. Purpose

For each shape in `shapes.txt`, validate that `shape_dist_traveled` strictly increases
along consecutive shape points (sorted by `shape_pt_sequence`), and emit notices when
two consecutive points have a decreasing or equal `shape_dist_traveled` value.

## 2. Input tables

| Table | Columns used |
|---|---|
| `shapes.txt` | `shape_id`, `shape_pt_lat`, `shape_pt_lon`, `shape_pt_sequence`, `shape_dist_traveled`, `csv_row_number` |

No other tables are read.

## 3. Validation logic

### Step 1: Guard

If `shapes.txt` is absent from the feed or its DataFrame is empty, return immediately
with no notices.

### Step 2: Group by shape_id

Group all rows by `shape_id`. Each group represents a single shape and is processed
independently.

### Step 3: Sort each group by shape_pt_sequence

Within each group, sort rows ascending by `shape_pt_sequence`. This is the canonical
ordering for shape points as specified in the GTFS reference.

### Step 4: Iterate consecutive pairs

For each consecutive pair `(prev, curr)` within the sorted group (i.e., index `i-1`
and `i` for `i` from 1 to N-1):

#### 4a: Skip if either point lacks shape_dist_traveled

If either `prev.shape_dist_traveled` or `curr.shape_dist_traveled` is null (not
provided), skip this pair entirely. No notice is emitted.

#### 4b: Check for decreasing distance (ERROR)

If `prev.shape_dist_traveled > curr.shape_dist_traveled`, emit a
`decreasing_shape_distance` notice (ERROR) and skip the remaining checks for this
pair (continue to the next pair).

#### 4c: Check for equal distance (three sub-cases)

If `prev.shape_dist_traveled == curr.shape_dist_traveled`, the coordinates are
examined:

**Sub-case 1: Same coordinates (WARNING)**

If `curr.shape_pt_lat == prev.shape_pt_lat` AND `curr.shape_pt_lon ==
prev.shape_pt_lon`, emit an `equal_shape_distance_same_coordinates` notice (WARNING).
This indicates a duplicated shape point.

**Sub-case 2: Different coordinates, distance >= threshold (ERROR)**

If the coordinates differ, compute the geodesic distance in meters between the two
points using the haversine / spherical model (S2Earth: Earth mean radius = 6,371,010
m, angular distance formula). The threshold is 1.11 metres.

If `distance_meters >= 1.11`, emit an `equal_shape_distance_diff_coordinates` notice
(ERROR).

**Sub-case 3: Different coordinates, distance > 0 and < threshold (WARNING)**

If `0 < distance_meters < 1.11`, emit an
`equal_shape_distance_diff_coordinates_distance_below_threshold` notice (WARNING).

**Sub-case 4: Different coordinates, distance == 0**

If `distance_meters == 0` (floating-point zero), no notice is emitted. This edge
case covers numerical noise where the S2 computation rounds to exactly zero despite
differing raw coordinate values.

#### 4d: Increasing distance (normal case)

If `prev.shape_dist_traveled < curr.shape_dist_traveled`, no action is taken.

### Step 5: Repeat for all shape groups

Each shape_id group is processed independently. A problematic pair in one shape does
not affect processing of other shapes.

## 4. Notices emitted

### `decreasing_shape_distance` (ERROR)

Emitted when consecutive shape points (sorted by sequence) have decreasing
`shape_dist_traveled`.

| Field | Type | Source | Description |
|---|---|---|---|
| `shape_id` | string | `curr.shape_id` | The identifier of the affected shape |
| `csv_row_number` | integer | `curr.csv_row_number` | 1-based CSV row number of the current (offending) point |
| `shape_dist_traveled` | float | `curr.shape_dist_traveled` | Distance value at the current (offending) point |
| `shape_pt_sequence` | integer | `curr.shape_pt_sequence` | Sequence value at the current (offending) point |
| `prev_csv_row_number` | integer | `prev.csv_row_number` | 1-based CSV row number of the previous point |
| `prev_shape_dist_traveled` | float | `prev.shape_dist_traveled` | Distance value at the previous point |
| `prev_shape_pt_sequence` | integer | `prev.shape_pt_sequence` | Sequence value at the previous point |

Note: Java constructor signature is `DecreasingShapeDistanceNotice(GtfsShape current,

lower distance), and `previous` maps to the "prev" row. Field naming follows the
current/previous distinction above.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `shapes.txt` absent from feed | Return no notices immediately. |
| `shapes.txt` present but empty | Return no notices immediately. |
| A shape has only one point | No pairs to compare; no notices produced. |
| `shape_dist_traveled` is null for prev | Skip the pair entirely; no notice. |
| `shape_dist_traveled` is null for curr | Skip the pair entirely; no notice. |
| Both `shape_dist_traveled` are null | Skip the pair entirely; no notice. |
| `shape_dist_traveled` not provided for any point | All pairs skipped; no notices. |
| Decreasing distance, then additional pairs | `decreasing_shape_distance` emitted and `continue` to next pair; subsequent pairs still checked independently. |
| Equal distance, exactly same coordinates | `equal_shape_distance_same_coordinates` (WARNING). |
| Equal distance, different coordinates, distance exactly == 1.11 | `equal_shape_distance_diff_coordinates` (ERROR) — threshold is `>= 1.11`. |
| Equal distance, different coordinates, distance == 0.0 exactly | No notice emitted (the `distanceBetweenShapePoints > 0` guard in sub-case 3 excludes zero). |
| Multiple shapes with independent issues | Each shape group is processed independently; notices from different shapes do not interfere. |
| Points within the same shape not sorted in the CSV | Java sorts by `shape_pt_sequence` via `@SequenceKey`; Python must sort by `shape_pt_sequence` ascending within each group before iterating. |

## 7. Implementation notes

### Algorithm: plain Python per-group loop preferred over forced Polars

The core logic is a pairwise comparison within sorted groups. This is a natural
sequential algorithm. Per AGENTS.md: "Use plain Python algorithms for
graph/geometry/interval logic when clearer and safer than forcing Polars." Collect
each group into a list and iterate consecutive pairs.

The recommended approach:

1. Guard on missing/empty table.
2. Group the DataFrame by `shape_id`.
3. For each group, sort by `shape_pt_sequence` ascending and convert to row dicts or
   named tuples (small list per shape).
4. Iterate pairs with a standard `for i in range(1, len(pts)):` loop.
5. Apply the five-branch decision tree from Section 3.

### Geodesic distance computation

The Java implementation uses Google's S2 geometry library
(`S2LatLng.getDistance()`), which computes the central angle between two
lat/lon points on a sphere and multiplies by the Earth mean radius (6,371,010 m).

This is equivalent to the haversine formula. In Python, use `math` only:

```python
import math

EARTH_RADIUS_METERS = 6_371_010.0

def _geodesic_distance_meters(lat1: float, lon1: float, lat2: float, lon2: float) -> float:
    """Great-circle distance in metres using the haversine formula (matches S2Earth)."""
    phi1, phi2 = math.radians(lat1), math.radians(lat2)
    dphi = math.radians(lat2 - lat1)
    dlambda = math.radians(lon2 - lon1)
    a = math.sin(dphi / 2) ** 2 + math.cos(phi1) * math.cos(phi2) * math.sin(dlambda / 2) ** 2
    return 2 * math.atan2(math.sqrt(a), math.sqrt(1 - a)) * EARTH_RADIUS_METERS
```

Do not use external geospatial libraries (shapely, pyproj) as they are not in the
declared dependency set.

### Distance threshold

```python
DISTANCE_THRESHOLD_METERS: float = 1.11
```

- `distance >= 1.11` → ERROR (`equal_shape_distance_diff_coordinates`)
- `0 < distance < 1.11` → WARNING (`equal_shape_distance_diff_coordinates_distance_below_threshold`)
- `distance == 0.0` → no notice

### Coordinate equality check

The Java code checks `curr.shapePtLon() == prev.shapePtLon() && curr.shapePtLat() ==
prev.shapePtLat()` using exact floating-point equality (no epsilon). Python must use
the same exact `==` comparison, not `math.isclose`, to preserve behavioral parity.

### Null handling for shape_dist_traveled

The Java `hasShapeDistTraveled()` guard skips any pair where either value is absent.
In Python, after loading, `shape_dist_traveled` will be a nullable `Float64` column.
Before the pairwise loop, filter out rows where `shape_dist_traveled` is null (or
handle null checks inside the loop).

However, note the semantics: the skip applies per-pair, not per-point. A shape where
point A has a value, point B is null, and point C has a value will skip pairs (A,B)
and (B,C) but would check (A,C) only if the grouping exposed non-consecutive pairs —
which it does not (the loop is consecutive). So the practical effect is that any pair
involving a null point is skipped without affecting other pairs in the same shape.

### Constructor argument order caution

Two notice constructors take `(previous, current)` but one takes `(current, previous)`:

- `DecreasingShapeDistanceNotice(GtfsShape current, GtfsShape previous)` — note
  reversed argument order; fields are set from `current` (the lower-distance row) as
  the "faulty" point.
- `EqualShapeDistanceSameCoordinatesNotice(GtfsShape previous, GtfsShape current)`
- `EqualShapeDistanceDiffCoordinatesNotice(GtfsShape previous, GtfsShape current)`
- `EqualShapeDistanceDiffCoordinatesDistanceBelowThresholdNotice(GtfsShape previous, GtfsShape current)`

For the Python implementation, all four notices should consistently assign:

- `shape_id`, `csv_row_number`, `shape_dist_traveled`, `shape_pt_sequence` from the
  **current** (second / higher-sequence) point.
- `prev_csv_row_number`, `prev_shape_dist_traveled`, `prev_shape_pt_sequence` from the
  **previous** (first / lower-sequence) point.

This matches what the Java constructors ultimately assign to their fields, regardless
of argument order.
