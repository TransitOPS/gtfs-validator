# Analysis: StopTimesTripBlockOrderValidator

## 1. Purpose

Checks that all stop_times rows for a given trip are grouped contiguously in
`stop_times.txt` and that their `stop_sequence` values are strictly increasing
in file order.

## 2. Input tables

| Table | Columns used |
|---|---|
| `stop_times.txt` | `trip_id`, `stop_sequence`, `csv_row_number` |

### Column semantics

- `trip_id` — string; identifies which trip a stop_time row belongs to. Rows
  with a null `trip_id` are skipped entirely.
- `stop_sequence` — integer; expected to increase monotonically within a trip
  in file order. The validator uses file-order comparison, not sorted order.
- `csv_row_number` — integer; the 1-based row number in the CSV file. Used to
  determine the contiguous file span of a trip's rows and included in notice
  payloads.

## 3. Validation logic

The validator performs two passes over `stop_times.txt`.

### Pass 1 — Collect per-trip statistics (file order)

Iterate rows in the order they appear in the CSV file (file order, not sorted).
For each row:

1. Skip the row if `trip_id` is null.
2. Accumulate the row count for this `trip_id`.
3. Track the minimum and maximum `csv_row_number` seen for this `trip_id`.
4. Compare the row's `stop_sequence` to the last `stop_sequence` seen for this
   `trip_id` (in file order). If `stop_sequence <= last_stop_sequence`, mark
   this `trip_id` as having an unsorted sequence. Update `last_stop_sequence`
   to the current row's value.

### Pass 2 — Detect violations and emit notices

For each `trip_id` collected in pass 1:

1. Compute `span = max_csv_row_number - min_csv_row_number + 1`.
2. Determine `non_contiguous = (span > row_count)`. This is true when the
   trip's rows are not all adjacent in the file (other trips' rows appear
   between them).
3. Determine `unsorted_sequence = trip was marked in pass 1`.
4. If `non_contiguous OR unsorted_sequence`, emit one
   `UnsortedStopTimesNotice` for this trip.

Each trip emits at most one notice regardless of how many contiguity gaps or
sequence inversions exist.

### Contiguity check detail

If a trip has `N` rows and the file-row span from its first to its last row is
exactly `N`, then all its rows are consecutive in the file (no other trip's
rows interleave). If the span is greater than `N`, at least one foreign row
appears between the trip's rows.

### Unsorted sequence check detail

The comparison is `stop_sequence <= last_stop_sequence`, using file order.
Equality also triggers the notice — duplicate `stop_sequence` values within a
trip are treated as unsorted. The check uses the actual `stop_sequence` integer
value, not position.

## 4. Notices emitted

### `unsorted_stop_times` (INFO)

Emitted when a trip's stop_times rows are non-contiguous in the file OR when
`stop_sequence` values for a trip are not strictly increasing in file order.

| Field | Type | Source | Description |
|---|---|---|---|
| `trip_id` | string | `stop_times.trip_id` | The trip whose rows are disordered or non-contiguous |
| `start_csv_row_number` | int | min `stop_times.csv_row_number` for this trip | CSV row number of the first stop_times row for this trip |
| `end_csv_row_number` | int | max `stop_times.csv_row_number` for this trip | CSV row number of the last stop_times row for this trip |

Severity: INFO.

Condition: `(max_csv_row_number - min_csv_row_number + 1) > row_count` (non-contiguous)
OR any `stop_sequence` in file order is not strictly greater than the previous
`stop_sequence` for the same trip.

One notice per trip, emitted at most once regardless of number of violations.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `stop_times.txt` absent from feed | Return `[]` immediately. |
| `stop_times.txt` present but empty (zero rows) | No trips collected; return `[]`. |
| Row with null `trip_id` | Skipped in pass 1; does not contribute to any trip. |
| Single-row trip | `span = 1`, `count = 1`; non-contiguous is false; no prior stop_sequence to compare; no notice. |
| Trip with all rows contiguous and stop_sequence strictly increasing | No notice. |
| Trip with rows interleaved by another trip's rows | `span > count`; non-contiguous is true; emit notice. |
| Trip with stop_sequence not strictly increasing in file order (e.g. 1, 3, 2) | Unsorted flag set in pass 1; emit notice. |
| Trip with duplicate stop_sequence values | `stop_sequence <= last` is true at the duplicate; unsorted flag set; emit notice. |
| Both contiguity and sequence violations on same trip | Still emits exactly one notice. |
| Trip that is contiguous but unsorted | Notice emitted. |
| Trip that is non-contiguous but sorted | Notice emitted. |
| Multiple trips, only one violating | Only the violating trip emits a notice. |
| All trips valid | No notices emitted. |

## 6. Test contracts

The Java test file (`StopTimesTripBlockOrderValidatorTest.java`) contains two
test methods.

### `UnsortedStopTimesNotice_generateNotice_nonContiguousTripBlock`

- Input: four rows, two trips interleaved:
  - Row 1: `trip_id="0914"`, `stop_id="S1"`, `stop_sequence=1`
  - Row 2: `trip_id="0914"`, `stop_id="S2"`, `stop_sequence=2`
  - Row 3: `trip_id="0915"`, `stop_id="S3"`, `stop_sequence=1`
  - Row 4: `trip_id="0914"`, `stop_id="S4"`, `stop_sequence=3`
- Expected: notice list contains
  `UnsortedStopTimesNotice(trip_id="0914", start_csv_row_number=1, end_csv_row_number=4)`.
- Rationale: trip `"0914"` has 3 rows (rows 1, 2, 4) but its span is
  `4 - 1 + 1 = 4 > 3`, so it is non-contiguous. Trip `"0915"` has span 1 and
  count 1, so it is clean.
- Note: the test uses `contains`, not equality — does not assert that no other
  notices are present (though only one should be generated).

### `UnsortedStopTimesNotice_generateNotice_nonIncreasingStopSequence`

- Input: three rows, one trip with non-monotonic stop_sequence:
  - Row 1: `trip_id="0916"`, `stop_id="S1"`, `stop_sequence=1`
  - Row 2: `trip_id="0916"`, `stop_id="S2"`, `stop_sequence=3`
  - Row 3: `trip_id="0916"`, `stop_id="S3"`, `stop_sequence=2`
- Expected: notice list contains
  `UnsortedStopTimesNotice(trip_id="0916", start_csv_row_number=1, end_csv_row_number=3)`.
- Rationale: at row 3, `stop_sequence=2 <= last=3`, so the unsorted flag is set
  for `"0916"`. Span is `3 - 1 + 1 = 3 = count = 3`, so contiguity is fine;
  the notice is triggered solely by the sequence check.

### What is NOT covered by the Java test suite

- `stop_times.txt` absent entirely.
- Empty `stop_times.txt` (zero rows).
- Single-row trip (no notice expected).
- Row with null `trip_id` (should be skipped).
- Duplicate `stop_sequence` values (equal, not less — triggers `<=` condition).
- A trip that is both non-contiguous AND has unsorted sequence (single notice
  still expected).
- Multiple violating trips in one feed.
- All trips fully valid (no notices expected).

## 7. Implementation notes

### Algorithm strategy

The Java implementation is a two-pass file-order loop that accumulates per-trip
statistics. The Polars equivalent can be done with groupby aggregations in a
single vectorized pass, plus a file-order window check for the sequence
monotonicity test.

The contiguity test is purely aggregated (no file-order dependency needed
beyond knowing `csv_row_number`):

```
span = max(csv_row_number) - min(csv_row_number) + 1
non_contiguous = span > count(csv_row_number)
```

The unsorted sequence test requires knowing file order. In Polars, this means
using `over` with `sort_keys=False` (or preserving the original row index) to
compute a within-group lag comparison that respects file insertion order rather
than sorted `stop_sequence` order.

### Recommended Polars approach

```python
def validate_stop_times_trip_block_order(
    feed: dict[str, pl.DataFrame], ctx: ValidationContext
) -> list[Notice]:
    if "stop_times" not in feed:
        return []

    st = feed["stop_times"]
    if st.is_empty():
        return []

    # Drop rows with null trip_id (mirrors the Java skip)
    st = st.filter(pl.col("trip_id").is_not_null())
    if st.is_empty():
        return []

    # --- Contiguity check (vectorized groupby) ---
    agg = st.group_by("trip_id").agg(
        pl.col("csv_row_number").count().alias("row_count"),
        pl.col("csv_row_number").min().alias("min_row"),
        pl.col("csv_row_number").max().alias("max_row"),
    ).with_columns(
        (pl.col("max_row") - pl.col("min_row") + 1).alias("span")
    ).with_columns(
        (pl.col("span") > pl.col("row_count")).alias("non_contiguous")
    )

    # --- Unsorted sequence check (file-order lag within trip) ---
    # Preserve file order by using the original row index.
    # Add a monotonic row index to sort back to file order after grouping.
    st_indexed = st.with_row_index("_file_row")

    # Within each trip (in file order), flag rows where stop_sequence <= prev
    st_lagged = st_indexed.with_columns(
        pl.col("stop_sequence")
          .shift(1)
          .over("trip_id", order_by="_file_row")
          .alias("_prev_seq")
    ).with_columns(
        (pl.col("stop_sequence") <= pl.col("_prev_seq")).alias("_is_unsorted")
    )

    unsorted_trips = (
        st_lagged
        .filter(pl.col("_is_unsorted"))
        .select("trip_id")
        .unique()
    )

    # --- Join and combine ---
    result = agg.join(
        unsorted_trips.with_columns(pl.lit(True).alias("unsorted_sequence")),
        on="trip_id",
        how="left",
    ).with_columns(
        pl.col("unsorted_sequence").fill_null(False)
    ).filter(
        pl.col("non_contiguous") | pl.col("unsorted_sequence")
    )

    notices: list[Notice] = []
    for row in result.iter_rows(named=True):
        notices.append(
            UnsortedStopTimesNotice(
                trip_id=row["trip_id"],
                start_csv_row_number=row["min_row"],
                end_csv_row_number=row["max_row"],
            )
        )
    return notices
```

### Polars vs plain Python

- The contiguity check (min/max/count groupby) is naturally vectorized —
  express it with Polars `group_by().agg()`.
- The file-order sequence monotonicity check requires a lag within groups
  ordered by file position, not by `stop_sequence`. Use Polars
  `shift(1).over("trip_id", order_by="_file_row")` to preserve file order.
- Notice construction is over a small violation set; `iter_rows(named=True)` is
  acceptable there.
- Do not sort `stop_times` by `stop_sequence` before the sequence check — the
  validator explicitly uses file order.

### Notice dataclass

```python
@dataclass
class UnsortedStopTimesNotice:
    code: ClassVar[str] = "unsorted_stop_times"
    severity: ClassVar[str] = "INFO"
    trip_id: str
    start_csv_row_number: int
    end_csv_row_number: int
```

### Notice code derivation

The Java class is `UnsortedStopTimesNotice`. The Python notice code follows
snake_case convention: `"unsorted_stop_times"`.

### Feed dict keys

- `"stop_times"` — `stop_times.txt`

No other tables are required.

### Validator registration

Required tables: `["stop_times"]`.

Feature flag: none needed. The validator runs whenever `stop_times.txt` is
present.

### One-notice-per-trip guarantee

The Java implementation uses a `Set<String> unsortedNotified` to ensure only
one notice per trip for unsorted sequences, and the groupby aggregation
naturally produces one row per trip for the contiguity check. The combined
approach above (join + filter) likewise produces at most one result row per
trip, so the one-notice-per-trip guarantee is automatically preserved.

### `csv_row_number` source

The Java validator uses `stopTime.csvRowNumber()`, which corresponds to the
1-based CSV file row number (including the header row). The Python loading layer
must expose this as the `csv_row_number` column; the validator relies on it for
both contiguity detection and notice payload.
