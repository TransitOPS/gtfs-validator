# Analysis: AgencyConsistencyValidator

Java source: `main/src/main/java/org/mobilitydata/gtfsvalidator/validator/AgencyConsistencyValidator.java`
Java tests: `main/src/test/java/org/mobilitydata/gtfsvalidator/validator/AgencyConsistencyValidatorTest.java`

## 1. Purpose

Validates that all agencies share the same timezone and language, and that `agency_id` is present (recommended for single agency, required for multiple agencies).

## 2. Input Tables

| Table | Columns Used |
|-------|-------------|
| `agency.txt` | `agency_id`, `agency_name`, `agency_timezone`, `agency_lang` |

No other tables are read. This is a single-file validator operating only on `agency.txt`.

## 3. Validation Logic

The validator has an early-exit guard: skip if the agency table is missing or empty (zero rows).

### Step 1: Single-agency path (exactly 1 row)

- If the single agency row has no `agency_id` value, emit `missing_recommended_field` (WARNING).
- Return immediately -- no timezone or language checks are performed for a single agency.

### Step 2: Multi-agency path (2+ rows)

#### 2a. Required agency_id check

- For every agency row that has no `agency_id`, emit `missing_required_agency_id` (ERROR).
- All rows are checked; multiple notices can fire.

#### 2b. Timezone consistency check

- Take the `agency_timezone` of the first row as the "expected" timezone.
- For every subsequent row (index 1..N-1), compare its `agency_timezone` to the expected value.
- If they differ, emit `inconsistent_agency_timezone` (ERROR) for that row.
- Note: `agency_timezone` is a required field, so it is assumed to always be present and already validated by load-time schema checks.

#### 2c. Language consistency check

- Iterate all rows. Skip any row where `agency_lang` is not set (null/empty).
- The first row that has a non-null `agency_lang` establishes the "expected" language.
- For every subsequent row that has a non-null `agency_lang` differing from the expected value, emit `inconsistent_agency_lang` (WARNING).
- If no rows have `agency_lang` set, no notices are emitted (the field is optional).

## 4. Notices Emitted

### `missing_recommended_field` (WARNING)

Fires when a single agency exists but has no `agency_id`.

| Field | Type | Description |
|-------|------|-------------|
| `filename` | str | Always `"agency.txt"` |
| `csv_row_number` | int | Row number of the agency |
| `field_name` | str | Always `"agency_id"` |

Note: This is a shared/generic notice class (`MissingRecommendedFieldNotice`), not specific to this validator.

### `missing_required_agency_id` (ERROR)

Fires when multiple agencies exist and any row lacks `agency_id`.

| Field | Type | Description |
|-------|------|-------------|
| `filename` | str | Always `"agency.txt"` |
| `csv_row_number` | int | Row number of the faulty agency |
| `agency_name` | str | The `agency_name` of the row missing its ID |

Note: This is a standalone notice class (`MissingRequiredAgencyIdNotice`). It is also used by other validators (routes, fare_attributes) when agency_id is missing in a multi-agency feed.

### `inconsistent_agency_timezone` (ERROR)

Fires when any agency has a different timezone than the first agency.

| Field | Type | Description |
|-------|------|-------------|
| `csv_row_number` | int | Row number of the mismatched agency |
| `expected` | str | Timezone string from the first agency (e.g. `"America/Montreal"`) |
| `actual` | str | Timezone string of the current agency |

### `inconsistent_agency_lang` (WARNING)

Fires when any agency has a different language than the first agency that specified one.

| Field | Type | Description |
|-------|------|-------------|
| `csv_row_number` | int | Row number of the mismatched agency |
| `expected` | str | Language code from the first agency with a language (e.g. `"en"`) |
| `actual` | str | Language code of the current agency |

## 5. Edge Cases

- **Missing/null agency table**: Guard clause returns early (validator is not called). In Python: return `[]` if `"agency"` not in `feed` or the DataFrame is empty.
- **Empty agency table (0 rows)**: Same as above -- guard returns early.
- **Single agency**: Only the `agency_id` recommended check runs. Timezone and language consistency checks are skipped entirely.
- **All `agency_lang` values null**: No `inconsistent_agency_lang` notice -- the field is optional and nulls are silently skipped.
- **Some `agency_lang` values null, rest consistent**: No notice. Null entries are skipped; only non-null values are compared.
- **Timezone comparison uses exact string equality**: `"America/Montreal"` vs `"America/Toronto"` are different even if they represent the same UTC offset. This matches Java `ZoneId.equals()`.
- **Language comparison uses locale language code**: The comparison is on the language portion of the locale (e.g. `"en"`, `"fr"`), not the full locale tag. `Locale.CANADA` ("en") and `Locale.CANADA_FRENCH` ("fr") are different.
- **First row sets the "expected" value**: Both timezone and language consistency use the first row (or first non-null for language) as the baseline. This is an arbitrary choice but matches Java behavior.

## 6. Test Contracts

### Test 1: Single agency, no agency_id -> WARNING
- Input: 1 agency, `agency_id=null`
- Expected: 1 `missing_recommended_field` notice (WARNING) with `filename="agency.txt"`, `field_name="agency_id"`

### Test 2: Multiple agencies, one missing agency_id -> ERROR
- Input: 2 agencies, first has `agency_id="first agency"`, second has `agency_id=null`
- Expected: 1 `missing_required_agency_id` notice (ERROR) for row 1 with `agency_name="agency name"`

### Test 3: Different timezones -> ERROR
- Input: 2 agencies, first with `America/Bogota`, second with `America/Montreal`
- Expected: 1 `inconsistent_agency_timezone` notice (ERROR) for row 1 with `expected="America/Bogota"`, `actual="America/Montreal"`

### Test 4: Same timezones -> no notices
- Input: 2 agencies, both with `America/Montreal`, same language
- Expected: no notices

### Test 5: Different languages -> WARNING
- Input: 2 agencies, first with `en` (CANADA), second with `fr` (FRANCE)
- Expected: 1 `inconsistent_agency_lang` notice (WARNING) for row 1 with `expected="en"`, `actual="fr"`

### Test 6: Same languages -> no notices
- Input: 2 agencies, both with `en` (CANADA)
- Expected: no notices

### Test 7: Some languages omitted, rest consistent -> no notices
- Input: 3 agencies. First has `agency_lang=null`, second and third have `fr` (CANADA_FRENCH)
- Expected: no notices (null is skipped; the two non-null values match)

### Test 8: Null agency table -> shouldCallValidate returns false
- Input: validator constructed with `null` table
- Expected: `shouldCallValidate()` returns false (in Python: return `[]` early)

### Test 9: Empty agency table -> shouldCallValidate returns false
- Input: validator constructed with empty agency list
- Expected: `shouldCallValidate()` returns false

### Test 10: Non-empty agency table -> shouldCallValidate returns true
- Input: validator constructed with 1 agency
- Expected: `shouldCallValidate()` returns true (validator proceeds)

## 7. Implementation Notes

### Approach: Polars expressions

This validator is well-suited to Polars tabular operations:

- **agency_id check**: Use `pl.col("agency_id").is_null()` filter. Branch on `len(df)` to decide between recommended (WARNING) and required (ERROR) severity.
- **Timezone consistency**: Use `pl.col("agency_timezone").n_unique()` -- if > 1, filter rows that differ from the first row's value.
- **Language consistency**: Filter non-null `agency_lang` rows, then check `n_unique()` on the filtered set.

### Notice reuse

- `missing_recommended_field` is a generic notice already used elsewhere in the system. Reuse the existing notice code.
- `missing_required_agency_id` is a shared notice also emitted by route and fare_attribute validators. Define it once in `notices.py` or a shared location.
- `inconsistent_agency_timezone` and `inconsistent_agency_lang` are specific to this validator.

### No utility dependencies

This validator has no external utility class dependencies. It operates purely on the agency table with simple equality comparisons.

```python
def validate_agency_consistency(

```
