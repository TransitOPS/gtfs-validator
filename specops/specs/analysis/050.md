# Analysis: RouteNameValidator

## 1. Purpose

Validates that each route in `routes.txt` has at least one of `route_short_name` or `route_long_name`, that the short name is not excessively long, that the long name does not redundantly contain the short name as a prefix, and that `route_desc` does not duplicate either name.

## 2. Input tables

| Table | Columns used |
|---|---|
| `routes.txt` | `route_id`, `csv_row_number`, `route_short_name`, `route_long_name`, `route_desc` |

No other tables are read. This is a single-table, per-row validator.

## 3. Validation logic

The validator iterates over each row in `routes.txt` and applies four independent checks. Checks 1 and 2 are independent of each other and of checks 3 and 4. Check 3 (desc vs. short name) includes an early-return that suppresses check 4 (desc vs. long name) for the same row.

### Check 1: Both names missing

If `route_short_name` is null/absent AND `route_long_name` is null/absent, emit `route_both_short_and_long_name_missing` (ERROR).

This check applies regardless of whether `route_desc` is present.

### Check 2: Short name too long

If `route_short_name` is present and its character length is greater than 12, emit `route_short_name_too_long` (WARNING).

The threshold constant is `MAX_SHORT_NAME_LENGTH = 12`. Exactly 12 characters is allowed; 13 or more is flagged.

### Check 3: Long name contains short name as prefix

This check applies only when both `route_short_name` and `route_long_name` are present.

Procedure:
1. Compare `route_long_name.lower()` against `route_short_name.lower()` using `startswith`.
2. If the long name does not start with the short name (case-insensitive), stop — no notice.
3. If it does start with the short name, extract the remainder: `remainder = long_name[len(short_name):]`.
4. Emit `route_long_name_contains_short_name` (WARNING) if:
   - The remainder is empty (the names are identical), OR
   - The remainder matches the regex `^\s?[\s\-\(\)].*` (the short name is followed by an optional space and then a separator character: space, hyphen, `(`, or `)`)

The regex test means: the remainder starts with zero or one whitespace characters, then at least one more character from the set `[\s\-\(\)]`, followed by anything. This covers patterns like:
- `"L1 Long Name"` — short name followed by space then content
- `"L1-Long Name"` — short name followed by hyphen
- `"L1 - Long Name"` — short name followed by space-hyphen-space
- `"L1(Long Name)"` — short name followed by `(`
- `"L1) Long Name"` — short name followed by `)`
- `"L1 (Long Name)"` — short name followed by space then `(`

If the long name begins with the short name but is followed by regular word characters (e.g., `"Bankford"` begins with `"BAN"` but the remainder `"kford"` does not match the separator regex), no notice is emitted.

### Check 4: Description duplicates a name

This check applies only when `route_desc` is present.

Sub-check 4a — short name vs. desc (runs when `route_short_name` is present):
- If `route_desc.lower() == route_short_name.lower()`, emit `same_name_and_description_for_route` (WARNING) with `specified_field = "route_short_name"`.
- Then **return immediately** — sub-check 4b is skipped for this row.

Sub-check 4b — long name vs. desc (runs when `route_long_name` is present, and only if 4a did not fire):
- If `route_desc.lower() == route_long_name.lower()`, emit `same_name_and_description_for_route` (WARNING) with `specified_field = "route_long_name"`.

The short-name check takes precedence: if both names are present and the desc matches the short name, only one notice is emitted and the long-name check is suppressed for that row.

The comparison is case-insensitive equality (not contains). The full strings must match (modulo case).

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `routes.txt` absent from feed | Return no notices immediately. |
| `routes.txt` present but empty | Return no notices. |
| Both `route_short_name` and `route_long_name` are null | Emit `route_both_short_and_long_name_missing` (ERROR). |
| Only `route_short_name` is present (no long name) | No missing-name notice; short-name length and desc checks run normally; long-name checks are skipped. |
| Only `route_long_name` is present (no short name) | No missing-name notice; long-name checks that require short name are skipped; desc vs. long name check runs if desc present. |
| `route_short_name` is exactly 12 characters | No `route_short_name_too_long` notice (threshold is strictly greater than 12). |
| `route_short_name` is 13 characters | Emit `route_short_name_too_long`. |
| Long name begins with short name but the remainder starts with a normal letter (e.g., `"BAN"` / `"Bankford"`) | No `route_long_name_contains_short_name` notice — the remainder `"kford"` does not match the separator regex. |
| Long name equals short name exactly (case-insensitive) | Remainder is empty — emit `route_long_name_contains_short_name`. |
| `route_desc` equals `route_short_name` (case-insensitive) | Emit `same_name_and_description_for_route` with `specified_field="route_short_name"`. Long name vs. desc check is suppressed for this row. |
| `route_desc` equals `route_long_name` but not `route_short_name` | Emit `same_name_and_description_for_route` with `specified_field="route_long_name"`. |
| `route_desc` equals both names (all three are equal) | Emit `route_long_name_contains_short_name` (names are equal) AND `same_name_and_description_for_route` with `specified_field="route_short_name"` (desc matches short name; long-name desc check suppressed). |
| `route_desc` is null/absent | Desc checks are entirely skipped for that row. |
| Multiple violations on one row (e.g., short name too long + names equal) | Each independent check emits its own notice; checks 1 and 2 do not gate each other. |

## 6. Test contracts

### `routeBothShortAndLongNameMissing`

- `createRoute(null, null, null)` → exactly `RouteBothShortAndLongNameMissingNotice("r1", 1)`.
- `createRoute("S", null, null)` → no notices.
- `createRoute(null, "Long", null)` → no notices.
- `createRoute("S", "Long", null)` → no notices.

### `routeShortNameTooLong`

- `createRoute("THISISMYSHORTNAME", null, null)` (17 chars) → exactly `RouteShortNameTooLongNotice("r1", 1, "THISISMYSHORTNAME")`.
- `createRoute("SH", null, null)` (2 chars) → no notices.

### `equalRouteShortNameAndRouteDescShouldGenerateNotice`

- `createRoute("duplicate", null, "duplicate")` → exactly `SameNameAndDescriptionForRouteNotice(1, "r1", "duplicate", "route_short_name")`.
- `createRoute("DuplicATE", null, "duplicate")` (case-insensitive) → exactly `SameNameAndDescriptionForRouteNotice(1, "r1", "duplicate", "route_short_name")`.

### `equalRouteLongNameAndRouteDescShouldGenerateNotice`

- `createRoute(null, "duplicate", "duplicate")` → exactly `SameNameAndDescriptionForRouteNotice(1, "r1", "duplicate", "route_long_name")`.
- `createRoute(null, "duplicate", "DuplicATE")` (case-insensitive, desc has mixed case) → exactly `SameNameAndDescriptionForRouteNotice(1, "r1", "DuplicATE", "route_long_name")`. Note: `route_desc` value stored in notice is the raw value from the feed (`"DuplicATE"`).

### `noLongNameDifferentRouteShortNameAndRouteDescShouldNotGenerateNotice`

- `createRoute("short name", null, "desc")` → no notices.

### `noShortNameDifferentRouteLongNameAndRouteDescShouldNotGenerateNotice`

- `createRoute(null, "long name", "desc")` → no notices.

### `allNamesProvidedAndDifferentFromRouteDescShouldNotGenerateNotice`

- `createRoute("short name", "long name", "desc")` → no notices.

### `equalRouteShortNameRouteLongNameAndRouteDescShouldGenerateTwoNotices`

- `createRoute("duplicate", "duplicate", "duplicate")` → contains both:
  - `RouteLongNameContainsShortNameNotice("r1", 1, "duplicate", "duplicate")` (names are equal)
  - `SameNameAndDescriptionForRouteNotice(1, "r1", "duplicate", "route_short_name")` (desc matches short name)

### `routeShortAndLongNameEqual`

- `createRoute("S", "S", null)` → exactly `RouteLongNameContainsShortNameNotice("r1", 1, "S", "S")`.
- `createRoute("SA", "Sa", null)` (case-insensitive equal) → exactly `RouteLongNameContainsShortNameNotice("r1", 1, "SA", "Sa")`.
- `createRoute("S", "Long", null)` → no notices.

### `routeLongNameContainsRouteShortNameShouldGenerateNotice`

Short name `"L1"` with each of these long names triggers exactly `RouteLongNameContainsShortNameNotice("r1", 1, "L1", <long_name>)`:

| Long name | Pattern |
|---|---|
| `"L1 Long Name"` | short + space + content |
| `"L1-Long Name"` | short + hyphen |
| `"L1- Long Name"` | short + hyphen + space |
| `"L1 - Long Name"` | short + space + hyphen |
| `"L1)Long Name"` | short + `)` |
| `"L1) Long Name"` | short + `)` + space |
| `"L1 ) Long Name"` | short + space + `)` |
| `"L1(Long Name)"` | short + `(` |
| `"L1 (Long Name)"` | short + space + `(` |
| `"L1( Long Name)"` | short + `(` + space |

### `routeLongNameContainsRouteShortNameInAllowedWay_noNotice`

- `createRoute("BAN", "Bankford", null)` → no notices. Long name starts with `"BAN"` but the remainder `"kford"` begins with a regular letter, not a separator.

## 7. Implementation notes

### Approach: row iteration vs. Polars expressions

This validator has moderate complexity due to the separator-regex check and the short-circuit in Check 4. Two approaches are reasonable:

**Option A — Plain Python row iteration (recommended)**

Iterate with `iter_rows(named=True)` after filtering to non-empty DataFrame. Apply each check as plain Python conditionals. This mirrors the Java structure faithfully and avoids forcing complex regex logic into Polars expressions.

```python
MAX_SHORT_NAME_LENGTH = 12
LONG_NAME_CONTAINS_SHORT_NAME_RE = re.compile(r"^\s?[\s\-\(\)].*")

for row in routes.iter_rows(named=True):
    short = row["route_short_name"]
    long_ = row["route_long_name"]
    desc  = row["route_desc"]
    route_id = row["route_id"]
    csv_row = row["csv_row_number"]

    if short is None and long_ is None:
        notices.append(...)  # route_both_short_and_long_name_missing

    if short is not None and len(short) > MAX_SHORT_NAME_LENGTH:
        notices.append(...)  # route_short_name_too_long

    if short is not None and long_ is not None:
        if long_.lower().startswith(short.lower()):
            remainder = long_[len(short):]
            if remainder == "" or LONG_NAME_CONTAINS_SHORT_NAME_RE.match(remainder):
                notices.append(...)  # route_long_name_contains_short_name

    if desc is not None:
        if short is not None and desc.lower() == short.lower():
            notices.append(...)  # same_name_and_description_for_route, field="route_short_name"
            continue  # skip long name desc check
        if long_ is not None and desc.lower() == long_.lower():
            notices.append(...)  # same_name_and_description_for_route, field="route_long_name"
```

**Option B — Polars for vectorized sub-checks**

Checks 1, 2, and the desc equality checks can be computed with Polars filter expressions. The prefix+separator check (check 3) is harder to vectorize cleanly given the regex on the remainder. A hybrid approach could vectorize checks 1 and 2, then iterate for check 3.

Given the expected small number of violations and the control-flow complexity of Check 4's early return, Option A (full row iteration after a guard) is preferred for clarity and correctness.

### Regex pattern

The Java regex `"^\\s?[\\s\\-\\(\\)].*"` translates to Python `r"^\s?[\s\-\(\)].*"`. Compile it once at module level.

The regex allows:
- Zero or one whitespace character (`\s?`)
- Then exactly one character from `[\s\-\(\)]` — a second whitespace, hyphen, open-paren, or close-paren
- Then anything (`.*`)

This means separators like `" "`, `"-"`, `"("`, `")"`, `"  "`, `" -"`, `" ("`, `" )"` all trigger the notice.

### Case sensitivity

- Check 3 (prefix): comparison via `.lower().startswith(...)`. The substring extraction uses the original-case short name length, but comparison is on lowercased strings.
- Check 4 (desc equality): comparison via `.lower() == other.lower()`.

The `route_short_name` and `route_long_name` values stored in notices are always the **original** (non-lowercased) values from the feed.

### Short-circuit in Check 4

The `return` (or `continue` in a loop) after emitting `same_name_and_description_for_route` for `route_short_name` is semantically significant: it prevents emitting a second `same_name_and_description_for_route` notice for `route_long_name` on the same row when `desc` matches the short name. The Python implementation must replicate this exactly.
