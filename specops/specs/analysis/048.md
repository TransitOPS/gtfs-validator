# Analysis: RouteAgencyIdValidator

## 1. Purpose

Validates that `routes.txt` rows include `agency_id`: emits an ERROR when the feed has more than one agency and the field is missing, and a WARNING when there is exactly one agency and the field is missing.

## 2. Input tables

| Table | Columns used |
|---|---|
| `agency.txt` | (row count only; no specific column values are read) |
| `routes.txt` | `csv_row_number`, `agency_id` |

The validator reads `agency.txt` only to determine how many agencies exist. It reads `routes.txt` to iterate over rows and check for a missing `agency_id`. No FK integrity check is done here; that is delegated to a separately generated FK validator.

## 3. Validation logic

### Step 1: Guard — skip unless both tables are present and non-empty

The Java `shouldCallValidate()` returns `false` (skip entirely) when:

- `agency.txt` is null or has zero rows.
- `routes.txt` is null or has zero rows.

In Python: return `[]` immediately if `"agency"` is absent from the feed dict, or `feed["agency"]` is empty, or `"routes"` is absent from the feed dict, or `feed["routes"]` is empty.

### Step 2: Determine the number of agencies

Count the total number of rows in `agency.txt`. This count determines whether a missing `agency_id` on a route is an ERROR or a WARNING.

### Step 3: For each route row where `agency_id` is missing, emit the appropriate notice

A missing `agency_id` means the field is null (the Java `hasAgencyId()` returns false when the value is an empty/unset Optional).

- If `total_agencies > 1`: emit `missing_required_agency_id` (ERROR) for that route row.
- If `total_agencies == 1`: emit `missing_recommended_field` (WARNING) for that route row.

Rows where `agency_id` is non-null produce no notice. The reference-integrity check (does the `agency_id` exist in `agency.txt`?) is explicitly excluded from this validator.

## 4. Notices emitted

### `missing_required_agency_id` (ERROR)

Emitted when a route row has no `agency_id` and the feed contains more than one agency. The field is required under those conditions.

| Field | Type | Source | Description |
|---|---|---|---|
| `filename` | string | literal `"routes.txt"` | File where the error occurs |
| `csv_row_number` | integer | `routes.csv_row_number` | Row number of the offending route record |
| `agency_name` | string or null | always `null` here | Agency name if obtainable; the Java validator always passes `null` for route rows |

Severity: ERROR.

Java class: `MissingRequiredAgencyIdNotice`.

Python notice code: `missing_required_agency_id`.

Note: `agency_name` is always `null` in this validator. The field exists on the notice class because the same notice is also emitted by the agency and fare-attribute validators, which can supply a name.

### `missing_recommended_field` (WARNING)

Emitted when a route row has no `agency_id` and the feed contains exactly one agency. The field is recommended but not required under that condition.

| Field | Type | Source | Description |
|---|---|---|---|
| `filename` | string | literal `"routes.txt"` | File where the warning occurs |
| `csv_row_number` | integer | `routes.csv_row_number` | Row number of the offending route record |
| `field_name` | string | literal `"agency_id"` | Name of the missing recommended field |

Severity: WARNING.

Java class: `MissingRecommendedFieldNotice`.

Python notice code: `missing_recommended_field`.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `agency.txt` absent from feed | Guard: return no notices. |
| `agency.txt` present but empty (zero rows) | Guard: return no notices. |
| `routes.txt` absent from feed | Guard: return no notices. |
| `routes.txt` present but empty (zero rows) | Guard: return no notices. |
| All route rows have `agency_id` set | No notices emitted (valid feed). |
| Single agency, all routes have `agency_id` | No notices emitted (valid feed). |
| Single agency, some routes missing `agency_id` | One `missing_recommended_field` WARNING per offending row. |
| Multiple agencies, some routes missing `agency_id` | One `missing_required_agency_id` ERROR per offending row. |
| Multiple agencies, all routes missing `agency_id` | One ERROR notice per row. |
| `agency_id` column absent from `routes.txt` header | All rows treated as having a null `agency_id`; all rows emit notices (severity depends on agency count). Treat absent column the same as null value. |

## 6. Test contracts

Setup:
- 2 agencies in `agency.txt`.
- 2 route rows: `csv_row_number=0` has `agency_id="agency0"`; `csv_row_number=1` has `agency_id=null`.

Expected: exactly 1 notice — `MissingRequiredAgencyIdNotice` with `filename="routes.txt"`, `csvRowNumber=1`, `agencyName=null`.

Setup:
- 1 agency in `agency.txt` (agency itself has no `agency_id`, but still counts as 1 row).
- 1 route row: `csv_row_number=0`, `agency_id=null`.

Expected: exactly 1 notice — `MissingRecommendedFieldNotice` with `filename="routes.txt"`, `csvRowNumber=0`, `fieldName="agency_id"`.

### `SingleAgencyAndAgencyIdSpecified_noNotice`

Setup:
- 1 agency in `agency.txt`.
- 2 route rows: both have `agency_id="agency1"`.

Expected: no notices.

### `MoreThanOneAgencyAndAgencyIdsSpecified_noNotice`

Setup:
- 2 agencies in `agency.txt`.
- 2 route rows: each has a non-null `agency_id`.

Expected: no notices.

### `shouldCallValidate_falseWhenAgencyTableNull`

Setup: `agencyTable=null`, non-empty `routeTable`.

Expected: `shouldCallValidate()` returns false (no validation runs).

### `shouldCallValidate_falseWhenAgencyTableEmpty`

Setup: empty `agencyTable`, non-empty `routeTable`.

Expected: `shouldCallValidate()` returns false.

### `shouldCallValidate_falseWhenRouteTableNull`

Setup: non-empty `agencyTable`, `routeTable=null`.

### `shouldCallValidate_falseWhenRouteTableEmpty`

Setup: non-empty `agencyTable`, empty `routeTable`.

Expected: `shouldCallValidate()` returns false.

## 7. Implementation notes

### Existing Python pattern

An analogous validator already exists at `src/gtfs_validator/validators/fare_attribute_agency_id.py`. It handles the identical multi-agency vs. single-agency branching pattern for `fare_attributes.txt`. The `routes.txt` validator should follow the same structure, substituting `"routes"` for `"fare_attributes"` and `"routes.txt"` for `"fare_attributes.txt"`.

### Recommended Polars approach

```python
routes = feed["routes"]
agency_df = feed["agency"]
total_agencies = len(agency_df)

missing = routes.filter(
    pl.col("agency_id").is_null() | (pl.col("agency_id") == "")
)

if missing.is_empty():
    return []

notices: list[Notice] = []
if total_agencies > 1:
    for row in missing.iter_rows(named=True):
        notices.append(Notice(
            code="missing_required_agency_id",
            severity=Severity.ERROR,
            fields={
                "filename": "routes.txt",
                "csv_row_number": row["csv_row_number"],
                "agency_name": None,
            },
        ))
else:
    for row in missing.iter_rows(named=True):
        notices.append(Notice(
            code="missing_recommended_field",
            severity=Severity.WARNING,
            fields={
                "filename": "routes.txt",
                "csv_row_number": row["csv_row_number"],
                "field_name": "agency_id",
            },
        ))
return notices
```

The missing-row set is small in practice, so `iter_rows` is acceptable here. If the `agency_id` column is entirely absent from the schema (an unusual but possible input), the filter will need to handle `KeyError` gracefully, or the column should be guaranteed by schema loading before this validator runs.

### Notice code mapping

| Java class | Python notice code |
|---|---|
| `MissingRequiredAgencyIdNotice` | `missing_required_agency_id` |
| `MissingRecommendedFieldNotice` | `missing_recommended_field` |

### Feed dict keys

- `"agency"` — `agency.txt`
- `"routes"` — `routes.txt`

### Columns required from `routes.txt`

- `csv_row_number`
- `agency_id`

### Validator registration

Required tables: `["agency", "routes"]`.

Guard: skip if `"agency"` is absent or empty, or if `"routes"` is absent or empty.

### No FK check

The validator comment explicitly states that reference integrity (does `routes.agency_id` match a valid `agency.agency_id`?) is handled elsewhere via the `@ForeignKey` annotation mechanism. The Python equivalent FK check is already handled by `load_validators.py`. Do not add an FK check inside this validator.
