# Analysis: SingleShapePointValidator

## 1. Purpose

Validate that every shape defined in `shapes.txt` (identified by `shape_id`) has more
than one shape point; emit a warning for each `shape_id` that appears only once.

## 2. Input tables

| Table | Columns used |
|---|---|
| `shapes.txt` | `shape_id`, `csv_row_number` |

Only `shapes.txt` is required. No cross-table join is performed.

## 3. Validation logic

### Step 1: Count shape points per shape_id

Iterate over every row in `shapes.txt`. Build two maps keyed by `shape_id`:

- `shapePointCounts`: count of rows for each `shape_id`.
- `shapePointRowNumbers`: `csv_row_number` of the **last** row encountered for each
  `shape_id` (the map is overwritten on each iteration, so the final stored value is
  that of the last row in file order).

### Step 2: Emit notice for shapes with exactly one point

Iterate over all entries in `shapePointCounts`. For each `shape_id` whose count equals
exactly `1`, emit a `SingleShapePointNotice` with:

- `shape_id`: the `shape_id` of the single-point shape.
- `csv_row_number`: the value from `shapePointRowNumbers` for that `shape_id` (which,
  because there is only one row for this `shape_id`, is that row's `csv_row_number`).

### Key behavioral detail: last-seen row number

The Java implementation overwrites `shapePointRowNumbers[shapeId]` on every row, so
the stored row number is always that of the **last** occurrence in file order. When
the count is exactly 1, there is only one occurrence, so this distinction does not
matter in practice — last == first == only. No deduplication step is needed here
because the count check already filters to shape IDs with exactly one row.

### Threshold: strictly one point triggers the notice

- Count == 0: cannot occur (iteration only inserts keys for observed rows).
- Count == 1: notice emitted.
- Count >= 2: no notice.

## 4. Notices emitted

### `single_shape_point` (WARNING)

Emitted when a `shape_id` in `shapes.txt` has exactly one associated shape point row.

| Field | Type | Source | Description |
|---|---|---|---|
| `shape_id` | string | `shapes.shape_id` | The shape ID with only one point |
| `csv_row_number` | integer | `shapes.csv_row_number` | Row number of the sole occurrence of this shape_id |

Condition: `COUNT(rows WHERE shapes.shape_id == shape_id) == 1`.

One notice per offending `shape_id`. When the count is 1, the row number is
unambiguous (only one row exists for that shape).

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `shapes.txt` is absent from the feed | No notices; guard returns early. |
| `shapes.txt` is present but empty | No notices; the iteration produces nothing. |
| A `shape_id` appears in exactly one row | One `single_shape_point` notice with that row's `csv_row_number`. |
| A `shape_id` appears in two or more rows | No notice for that shape. |
| All shapes have more than one point | Zero notices. |
| Every shape has exactly one point | One notice per distinct `shape_id`. |
| `shape_id` column contains nulls | Not expected (field is required in schema); if present as empty string or null, they would be grouped together and may or may not trigger a notice depending on count — treat null `shape_id` values as invalid and skip or handle upstream at load time. |

## 6. Test contracts

### `shapeWithMoreThanOneShapePointShouldNotGenerateNotice`

- One shape `"first shape id"` with two rows (csv rows 1 and 2, sequences 1 and 2).
- Expected: **0** notices.

### `unusedShapeShouldGenerateNotice`

(Note: the test is named "unusedShape" but actually tests the single-point condition,
likely a copy-paste from a related test suite.)

- Shape `"first shape id"`: two rows (csv rows 1 and 2, sequences 1 and 2) — valid,
  no notice.
- Shape `"second shape id"`: one row (csv row 3, sequence 1) — single point.
- Expected: exactly **1** `SingleShapePointNotice`:
  - `shape_id` = `"second shape id"`
  - `csv_row_number` = `3`

No tests cover the empty-table or absent-table cases, but Java iterator semantics
(empty container produces zero iterations) guarantee zero notices in those scenarios.

## 7. Implementation notes

### Polars approach

This validator is a simple group-by count check on a single table:

```python
import polars as pl
from gtfs_validator.notices import Notice

def validate_single_shape_point(
    feed: dict[str, pl.DataFrame],
    ctx,
) -> list[Notice]:
    if "shapes" not in feed or feed["shapes"].is_empty():
        return []

    shapes = feed["shapes"]

    # Count rows per shape_id and capture the row number of the only occurrence.
    # For shape IDs with count == 1, first == last == only, so .first() is correct.
    counts = (
        shapes
        .group_by("shape_id")
        .agg(
            pl.len().alias("point_count"),
            pl.col("csv_row_number").last().alias("csv_row_number"),
        )
        .filter(pl.col("point_count") == 1)
    )

    notices: list[Notice] = []
    for row in counts.iter_rows(named=True):
        notices.append(
            Notice(
                code="single_shape_point",
                severity="WARNING",
                fields={
                    "shape_id": row["shape_id"],
                    "csv_row_number": row["csv_row_number"],
                },
            )
        )
    return notices
```

The `.last()` aggregation faithfully mirrors the Java overwrite semantics. Since the
count is filtered to exactly 1, `.first()` and `.last()` are interchangeable; using
`.last()` matches the Java behavior for completeness.

### Alternative: preserve file-order row number explicitly

If strict equivalence to the Java last-row semantics is required even for counts > 1
(which do not emit a notice, so it has no observable effect), use `with_row_index` to
preserve original row order before grouping:

```python
counts = (
    shapes
    .with_row_index("_idx")
    .group_by("shape_id")
    .agg(
        pl.len().alias("point_count"),
        pl.col("csv_row_number").sort_by(pl.col("_idx")).last().alias("csv_row_number"),
    )
    .filter(pl.col("point_count") == 1)
)
```

For a single-point shape this is equivalent to the simpler form above.

### Guard clauses

Return `[]` immediately if:
- `"shapes"` is not in the feed dict.
- `feed["shapes"]` is empty (`.is_empty()` is `True`).
