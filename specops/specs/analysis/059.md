# Analysis: StopRequiredLocationValidator

## 1. Purpose

For every stop in `stops.txt` with `location_type` equal to STOP (0), STATION (1), or
ENTRANCE (2), verify that **both** `stop_lat` and `stop_lon` are present (non-null).

## 2. Input tables

| Table | Columns used |
|---|---|
| `stops.txt` | `csv_row_number`, `stop_id`, `stop_lat`, `stop_lon`, `location_type` |

This is a single-table validator operating on `stops.txt` only. No cross-table joins
are performed.

### Column semantics

- `location_type` — integer enum; values are `0` (STOP), `1` (STATION), `2`
  (ENTRANCE/EXIT), `3` (GENERIC_NODE), `4` (BOARDING_AREA). Defaults to `0` (STOP)
  when omitted from the row.
- `stop_lat` — optional double (latitude); conditionally required for location types 0,
  1, and 2. Null/absent means the field was not provided.
- `stop_lon` — optional double (longitude); conditionally required for location types 0,
  1, and 2. Null/absent means the field was not provided.

## 3. Validation logic

The Java validator is a `SingleEntityValidator<GtfsStop>`, meaning the `validate` method
is called once per row of `stops.txt`. A single check is performed.

### Step 1: Determine whether the location type requires coordinates

- If `location_type` is STOP (0), STATION (1), or ENTRANCE (2): coordinates are
  **required**.
- If `location_type` is GENERIC_NODE (3), BOARDING_AREA (4), UNRECOGNIZED, or anything
  else: coordinates are **not required** — skip this row entirely.

### Step 2: Check for missing lat/lon

The Java method `stop.hasStopLatLon()` returns `true` only when **both** `stop_lat` and
`stop_lon` are present (non-null). It returns `false` if either field is absent.

If `location_type` is in {0, 1, 2} AND `hasStopLatLon()` is `false` (i.e., at least one
of `stop_lat` or `stop_lon` is null/missing), emit `stop_without_location` (ERROR).

### Decision table

| location_type | stop_lat present | stop_lon present | Result |
|---|---|---|---|
| STOP (0) | no | no | `stop_without_location` ERROR |
| STOP (0) | yes | no | `stop_without_location` ERROR |
| STOP (0) | no | yes | `stop_without_location` ERROR |
| STOP (0) | yes | yes | No notice |
| STATION (1) | no | no | `stop_without_location` ERROR |
| STATION (1) | yes | no | `stop_without_location` ERROR |
| STATION (1) | no | yes | `stop_without_location` ERROR |
| STATION (1) | yes | yes | No notice |
| ENTRANCE (2) | no | no | `stop_without_location` ERROR |
| ENTRANCE (2) | yes | no | `stop_without_location` ERROR |
| ENTRANCE (2) | no | yes | `stop_without_location` ERROR |
| ENTRANCE (2) | yes | yes | No notice |
| GENERIC_NODE (3) | any | any | No notice |
| BOARDING_AREA (4) | any | any | No notice |
| UNRECOGNIZED | any | any | No notice |

## 4. Notices emitted

### `stop_without_location` (ERROR)

Emitted when a stop, station, or entrance is missing at least one of `stop_lat` /
`stop_lon`.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | integer | `stops.csv_row_number` | 1-based row number of the offending row |
| `stop_id` | string | `stops.stop_id` | Identifier of the stop |
| `location_type` | integer (enum) | `stops.location_type` | The location type requiring coordinates (0, 1, or 2) |

Condition: `location_type IN (0, 1, 2) AND (stop_lat IS NULL OR stop_lon IS NULL)`.

### Notice code mapping

| Java class | Python notice code |
|---|---|
| `StopWithoutLocationNotice` | `stop_without_location` |

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `stops.txt` absent from feed | Return `[]`; no notices. |
| `stops.txt` present but empty | Return `[]`; no notices. |
| `stop_lat` and `stop_lon` columns both absent from file header | Treated as null for all rows; any STOP/STATION/ENTRANCE rows will trigger the notice. |
| `stop_lat` present but `stop_lon` column absent | `hasStopLatLon()` is `false`; notice is emitted for STOP/STATION/ENTRANCE rows. |
| `stop_lon` present but `stop_lat` column absent | Same as above; notice is emitted. |
| `location_type` omitted from a row (defaults to 0, STOP) | Treated as STOP; triggers `stop_without_location` if either coordinate is absent. |
| `location_type` is GENERIC_NODE (3) with both coordinates missing | No notice. |
| `location_type` is BOARDING_AREA (4) with both coordinates missing | No notice. |
| `location_type` is UNRECOGNIZED with both coordinates missing | No notice. |
| Both coordinates present for STOP/STATION/ENTRANCE | No notice. |
| Multiple offending rows | One notice per offending row. |

### Note on misleading Java test names

The tests for "given lat but missing lon" and "given lon but missing lat" are named with
the suffix `_generatesNoNotice` in the Java source, but their assertions use
`containsExactly(new StopWithoutLocationNotice(...))`. The actual contract (and assertion)
is that a notice IS generated. The test names are incorrect — the behavioral contract is
what matters: missing either coordinate triggers the notice.

### Missing from test suite

The test suite does not cover:
- `location_type` defaulting to STOP (0) when omitted from the row.
- Empty DataFrame.
- `stop_lat` or `stop_lon` column absent from the file header entirely (as opposed to
  a null value in the column).
- Multiple offending rows in a single feed.

## 7. Implementation notes

### Polars approach

This check is a single vectorized filter pass over the `stops` DataFrame. No cross-table
join is needed.

```python
import polars as pl
from gtfs_validator.notices import Notice
from gtfs_validator.context import ValidationContext

REQUIRED_LOCATION_LOCATION_TYPES = {0, 1, 2}  # STOP, STATION, ENTRANCE


def validate_stop_required_location(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
    if "stops" not in feed:
        return []
    stops = feed["stops"]
    if stops.is_empty():
        return []

    # Build the filter: location_type in {0, 1, 2} AND (lat IS NULL OR lon IS NULL)
    lat_missing = (
        pl.col("stop_lat").is_null()
        if "stop_lat" in stops.columns
        else pl.lit(True)
    )
    lon_missing = (
        pl.col("stop_lon").is_null()
        if "stop_lon" in stops.columns
        else pl.lit(True)
    )

    offenders = stops.filter(
        pl.col("location_type").is_in(list(REQUIRED_LOCATION_LOCATION_TYPES))
        & (lat_missing | lon_missing)
    )

    notices: list[Notice] = []
    for row in offenders.iter_rows(named=True):
        notices.append(
            Notice(
                code="stop_without_location",
                severity="ERROR",
                fields={
                    "csv_row_number": row["csv_row_number"],
                    "stop_id": row["stop_id"],
                    "location_type": row["location_type"],
                },
            )
        )
    return notices
```

### Null semantics for stop_lat / stop_lon

The Java `stop.hasStopLatLon()` is a framework-generated method that returns `true` only
when both `stop_lat` and `stop_lon` are set (non-null). In the Python loading layer,
absent or unparseable float fields are represented as `null` in the Polars column. The
filter condition `stop_lat IS NULL OR stop_lon IS NULL` correctly captures both "column
absent from header" (handled by substituting `pl.lit(True)` for the missing column) and
"value missing from a specific row" (null in the DataFrame cell).

### Guard clause ordering

1. `"stops"` not in feed — return `[]`.
2. `stops.is_empty()` — return `[]`.
3. `"location_type"` not in `stops.columns` — all rows default to STOP (0); the check
   still runs (lat/lon absence for every row would trigger notices).
4. Filter for offending rows and emit one notice per row.

### Column absence vs null

If `stop_lat` or `stop_lon` is not present in the file header at all, the DataFrame will
not have that column. The implementation must treat a missing column as equivalent to
all values being null for that column (i.e., use `pl.lit(True)` for the missing-column
branch of the filter).

### Enum integer values

| GtfsLocationType name | Integer value |
|---|---|
| STOP | 0 |
| STATION | 1 |
| ENTRANCE | 2 |
| GENERIC_NODE | 3 |
| BOARDING_AREA | 4 |
| UNRECOGNIZED | (any value not in 0–4) |

### Validator registration

Required tables: `["stops"]`.

Activation condition: `stops.txt` is present. No column-level guard is applied (unlike
some other validators). If `location_type` is absent the GTFS spec implies all rows
default to type 0 (STOP), which requires coordinates.

### Feed dict keys

- `"stops"` — `stops.txt`
