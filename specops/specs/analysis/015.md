# Analysis: FareProductDefaultRiderCategoriesValidator

## 1. Purpose

Validates that each fare product in `fare_products.txt` is associated with at most one rider category from `rider_categories.txt` that is marked as the default fare category (`is_default_fare_category = 1`).

A fare product may be listed multiple times in `fare_products.txt` (with different `fare_media_id` or `rider_category_id` combinations forming a composite primary key). The validator groups rows by `fare_product_id` and counts how many distinct default-marked rider categories are linked to that product. If any fare product is linked to two or more distinct default rider categories, one error notice is emitted per such product, referencing the first two offending rows.

This validator requires both `fare_products.txt` and `rider_categories.txt` to be present. If `rider_categories.txt` is absent, the validator is skipped entirely.

## 2. Input tables

| Table | Columns used |
|---|---|
| `fare_products.txt` | `fare_product_id`, `rider_category_id`, `csv_row_number` |
| `rider_categories.txt` | `rider_category_id`, `is_default_fare_category` |

### Schema reference

`fare_products.txt` (`GtfsFareProductSchema`):

| Column | Type | Constraint |
|---|---|---|
| `fare_product_id` | ID (string) | Required, part of composite primary key |
| `fare_product_name` | string | Optional |
| `amount` | decimal | Required, non-negative |
| `currency` | currency code | Required |
| `fare_media_id` | ID (string) | Optional, FK → `fare_media.txt`, part of composite PK |
| `rider_category_id` | ID (string) | Optional, FK → `rider_categories.txt`, part of composite PK |

`rider_categories.txt` (`GtfsRiderCategoriesSchema`):

| Column | Type | Constraint |
|---|---|---|
| `rider_category_id` | ID (string) | Required, primary key |
| `rider_category_name` | string | Required |

`GtfsRiderFareCategory` enum values:

| Name | Integer value | Meaning |
|---|---|---|
| `NOT_DEFAULT` | 0 | Rider category is not the default |
| `IS_DEFAULT` | 1 | Rider category is the default fare category |

## 3. Validation logic

### Skip condition

Run only when `rider_categories.txt` is present and not a missing file. If `rider_categories.txt` is absent, return immediately with no notices. `fare_products.txt` being absent or empty is not an explicit skip condition in the Java code; an absent or empty `fare_products.txt` will simply produce no iterations and thus no notices.

In Python:

```python
if "rider_categories" not in feed or feed["rider_categories"].is_empty():
    return []
if "fare_products" not in feed or feed["fare_products"].is_empty():
    return []
```

### Algorithm

The Java validator uses an iterative, stateful approach with three hash maps keyed by `fare_product_id`:

- `fareProductDefaultCount`: maps `fare_product_id` → count of distinct default rider categories seen so far.
- `fareProductRiderCategories`: maps `fare_product_id` → list of distinct default `rider_category_id` values seen so far.
- `fareProductRows`: maps `fare_product_id` → list of `csv_row_number` values corresponding to each distinct default rider category entry.

**Phase 1 — accumulate per fare_product_id:**

For each row in `fare_products.txt` (in CSV order):

1. Look up `rider_category_id` in `rider_categories.txt`.
2. If the rider category is found AND its `is_default_fare_category` equals `IS_DEFAULT` (1):
   a. If this `fare_product_id` has not been seen before: record it with count=1, store the `rider_category_id`, store the `csv_row_number`.
   b. Else if the `rider_category_id` is NOT already recorded for this `fare_product_id`: increment the count, append the `rider_category_id`, append the `csv_row_number`.
   c. Else (same `rider_category_id` appearing again for the same `fare_product_id`): do nothing (de-duplication on rider category identity).

**Phase 2 — emit notices:**

For each `fare_product_id` whose count exceeds 1:

- Emit exactly one `fare_product_with_multiple_default_rider_categories` notice using the first two distinct default-category rows/rider-category-ids that were recorded.

### Key behavioral details

- De-duplication is by `rider_category_id` identity. If the same default rider category appears on multiple rows for the same fare product (e.g., two rows with the same `fare_product_id` and `rider_category_id` but different `fare_media_id`), only the first occurrence is counted. The rider category must be distinct to be counted as a second default.
- The notice references exactly rows 0 and 1 from the accumulated lists (the first two distinct default rider category rows for the product). If there are three or more distinct default rider categories, only one notice is still emitted per product (with the first two rows).
- Rider categories that are `NOT_DEFAULT` (0) are completely ignored.
- A `rider_category_id` referenced by a fare product row that does not exist in `rider_categories.txt` is silently skipped (the FK lookup returns an empty Optional).

### Pseudocode

```
per_product_defaults: dict[fare_product_id -> {count, rider_category_ids[], row_numbers[]}]

for each fare_product_row in fare_products (in CSV order):
    rcat = lookup rider_categories by fare_product_row.rider_category_id
    if rcat not found:
        continue
    if rcat.is_default_fare_category != IS_DEFAULT:
        continue
    entry = per_product_defaults.get(fare_product_row.fare_product_id)
    if entry is None:
        per_product_defaults[fare_product_id] = {
            count: 1,
            rider_category_ids: [rcat.rider_category_id],
            row_numbers: [fare_product_row.csv_row_number]
        }
    elif rcat.rider_category_id not in entry.rider_category_ids:
        entry.rider_category_ids.append(rcat.rider_category_id)
        entry.row_numbers.append(fare_product_row.csv_row_number)
        entry.count += 1

for fare_product_id, entry in per_product_defaults:
    if entry.count > 1:
        emit fare_product_with_multiple_default_rider_categories(
            fare_product_id=fare_product_id,
            csv_row_number1=entry.row_numbers[0],
            csv_row_number2=entry.row_numbers[1],
            rider_category_id1=entry.rider_category_ids[0],
            rider_category_id2=entry.rider_category_ids[1]
        )
```

### What is NOT checked here

- Whether `fare_product_id` or `rider_category_id` exists and is non-null (required field / PK checks at load time).
- Whether `rider_category_id` in `fare_products.txt` resolves to a known record (FK check at load time).
- Whether `is_default_fare_category` is a valid enum value (domain check at load time).
- Uniqueness of the composite primary key in `fare_products.txt` (PK check at load time).

## 4. Notices emitted

### `fare_product_with_multiple_default_rider_categories`

Severity: **ERROR**

Emitted once per `fare_product_id` that is linked to two or more distinct rider categories both marked as `IS_DEFAULT`.

| Field | Type | Description |
|---|---|---|
| `fare_product_id` | string | The fare product with multiple default rider categories |
| `csv_row_number1` | int | CSV row number of the first occurrence (first distinct default rider category row) |
| `csv_row_number2` | int | CSV row number of the second occurrence (second distinct default rider category row) |
| `rider_category_id1` | string | ID of the first default rider category |
| `rider_category_id2` | string | ID of the second default rider category |

Both row numbers refer to rows in `fare_products.txt`.

## 5. Edge cases

- **`rider_categories.txt` absent**: Validator is skipped entirely; no notices.
- **`fare_products.txt` absent or empty**: No rows to iterate; no notices.
- **Fare product with zero default rider categories**: No entry in accumulator; no notice.
- **Fare product with exactly one default rider category**: Count = 1; no notice.
- **Fare product with two or more distinct default rider categories**: Count > 1; exactly one notice per product, always referencing first and second distinct occurrences.
- **Same default rider category appearing on multiple fare_product rows (same `fare_product_id` + `rider_category_id`, different `fare_media_id`)**: De-duplicated; counted only once. No notice emitted for this case alone.
- **`rider_category_id` in fare_products.txt not found in rider_categories.txt**: Silently skipped (missing FK target); no notice from this validator (FK violation handled at load time).
- **`rider_category_id` found in rider_categories.txt but `is_default_fare_category = NOT_DEFAULT` (0)**: Skipped; does not contribute to the default count.
- **Three or more distinct default rider categories for one fare product**: Still emits exactly one notice per product, referencing only the first two distinct rider categories / rows. The third and beyond are not referenced in the notice.
- **Different fare products each with two default rider categories**: Each product emits its own separate notice.
- **Default rider category that resolves via FK but `fare_product_id` is repeated with the same `rider_category_id`**: Only the first row encountering that pair is counted; subsequent same-rider-category rows for the same product are ignored.
- **`fare_products.txt` present but `rider_categories.txt` is an empty file**: The Java `shouldCallValidate` checks `isMissingFile()`, not emptiness. An empty-but-present `rider_categories.txt` would pass the skip guard and be processed; all FK lookups would return empty Optional, so no notices would be emitted.

## 7. Implementation notes

### Validator type

Cross-table validator. Requires join between `fare_products.txt` and `rider_categories.txt`. The core logic groups fare product rows by `fare_product_id` and tracks distinct default rider categories per group.

### Validator signature

```python
def validate_fare_product_default_rider_categories(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
```

### Skip logic

```python
if "rider_categories" not in feed or feed["rider_categories"].is_empty():
    return []
if "fare_products" not in feed or feed["fare_products"].is_empty():
    return []
```

### Polars implementation strategy

The Java logic is stateful and row-ordered due to its de-duplication requirement (same `rider_category_id` for the same `fare_product_id` must not be double-counted). This can be expressed in Polars using joins and group-by operations:

**Step 1**: Join `fare_products` with `rider_categories` on `rider_category_id` to bring in `is_default_fare_category`. Use a left join to retain all fare product rows; non-matching rows will have null `is_default_fare_category`.

**Step 2**: Filter to rows where `is_default_fare_category == 1` (IS_DEFAULT).

**Step 3**: Drop duplicate `(fare_product_id, rider_category_id)` pairs (de-duplication as in Java). Keep the first occurrence by `csv_row_number` within each pair to preserve the row ordering behavior.

**Step 4**: Group by `fare_product_id`. For each group with two or more rows, collect the first two `csv_row_number` and `rider_category_id` values (ordered by original CSV row number to match Java's iteration order).

**Step 5**: Emit one notice per violating `fare_product_id`.

```python
df_fp = feed["fare_products"]
df_rc = feed["rider_categories"].select(["rider_category_id", "is_default_fare_category"])

# Join to get default flag
joined = df_fp.join(df_rc, on="rider_category_id", how="left")

# Keep only IS_DEFAULT rows
defaults = joined.filter(pl.col("is_default_fare_category") == 1)

# De-duplicate: one row per (fare_product_id, rider_category_id), keep earliest by csv_row_number
deduped = (
    defaults
    .sort("csv_row_number")
    .unique(subset=["fare_product_id", "rider_category_id"], keep="first")
    .sort("csv_row_number")  # restore order after unique
)

# Group by fare_product_id, collect first two rider_category_ids and row numbers
notices = []
for fare_product_id, group in deduped.group_by("fare_product_id"):
    group_sorted = group.sort("csv_row_number")
    if len(group_sorted) > 1:
        rows = group_sorted.iter_rows(named=True)
        r1 = next(rows)
        r2 = next(rows)
        notices.append(Notice(
            code="fare_product_with_multiple_default_rider_categories",
            severity=Severity.ERROR,
            fields={
                "fare_product_id": fare_product_id,
                "csv_row_number1": r1["csv_row_number"],
                "csv_row_number2": r2["csv_row_number"],
                "rider_category_id1": r1["rider_category_id"],
                "rider_category_id2": r2["rider_category_id"],
            },
        ))
return notices
```

Note: `group_by` in Polars does not guarantee order of groups. The notice ordering across multiple violating products is not specified by the Java implementation (HashMap iteration order is undefined), so any group ordering is acceptable. Within each group, sort by `csv_row_number` to ensure `row1/id1` always refers to the earlier row, consistent with Java's insertion-order accumulation.

### Relationship to load-time validation

The following are handled at load time and must not be duplicated here:

- `fare_product_id` required and non-null.
- `rider_category_id` in `fare_products.txt` is a valid FK into `rider_categories.txt`.
- `is_default_fare_category` is a valid enum value (0 or 1).
- Composite PK uniqueness of `(fare_product_id, fare_media_id, rider_category_id)` in `fare_products.txt`.

This validator only adds the cross-product business rule: a single fare product must not be associated with more than one distinct default rider category.

### Relationship to `rider_categories.txt` presence check

The Java `shouldCallValidate()` tests `riderCategoriesTable != null && !riderCategoriesTable.isMissingFile()`. In Python, this maps to checking whether `"rider_categories"` is a key in the feed dict. The Python skip check should guard on both `rider_categories` and `fare_products` being present and non-empty before proceeding.
