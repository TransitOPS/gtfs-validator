# Analysis: StopTimesRecordValidator

## 1. Purpose

Validates that any `stop_times.txt` row describing a flexible-service location
(one that has both `start_pickup_dropoff_window` and `end_pickup_dropoff_window`
set, and requires a phone call for both pickup and drop-off) is not the sole
record for its trip — because travel within the same location group or GeoJSON
location requires exactly two stop_times records sharing the same
`location_group_id` or `location_id`.

## 2. Input tables

| Table | Columns used |
|---|---|
| `stop_times.txt` | `trip_id`, `start_pickup_dropoff_window`, `end_pickup_dropoff_window`, `pickup_type`, `drop_off_type`, `location_group_id`, `location_id`, `csv_row_number` |

### Column semantics

- `start_pickup_dropoff_window` — optional time; the start of the flexible
  pickup/drop-off window. Non-null presence is what triggers this validator's
  per-row check.
- `end_pickup_dropoff_window` — optional time; the end of the flexible window.
  Non-null presence is required alongside the start window.
- `pickup_type` — integer enum; `2` means `MUST_PHONE` (passenger must phone to
  arrange pickup).
- `drop_off_type` — integer enum; `2` means `MUST_PHONE` (passenger must phone to
  arrange drop-off).
- `trip_id` — string; used to group records by trip and count siblings.
- `location_group_id` — optional string; identifies a flexible location group.
  Included in the notice payload for diagnostic context.
- `location_id` — optional string; identifies a GeoJSON location area. Included
  in the notice payload for diagnostic context.
- `csv_row_number` — integer; source CSV row number, included in notice payload.

### `GtfsPickupDropOff` enum values

| Name | Integer value |
|---|---|
| `REGULAR` | 0 |
| `NOT_AVAILABLE` | 1 |
| `MUST_PHONE` | 2 |
| `ON_REQUEST_TO_DRIVER` | 3 |

The validator checks specifically for value `2` (`MUST_PHONE`) on both
`pickup_type` and `drop_off_type`.

## 3. Validation logic

This is a `FileValidator` that iterates over all rows in `stop_times.txt` after
the table is fully loaded.

### Guard clause (`shouldCallValidate`)

Before any row-level logic runs, the validator checks that all four columns are
present as headers in `stop_times.txt`:

- `start_pickup_dropoff_window`
- `end_pickup_dropoff_window`
- `pickup_type`
- `drop_off_type`

If `stop_times.txt` is absent entirely, or any of these four columns is missing
from the file header, the validator skips entirely and returns no notices.

### Per-row check

For each row in `stop_times.txt`:

1. Check that `start_pickup_dropoff_window` is present (non-null) for this row.
2. Check that `end_pickup_dropoff_window` is present (non-null) for this row.
3. Check that `pickup_type == 2` (MUST_PHONE).
4. Check that `drop_off_type == 2` (MUST_PHONE).
5. If all four conditions in steps 1–4 are true:
   a. Count how many rows in `stop_times.txt` share this row's `trip_id`. Call
      this `trip_stop_count`.
   b. If `trip_stop_count == 1` (this is the only record for the trip):
      - Emit `missing_stop_times_record` with the row's `csv_row_number`,
        `trip_id`, `location_group_id`, and `location_id`.
6. If any condition in steps 1–4 is false, no notice is emitted for this row.

The check is a conjunction: all four conditions must hold before the trip-count
lookup and notice emission occur.

### Why trip_stop_count == 1 is the trigger

GTFS flexible service semantics require that a trip using a GeoJSON location or
location group must have two stop_times records: one representing the origin
within the area and one representing the destination within the same area (or a
different area). A trip with only one such record is malformed — it has no
destination record.

## 4. Notices emitted

### `missing_stop_times_record` (ERROR)

Emitted when a `stop_times.txt` row describing a flexible-service location
(has both window times and both types set to MUST_PHONE) is the only record
for its `trip_id`.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | int | `stop_times.csv_row_number` | CSV row number of the offending row |
| `trip_id` | string | `stop_times.trip_id` | The trip that has only one stop_times record |
| `location_group_id` | string or null | `stop_times.location_group_id` | Location group ID from the row, if present |
| `location_id` | string or null | `stop_times.location_id` | GeoJSON location ID from the row, if present |

Condition: `start_pickup_dropoff_window` is non-null AND
`end_pickup_dropoff_window` is non-null AND `pickup_type == 2` AND
`drop_off_type == 2` AND the count of rows with the same `trip_id` in
`stop_times.txt` is exactly 1.

The notice is defined as inner class
`StopTimesRecordValidator.MissingStopTimesRecordNotice` in the Java source. In
Python it should be a standalone notice dataclass with code
`"missing_stop_times_record"` and severity ERROR.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `stop_times.txt` absent from feed | Guard: return `[]` immediately. |
| `stop_times.txt` present but empty (zero rows) | No rows satisfy conditions; return `[]`. |
| Any of the four guard columns missing from file header | `shouldCallValidate` returns false; validator skips entirely; return `[]`. |
| Row has both windows and both types are MUST_PHONE, but `trip_id` has 2+ records | `trip_stop_count > 1`; condition not met; no notice. |
| Row has both windows but `pickup_type != MUST_PHONE` | Conjunction fails; no notice. |
| Row has both windows but `drop_off_type != MUST_PHONE` | Conjunction fails; no notice. |
| Row has `pickup_type == MUST_PHONE` and `drop_off_type == MUST_PHONE` but no window times | `hasStartPickupDropOffWindow` is false; conjunction fails; no notice. |
| Row satisfies all conditions AND is the sole record for the trip | Emit `missing_stop_times_record` with `location_group_id` and `location_id` from that row (either or both may be null). |
| Multiple trips each with exactly one MUST_PHONE window record | One notice emitted per qualifying trip. |
| `location_group_id` is null on the offending row | Included in notice payload as null. |
| `location_id` is null on the offending row | Included in notice payload as null. |

## 6. Test contracts

### `containsStopTimesRecordShouldNotGenerateNotice1` (no notice)

- Input: a single stop_time row with:
  - `trip_id = "trip1"`, `location_group_id = "locationGroupId1"`,
    `location_id = "locationId1"`
  - `pickup_type = REGULAR (0)`, `drop_off_type = REGULAR (0)`
  - `start_pickup_dropoff_window = 08:00:00`,
    `end_pickup_dropoff_window = 09:00:00`
- Expected: empty notices list.
- Covers: row with window times present but pickup/drop-off types are REGULAR,
  not MUST_PHONE, so the conjunction fails.

Note: this is the only "no notice" test in the suite. It does not test the case
where MUST_PHONE is set but `trip_stop_count > 1`. That case is implied by the
logic but has no explicit Java test.

### `missingStopTimesRecordShouldGenerateNotice` (notice)

- Input: a single stop_time row with:
  - `trip_id = "trip2"`, `location_group_id = "locationGroupId1"`,
    `location_id = "locationId1"`
  - `pickup_type = MUST_PHONE (2)`, `drop_off_type = MUST_PHONE (2)`
  - `start_pickup_dropoff_window = 08:00:00`,
    `end_pickup_dropoff_window = 09:00:00`
- Expected: exactly one `MissingStopTimesRecordNotice` with:
  - `csv_row_number = 1`
  - `trip_id = "trip2"`
  - `location_group_id = "locationGroupId1"`
  - `location_id = "locationId1"`
- Covers: all four conditions met and the trip has only one stop_times record.

### What is NOT covered by the Java test suite

- `stop_times.txt` absent entirely.
- Any of the four guard columns missing from the file header (the
  `shouldCallValidate` path).
- Empty `stop_times.txt` (zero rows).
- A trip with two or more records that all satisfy the window+MUST_PHONE
  conditions (no notice expected).
- A row with MUST_PHONE types but missing window times (no notice expected).
- Multiple offending rows across multiple trips.
- Rows where `location_group_id` or `location_id` is null on the offending row.

## 7. Implementation notes

### Algorithm strategy

The validator has two distinct phases:

1. **Guard clause**: check that all four required columns are present.
2. **Filter and count**: for rows that pass the four-condition filter, look up
   the trip-level count and emit notices where count == 1.

The per-row conjunction is naturally vectorized. The trip count lookup can be
precomputed as a group-by aggregation.

### Recommended Polars approach

```python
def validate_stop_times_record(
    feed: dict[str, pl.DataFrame], ctx: ValidationContext
) -> list[Notice]:
    if "stop_times" not in feed:
        return []

    st = feed["stop_times"]

    # Guard: all four columns must be present as columns
    required_cols = {
        "start_pickup_dropoff_window",
        "end_pickup_dropoff_window",
        "pickup_type",
        "drop_off_type",
    }
    if not required_cols.issubset(set(st.columns)):
        return []

    if st.is_empty():
        return []

    # Precompute per-trip row count
    trip_counts = (
        st.group_by("trip_id")
        .agg(pl.len().alias("trip_stop_count"))
    )

    # Join count back onto stop_times
    st_with_count = st.join(trip_counts, on="trip_id", how="left")

    # Apply the four-condition filter + singleton trip check
    MUST_PHONE = 2
    violations = st_with_count.filter(
        pl.col("start_pickup_dropoff_window").is_not_null()
        & pl.col("end_pickup_dropoff_window").is_not_null()
        & (pl.col("pickup_type") == MUST_PHONE)
        & (pl.col("drop_off_type") == MUST_PHONE)
        & (pl.col("trip_stop_count") == 1)
    )

    notices: list[Notice] = []
    for row in violations.iter_rows(named=True):
        notices.append(
            MissingStopTimesRecordNotice(
                csv_row_number=row["csv_row_number"],
                trip_id=row["trip_id"],
                location_group_id=row.get("location_group_id"),
                location_id=row.get("location_id"),
            )
        )
    return notices
```

### Guard clause ordering

1. `"stop_times"` not in feed → return `[]`.
2. Not all four required columns present in `stop_times.columns` → return `[]`.
3. `stop_times` is empty (0 rows) → return `[]` (naturally handled by empty
   filter results, but can be short-circuited for clarity).

### Polars vs plain Python

- The four-condition conjunction and the `trip_stop_count == 1` check are all
  vectorized via Polars filter expressions.
- A `group_by` aggregation replaces the Java per-row `byTripId(...).size()`
  lookup, which would otherwise be O(n) per row.
- `iter_rows(named=True)` is used only for the final notice construction over
  the (typically small) set of violations.

### Notice dataclass

```python
@dataclass
class MissingStopTimesRecordNotice:
    code: ClassVar[str] = "missing_stop_times_record"
    severity: ClassVar[str] = "ERROR"
    csv_row_number: int
    trip_id: str
    location_group_id: str | None
    location_id: str | None
```

### Optional columns in the notice payload

`location_group_id` and `location_id` may not be present as columns at all (they
are optional GTFS flex fields). If they are absent from the DataFrame entirely,
use `None` in the notice. Guard with `"location_group_id" in st.columns` and
`"location_id" in st.columns` before selecting those fields, or use
`.get(column, None)` when iterating rows.

### Feed dict keys

- `"stop_times"` — `stop_times.txt`

No other tables are required.

### Validator registration

Required tables: `["stop_times"]`.

Feature flag: none needed. The validator runs whenever `stop_times.txt` is
present and contains all four required column headers.

### MUST_PHONE constant

The `GtfsPickupDropOff.MUST_PHONE` Java enum value corresponds to integer `2`.
In Python, define a module-level constant `MUST_PHONE = 2` or reference the
equivalent enum in `schemas.py` if one is defined there.
