# Analysis: StopNameValidator

## 1. Purpose

Validate that `stops.stop_name` is present for stops, stations, and entrances
(location_type 0, 1, 2), and that `stops.stop_desc` is not identical (case-insensitively)
to `stops.stop_name` when both fields are populated.

## 2. Input tables

| Table | Columns used |
|---|---|
| `stops.txt` | `csv_row_number`, `stop_id`, `stop_name`, `stop_desc`, `location_type` |

This is a single-table validator operating on `stops.txt` only. No cross-table joins
are performed.

### Column semantics

- `stop_name` — optional string; required when `location_type` is 0, 1, or 2.
  Null/absent means the field was not provided.
- `stop_desc` — optional string; when provided must not duplicate `stop_name`.
  Null/absent means the field was not provided.
- `location_type` — integer enum; values are `0` (STOP), `1` (STATION), `2`
  (ENTRANCE/EXIT), `3` (GENERIC_NODE), `4` (BOARDING_AREA). Defaults to `0` (STOP)
  when omitted from the row.

## 3. Validation logic

The Java validator is a `SingleEntityValidator<GtfsStop>`, meaning the `validate` method
is called once per row of `stops.txt`. Two independent checks are performed.

### Step 1: Guard — skip entire validator if required columns are absent

The `shouldCallValidate` method returns `false` (and the validator is never called)
when **both** `stop_name` and `location_type` columns are missing from the file header.
The validator still runs if at least one of these columns is present.

In Python: if neither `stop_name` nor `location_type` is present in the `stops`
DataFrame columns, return `[]` immediately.

### Step 2: Check A — missing stop_name for required location types

For each row:
1. Evaluate `location_type`. If it equals STOP (0), STATION (1), or ENTRANCE (2):
   - If `stop_name` is empty/null, emit `missing_stop_name` (ERROR).
   - If `stop_name` is non-empty, no notice.
2. If `location_type` is GENERIC_NODE (3), BOARDING_AREA (4), UNRECOGNIZED, or anything
   else: skip this check entirely — `stop_name` is not required.

### Step 3: Check B — stop_desc duplicates stop_name

After Check A (regardless of its result):
1. If `stop_name` is null/absent (`!stop.hasStopName()`) OR `stop_desc` is null/absent
   (`!stop.hasStopDesc()`): skip this check (early return in Java).
2. If both `stop_name` and `stop_desc` are present: compare them case-insensitively.
   - If they are equal (ignoring case), emit `same_name_and_description_for_stop` (WARNING).
   - If they differ, no notice.

### Decision table — missing_stop_name

| location_type | stop_name present | Result |
|---|---|---|
| STOP (0) | no (null/empty) | `missing_stop_name` ERROR |
| STOP (0) | yes | No notice |
| STATION (1) | no (null/empty) | `missing_stop_name` ERROR |
| STATION (1) | yes | No notice |
| ENTRANCE (2) | no (null/empty) | `missing_stop_name` ERROR |
| ENTRANCE (2) | yes | No notice |
| GENERIC_NODE (3) | no | No notice |
| BOARDING_AREA (4) | no | No notice |
| UNRECOGNIZED | no | No notice |

### Decision table — same_name_and_description_for_stop

| stop_name present | stop_desc present | stop_name == stop_desc (case-insensitive) | Result |
|---|---|---|---|
| no | any | N/A | No notice |
| any | no | N/A | No notice |
| yes | yes | yes | `same_name_and_description_for_stop` WARNING |
| yes | yes | no | No notice |

## 4. Notices emitted

### `missing_stop_name` (ERROR)

Emitted when a stop, station, or entrance has no `stop_name`.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | integer | `stops.csv_row_number` | 1-based row number of the offending row |
| `stop_id` | string | `stops.stop_id` | Identifier of the stop |
| `location_type` | integer (enum) | `stops.location_type` | The location type requiring a name (0, 1, or 2) |

Condition: `location_type IN (0, 1, 2) AND (stop_name IS NULL OR stop_name == '')`.

### `same_name_and_description_for_stop` (WARNING)

Emitted when `stop_desc` duplicates `stop_name` (case-insensitive comparison).

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | integer | `stops.csv_row_number` | 1-based row number of the offending row |
| `stop_id` | string | `stops.stop_id` | Identifier of the stop |
| `stop_desc` | string | `stops.stop_desc` | The description that duplicates the name |

Condition: `stop_name IS NOT NULL AND stop_desc IS NOT NULL AND lower(stop_name) == lower(stop_desc)`.

Note: `stop_name` is not included in the `SameNameAndDescriptionForStopNotice` fields —
only `csv_row_number`, `stop_id`, and `stop_desc` are recorded in the Java notice.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `stops.txt` absent from feed | Return `[]`; no notices. |
| `stops.txt` present but empty | Return `[]`; no notices. |
| Both `stop_name` and `location_type` columns absent from file header | Return `[]` immediately (column-level guard). |
| Only `stop_name` absent but `location_type` present | Validator still runs (guard passes if at least one column exists). |
| Only `location_type` absent but `stop_name` present | Validator still runs. |
| `location_type` omitted from a row (defaults to 0, STOP) | Treated as STOP; triggers `missing_stop_name` if `stop_name` is also absent. |
| `location_type` is GENERIC_NODE (3) with null `stop_name` | No `missing_stop_name` notice. |
| `location_type` is BOARDING_AREA (4) with null `stop_name` | No `missing_stop_name` notice. |
| `location_type` is UNRECOGNIZED with null `stop_name` | No `missing_stop_name` notice. |
| Both checks could fire on the same row | Both notices are emitted independently (Check A and Check B are independent). In practice, Check B requires both `stop_name` and `stop_desc` to be present, so a row with null `stop_name` can only trigger Check A. |
| `stop_name` and `stop_desc` differ only in case (e.g. "Stop" vs "stop") | `same_name_and_description_for_stop` WARNING emitted. |
| `stop_name` present but `stop_desc` null | No `same_name_and_description_for_stop` notice. |
| `stop_name` null but `stop_desc` present | No `same_name_and_description_for_stop` notice. |
| Multiple offending rows | One notice per offending row per check. |

### Missing from test suite

The test suite does not cover:
- Case-insensitive name/desc match (e.g. "Stop" vs "STOP").
- A row triggering both checks simultaneously (not possible since Check B requires
  non-null `stop_name`, but Check A fires only when `stop_name` is null).
- The `shouldCallValidate` guard (both columns absent from file header).
- Empty DataFrame.
- `location_type` defaulting to STOP (0) when omitted from the row.

## 7. Implementation notes

### Polars approach

Both checks are independent vectorized filter passes over the `stops` DataFrame. There
is no need for row-by-row iteration during the filter phase; `iter_rows` is used only
to construct the notice list from the already-filtered subset.

```python
import polars as pl
from gtfs_validator.notices import Notice
from gtfs_validator.context import ValidationContext

REQUIRED_NAME_LOCATION_TYPES = {0, 1, 2}  # STOP, STATION, ENTRANCE


def validate_stop_name(
    feed: dict[str, pl.DataFrame],
    ctx: ValidationContext,
) -> list[Notice]:
    if "stops" not in feed:
        return []
    stops = feed["stops"]
    if stops.is_empty():
        return []

    # Column-level guard: skip if neither stop_name nor location_type is present
    if "stop_name" not in stops.columns and "location_type" not in stops.columns:
        return []

    notices: list[Notice] = []

    # Check A: missing stop_name for STOP/STATION/ENTRANCE
    if "stop_name" in stops.columns and "location_type" in stops.columns:
        missing_name = stops.filter(
            pl.col("location_type").is_in(list(REQUIRED_NAME_LOCATION_TYPES))
            & (pl.col("stop_name").is_null() | (pl.col("stop_name") == ""))
        )
        for row in missing_name.iter_rows(named=True):
            notices.append(
                Notice(
                    code="missing_stop_name",
                    severity="ERROR",
                    fields={
                        "csv_row_number": row["csv_row_number"],
                        "stop_id": row["stop_id"],
                        "location_type": row["location_type"],
                    },
                )
            )

    # Check B: stop_desc duplicates stop_name (case-insensitive)
    if "stop_name" in stops.columns and "stop_desc" in stops.columns:
        same_name_desc = stops.filter(
            pl.col("stop_name").is_not_null()
            & pl.col("stop_desc").is_not_null()
            & (pl.col("stop_name").str.to_lowercase() == pl.col("stop_desc").str.to_lowercase())
        )
        for row in same_name_desc.iter_rows(named=True):
            notices.append(
                Notice(
                    code="same_name_and_description_for_stop",
                    severity="WARNING",
                    fields={
                        "csv_row_number": row["csv_row_number"],
                        "stop_id": row["stop_id"],
                        "stop_desc": row["stop_desc"],
                    },
                )
            )

    return notices
```

### Null semantics for stop_name

The Java `stop.stopName().isEmpty()` check returns true when `stop_name` is an empty
string. The Java `stop.hasStopName()` check returns false when the field is null/unset.
In the Python loading layer, empty strings should be normalized to null at load time.
If they are preserved as empty strings, the Check A filter should use
`pl.col("stop_name").is_null() | (pl.col("stop_name") == "")`.

### Case-insensitive comparison

The Java `isValidStopDesc` method uses `stopDesc.equalsIgnoreCase(stopName)`. The
Polars equivalent is `pl.col("stop_name").str.to_lowercase() == pl.col("stop_desc").str.to_lowercase()`.

### Guard clause ordering

1. `"stops"` not in feed → return `[]`
2. `stops.is_empty()` → return `[]`
3. Neither `"stop_name"` nor `"location_type"` in `stops.columns` → return `[]`
4. Perform Check A if both `stop_name` and `location_type` columns exist.
5. Perform Check B if both `stop_name` and `stop_desc` columns exist.

|---|---|
| `MissingStopNameNotice` | `missing_stop_name` |
| `SameNameAndDescriptionForStopNotice` | `same_name_and_description_for_stop` |
