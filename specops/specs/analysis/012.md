# Analysis: FareAttributeAgencyIdValidator

## 1. Purpose

Checks that `agency_id` is present on every row of `fare_attributes.txt`. The requirement level depends on the number of agencies in the feed:

- When the feed has **more than one agency**, `agency_id` is **required** on every fare attribute row. Missing `agency_id` in this case is an error, because the fare cannot be unambiguously attributed to an agency.
- When the feed has **exactly one agency**, `agency_id` is **recommended** but not required. Missing `agency_id` in this case is a warning.

Reference integrity (checking that a supplied `agency_id` actually exists in `agency.txt`) is handled separately by the FK annotation mechanism and is not re-checked here.

## 2. Input tables

| Table | Columns used |
|---|---|
| `agency.txt` | (count only — entity count determines single vs. multi-agency) |
| `fare_attributes.txt` | `agency_id`, `fare_id` (fare_id used for identity/logging only), `csv_row_number` |

### Schema reference

| Column | Table | Type | Constraints |
|---|---|---|---|
| `agency_id` | `agency.txt` | ID (string) | Optional (some feeds have a single agency with no ID) |
| `fare_id` | `fare_attributes.txt` | ID (string) | Required, primary key |
| `agency_id` | `fare_attributes.txt` | ID (string) | Conditionally required (required when multiple agencies) |

## 3. Validation logic

### Skip condition

Do not run validation if any of the following is true:

- `agency.txt` table is absent (null) or has zero rows.
- `fare_attributes.txt` table is absent (null) or has zero rows.

### Main logic

1. Count total agencies: `total_agencies = len(agency_df)`.
2. For each row in `fare_attributes.txt`:
   - If `agency_id` is null/empty:
     - If `total_agencies > 1`: emit `missing_required_agency_id` (ERROR) for that row.
     - If `total_agencies == 1`: emit `missing_recommended_field` (WARNING) for that row.
   - If `agency_id` is present: no notice.

This is a per-row check. Each fare attribute row is evaluated independently. Multiple missing `agency_id` values each produce their own notice.

### What is NOT checked here

- Whether the provided `agency_id` value actually references a valid agency in `agency.txt`. That is handled by FK validation.

## 4. Notices emitted

### `missing_required_agency_id`

Severity: **ERROR**

Emitted when `agency_id` is missing from a `fare_attributes.txt` row and the feed has more than one agency.

| Field | Type | Description |
|---|---|---|
| `filename` | string | The filename (`"fare_attributes.txt"`) |
| `csv_row_number` | int | The row number of the offending fare attribute record |
| `agency_name` | string or null | The agency name if obtainable; always passed as `null` in the Java implementation |

Note: In the Java source, `agencyName` is always passed as `null` when constructing `MissingRequiredAgencyIdNotice`. The Python implementation should match this (pass `None` for `agency_name`).

### `missing_recommended_field`

Severity: **WARNING**

Emitted when `agency_id` is missing from a `fare_attributes.txt` row and the feed has exactly one agency.

| Field | Type | Description |
|---|---|---|
| `filename` | string | The filename (`"fare_attributes.txt"`) |
| `csv_row_number` | int | The row number of the offending fare attribute record |
| `field_name` | string | The name of the missing field: `"agency_id"` |

## 5. Edge cases

- **`agency.txt` absent or empty**: Skip entirely. No notices emitted, even if `fare_attributes.txt` has rows with missing `agency_id`.
- **`fare_attributes.txt` absent or empty**: Skip entirely. No notices emitted.
- **Single agency, `agency_id` missing**: WARNING, not ERROR. One `missing_recommended_field` notice per offending row.
- **Multiple agencies, `agency_id` missing on some rows but not others**: Only the rows with missing `agency_id` get notices. Rows with a valid `agency_id` are silent.
- **Multiple agencies, all rows have `agency_id`**: No notices at all.
- **Single agency, all rows have `agency_id`**: No notices.
- **Single agency with no `agency_id` in `agency.txt` itself**: The agency count is still 1. Missing `fare_attributes.agency_id` still emits a WARNING (not an ERROR).
- **Multiple fare attributes missing `agency_id` with multiple agencies**: Each missing row emits its own independent `missing_required_agency_id` ERROR notice.
- **`agency_id` is an empty string vs. null**: In Java, `hasAgencyId()` returns false for both null and the empty-string sentinel. The Python implementation should treat both null and empty string as "missing" for this check.

## 7. Implementation notes

### Validator type

File-level (cross-table) validator. Consumes `agency.txt` (count only) and `fare_attributes.txt` (per-row check).

### Skip logic

Implement as the `should_skip` guard in the Python runner integration:

```python
if "agency" not in feed or feed["agency"].is_empty():
    return []
if "fare_attributes" not in feed or feed["fare_attributes"].is_empty():
    return []
```

### Polars implementation strategy

The check is per-row on `fare_attributes.txt` filtered to rows where `agency_id` is null (or empty). Use a Polars filter expression rather than a Python loop:

1. Compute `total_agencies = len(feed["agency"])`.
2. Filter `fare_attributes` to rows where `agency_id` is null or `agency_id == ""`.
3. Iterate over the filtered result (typically small) to emit one notice per row.

This avoids a full Python loop over the unfiltered fare_attributes table.

### Notice field: `agency_name` is always null

The Java implementation always passes `null` for `agencyName` in `MissingRequiredAgencyIdNotice`. The Python `missing_required_agency_id` notice should include `agency_name=None` to maintain wire-format compatibility.

### Field name constant

For `missing_recommended_field`, the `field_name` value must be the string `"agency_id"` (matching `GtfsFareAttribute.AGENCY_ID_FIELD_NAME` in Java).

### Threshold: strictly greater than 1

The multi-agency branch fires when `total_agencies > 1`. A feed with exactly one agency (even if that agency row has no `agency_id`) always uses the warning branch.

### Notice codes (Python)

| Java notice class | Python notice code |
|---|---|
| `MissingRequiredAgencyIdNotice` | `missing_required_agency_id` |
| `MissingRecommendedFieldNotice` | `missing_recommended_field` |

`missing_recommended_field` is a generic notice shared across multiple validators. The `field_name` field distinguishes which field is missing. The Python dataclass for this notice should already exist (or be added to `notices.py`) as a reusable type.
