# Analysis: TimepointTimeValidator

## 1. Purpose

Validates that every `stop_times.txt` row marked as an exact timepoint
(`timepoint = 1`) provides both `arrival_time` and `departure_time`, and that
any row supplying at least one of those time fields also provides a value for
`timepoint`.

## 2. Input tables

| Table | Columns used |
|---|---|
| `stop_times.txt` | `trip_id`, `stop_sequence`, `arrival_time`, `departure_time`, `timepoint`, `csv_row_number` |

### Column semantics

- `timepoint` — optional integer enum; `0` = approximate, `1` = exact. The
  column itself is optional in the header; see Section 5 for the guard clause
  when it is entirely absent.
- `arrival_time` — optional `GtfsTime` (stored as Utf8 HH:MM:SS in the Python
  implementation). Absent when the field is empty or the column is missing.
- `departure_time` — optional `GtfsTime` (same representation as
  `arrival_time`).
- `trip_id` — string identifier for the trip; carried into notices.
- `stop_sequence` — non-negative integer; carried into notices.
- `csv_row_number` — integer; carried into notices.

## 3. Validation logic

The Java implementation is a `FileValidator` that iterates over all rows of
`stop_times.txt`. The first action is a header-level guard; the two checks
below only run after that guard passes.

### Guard — `timepoint` column absent from header

```
if "timepoint" column NOT in stop_times header:
    return   # emit nothing
```

Legacy feeds omit the `timepoint` column entirely. When the column is absent,
this validator produces no notices (header-level issues are flagged elsewhere).
The subsequent checks are not run.

### Check 1 — Row has time(s) but is missing `timepoint` value

```
for each row in stop_times:
    if (row.arrival_time IS NOT NULL OR row.departure_time IS NOT NULL)
       AND row.timepoint IS NULL:
        emit MissingTimepointValueNotice(row)
```

Condition: the `timepoint` column is present in the header but the individual
cell is empty/null, AND at least one time field (`arrival_time` or
`departure_time`) is non-null.

This is a WARNING — the spec says `timepoint` *should* be defined in this
situation, not that it *must* be.

### Check 2 — Exact timepoint missing `arrival_time` or `departure_time`

```
for each row in stop_times:
    if row.timepoint IS NOT NULL AND row.timepoint == 1:   # EXACT
        if row.arrival_time IS NULL:
            emit StopTimeTimepointWithoutTimesNotice(row, field_name="arrival_time")
        if row.departure_time IS NULL:
            emit StopTimeTimepointWithoutTimesNotice(row, field_name="departure_time")
```

The two sub-checks are independent. A single row with `timepoint = 1` and
both times absent emits two notices (one for each missing field).

`timepoint = 0` (APPROXIMATE) rows are entirely skipped by this check — it is
valid for approximate timepoints to omit times.

### Interaction between Check 1 and Check 2

Both checks iterate over the same rows independently. A row can trigger
notices from both checks simultaneously only if `timepoint IS NULL` (null
timepoint prevents `isTimepoint()` from returning true, so Check 2 can never
fire when Check 1 fires). In practice the two checks are mutually exclusive
on a per-row basis.

Emission order per row: Check 1 before Check 2 (Java iterates one loop with
Check 1 evaluated first, then `isTimepoint()` called after).

## 4. Notices emitted

### `stop_time_timepoint_without_times` (ERROR)

Emitted once per missing time field on each exact-timepoint row.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | int | `stop_times.csv_row_number` | Row number of the offending entry |
| `trip_id` | string | `stop_times.trip_id` | Trip identifier |
| `stop_sequence` | int | `stop_times.stop_sequence` | Stop sequence number |
| `specified_field` | string | literal `"arrival_time"` or `"departure_time"` | Which time field is missing |

Severity: ERROR.

Condition: `timepoint IS NOT NULL AND timepoint == 1 AND (arrival_time IS NULL
OR departure_time IS NULL)`. One notice per null time field per row; up to two
notices per row.

### `missing_timepoint_value` (WARNING)

Emitted when a row defines at least one time but leaves `timepoint` blank.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | int | `stop_times.csv_row_number` | Row number of the offending entry |
| `trip_id` | string | `stop_times.trip_id` | Trip identifier |
| `stop_sequence` | int | `stop_times.stop_sequence` | Stop sequence number |

Severity: WARNING.

Condition: `timepoint IS NULL AND (arrival_time IS NOT NULL OR departure_time
IS NOT NULL)`.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `stop_times.txt` absent from feed | Return `[]` immediately (no table to iterate). |
| `stop_times.txt` present but empty (zero rows) | Return `[]` immediately. |
| `timepoint` column absent from the header | Return `[]` immediately (guard clause fires before any row iteration). |
| `timepoint` column present in header but all cells null | Check 1 runs per row; rows with times emit `missing_timepoint_value`. Check 2 never fires (null timepoint is not EXACT). |
| `timepoint = 0` (APPROXIMATE), times absent | No notices from either check. |
| `timepoint = 0` (APPROXIMATE), times present | No notices from either check. |
| `timepoint = 1` (EXACT), both times present | No notices. |
| `timepoint = 1` (EXACT), `arrival_time` null only | One `stop_time_timepoint_without_times` notice for `arrival_time`. |
| `timepoint = 1` (EXACT), `departure_time` null only | One `stop_time_timepoint_without_times` notice for `departure_time`. |
| `timepoint = 1` (EXACT), both times null | Two `stop_time_timepoint_without_times` notices (one per field). |
| `timepoint` null, no times | No notices (Check 1 requires at least one time to be present). |
| `timepoint` null, one or both times present | One `missing_timepoint_value` notice (WARNING). |
| Multiple rows with mixed violations | Each row is checked independently; notices accumulate across rows. |

## 6. Test contracts

The Java test file contains eight test methods.

### `timepointWithNoTimeShouldGenerateNotices`

- One row: `timepoint=1`, `arrival_time=null`, `departure_time=null`.
- Expected: exactly two `StopTimeTimepointWithoutTimesNotice` — one for
  `arrival_time` and one for `departure_time`.

### `timepointWithBothTimesShouldNotGenerateNotice`

- One row: `timepoint=1`, `arrival_time=450s`, `departure_time=580s`.
- Expected: no notices.

### `timepoint_missingDepartureTimeShouldGenerateNotice`

- One row: `timepoint=1`, `arrival_time=450s`, `departure_time=null`.
- Expected: exactly one `StopTimeTimepointWithoutTimesNotice` for
  `departure_time`.

### `timepoint_missingArrivalTimeShouldGenerateNotice`

- One row: `timepoint=1`, `arrival_time=null`, `departure_time=450s`.
- Expected: exactly one `StopTimeTimepointWithoutTimesNotice` for
  `arrival_time`.

### `nonTimepoint_noTimeProvided_shouldNotGenerateNotice`

- One row: `timepoint=0`, `arrival_time=null`, `departure_time=null`.
- Expected: no notices.

### `nonTimepoint_timesProvided_shouldNotGenerateNotice`

- One row: `timepoint=0`, `arrival_time=450s`, `departure_time=580s`.
- Expected: no notices.

### `emptyTimepoint_noArrivalTime_noDepartureTime_noTimePointProvided_shouldNotGenerateNotice`

- One row: `timepoint=null` (column present in header, cell null),
  `arrival_time=null`, `departure_time=null`.
- Expected: does NOT contain a `MissingTimepointValueNotice` (no times
  present, so Check 1 condition is false).

### `emptyTimepoint_timesProvided_shouldGenerateNotice`

- One row: `timepoint=null` (column present in header, cell null),
  `arrival_time=450s`, `departure_time=580s`.
- Expected: exactly one `MissingTimepointValueNotice`.

### What is NOT covered by the Java test suite

- `timepoint` column absent from header entirely (guard clause behavior).
- `stop_times.txt` absent or empty.
- Multiple rows with mixed `timepoint` values.
- A row where `timepoint=null` and exactly one time field is present (only
  one time, not both).
- `timepoint = 1` with both times missing AND `timepoint` also producing a
  `MissingTimepointValueNotice` simultaneously (mutually exclusive — can't
  happen: null timepoint never equals EXACT).

## 7. Implementation notes

### Algorithm strategy

The Java validator iterates row-by-row as a `FileValidator`. The Python
implementation should use vectorized Polars expressions rather than a Python
loop. Two filter passes (one per check) are sufficient.

### Header-column guard

The `timepoint` column being absent from the header is distinct from all cells
being null. In the Python implementation, check whether `"timepoint"` is in
`feed["stop_times"].columns` before running any row-level logic. If the column
is absent, return `[]` immediately.

### Timepoint enum values

```
APPROXIMATE = 0
EXACT       = 1
```

Only `timepoint == 1` triggers Check 2. `timepoint == 0` is treated as
non-timepoint and is ignored for the time-presence check.

### Time field representation

`arrival_time` and `departure_time` are stored as Utf8 strings after loading
(format-validated but not numerically cast). A non-null value means a time was
provided; null means the field was absent. No numeric comparison is needed in
this validator — only null-checking.

### Recommended Polars approach

```python
def validate_timepoint_time(
    feed: dict[str, pl.DataFrame], ctx: ValidationContext
) -> list[Notice]:
    if "stop_times" not in feed or feed["stop_times"].is_empty():
        return []

    st = feed["stop_times"]

    # Guard: timepoint column must be present in the header
    if "timepoint" not in st.columns:
        return []

    notices: list[Notice] = []

    # Check 1: row has at least one time but timepoint is null (WARNING)
    has_time = pl.col("arrival_time").is_not_null() | pl.col("departure_time").is_not_null()
    missing_tp = pl.col("timepoint").is_null()

    check1 = st.filter(has_time & missing_tp)
    for row in check1.iter_rows(named=True):
        notices.append(
            MissingTimepointValueNotice(
                csv_row_number=row["csv_row_number"],
                trip_id=row["trip_id"],
                stop_sequence=row["stop_sequence"],
            )
        )

    # Check 2: exact timepoints (timepoint == 1) missing arrival or departure
    exact = st.filter(pl.col("timepoint") == 1)

    for row in exact.filter(pl.col("arrival_time").is_null()).iter_rows(named=True):
        notices.append(
            StopTimeTimepointWithoutTimesNotice(
                csv_row_number=row["csv_row_number"],
                trip_id=row["trip_id"],
                stop_sequence=row["stop_sequence"],
                specified_field="arrival_time",
            )
        )

    for row in exact.filter(pl.col("departure_time").is_null()).iter_rows(named=True):
        notices.append(
            StopTimeTimepointWithoutTimesNotice(
                csv_row_number=row["csv_row_number"],
                trip_id=row["trip_id"],
                stop_sequence=row["stop_sequence"],
                specified_field="departure_time",
            )
        )

    return notices
```

### Emission order

The Java validator emits in the following order within one iteration:
1. `MissingTimepointValueNotice` (Check 1) for the current row.
2. `StopTimeTimepointWithoutTimesNotice` for `arrival_time` (Check 2) for the
   current row.
3. `StopTimeTimepointWithoutTimesNotice` for `departure_time` (Check 2) for
   the current row.

The Python implementation above separates these into three batch passes. The
absolute emission order differs from Java's row-interleaved order but is
behaviorally equivalent for notice counting and correctness purposes. If strict
ordering is required, sort the final notice list by `csv_row_number` then by
notice type.

### Notice dataclasses

```python
@dataclass
class MissingTimepointValueNotice:
    code: ClassVar[str] = "missing_timepoint_value"
    severity: ClassVar[str] = "WARNING"
    csv_row_number: int
    trip_id: str
    stop_sequence: int


@dataclass
class StopTimeTimepointWithoutTimesNotice:
    code: ClassVar[str] = "stop_time_timepoint_without_times"
    severity: ClassVar[str] = "ERROR"
    csv_row_number: int
    trip_id: str
    stop_sequence: int
    specified_field: str  # "arrival_time" or "departure_time"
```

### Feed dict key

- `"stop_times"` — `stop_times.txt`

### Validator registration

Required tables: `["stop_times"]`. The validator self-guards on presence,
emptiness, and missing `timepoint` column.

Feature flag: none.

### No cross-table logic

This validator reads only `stop_times.txt`. No joins or lookups into other
tables are required.
