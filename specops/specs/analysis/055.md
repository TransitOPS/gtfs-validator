# Analysis: ShapeUsageValidator

## 1. Purpose

Validate that every `shape_id` defined in `shapes.txt` is referenced by at least one
trip in `trips.txt`; emit a warning for each unused shape ID.

## 2. Input tables

| Table | Columns used |
|---|---|
| `shapes.txt` | `shape_id`, `csv_row_number` |
| `trips.txt` | `shape_id` |

Both tables must be present. Only `shape_id` values are compared; no other columns
are needed for the validation logic itself.

## 3. Validation logic

### Step 1: Collect all shape IDs referenced by trips

Build a set of all distinct `shape_id` values present in `trips.txt`. Null/empty
`shape_id` values in trips are ignored (they simply add nothing to the reference set).

### Step 2: Iterate over shapes, deduplicated by shape_id

Iterate over every row of `shapes.txt` in file order. Maintain a set of already-
reported shape IDs (`reported_shapes`). For each row:

1. Read `shape_id` and `csv_row_number`.
2. If `shape_id` has already been added to `reported_shapes`, skip this row (avoid
   emitting duplicate notices for the same shape ID that spans multiple rows).
3. Add `shape_id` to `reported_shapes`.
4. If `shape_id` is **not** present in the trips reference set, emit one
   `UnusedShapeNotice` using the current row's `csv_row_number`.

### Key behavioral detail: one notice per shape_id, not per row

Because `shapes.txt` typically contains multiple rows for each `shape_id` (one per
shape point), the deduplication in step 2 ensures that at most one notice is emitted
per distinct `shape_id`, using the `csv_row_number` of its first occurrence in the
file.

## 4. Notices emitted

### `unused_shape` (WARNING)

Emitted when a `shape_id` found in `shapes.txt` is not referenced by any trip in
`trips.txt`.

| Field | Type | Source | Description |
|---|---|---|---|
| `shape_id` | string | `shapes.shape_id` | The unused shape ID |
| `csv_row_number` | integer | `shapes.csv_row_number` | Row number of the first occurrence of this shape_id in shapes.txt |

Condition: `shape_id` in `shapes.txt` has no matching row in `trips.txt` (where
`trips.shape_id == shape_id`).

Deduplication: one notice per distinct `shape_id`; the first row in file order for
that `shape_id` determines the `csv_row_number`.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `shapes.txt` is absent or empty | No notices; nothing to check. |
| `trips.txt` is absent or empty | Every shape_id in `shapes.txt` is unused; one notice per distinct shape_id. |
| A `shape_id` appears in multiple rows of `shapes.txt` (normal case) | One notice emitted using the `csv_row_number` of the first occurrence. |
| All shape IDs in `shapes.txt` are referenced by trips | No notices. |
| A trip has a null/empty `shape_id` | That trip does not contribute to the reference set; shape IDs are not matched against null. |
| `shapes.txt` has only one row per shape_id | Deduplication set is still built; behavior is identical. |

## 6. Test contracts

### `allShapeUsedShouldNotGenerateNotice`

- Two shape points (rows 1 and 3) with distinct shape IDs: `"first shape id"` and
  `"second shape id"`.
- Two trips (rows 2 and 4), each referencing one of the two shape IDs.
- Expected: **0** notices.

### `unusedShapeShouldGenerateNotice`

- Two shape points (rows 1 and 3): `"first shape id"` and `"second shape id"`.
- One trip (row 2) referencing only `"first shape id"`.
- Expected: exactly **1** `UnusedShapeNotice`:
  - `shape_id` = `"second shape id"`
  - `csv_row_number` = `3`

Note: there are no tests for the case where `shapes.txt` or `trips.txt` is absent,
but the guard on empty tables is required from the Java iterator semantics (iterating
over an empty container simply produces zero notices).

## 7. Implementation notes

### Polars approach

This validator is a straightforward set-membership check and maps cleanly to Polars:

```python
# Step 1: build set of shape_ids referenced by trips
trip_shape_ids = set(
    feed["trips"]
    .filter(pl.col("shape_id").is_not_null() & (pl.col("shape_id") != ""))
    ["shape_id"]
    .to_list()
)

# Step 2: find first occurrence of each shape_id in shapes.txt
# (preserving file order for csv_row_number of first occurrence)
first_occurrences = (
    feed["shapes"]
    .with_row_index("_row_idx")
    .group_by("shape_id")
    .agg(pl.col("csv_row_number").first(), pl.col("_row_idx").min())
    .sort("_row_idx")
)

# Step 3: filter for unused shapes
unused = first_occurrences.filter(
    ~pl.col("shape_id").is_in(list(trip_shape_ids))
)
```

Emit one `unused_shape` notice per row in `unused`.

Alternative: use a Polars anti-join instead of a Python set:

```python
trips_shape_ids_df = (
    feed["trips"]
    .select("shape_id")
    .filter(pl.col("shape_id").is_not_null() & (pl.col("shape_id") != ""))
    .unique()
)

first_occurrences = (
    feed["shapes"]
    .with_row_index("_row_idx")
    .group_by("shape_id")
    .agg(pl.col("csv_row_number").first(), pl.col("_row_idx").min())
    .sort("_row_idx")
)

unused = first_occurrences.join(trips_shape_ids_df, on="shape_id", how="anti")
```

Both approaches are equivalent; the anti-join form is more idiomatic Polars for
cross-table membership checks.

### Guard clauses

Return `[]` immediately if:
- `"shapes"` is not in the feed dict, or `feed["shapes"]` is empty.
- `"trips"` is not in the feed dict (treat as empty trips set — all shapes are unused).

When `trips.txt` is empty, `trip_shape_ids` is the empty set, so all shapes produce
notices automatically; no special-casing is needed beyond the table presence check.

### `csv_row_number` semantics

The Java validator reports the `csv_row_number` of the **first row in file order**
where the `shape_id` appears. In Polars, preserve this by using `.first()` after
sorting by file-order index (via `with_row_index`). Do not use `.min()` on
`csv_row_number` directly, as that would give the numerically smallest row number
which may not be the first appearance in a pathological file.

### Notice code mapping

| Java class | Python notice code |
|---|---|
| `UnusedShapeNotice` | `unused_shape` |

### Validator registration

Required tables: `["shapes", "trips"]`.

Only `shapes.txt` needs to be non-empty for the validator to run. If `trips.txt` is
absent, treat it as an empty DataFrame (all shapes are unused).

### Feed dict keys

- `"shapes"` — `shapes.txt`
- `"trips"` — `trips.txt`
