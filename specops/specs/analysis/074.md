# Analysis: TransfersInSeatTransferTypeValidator

## 1. Purpose

Validates that `transfers.txt` rows with an in-seat transfer type (`transfer_type` 4 or 5) have the required trip IDs present and that the referenced stop is not a station and appears at the correct position (last stop for the from-trip, first stop for the to-trip) in the trip's stop-times.

## 2. Input tables

| Table | Columns used |
|---|---|
| `transfers.txt` | `transfer_type`, `from_stop_id`, `to_stop_id`, `from_trip_id`, `to_trip_id`, `csv_row_number` |
| `stops.txt` | `stop_id`, `location_type` |
| `stop_times.txt` | `trip_id`, `stop_id`, `stop_sequence` |

### Column semantics

- `transfer_type` — integer enum (0–5); required. Only values 4 (`IN_SEAT_TRANSFER_ALLOWED`) and 5 (`IN_SEAT_TRANSFER_NOT_ALLOWED`) activate this validator's checks.
- `from_stop_id` / `to_stop_id` — conditionally required string IDs; must be non-null for in-seat transfer types (otherwise validated elsewhere).
- `from_trip_id` / `to_trip_id` — conditionally required string IDs; must be non-null for in-seat transfer types.
- `csv_row_number` — row number from `transfers.txt`; carried into notices.
- `stop_id` in `stops.txt` — the identifier used for lookup; `location_type` integer (0 = STOP, 1 = STATION, 2 = ENTRANCE, 3 = GENERIC_NODE, 4 = BOARDING_AREA).
- `trip_id`, `stop_id`, `stop_sequence` in `stop_times.txt` — used to look up the ordered stop-time sequence for a trip and check stop positions.

### Transfer type enum

| Integer value | Constant | In-seat? |
|---|---|---|
| 0 | `RECOMMENDED` | No |
| 1 | `TIMED` | No |
| 2 | `MINIMUM_TIME` | No |
| 3 | `IMPOSSIBLE` | No |
| 4 | `IN_SEAT_TRANSFER_ALLOWED` | Yes |
| 5 | `IN_SEAT_TRANSFER_NOT_ALLOWED` | Yes |

### Location type enum

| Integer value | Constant |
|---|---|
| 0 | `STOP` |
| 1 | `STATION` |
| 2 | `ENTRANCE` |
| 3 | `GENERIC_NODE` |
| 4 | `BOARDING_AREA` |

## 3. Validation logic

The validator iterates every row of `transfers.txt`. For each row, the following checks are applied:

```
for each transfer in transfers:
    if transfer.transfer_type IS NULL:
        skip row

    if transfer.transfer_type NOT IN {4, 5}:
        skip row   # not an in-seat transfer type

    # --- In-seat transfer: apply checks for both directions ---
    for direction in [FROM, TO]:
        trip_id_field = "from_trip_id" if direction == FROM else "to_trip_id"
        stop_id_field = "from_stop_id" if direction == FROM else "to_stop_id"

        # Check 1: trip_id is required for in-seat transfers
        if trip_id IS NULL for this direction:
            emit MissingRequiredFieldNotice(
                filename="transfers.txt",
                csv_row_number=transfer.csv_row_number,
                field_name=trip_id_field)

        # Check 2: stop location type check (station forbidden)
        stop_id = transfer[stop_id_field]
        if stop_id NOT IN stops:
            # FK validation is handled elsewhere; skip stop checks
            continue to next direction

        location_type = stops[stop_id].location_type
        if location_type == STATION (1):
            emit TransferWithInvalidStopLocationTypeNotice(
                csv_row_number=transfer.csv_row_number,
                stop_id_field_name=stop_id_field,
                stop_id=stop_id,
                location_type_value=1,
                location_type_name="STATION")

        # Check 3: stop must appear in the trip's stop-times
        stop_times_for_trip = stop_times where trip_id == transfer[trip_id_field]
        if stop_times_for_trip is empty
           OR stop_id NOT IN {st.stop_id for st in stop_times_for_trip}:
            # Cross-check with trip reference is handled elsewhere; skip position check
            continue to next direction

        # Check 4: position check — from_stop_id must be last stop; to_stop_id must be first stop
        stop_times_for_trip sorted by stop_sequence:
            expected_stop = last stop if direction == FROM else first stop

        if expected_stop.stop_id != stop_id:
            emit TransferWithSuspiciousMidTripInSeatNotice(
                csv_row_number=transfer.csv_row_number,
                trip_id_field_name=trip_id_field,
                trip_id=transfer[trip_id_field],
                stop_id_field_name=stop_id_field,
                stop_id=stop_id)
```

### Important ordering details

- Both directions (FROM and TO) are always checked for every in-seat transfer row.
- The trip ID presence check (Check 1) and the stop checks (Checks 2–4) are independent — a missing trip ID does not prevent the stop checks from running.
- The stop lookup uses the `stop_id` field regardless of whether `trip_id` is null. The Java implementation calls `transferDirection.stopId(transfer)` which returns an empty string if the field is absent, which will simply not be found in the stops map.
- Stop-times are ordered by their `stop_sequence` column within each trip. The Java implementation uses the `GtfsStopTimeTableContainer.byTripId()` which returns entries ordered by stop sequence.
- Check 4 compares the stop at the terminal position of the trip against the transfer stop. If they differ, the transfer is flagged as a suspicious mid-trip transfer.

## 4. Notices emitted

### `missing_required_field` (ERROR)

Emitted when `from_trip_id` or `to_trip_id` is absent on a row with an in-seat `transfer_type`.

| Field | Type | Source | Description |
|---|---|---|---|
| `filename` | string | literal `"transfers.txt"` | File containing the offending row |
| `csv_row_number` | int | `transfers.csv_row_number` | Row number of the offending transfer |
| `field_name` | string | `"from_trip_id"` or `"to_trip_id"` | Name of the missing field |

Severity: ERROR.

Conditions:
- `transfer_type` IS NOT NULL, AND
- `transfer_type` IN {4, 5}, AND
- `from_trip_id` IS NULL → one notice with `field_name="from_trip_id"`
- `to_trip_id` IS NULL → one notice with `field_name="to_trip_id"`

Both fields are checked independently; a single row may produce zero, one, or two notices of this type.

### `transfer_with_invalid_stop_location_type` (ERROR)

Defined in `TransfersStopTypeValidator`. Emitted when a stop referenced by `from_stop_id` or `to_stop_id` on an in-seat transfer row has `location_type == STATION (1)`.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | int | `transfers.csv_row_number` | Row number of the offending transfer |
| `stop_id_field_name` | string | `"from_stop_id"` or `"to_stop_id"` | Name of the stop ID field |
| `stop_id` | string | `transfers.from_stop_id` or `to_stop_id` | The referenced stop ID |
| `location_type_value` | int | `stops.location_type` | Numeric value of the invalid location type |
| `location_type_name` | string | `stops.location_type` name | Name of the invalid location type (e.g., `"STATION"`) |

Severity: ERROR.

Conditions:
- `transfer_type` IN {4, 5}, AND
- Stop ID resolves in `stops.txt`, AND
- `location_type == 1` (STATION).

Note: For non-in-seat transfers, `TransfersStopTypeValidator` handles invalid location type checks (where both STOP and STATION are valid, and other types are invalid). For in-seat transfers, this validator uses the same notice but with a stricter rule: only STOP (0) is allowed; STATION (1) is specifically forbidden.

### `transfer_with_suspicious_mid_trip_in_seat` (WARNING)

Emitted when the transfer stop is not in the expected terminal position in the trip's stop-times: `from_stop_id` must be the last stop and `to_stop_id` must be the first stop.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | int | `transfers.csv_row_number` | Row number of the offending transfer |
| `trip_id_field_name` | string | `"from_trip_id"` or `"to_trip_id"` | Name of the trip ID field for the direction |
| `trip_id` | string | `transfers.from_trip_id` or `to_trip_id` | The referenced trip ID |
| `stop_id_field_name` | string | `"from_stop_id"` or `"to_stop_id"` | Name of the stop ID field for the direction |
| `stop_id` | string | `transfers.from_stop_id` or `to_stop_id` | The referenced stop ID |

Severity: WARNING.

Conditions:
- `transfer_type` IN {4, 5}, AND
- Stop ID resolves in `stops.txt`, AND
- Stop ID appears somewhere in the trip's stop-times (otherwise checked elsewhere), AND
- For `TRANSFER_FROM`: the stop is NOT the last stop-time in the trip (by stop_sequence order).
- For `TRANSFER_TO`: the stop is NOT the first stop-time in the trip (by stop_sequence order).

Both directions are checked independently. A single transfer row may produce zero, one, or two notices of this type.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `transfers.txt` absent from feed | Return `[]` immediately (guard in runner). |
| `transfers.txt` present but empty | Return `[]` (loop body never executes). |
| `transfer_type` IS NULL on a row | Row is skipped entirely; no checks performed. |
| `transfer_type` is 0–3 (non-in-seat) | Row is skipped entirely; no checks performed. |
| `from_stop_id` or `to_stop_id` IS NULL on in-seat row | The stop lookup produces an empty result (the Java `byStopId()` returns empty Optional); all stop-related checks (location type and position) are skipped for that direction. The trip ID missing check still runs. |
| `stops.txt` absent or stop ID not found in `stops.txt` | Stop checks (location type check and position check) are silently skipped for that direction; FK validation is handled by a separate FK validator. |
| `stop_times.txt` absent or trip ID has no stop-times | Position check is skipped; that cross-reference validation is handled by `TransfersTripReferenceValidator`. |
| Stop ID is in the trip's stop-times but at a mid-trip position | `TransferWithSuspiciousMidTripInSeatNotice` is emitted as a WARNING. |
| Stop ID is NOT in the trip's stop-times at all | Position check is skipped (the FK absence is handled by `TransfersTripReferenceValidator`). |
| Both `from_trip_id` and `to_trip_id` are missing | Two `missing_required_field` notices emitted (one per field). |
| `location_type` is neither STOP nor STATION (e.g., ENTRANCE=2) | In-seat validator only checks for STATION (value 1). Values 2, 3, 4 are not explicitly flagged by this validator; the broader `TransfersStopTypeValidator` handles them for non-in-seat transfers. |
| Multiple in-seat rows in `transfers.txt` | Each row is validated independently. |

## 6. Test contracts

The Java test file contains three test methods.

### `testValidInSeatTransfer`

- Builds two stops (`s0` = STOP, `s1` = STOP).
- Builds four stop-times: trip `t0` has stops `[s?, s0]` (s0 is last); trip `t1` has stops `[s1, s?]` (s1 is first).
- Builds one transfer: `from_stop_id=s0`, `to_stop_id=s1`, `from_trip_id=t0`, `to_trip_id=t1`, `transfer_type=4`.
- Expected: zero notices.
- Confirms: when `from_stop_id` is the last stop of the from-trip and `to_stop_id` is the first stop of the to-trip, and neither is a station, no notices are produced.

### `testInvalidInSeatTransferToStation`

- Builds two stops: `s0` = STOP, `s1` = STATION.
- Builds the same stop-times structure as above (s0 last in t0, s1 first in t1).
- Builds a transfer `transfer_type=4` with `from_stop_id=s0`, `to_stop_id=s1`.
- Expected: exactly one `TransferWithInvalidStopLocationTypeNotice` for direction `TRANSFER_TO` (the `to_stop_id=s1` which is a STATION).
- Confirms: station location type is specifically forbidden for in-seat transfers on the to-side; the from-side (STOP) is clean and produces no notice.

### `testSuspiciousMidTripInSeatTransfer`

- Builds two stops (`s0` = STOP, `s1` = STOP).
- Builds stop-times where `s0` is the FIRST stop of trip `t0` (not the last), and `s1` is the LAST stop of trip `t1` (not the first): `t0 = [s0, s?]`, `t1 = [s?, s1]`.
- Builds a transfer `transfer_type=4` with `from_stop_id=s0`, `to_stop_id=s1`.
- Expected: exactly two `TransferWithSuspiciousMidTripInSeatNotice` instances — one for `TRANSFER_FROM` (s0 is not the last stop of t0) and one for `TRANSFER_TO` (s1 is not the first stop of t1).
- Confirms: both directions are checked independently for positional correctness, and both can fail simultaneously.

### What is NOT covered by the Java test suite

- Transfer row with `transfer_type` null (the null-guard).
- Non-in-seat transfer types (0–3); these are skipped without a test.
- Missing `from_trip_id` or `to_trip_id` (the `MissingRequiredFieldNotice` path).
- `stops.txt` absent or stop ID not found in stops.
- `stop_times.txt` absent or trip ID not found in stop-times.
- Stop ID present in stop-times at a non-terminal position but also stop's `location_type` is STATION simultaneously (combined notice scenario).
- Multiple rows in a single feed producing a mix of passing and failing transfers.

## 7. Implementation notes

### Algorithm strategy

This validator is inherently cross-table and requires lookups into `stops` and `stop_times`. The Java implementation uses in-memory indexed maps (by stop ID and by trip ID). The Python/Polars implementation should pre-build these lookup structures rather than scanning full DataFrames on every transfer row.

Given that `transfers.txt` is typically small, the recommended approach is:

1. Filter `transfers` to in-seat rows (type 4 or 5) up front using a Polars filter.
2. Use Python dicts keyed by `stop_id` and `trip_id` for the cross-table lookups (built once from the stops and stop_times DataFrames).
3. Iterate the filtered in-seat transfers in Python (row-by-row) to emit notices with correct per-row context.

A fully vectorized Polars join-based approach is possible but complex given the positional (first/last stop per trip) logic. Plain Python for the outer loop is acceptable per the project coding rules since `transfers.txt` is small.

### Pre-building the lookup structures

```python
# Build stops lookup: stop_id -> location_type (int)
stops_df = feed.get("stops")
stops_by_id: dict[str, int] = {}
if stops_df is not None:
    for row in stops_df.select(["stop_id", "location_type"]).iter_rows(named=True):
        stops_by_id[row["stop_id"]] = row["location_type"]

# Build stop-times lookup: trip_id -> list of stop_ids ordered by stop_sequence
stop_times_df = feed.get("stop_times")
trip_stops: dict[str, list[str]] = {}
if stop_times_df is not None:
    sorted_st = stop_times_df.sort("stop_sequence").select(["trip_id", "stop_id"])
    for row in sorted_st.iter_rows(named=True):
        trip_stops.setdefault(row["trip_id"], []).append(row["stop_id"])
```

### Positional check

For a given trip's stop-time list (ordered by `stop_sequence`):

- `TRANSFER_FROM`: expected stop is `trip_stops[trip_id][-1]` (last element).
- `TRANSFER_TO`: expected stop is `trip_stops[trip_id][0]` (first element).

### Notices

Two notice classes are needed:

1. `MissingRequiredFieldNotice` (already in `notices.py`): reuse as-is.
2. `TransferWithInvalidStopLocationTypeNotice` (ERROR): already used/defined via `TransfersStopTypeValidator`; ensure it is available in the Python notices registry.
3. `TransferWithSuspiciousMidTripInSeatNotice` (WARNING): new notice specific to this validator.

### Guard clauses

```python
def validate_transfers_in_seat_transfer_type(
    feed: dict[str, pl.DataFrame], ctx: ValidationContext
) -> list[Notice]:
    if "transfers" not in feed:
        return []
    transfers = feed["transfers"]
    if transfers.is_empty():
        return []
    if "transfer_type" not in transfers.columns:
        return []
```

### Feed dict keys

- `"transfers"` — `transfers.txt`
- `"stops"` — `stops.txt`
- `"stop_times"` — `stop_times.txt`

### Validator registration

Required tables: `["transfers", "stops", "stop_times"]`. No feature flag required.

### Relationship to other validators

- `TransfersStopTypeValidator` (separate validator): validates that stop IDs in transfers reference stops or stations for non-in-seat types. For in-seat types, this validator re-uses its `TransferWithInvalidStopLocationTypeNotice` with a stricter rule (station is forbidden, only stop is valid).
- `TransfersTripReferenceValidator` (separate validator): validates that trip IDs referenced in transfers exist in `trips.txt` and that the stop appears in that trip's stop-times. This validator defers to it when the stop is not found in the trip's stop-times.
- `GtfsTransferFromStopIdForeignKeyValidator` / `GtfsTransferToStopIdForeignKeyValidator` (separate FK validators): validate stop ID references; this validator defers to them when a stop ID is not found in `stops.txt`.

### Notice ordering

The Java implementation processes FROM direction before TO direction for each transfer row, and emits the trip-ID missing notice before the stop-related notices (since `validateEntity` calls the trip-ID check inside the same loop iteration as `validateStop`). Preserve this ordering: for each in-seat row, emit FROM notices before TO notices, and within each direction emit `missing_required_field` (for trip ID) before `transfer_with_invalid_stop_location_type` and `transfer_with_suspicious_mid_trip_in_seat`.

### Polars vs plain Python

The outer loop over filtered in-seat transfer rows is best handled in plain Python (row-by-row) given the multi-table lookups and per-row notice construction. The pre-filtering of in-seat rows and the building of lookup dicts should use Polars expressions. The stop-times ordering must use `.sort("stop_sequence")` before building the trip_stops dict to ensure correct first/last semantics.
