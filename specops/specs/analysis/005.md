# Analysis: BlockTripsWithOverlappingStopTimesValidator

## 1. Purpose

Detects trips within the same block that have overlapping stop time intervals and are active on the same service day. When two trips share a `block_id`, a vehicle is expected to serve them sequentially. If their time intervals overlap and they operate on a common service date, the schedule is physically impossible.

## 2. Input tables

| Table | Columns used |
|---|---|
| `trips.txt` | `trip_id`, `service_id`, `block_id` |
| `stop_times.txt` | `trip_id`, `arrival_time`, `departure_time`, `stop_sequence` |
| `calendar.txt` | `service_id`, `monday`..`sunday`, `start_date`, `end_date` |
| `calendar_dates.txt` | `service_id`, `date`, `exception_type` |

This is a cross-table validator requiring all four tables. Calendar tables are used to resolve service dates for overlap checking.

## 3. Validation logic

The algorithm proceeds in stages:

### Stage 1: Build service date lookup

Combine `calendar.txt` and `calendar_dates.txt` to produce a mapping from each `service_id` to its full set of active dates. This uses the same calendar resolution logic as elsewhere: weekly patterns from `calendar.txt` expanded into date sets, then `calendar_dates.txt` additions (exception_type=1) and removals (exception_type=2) applied. A `ServiceIdIntersectionCache` wraps this map to efficiently answer "do these two service IDs share any active date?" queries with caching.

### Stage 2: Group trips by block_id

Group all trips by `block_id`. Skip trips that have no `block_id` (empty/null).

### Stage 3: Build trip time intervals

For each trip in a block, look up its stop times (ordered by `stop_sequence`). Extract the time interval as:
- `first_arrival` = `arrival_time` of the first stop
- `first_departure` = `departure_time` of the first stop
- `last_arrival` = `arrival_time` of the last stop
- `last_departure` = `departure_time` of the last stop

**Skip** a trip if:
- It has no stop times, OR
- The first or last stop time is missing any of `arrival_time` or `departure_time` (all four values must be present)

Sort the intervals by `(first_arrival, last_departure)` ascending.

### Stage 4: Pairwise overlap detection

For each pair `(i, j)` where `j > i` in the sorted interval list:

1. **No more overlap possible**: If `interval[i].last_departure <= interval[j].first_arrival`, break the inner loop (since intervals are sorted, no further `j` can overlap with `i`).

2. **Block transfer exception**: If `interval[i].last_arrival == interval[j].first_arrival` AND `interval[i].last_departure == interval[j].first_departure`, skip this pair. This allows the common pattern where agencies model block transfers by duplicating the stop time entry at the transfer point.

3. **Service date intersection**: Check if the two trips' `service_id` values share any common active date. If yes, emit a notice with the first intersecting date.

### Overlap condition (precise)

Two trip intervals overlap when:
- `trip_i.last_departure > trip_j.first_arrival` (strict greater-than), AND
- The block transfer exception does NOT apply, AND
- The two trips share at least one active service date.

Note: the comparison is `<=` for the break condition, meaning `last_departure == first_arrival` does NOT constitute overlap (touching intervals are allowed).

## 4. Notices emitted

### `block_trips_with_overlapping_stop_times`

- **Severity**: ERROR
- **Condition**: Two trips in the same block have overlapping time intervals and share at least one active service date.
- **Fields**:
  | Field | Type | Description |
  |---|---|---|
  | `csv_row_number_a` | int | Row number of the first trip in `trips.txt` |
  | `trip_id_a` | str | Trip ID of the first trip |
  | `service_id_a` | str | Service ID of the first trip |
  | `csv_row_number_b` | int | Row number of the second trip in `trips.txt` |
  | `trip_id_b` | str | Trip ID of the second trip |
  | `service_id_b` | str | Service ID of the second trip |
  | `block_id` | str | The shared block ID |
  | `intersection` | date | The first date on which both service IDs are active |

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `trips.txt` or `stop_times.txt` is empty | Validator returns immediately; no notices |
| Trip has no `block_id` (empty/null) | Trip is skipped entirely |
| Trip has no stop times | Trip is excluded from interval construction (reported by other validators) |
| Trip's first or last stop time is missing arrival or departure time | Trip is excluded from interval construction |
| Trip has only 1 stop | First and last stop are the same row; interval is constructed if arrival/departure are present (degenerate zero-length interval) |
| Two trips in same block with non-overlapping times | No notice |
| Two trips in same block, overlapping times, same service_id | Notice emitted |
| Two trips in same block, overlapping times, different service_ids with shared active date | Notice emitted |
| Two trips in same block, overlapping times, different service_ids with NO shared active date (e.g., weekday vs Saturday) | No notice |
| Block transfer pattern: trip A's last stop times match trip B's first stop times exactly | No notice (block transfer exception) |
| Touching intervals: trip A ends at 09:00, trip B starts at 09:00, but not a block transfer match | No notice (`last_departure <= first_arrival` means no overlap) |
| More than two trips in a block, partial overlaps | Each overlapping pair generates its own notice independently |
| Service ID with no calendar entries (no active dates) | `findIntersectingDate` returns empty; no notice |

## 6. Test contracts

### `goodFeed`
- **Input**: 6 trips in block "b1": 3 weekday trips (t0-t2) with non-overlapping times (08-09, 10-11, 12-13) and 3 Saturday trips (t3-t5) with the same times. All trips have 2 stops each.
- **Expected**: No notices. Weekday trips don't overlap each other in time, and Saturday trips run on a different service day than weekday trips.

### `overlapWithSameServiceId`
- **Input**: 3 trips in block "b1", all service "WEEK". t0: 08:00-09:00, t1: 08:30-09:30, t2: 12:00-13:00. 2 stops each.
- **Expected**: 1 notice for (t0, t1) overlap with intersection date 2021-01-04. t2 does not overlap with either.

### `overlapWithDifferentServiceId`
- **Input**: 2 trips in block "b1", t0 with service "WEEK", t1 with service "WEEK-ALT" (both cover the same weekday date range). t0: 08:00-09:00, t1: 08:30-09:30.
- **Expected**: 1 notice for (t0, t1) overlap with intersection date 2021-01-04. Different service IDs but they share active dates.

### `tripsWith0or1Stop`
- **Input**: 2 trips in block "b1", both service "WEEK". t0 has 1 stop at 08:00:00, t1 has no stop times at all.
- **Expected**: No notices. t0 with 1 stop has first==last stop so the interval could technically be built (if arrival/departure present), but t1 has no stops. With only one valid trip interval there is no pair to compare.

## 7. Implementation notes

### Polars vs plain Python

This validator is best implemented with **plain Python algorithms on extracted data**, not pure Polars expressions. The core logic involves:
- Grouping trips by block_id (Polars `group_by` or `partition_by` can help here)
- Sorting intervals and doing pairwise comparisons with early termination
- Calendar date intersection with caching

The pairwise overlap detection with the break optimization and block transfer exception is inherently sequential/algorithmic. Forcing it into Polars expressions would be unnatural and harder to reason about.

### Recommended approach

1. **Service date resolution**: Build a `dict[str, set[date]]` mapping each `service_id` to its active dates, using `calendar.txt` and `calendar_dates.txt`. Implement a caching wrapper for pairwise intersection queries (the cache key can be a frozenset or sorted tuple of the two service IDs).

2. **Data extraction**: Use Polars to extract the needed columns, then convert to Python structures for the algorithmic portion:
   ```python
   # Get trips with block_id, grouped
   trips_with_blocks = trips.filter(pl.col("block_id").is_not_null() & (pl.col("block_id") != ""))

   # For each trip, get first and last stop times
   # Join stop_times with trips, compute per-trip first/last arrival/departure
   trip_intervals = (
       stop_times
       .sort("trip_id", "stop_sequence")
       .group_by("trip_id")
       .agg([
           pl.col("arrival_time").first().alias("first_arrival"),
           pl.col("departure_time").first().alias("first_departure"),
           pl.col("arrival_time").last().alias("last_arrival"),
           pl.col("departure_time").last().alias("last_departure"),
       ])
   )
   ```

3. **Overlap detection**: Extract rows to Python and run the sorted pairwise comparison loop with early break.

### Service date intersection cache

The Java implementation uses `ServiceIdIntersectionCache` which:
- Normalizes key ordering (smaller service_id first) for cache symmetry
- Uses `LocalDate.EPOCH` as a sentinel for "no overlap" to avoid storing `Optional` in the cache
- Delegates to `CalendarUtil.firstIntersectingDate` which does a merge-join-style linear scan of two sorted date sets

In Python, a simple `dict[tuple[str, str], date | None]` cache with sorted keys achieves the same. The intersection itself can use `set.intersection()` since Python sets handle this efficiently; take `min()` of the intersection to get the first date.

### Time representation

GTFS times can exceed 24:00:00 (e.g., "25:30:00" for trips past midnight). The comparisons are purely ordinal (comparing total seconds), so times should be stored as integer seconds-since-midnight for comparison purposes.

### Block transfer exception

The exact condition allowing "touching" intervals at a transfer point is:
- `trip_i.last_arrival == trip_j.first_arrival` AND `trip_i.last_departure == trip_j.first_departure`

This is a specific pattern where agencies duplicate the transfer stop's time entry in both trips. It must be checked BEFORE the service date intersection (to avoid unnecessary cache lookups).

### Utility dependencies

- Service date resolution from `calendar.txt` + `calendar_dates.txt` (shared utility, likely already exists for other validators)
- Service ID intersection cache (can be shared across validators that need this check)

### Notice code derivation

The Java class `BlockTripsWithOverlappingStopTimesNotice` maps to snake_case notice code `block_trips_with_overlapping_stop_times`.
