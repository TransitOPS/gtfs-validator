# Analysis: PathwayReachableLocationValidator

## 1. Purpose

Validates that every platform, boarding area, and generic node inside a station with pathways is reachable in both directions: reachable from at least one entrance (following pathway directions), and able to reach at least one entrance (following pathway directions in reverse or via bidirectional pathways).

## 2. Input tables

| Table | Columns used |
|---|---|
| `stops.txt` | `stop_id`, `location_type`, `parent_station`, `stop_name`, `csv_row_number` |
| `pathways.txt` | `from_stop_id`, `to_stop_id`, `is_bidirectional` |

Both tables are required. The validator does nothing meaningful if either is absent or empty.

## 3. Validation logic

This validator performs graph reachability analysis using two breadth-first searches (BFS) over the pathway graph.

### Step 1: Identify pathway endpoints

Collect all stop IDs that appear in any `from_stop_id` or `to_stop_id` cell in `pathways.txt`. These are the pathway endpoints.

### Step 2: Find stations that have pathways

For each pathway endpoint stop ID, walk up the `parent_station` chain (up to 3 levels deep) to find whether it belongs to a station (`location_type == 1`). Collect the `stop_id` of every such station into the set `stations_with_pathways`.

The walk-up logic (`getIncludingStation`):
1. Look up the stop by `stop_id`.
2. If the stop is a station, return it.
3. If the stop has a `parent_station`, repeat from step 1 using the parent's `stop_id`.
4. Repeat up to 3 times. If no station is found, return nothing.

This prevents false positives for stations that have no pathways at all.

### Step 3: BFS from entrances — forward direction (FROM_ENTRANCES)

Seed the BFS queue with all stops whose `location_type == 2` (entrance). Mark each as visited.

While the queue is not empty:
- Dequeue a stop ID (`curr`).
- For each pathway where `from_stop_id == curr`: follow to `to_stop_id` — applicable when traversal is `FROM_ENTRANCES` OR the pathway `is_bidirectional == 1`.
- For each pathway where `to_stop_id == curr`: follow to `from_stop_id` — applicable only when `is_bidirectional == 1` (bidirectional, followed in the reverse direction of the edge, which is still valid as a forward-reachable path).
- If the neighbor has not been visited, mark it and enqueue it.

The resulting `locations_having_entrances` set contains all stop IDs reachable from any entrance by following pathways in their declared direction (or bidirectionally).

### Step 4: BFS to exits — reverse direction (TO_EXITS)

Seed the BFS queue with all stops whose `location_type == 2` (entrance). Mark each as visited.

While the queue is not empty:
- Dequeue a stop ID (`curr`).
- For each pathway where `to_stop_id == curr`: follow to `from_stop_id` — applicable when traversal is `TO_EXITS` OR the pathway `is_bidirectional == 1`.
- For each pathway where `from_stop_id == curr`: follow to `to_stop_id` — applicable only when `is_bidirectional == 1`.
- If the neighbor has not been visited, mark it and enqueue it.

The resulting `locations_having_exits` set contains all stop IDs from which some entrance can eventually be reached by following pathways (or bidirectional pathways in reverse).

**Intuition**: A stop has an "exit" if you can walk from that stop to an entrance. The BFS explores backwards from entrances along reversed pathway edges, which is equivalent to finding all stops that can reach an entrance forwards.

### Step 5: Emit notices

Iterate over every stop in `stops.txt`. For each stop:

1. Determine the including station via the `getIncludingStation` walk (same 3-level parent chain as step 2).
2. Skip the stop if it does not belong to any station, or if that station is not in `stations_with_pathways`.
3. Skip the stop if its `location_type` is NOT one of:
   - `0` (STOP/platform) — but only if it has NO children of its own that are boarding areas (i.e., `byParentStation(stop_id)` is empty). Platforms with boarding areas are skipped because the boarding areas are checked instead.
   - `3` (GENERIC_NODE)
   - `4` (BOARDING_AREA)
4. Check reachability:
   - `has_entrance = stop_id in locations_having_entrances`
   - `has_exit = stop_id in locations_having_exits`
5. If NOT (`has_entrance AND has_exit`), emit `pathway_unreachable_location`.

Entrances (`location_type == 2`) and stations (`location_type == 1`) are never targets of this notice. Platforms that have boarding areas are also skipped.

## 4. Notices emitted

### `pathway_unreachable_location` (ERROR)

Emitted when a platform, boarding area, or generic node inside a station with pathways cannot be reached from an entrance, cannot reach any entrance, or both.

| Field | Type | Source | Description |
|---|---|---|---|
| `csv_row_number` | integer | `stops.txt` row | Row number of the unreachable location |
| `stop_id` | string | `stops.stop_id` | ID of the unreachable location |
| `stop_name` | string | `stops.stop_name` | Name of the unreachable location |
| `location_type` | integer | `stops.location_type` (raw int) | Location type of the unreachable location |
| `parent_station` | string | `stops.parent_station` | Parent station ID |
| `has_entrance` | boolean | computed | Whether the location is reachable from some entrance |
| `has_exit` | boolean | computed | Whether some entrance is reachable from this location |

Severity: ERROR.

Java class: `PathwayUnreachableLocationNotice`.

Referenced files: `pathways.txt`, `stops.txt`.

## 5. Edge cases

| Scenario | Expected behavior |
|---|---|
| `pathways.txt` absent or empty | No pathway endpoints; `stations_with_pathways` is empty; all stops skipped; no notices. |
| `stops.txt` absent or empty | No locations to check; no notices. |
| Station with no pathways at any child | Not in `stations_with_pathways`; all its children skipped; no notices. |
| Location with no `parent_station` chain reaching a station | `getIncludingStation` returns empty; location skipped; no notices. |
| Entrance: `location_type == 2` | Skipped in step 5 (filter requires STOP without boarding areas, GENERIC_NODE, or BOARDING_AREA). |
| Station: `location_type == 1` | Skipped in step 5 (same filter). |
| Platform with boarding areas | Skipped (has children in `byParentStation`); only the boarding areas are checked. |
| Platform with no boarding areas | Included in step 5 check. |
| Bidirectional pathway | Traversable in both BFS directions naturally. |
| Unidirectional pathway A→B | `FROM_ENTRANCES` BFS can use it A→B; `TO_EXITS` BFS can use it B→A (reverse). |
| Cycle in parent_station chain | `getIncludingStation` caps at 3 iterations to avoid infinite loops. |
| Stop referenced in pathway but not in stops.txt | BFS visits the ID but the stop is absent from the stop iteration; no notice for that ID. |
| `stop_name` absent | Java sets it from `location.stopName()` which may be empty string; Python should use null-safe access. |

## 6. Test contracts

### `unreachablePlatforms_yieldsNotice`

Setup: Station (row 10), platforms 11/12/13 under it, entrance 14 under it. Pathways: 11→14 unidirectional, 14→12 unidirectional.

- Platform 11: reachable from entrance? No (`FROM_ENTRANCES` BFS starts at 14, reaches 12 only). Can it reach entrance? Yes (11→14). `has_entrance=false, has_exit=true` → notice.
- Platform 12: reachable from entrance? Yes (14→12). Can it reach entrance? No (no outgoing path back). `has_entrance=true, has_exit=false` → notice.
- Platform 13: no pathway connections at all. `has_entrance=false, has_exit=false` → notice.

Expected: exactly 3 notices, one per platform, with correct boolean flags.

### `unreachableGenericNodes_yieldsNotice`

Same topology as above but with `location_type == 3` (GENERIC_NODE) instead of STOP. Result is identical — 3 notices.

### `reachablePlatform_yieldsNoNotice`

Station (10), platform 11, entrance 12. Pathways: 11→12 unidirectional AND 12→11 unidirectional. Platform 11 can be reached from entrance 12 (12→11 path for `FROM_ENTRANCES`) and can reach entrance 12 (11→12 for `TO_EXITS`). No notice.

### `bidirectionalPathway_yieldsNoNotice`

Station (10), platform 11, entrance 12. Single pathway 11→12 BIDIRECTIONAL. BFS `FROM_ENTRANCES`: starts at 12, uses bidirectional edge to reach 11. BFS `TO_EXITS`: starts at 12, uses bidirectional edge to reach 11. Both true → no notice.

### `unidirectionalPathway_yieldsNotice`

Station (10), platform 11, entrance 12. Single pathway 11→12 UNIDIRECTIONAL. BFS `FROM_ENTRANCES`: starts at 12, no outgoing edge from 12 → 11 not reached (`has_entrance=false`). BFS `TO_EXITS`: starts at 12, reverse of 11→12 is 12→11 but `TO_EXITS` looks for `to_stop_id == curr` which is `to_stop_id == 12` matching the 11→12 pathway, so it follows to `from_stop_id` = 11 → 11 reached (`has_exit=true`). Result: notice with `has_entrance=false, has_exit=true`.

### `reachableBoardingAreas_yieldsNoNotice`

Station (10), platform 11 (child of 10), boarding areas 12 and 13 (children of 11), entrance 14 (child of 10). Pathways: 12↔14 bidirectional, 13↔14 bidirectional. Platform 11 is skipped (has boarding area children). Boarding areas 12 and 13 are each reachable from and can reach entrance 14. No notices.

### `unreachableBoardingArea_yieldsNotice`

Same structure but only pathway 12↔14 bidirectional (no pathway for boarding area 13). Boarding area 13: `has_entrance=false, has_exit=false` → 1 notice. Platform 11 still skipped (has boarding area children). Boarding area 12 fully reachable → no notice.

## 7. Implementation notes

### Algorithm choice

The core logic requires graph BFS, which is inherently sequential and graph-structural. Use plain Python with sets and a `collections.deque` for both BFS passes. Do not attempt to vectorize this with Polars — the graph traversal has no natural Polars representation.

Pre-processing steps (building adjacency maps and parent-chain lookups) can use Polars to construct dictionaries efficiently.

### Recommended data structures

Build these once before the BFS:

```python
# From pathways.txt:
from_stop_to_pathways: dict[str, list[tuple[str, int]]]  # from_stop_id -> [(to_stop_id, is_bidirectional)]
to_stop_to_pathways:   dict[str, list[tuple[str, int]]]  # to_stop_id   -> [(from_stop_id, is_bidirectional)]

# From stops.txt:
stop_by_id:   dict[str, dict]      # stop_id -> row dict (location_type, parent_station, ...)
children_of:  dict[str, list[str]] # parent_station -> [child stop_ids]
```

### `get_including_station` helper

```python
def get_including_station(stop_id: str, stop_by_id: dict) -> str | None:
    for _ in range(3):
        stop = stop_by_id.get(stop_id)
        if stop is None:
            return None
        if stop["location_type"] == 1:  # STATION
            return stop_id
        parent = stop.get("parent_station")
        if not parent:
            return None
        stop_id = parent
    return None
```

### BFS helper

```python
from collections import deque

def bfs_from_entrances(
    entrances: list[str],
    from_map: dict[str, list[tuple[str, int]]],
    to_map:   dict[str, list[tuple[str, int]]],
    direction: str,  # "FROM_ENTRANCES" or "TO_EXITS"
) -> set[str]:
    visited: set[str] = set(entrances)
    queue: deque[str] = deque(entrances)
    while queue:
        curr = queue.popleft()
        # Follow forward edges from curr
        for to_id, is_bidir in from_map.get(curr, []):
            if direction == "FROM_ENTRANCES" or is_bidir == 1:
                if to_id not in visited:
                    visited.add(to_id)
                    queue.append(to_id)
        # Follow reverse edges into curr
        for from_id, is_bidir in to_map.get(curr, []):
            if direction == "TO_EXITS" or is_bidir == 1:
                if from_id not in visited:
                    visited.add(from_id)
                    queue.append(from_id)
    return visited
```

### Platform-with-boarding-areas check

A platform (STOP, `location_type == 0`) is skipped if it has any children in `children_of`. This can be precomputed:

```python
platforms_with_boarding_areas = {
    pid for pid, children in children_of.items()
    if any(stop_by_id.get(c, {}).get("location_type") == 4 for c in children)
}
```

Or more simply: a STOP is skipped if `children_of.get(stop_id, [])` is non-empty (any child type suffices based on Java's `byParentStation` which returns all children regardless of type).

### Null semantics

- A stop with no `parent_station` cell (null) is treated as having no parent — the `get_including_station` walk terminates.
- `stop_name` may be null for some location types; include it as-is in the notice fields.
- `is_bidirectional` should be cast to integer; treat null as unidirectional (0).

### Location type constants

| Name | Integer |
|---|---|
| STOP (platform) | 0 |
| STATION | 1 |
| ENTRANCE | 2 |
| GENERIC_NODE | 3 |
| BOARDING_AREA | 4 |

### Performance

For large feeds, pre-build all dictionaries in a single Polars pass over each table, then execute the BFS in pure Python. The BFS itself is O(V + E) over the pathway graph and will be fast in practice.
